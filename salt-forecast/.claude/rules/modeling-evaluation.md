# 모델링과 채점

## 1. 무엇을 예측하나

- 대상: 종목 × 기간 h ∈ {1, 2, 3, 4주} 의 **로그수익률** `r = ln(P[t+h] / P[t])`.
  가격을 직접 예측하지 않는다(종목 간 스케일이 달라 학습이 깨진다). 가격 · 원화는 **서버가** 분위수에서 되돌린다.
- 출력: 분위수 q ∈ {0.05, 0.10, 0.25, 0.50, 0.75, 0.90, 0.95} + `P(r > 0)` + (보유) 규칙 가격 도달 확률. 화면 기본 = 90% 구간(q05~q95).
- **분위수 교차 금지**: 저장 전 정렬(`np.sort`)로 단조성을 강제하고, 교차 발생 수를 기록한다.
- 한 점 예측(평균 · 목표가)은 **저장하지 않는다**(ADR-003). 중앙값은 분위수의 하나일 뿐이다.

## 2. 모델 계층

| 순서 | 모델 | 왜 |
|---|---|---|
| 0 | **기준 A — 무작위 보행**: 중앙값 0, 과거 변동성 × √h 정규 분위수 | 이걸 못 이기면 예측이 아니다 |
| 0 | **기준 B — 경험 분위수**: 최근 N주 h-주 수익률의 경험 분위수 | 변동성 군집 · 꼬리를 공짜로 반영 |
| 0 | **기준 C — ETS 변동성 구간**(`statsforecast`) | 리서치 §4.3 권장 기준 |
| 1 | 분위수 GBM(LightGBM `objective=quantile`) — 가격 · 수급 · 공시 · 내부자 · 온체인 · 감성 피처 | 주력 |
| 2 | (선택) Chronos-Bolt small 제로샷(Apache-2.0, CPU) | 구간 폭 보조. 방향은 거의 동전(리서치 §2.2) — 기준 대비 양수일 때만 앙상블. **Moirai(CC-BY-NC) 금지** |
| 최종 | 분위수 평균/가중 앙상블 → **conformal 보정**(MAPIE ACI — 분포 변화에 적응) | 커버리지를 명목에 맞춘다 |

**복잡한 모델은 단순 모델을 채점으로 이겼을 때만 들어간다.** "최신 논문 모델"은 근거가 아니다.

## 3. 워크포워드

- 학습 창: 최근 3~5년, **종목 풀링 패널 하나**(종목별 모델 금지 — 표본이 모자라 과적합). 풀링 종목이 200개 미만이면 LightGBM 을 켜지 않고 기준 + conformal 만. 재학습: 주 1회(주말), 예측 · 보정 갱신: 매일.
- 검증: 한 주씩 전진. 엠바고 h 주(`time-and-leakage.md` §4).
- 보정 잔차 창: 최근 52주 out-of-sample 잔차.
- **리포트**: `reports/<model>-<version>-<as_of>.md` — 종목 × h 별 지표 표 + 기준 대비 + 표본 수 + 선택 방식.
  리포트는 커밋한다. 모델 등록의 근거다.

## 4. 지표

| 지표 | 정의 | 화면 |
|---|---|---|
| 방향 적중 | `sign(q50) == sign(r)` 비율 (r=0 은 제외, 제외 수 기록) | "방향 적중 56%" |
| 구간 커버리지 | `q05 <= r <= q95` 비율 (명목 90%), 보조로 q10~q90 (80%) | "실제 89% 맞음" |
| 구간 폭 | 중앙값 `q95 − q05` (로그수익률) · 같은 커버리지 기준 모델 폭 | "±9% · 단순 예측(±13%)보다 31% 좁음" |
| 선택적 방향 | 임계 넘은 주만 판정 — 판정 수 · 적중 수 · abstain 수 | "52주 중 14주 판정 · 10번 맞음" |
| pinball loss | 분위수별 평균 | "기준 모델보다 오차 12% 작음" (= 1 − 모델/기준A) |
| CRPS 근사 | 분위수 pinball 합 | 내부 |
| 확률 보정 | `P(r>0)` 의 신뢰도 곡선(10분위) · Brier | 내부 |

- **적중률은 단독으로 내보내지 않는다.** 커버리지는 폭 · 기준 폭과, 방향 적중은 판정 수 · 항상 오른다 비율과 한 행으로 저장 · 제공한다. 넓혀서 맞히는 것, 쉬운 주만 골라 맞히는 것을 숨기지 않기 위해서다(FEATURE-008 FR-10).
- 모든 지표에 **표본 수**와 **95% 신뢰구간**(부트스트랩)을 같이 저장한다. 표본 < 26 이면 화면 판정에 쓰지 않는다.
- **현실 목표는 주간 방향 52~55%**(리서치 §0). 60% 를 넘으면 먼저 `time-and-leakage.md` §6 을 다시 돌린다.
- **라이브 52주 전의 성적은 "백테스트" 로 표시**하고 라이브 채점과 섞지 않는다(`score.kind = backtest | live`). 표본 52 의 적중률 표준오차가 약 7%p 다.
- 방향 적중은 **50% 가 기준이 아니다** — 같은 기간 상승 비율(항상 "오른다" 전략)과 비교한다. 상승장에선 그게 60% 일 수 있다.

## 5. 자동 소등 (ADR-003 §3 · FEATURE-008 FR-6)

종목 × h 마다 매일 판정해 `forecast.gate` 에 쓴다.

| 조건 | `blocked_reason` |
|---|---|
| 채점 표본 < 26 주 | `insufficient_sample` |
| 최근 26주 pinball ≥ 기준 A | `underperforms_baseline` |
| 최근 26주 90% 구간 커버리지 < 80% 또는 > 97% | `miscalibrated` |
| 최근 26주 90% 구간 폭 ≥ 기준 A 폭(같은 커버리지) | `not_sharper_than_baseline` |
| 입력 데이터 신선도 초과(`data-pipeline.md` §4) | `stale_inputs` |

소등은 **자동**, 재점등도 자동(조건 해소 시). 사람이 강제로 켜는 플래그를 만들지 않는다.

## 6. 모델 버전

- `model_version = "<name>@<semver>+<git short sha>"`. 피처 목록 · 하이퍼파라미터 · 학습 창을 `forecast.model` 행에 JSON 으로.
- 예측 · 채점 행마다 버전. **버전을 섞어 지표를 내지 않는다.**
- 아티팩트는 `artifacts/<version>/`(gitignore) + 해시를 DB 에. 로드 시 해시 불일치면 실패.

## 7. 피처 규칙

- 피처 함수 하나 = 이름 하나 = 테스트 하나. 이름은 `<source>_<what>_<window>` (`insider_net_sell_krw_90d`).
- 결측은 **결측으로** 둔다(LightGBM 이 다룬다). 0 으로 채우면 "매도 0건"과 "데이터 없음"이 같아진다.
- 규모가 다른 종목끼리 쓰는 값은 비율 · 순위로(`시가총액 대비 자사주 처분 비율`).
- 피처 중요도를 리포트에 남긴다 — 해설 에이전트가 "무엇이 전망을 움직였나"를 말할 근거(`getForecast` 도구의 `drivers`).

## 8. 하지 않는 것

- 테스트 기간 성적을 보고 모델 · 피처 고르기 (그 기간은 이미 학습에 쓴 것이다)
- 적중률이 높아 보이는 종목만 골라 켜기 — 소등 규칙만이 켜고 끈다
- 백테스트 거래 전략 수익률을 모델 성적으로 표시 — 우리는 분포를 채점한다
