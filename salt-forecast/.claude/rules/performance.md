# 성능

배치라도 느리면 매일 못 돈다. 예산을 넘으면 validate 에서 실패로 본다.

## 1. 예산 (로컬 M 시리즈 CPU 기준, 체크리스트에 실측을 붙인다)

| 작업 | 규모 | 예산 |
|---|---|---|
| 일봉 백필 | 업비트 원화 마켓 ~300종목 × 4년 | < 10분 (API 한도가 병목 — 초당 8 요청) |
| 일봉 증분 수집 | ~300종목 × 최근 봉 | < 1분 |
| 워크포워드 백테스트 | ~300종목 × ~150주 × 4기간 × 모델 2 | < 5분 · 피크 메모리 < 2GB |
| 매일 예측 + 채점 + 게이트 | ~300종목 × 4기간 | < 1분 |
| 서버가 읽는 `v_forecast_card` 한 종목 | 4행 | p95 < 50ms (`EXPLAIN (ANALYZE, BUFFERS)` 첨부) |

## 2. 계산

- **한 번 읽고 메모리에서 돈다.** 작업 시작 시 필요한 시계열을 한 쿼리로 읽는다. 루프 안에서 DB 를 부르지 않는다(N+1 금지).
- 종목 루프 안에서 **종목과 무관한 계산을 반복하지 않는다** — 풀링 보정 조정량 · 임계 선택은 as_of × 기간마다 한 번.
- 잔차 · 점수는 dataclass 리스트가 아니라 **numpy 배열**로 쌓는다. 파이썬 루프는 종목 · as_of 수준까지만.
- as-of 자르기는 `np.searchsorted`(O(log n)). 매번 마스크로 전체를 훑지 않는다.
- 모델 학습(LightGBM, 슬라이스 20)은 `n_jobs` 를 CPU 수 − 1 로. 파운데이션 모델은 배치 추론.

## 3. DB

- **대량 쓰기는 COPY → 임시 테이블 → `INSERT … ON CONFLICT`** 한 문장(`store/bulk.py`). 행 단위 INSERT 반복 금지.
- 청크 커밋(5만 행)으로 긴 트랜잭션 · WAL 폭증을 막는다.
- 읽기 쿼리는 인덱스를 타는지 `EXPLAIN` 으로 확인한다. `forecast.prediction` 은 `(symbol, horizon_weeks, as_of DESC)`.
- 서버 요청 경로는 **뷰 하나 · 종목 하나**만 읽는다. 집계는 게이트 작업이 미리 해 둔다 — 요청 시 집계 금지.

## 4. 네트워크

- 소스별 pacer 로 한도의 80%. 동시성은 한도 안에서만(업비트는 순차 + pacer 가 한도를 이미 채운다).
- 백필은 재시작 가능해야 한다 — 종목별로 이미 있는 가장 이른 봉부터 이어서.

## 5. 측정

- 모든 작업이 `job_run` 에 `rows` · 소요 시간을 남긴다. 예산은 이 값으로 확인한다.
- 느려졌을 때 추측하지 않고 `python -X importtime` · `cProfile` 결과를 체크리스트에 붙인다.
