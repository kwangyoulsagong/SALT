# FC-REQ-008 회고 — 규칙 항목별 IC

- **사전등록을 결과보다 먼저 커밋한 것이 실제로 쓸모 있었다.** 단타 총점이 거꾸로 맞힌다는 결과는 "규칙을 조금 손보면 맞겠다"는 유혹을 만든다.
  판정 규칙(반대 → 부호 반전, 0 포함 → 가중 0)이 이미 커밋돼 있어서 결과를 보고 규칙을 고를 여지가 없었다
- **구현된 규칙 그대로를 재현했다**(RSI `losses || 1` · 공포탐욕 0 무시). 고쳐서 재면 지금 화면이 내는 판단의 성적이 아니다. 대신 규칙이 두 벌이 됐다 —
  서버 특성화 테스트 값을 Python 테스트가 똑같이 주장하는 것으로 묶었다. 서버 규칙 버전을 올리면 여기 재현도 버전을 올려야 한다
- **"더 긴 데이터" 요청을 용량으로 번역한 게 맞았다.** 4년치 aggTrades 는 수백 GB, 1년 30종목은 25분이었다. 일봉 · 공포탐욕 · 테이커는 호출 몇 번이라
  같이 받았고, 그 덕에 공포탐욕 판정은 8년치로 냈다
- 고래 1년치 결과는 CI 가 넓다(±0.03). "고래가 틀렸다"가 아니라 **"1년 30종목으로는 0 과 구별할 수 없고, 점추정은 음수"** 다. 라이브 원장이 업비트
  원문으로 다시 잰다
- 누수 테스트가 우연히 통과했던 것을 코드를 다시 읽다 발견했다. **통과한 테스트도 구성을 한 번 의심한다** — 특히 문턱 함수는 입력이 달라도 출력이 같기 쉽다
