# FC-REQ-012 회고 — 목표 비중 안내 규칙 과거 성적 (F010 슬라이스 5, 2026-09-29)

## 결과

리서치 §4-1 이 인용한 외부 결과("변동성 스케일링만으로 최악 손실 84% → 17%")는 이 시장에서도 방향은 맞았다(−86 → −36%, 목표 σ 15%).
다만 **두 가지가 외부 인용보다 나빴다**: 수익이 BTC 보유 아래이고(11.5 vs 18.6%), 같은 평균 비중을 고정으로 둔 것과 차이가 증명되지
않는다. 즉 이 규칙이 주는 것은 "얼마를 들고 있나"이지 "언제"가 아니다. 화면 문구도 그렇게 등록했다(`[claims]` timing).

**알트를 섞으면 나빠진다**는 결과가 가장 컸다. 사용자 결정(보유 + BTC · ETH)대로 서버는 보유 알트에도 비중을 주는데, 그 조합의 기록은
화면에 쓰지 않도록 결과 전에 정해 두었다. 이것은 다음 등록의 첫 질문이다.

## 잘 된 것

- 결과 전에 "화면이 쓸 수 있는 문장"까지 등록했다 — 타이밍 몫이 0 이라는 결과를 보고도 문구를 고르지 않고 "증명하지 못했어요"를 그대로 쓴다
- 서버 · Python 이 같은 고정 벡터를 테스트해 규칙이 두 벌로 갈라지지 않는다. 서버 상수는 리포트 표와 테스트가 대조한다
- 실데이터로 서버를 돌려 보다가 **서버가 게이트된 σ(`annualized`)를 읽어 ETH 가 빠지는 것**을 찾았다 — 등록 정의(EWMA)로 고쳤다(`SRV-REQ-024` FR-183)

## 아쉬운 것

- 첫 고정 벡터를 손으로 틀리게 적었다(묶음 σ 를 잘못 셈). 닫힌 꼴(w = 목표 ÷ (n σ))을 먼저 적었으면 바로 맞았다
- 누수 테스트 첫 판이 난수 소비 순서 때문에 과거 봉까지 바꿨다 — 흔드는 난수는 따로 두어야 한다
- core_alts 의 "평균 비중 고정" 기준은 순환하는 알트 전체에 평균 비중을 두어 상장 전 종목이 현금처럼 앉는다 — 등록 정의 그대로 돌렸지만 이 기준은 약하다

## Action

- `target-weight@2` 를 등록할 때: (a) 알트를 안내에서 빼거나 알트 몫 기록을 고지에 쓰는 규칙을 결과 전에 (b) core 모델 포트폴리오 매일 발행(라이브 채점)
- 고정 벡터는 닫힌 꼴로 적고 테스트 주석에 식을 둔다
- 누수 테스트의 흔들기 난수는 별도 시드
