# 모바일 성능 규칙 (React Native)

## 0. 웹과 다른 전제

| 조건 | 결과 |
|---|---|
| 기기 성능 폭이 넓다 | 저가 Android가 하한선이다. 시뮬레이터로 판단하지 않는다 |
| 네트워크가 끊긴다 | 캐시와 오프라인 표시가 성능 요구의 일부다 |
| JS 스레드가 하나다 | 무거운 계산이 프레임을 떨어뜨린다 |
| 앱 시작이 사용자에게 보인다 | 웹의 첫 페인트보다 체감 비중이 크다 |

## 1. 예산

| 지점 | 예산 | 측정 방법 |
|---|---|---|
| 콜드 스타트 → 첫 화면 | **2s** | 저가 Android 실기기 |
| 웜 스타트 | 600ms | |
| 탭 전환 | 200ms | 3탭 간 |
| 리스트 스크롤 | **60fps** | 보유 목록 · 거래 내역 · 대화 |
| 코치 첫 토큰 도착 | 1s | SSE |
| 대화 스크롤(메시지 200개) | 60fps | |
| 입력 → 화면 반영 | 100ms | |
| OTA 번들 다운로드 | 3s (LTE) | |
| JS 번들 크기 | **4MB 이하** (Hermes 바이트코드) | 넘으면 `rn-microfrontend.md` Phase 2 검토 |

## 2. 앱 시작

- **Hermes를 켠다.** JS를 사전 컴파일하면 파싱 비용이 사라진다.
- 스플래시에서 첫 화면까지 **네트워크를 기다리지 않는다.** 마지막 캐시를 먼저 그리고 갱신한다.
- `src/app`의 프로바이더에서 무거운 초기화를 하지 않는다. 필요한 시점에 lazy로 만든다.
- 폰트·아이콘을 번들에 넣고 런타임 다운로드를 하지 않는다.

## 3. 리스트

- **`FlatList`/`FlashList`를 쓴다.** `ScrollView`에 100개를 넣지 않는다.
- `keyExtractor`를 안정된 id로 준다. index 금지.
- 행 컴포넌트를 `memo`로 감싼다 — **여기는 예방적 메모가 정당한 자리다.** 리스트 행은 부모 갱신마다 전부 리렌더되고, 그 비용이 측정 없이도 확실하다.
- `getItemLayout`을 줄 수 있으면 준다. 스크롤 점프가 사라진다.
- 이미지(코인 로고)는 크기를 고정하고 캐시한다.

## 4. 대화 화면 — 이 앱의 고유 위험

코치 대화가 제품의 핵심이고, **스트리밍 중 매 토큰마다 리렌더**될 수 있다.

- 스트리밍 텍스트는 **마지막 말풍선만** 갱신한다. 리스트 전체를 다시 그리지 않는다.
- 토큰을 **버퍼링해서 프레임 단위로 반영**한다. 토큰마다 setState하면 JS 스레드가 막힌다.
- 메시지 목록은 역순 `FlatList`(`inverted`)로 두고 위로 페이징한다.
- 대화 히스토리를 무한히 메모리에 두지 않는다. 화면에서 멀어진 것은 잘라낸다.

## 5. 금액 계산은 JS 스레드에서 하지 않는다

세금 시나리오 슬라이더가 유일한 클라이언트 재계산이다(`fsd-features.md`).

- 계산은 순수 함수로 두고 **`InteractionManager` 또는 프레임 예산 안에서** 돌린다.
- 슬라이더를 놓을 때 서버 값과 대조한다. 대조 요청이 프레임을 막지 않게 비동기로 띄운다.
- 그 외 모든 금액은 **서버가 계산한다.** 앱에서 반사실·취득가액·솔버를 돌리지 않는다.

## 6. 이미지와 애니메이션

- `transform`·`opacity`만 애니메이션한다. `react-native-reanimated`를 쓰면 **UI 스레드**에서 돌게 한다.
- 리스트 스크롤 중 애니메이션을 동시에 돌리지 않는다.
- 기기 접근성 설정(감소된 모션)을 존중한다. 로딩 표시는 멈추지 않고 느려진다.

## 7. 메모리

- 차트·큰 이미지·대화 히스토리가 누수의 주범이다. 화면 언마운트 시 정리한다.
- 이미지 캐시 상한을 둔다. 코인 로고가 수천 개 쌓일 수 있다.
- **저가 Android에서 백그라운드 복귀 후 강제 종료되는지** 확인한다. 그게 메모리 문제의 실제 증상이다.

## 8. 측정

- **실기기에서 측정한다.** 저가 Android 1대를 기준 기기로 정하고 그 수치를 기록한다.
- Flipper/DevTools의 프레임 그래프로 60fps 이탈 지점을 찾는다.
- 릴리스 빌드로 측정한다. 개발 빌드는 느리고 그 수치는 쓸 수 없다.
- 성능 수정 커밋에 before/after 수치를 남긴다.

## 9. 번들이 커지면

`rn-microfrontend.md` Phase 2(Re.Pack 5 + Module Federation 2) 도입 조건 중 하나가 **번들 크기로 초기 로딩 예산 초과**다. 그 판단을 감으로 하지 않는다 — §1의 4MB와 콜드 스타트 2s를 측정값으로 확인한 뒤 검토한다.
