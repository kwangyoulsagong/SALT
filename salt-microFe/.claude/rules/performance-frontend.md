# 웹 성능 규칙

## 0. 측정 없이 최적화하지 않는다

`memo` · `useMemo` · `useCallback`을 **예방적으로 붙이지 않는다.** 비교 비용과 코드 노이즈는 확실하고 이득은 불확실하다.

```
느리다는 관찰 → Profiler 로 원인 특정 → 고침 → 다시 측정 → 커밋 메시지에 수치 기록
```

## 1. 예산 — 넘으면 성능 작업이 필요하다

| 지점 | 예산 | 근거 |
|---|---|---|
| 홈 **첫 블록** 페인트 | **300ms** | 스트리밍 이득의 판정 기준 (`streaming-ssr.md` §6) |
| 홈 전체 완료 | 1.5s | 청구서 스냅샷 미스가 최악 케이스 |
| 코치 대화 첫 페인트 | 400ms | 최신 insight 읽기 |
| 코치 첫 토큰 도착 | 1s | SSE. 이후 스트리밍 |
| 세금 콕핏 조회 | 600ms | D-Day 칩은 즉시(클라이언트 계산) |
| 손실수확 솔버 | 500ms | 종목 50개 기준 |
| 청구서(스냅샷 히트) | 300ms | 스냅샷 미스는 1.5s |
| 라우트 전환(같은 zone) | 200ms | soft navigation |
| zone 전환(`/tax`) | **예산 제외** | hard navigation. 별도 측정 |
| 입력 → 화면 반영 | 100ms | 검색 · 슬라이더 |
| 실시간 테이블 스크롤 | 60fps | 100행 + WS 갱신 |
| 연말 시가 슬라이더 | 60fps | 클라이언트 재계산 |

## 2. 실시간 테이블 — 이 앱의 고유 위험

`limit=100`으로 100행을 받고 **WebSocket으로 초당 여러 번 갱신**된다. 변동률 blink 2초 애니메이션이 붙어 있다(변경 금지).

- **행 컴포넌트를 셀 단위로 쪼갠다.** 가격 셀만 바뀔 때 행 전체가 리렌더되면 100행 × 초당 N회다.
- WS 메시지를 **throttle**한다(`@repo/ui/useThrottle`). 화면 갱신 주기는 60fps 이상 필요하지 않다.
- **100행은 가상화 임계값 경계다.** 서버 페이징이 이미 있으므로 가상화 전에 페이징을 먼저 검토한다. 가상화하면 `Ctrl+F`가 안 먹는다.
- blink는 `transform`/`opacity`만 쓴다. `background-color` 애니메이션은 페인트를 유발한다.
- 리스트 `key`에 index를 쓰지 않는다 — 정렬·필터 5종이 있어 전부 재마운트된다.

## 3. 차트

`lightweight-charts`는 클라이언트 전용이고 무겁다.

- **`next/dynamic` + `ssr: false`.** 초기 번들에 들어가면 첫 화면이 그만큼 늦어진다.
- 차트 인스턴스를 **재사용**한다. 종목을 바꿀 때 새로 만들지 않고 데이터만 교체한다.
- 언마운트 시 `remove()`를 호출한다. 안 하면 종목을 여러 번 바꿀 때 메모리가 샌다.
- 5분봉 + 실시간 캔들 수신은 동작이 확인된 코드다(변경 금지). 성능 작업 시 **동작을 먼저 보존**한다.

## 4. 스트리밍 SSR 관련

- Suspense 경계는 **화면당 5개 이하**. 많으면 레이아웃 시프트가 늘고 TTFB 이득이 사라진다.
- **스켈레톤 높이 = 실제 블록 높이.** CLS를 만들면 스트리밍 이득이 상쇄된다.
- `"use client"` 경계 오설정이 번들을 키운다. 이관 전/후 클라이언트 JS gzip을 기록하고 **증가분 40KB 이하**.
- 서버 컴포넌트에서 부르는 BFF 호출은 병렬로 띄운다. `await`를 연달아 쓰면 서버 워터폴이 된다.

## 5. 리렌더

- **Zustand는 필요한 값만 구독한다.** 전체 store 구독 금지. 여러 값은 `useShallow`.
- **React Query는 `select`로 좁힌다.** 리스트 전체를 구독하고 컴포넌트에서 `.find()` 하면 무관한 항목 변경에도 리렌더된다.
- Context에 자주 바뀌는 값을 넣지 않는다. 넣어야 하면 값 Context와 액션 Context를 분리한다.

## 6. React Query

- `staleTime`을 **명시적으로** 준다. 기본값 0이면 포커스마다 재요청한다.
- 서버 컴포넌트가 준 데이터를 **다시 요청하지 않는다**(`fsd-app.md` 역할 분담).
- **폴링에는 중단 조건을 함께 쓴다.** 코치 재생성 상태 폴링은 완료·실패에서 `refetchInterval: false`.
- 긴 요청(반사실 계산·솔버·LLM)에 `AbortSignal`을 연결한다. 화면을 떠난 뒤에도 도는 요청이 서버 CPU를 먹는다.

## 7. 번들

- **라우트 단위 코드 분할**이 기본이다.
- 별도 청크로 강제할 것: `lightweight-charts` · `MovableGrid` · Storybook 관련 코드.
- `@repo/ui`는 subpath별 export이므로 **import한 것만 들어온다.** barrel로 다시 묶지 않는다.
- 세금 zone에만 필요한 코드(솔버·환율 로직)가 **default zone 번들에 들어가면 zone 분리가 무의미**하다. 빌드마다 확인한다.
- 새 의존성 추가 시 **번들 증가분을 PR에 적는다.**

## 8. 애니메이션

- `transform`과 `opacity`만 애니메이션한다.
- 스크롤·리사이즈 핸들러에서 레이아웃 속성(`offsetWidth`)을 읽지 않는다. 읽어야 하면 `requestAnimationFrame`으로 묶는다.
- `prefers-reduced-motion`을 존중한다. 단 **로딩 표시는 멈추지 않고 느려진다** — 필수 피드백이다.

## 9. 측정 기록 의무

성능 수정 커밋에는 **before/after 수치**를 남긴다. 없으면 다음 사람이 되돌린다. 예산 관련 측정값은 `requirements/reports/checklists/<REQ-ID>.md`에 넣는다.
