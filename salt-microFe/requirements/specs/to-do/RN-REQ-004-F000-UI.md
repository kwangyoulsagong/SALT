## Summary

모바일에는 **수리할 기존 화면이 없다** — 앱이 새로 생긴다. 그래서 F000의 모바일 작업은 **웹의 수리 결과를 처음부터 올바르게 구현하는 것**이다. 웹이 고생해서 고친 것(터치 선택·반응형·하드코딩·더미)을 모바일은 처음부터 안 만든다.

가장 큰 설계 결정: **웹의 5컬럼 실시간 테이블을 좁은 화면에 어떻게 넣을지.**

## 실시간 시세 — 5컬럼을 어떻게 넣는가

웹은 5컬럼 표(현재가·변동률·최고가·최저가·거래대금) + 우측 392px 프리뷰다. 모바일 폭에서 그 표는 읽을 수 없다.

| 후보 | 판정 |
|---|---|
| 5컬럼 표를 가로 스크롤 | ✗ 세로 스크롤과 충돌한다. 한 손으로 못 쓴다 |
| 컬럼을 3개로 줄인다 | ✗ 웹과 정보가 달라진다. "같은 정보"라는 IA 원칙에 어긋난다 |
| **행을 2줄 카드로 재구성** | **✓ 채택.** 1줄: 로고·종목명·현재가·변동률 / 2줄: 최고·최저·거래대금(작게) |
| 종목 상세를 push | ✓ 병행. 행 탭 → 상세 화면(차트·게이지·뉴스) |

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | 시세 목록 행을 **2줄 카드**로 구성한다. 1줄에 로고·종목명·현재가·변동률, 2줄에 최고·최저·거래대금 | Must |
| FR-2 | **정보를 줄이지 않는다.** 웹의 5컬럼 값이 전부 보인다 | Must |
| FR-3 | **변동률 blink 2초**를 모바일에서도 구현한다. 웹의 변경 금지 목록과 같은 시각 언어 | Must |
| FR-4 | 색 토큰: 상승 `#FF2E55` / 하락 `#1677EE`. `@repo/tokens`에서 온다 | Must |
| FR-5 | 필터(정렬 5 / 순서 2 / 기간 7)를 **`BottomSheet`** 로 제공한다. 화면 상단에 필터 칩 3개를 늘어놓지 않는다 | Must |
| FR-6 | 행을 탭하면 **종목 상세를 push**한다. 상세에 차트·심리 온도계·스마트 머니 게이지·뉴스 | Must |
| FR-7 | 별 아이콘으로 관심 종목을 추가/제거한다. 터치 타깃 **44×44 이상** | Must |

## UX 상태

> **개정 2026-09-21** — 투자 화면 상태를 블록 단위로 넓혔다(기본안 — 감사 문서 B22, 웹 `FE-REQ-010` FR-100~107 과 같은 원칙). 모바일은 웹과 달리 **오프라인 배너가 있다**(persist 캐시가 있으므로).

- **Loading**: 시세 목록 스켈레톤. 캐시 있으면 먼저
- **Loading (검색)**: 첫 요청만 3행 스켈레톤, 이후 이전 결과 유지 + 검색바 스피너
- **Error (시세 목록)**: **빈 목록 금지.** "시세를 불러오지 못했어요" + 다시 시도. 캐시가 있으면 캐시 + 배너
- **Partial (종목 상세)**: 차트 · 게이지 · 뉴스 중 실패한 블록만 오류. 나머지는 렌더
- **Empty (검색 0건)**: "'{q}' 와 맞는 종목이 없어요"
- **Empty (북마크 0건)**: "북마크한 뉴스가 없어요 · 기사의 ☆ 를 눌러 모으세요"
- **Limit (추적 상한)**: ★ 되돌림 + 인라인 안내 · 카운터 `10 / 10`
- **Offline (검색 · 북마크)**: 검색바 비활성 + "오프라인에서는 검색할 수 없어요". ★ · ☆ 비활성(RN-REQ-005 FR-53)
- **Empty (관심 종목 0건)**: "시세 목록에서 별을 눌러 추가하세요" + `🔍 종목 검색` 버튼(개정 2026-09-21). 보유가 있으면 0건이 아니다
- **Empty (뉴스 0건)**: "관련 뉴스가 없습니다". 더미 0건
- **Empty (온보딩 미완료)**: 온보딩 카드 1개
- **Offline**: 캐시 + "오프라인 · {시각} 기준"
- **Error (WS 끊김)**: 헤더에 표시 + 재연결 시도
- **Optimistic update**: 별 아이콘 · ☆ 북마크만 허용(개정 2026-09-21)
