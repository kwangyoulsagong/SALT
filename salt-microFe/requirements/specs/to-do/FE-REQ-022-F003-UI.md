## Summary

**화면에 숫자 하나.** "이번 주 BTC에 375,000원." 그게 끝이다. 나머지는 근거다. 그리고 **실패 이력이 없으면 배수 카드를 렌더하지 않는다.**

## FSD 배치

| 레이어 | 슬라이스 | 컴포넌트 |
|---|---|---|
| `pages` | `home` · `assets` | 홈 블록 + 적립 상세 |
| `widgets` | `home-briefing` | 홈 ② 블록 |
| `features` | `complete-weekly-plan` | 적립 완료 체크 |

## 화면 구조

```
홈 ② 블록
  이번 주 적립 475,000원
  BTC 375,000 · VOO 100,000            [자세히]

적립 상세 (자산 탭 또는 홈에서 push)
┌─ 이번 주 적립 475,000원  (큰 숫자)
├─ 자산별 분해
│   BTC — 기본 125,000원 × 3.0배 = 375,000원
│     근거: MVRV Z −0.3 → 극단 저평가 밴드(Z < 0)
│           과거 4개 사이클 바닥이 이 구간에서 나왔습니다
│     [실패 이력 보기 ▾]  ← 없으면 이 카드가 렌더되지 않는다
│   VOO — 기본 200,000원 × 0.5배 = 100,000원
│     근거: CAPE 40.6 → 98.8 퍼센타일
├─ 김프 게이지
│   업비트 BTC vs 바이낸스 +1.2%
│   375,000원 중 약 4,500원이 프리미엄 비용입니다
├─ 밴드 표 (5밴드 × 배수 × 현재 위치)
├─ 실패 이력 아코디언
│   ✅ MVRV Z 바닥 신호: 2011·2015·2018·2022 4/4 적중
│   ❌ 2025-10 사이클 톱에서 이 지표는 매도 신호를 내지 못했습니다 (이후 −52%)
├─ [이번 주 적립 완료]
├─ 12주 연속 적립 중 · 누적 4,120,000원 · 12주 중 1주 미실행
└─ 국내주식 제외 안내
```

## Requirements

### A. 한 숫자

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | **총액을 가장 크게** 표시한다. 자산별 분해는 그다음 | Must |
| FR-2 | 금액은 **1,000원 단위**다. 서버가 반올림한 값을 그대로 | Must |
| FR-3 | 홈 블록에는 총액 + 자산별 한 줄만. 상세는 push | Must |
| FR-4 | 큰 금액에 `aria-label`("이번 주 적립 사십칠만 오천원") | Must |

### B. 실패 이력 게이트

FEATURE-003 FR-10: *"실패 이력 데이터가 없으면 배수 카드를 렌더하지 않는다."*

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | **`renderable: false`면 배수 카드 대신 회색 박스** + 사유를 표시한다 | Must |
| FR-11 | 사유에 **"이것은 정상 동작입니다"** 를 명시한다 | Must |
| FR-12 | `trackRecordId`가 있으면 **실패 이력 링크를 반드시 노출**한다 | Must |
| FR-13 | **우회 prop이 0건**이다 | Must |
| FR-14 | 게이트가 홈 블록에도 적용된다. 홈에서만 보이고 상세에서 막히면 안 된다 | Must |
| FR-15 | 게이트 미충족이어도 **기본액은 표시**한다. "밴드 조정 없음"이라고 알린다 | Must |

### C. 근거와 밴드

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | 근거 한 줄: **지표값 + 밴드명 + 과거 맥락**. `reasonCode` + `reasonParams`를 i18n으로 조립 | Must |
| FR-21 | `narrative`(LLM 문장)가 있으면 보강으로 보여주고 없으면 규칙 문장만 | Must |
| FR-22 | **밴드 표를 항상 볼 수 있게** 한다. 5밴드 × 배수 × **현재 위치 강조** | Must |
| FR-23 | 밴드 표는 실제 `<table>` + `<caption>` | Must |
| FR-24 | `BandGauge`는 **색 + 밴드명 텍스트 동시 표기**. 색만으로 구분하지 않는다 | Must |
| FR-25 | `secondaryIndicators`(Puell)를 표시하되 **"배수에 반영되지 않음"** 을 명시한다 | Must |
| FR-26 | `staleDays >= 3`이면 **`지표 N일 지연` 배지 + 중립 폴백 안내** | Must |
| FR-27 | 지표 전체 실패 시 **"밴드 조정 없음(지표 조회 실패)"** + 기본액 표시 | Must |

### D. 실패 이력 아코디언

## UX 상태

- **Loading**: 금액 자리 스켈레톤. **밴드 표는 정적이므로 즉시 렌더**
- **Empty (설정 없음)**: 온보딩 1스텝 — "월 얼마씩 넣을 계획인가요?"
- **Stale (지표 3일+ 결측)**: `지표 N일 지연` 배지 + 중립 폴백 안내
- **Warning (김프 ≥ +3%)**: 게이지 강조 + **사실 서술**
- **Warning (0x)**: "이번 주 신규 적립 지시 없음" + 밴드 설명. **매도 지시 0건**
- **Blocked (실패 이력 없음)**: 회색 박스 + 사유 + "정상 동작입니다"
- **Error (지표 전체 실패)**: 기본액 + "밴드 조정 없음"
- **Optimistic update**: **적립 완료 체크만**

## Acceptance Criteria

- [ ] 홈에 이번 주 총액과 자산별 금액이 **1,000원 단위**로 표시된다
- [ ] 총액이 가장 크게 표시된다
- [ ] **`renderable: false`에서 배수 카드 대신 회색 박스 + 사유가 나온다**
- [ ] 사유에 "정상 동작입니다"가 있다
- [ ] `trackRecordId`가 있으면 실패 이력 링크가 노출된다
- [ ] **우회 prop이 0건이다**
- [ ] 홈 블록에도 게이트가 적용된다
- [ ] 게이트 미충족 시에도 기본액이 표시된다
- [ ] 근거 한 줄이 지표값 + 밴드명 + 과거 맥락이다
- [ ] **밴드 표가 항상 보이고 현재 위치가 강조된다**
- [ ] 밴드 표가 실제 `<table>`이다
- [ ] `BandGauge`가 색 + 텍스트 동시 표기다
- [ ] Puell이 "배수에 반영되지 않음"과 함께 표시된다
- [ ] **`staleDays >= 3`에서 배지 + 폴백 안내가 나온다**
- [ ] 지표 전체 실패 시 기본액이 표시된다
- [ ] **실패 이력에 MVRV Z 바닥 4/4와 2025-10 톱 미검출이 있다**
- [ ] hits와 misses가 같은 시각적 비중이다
- [ ] 김프 게이지에 프리미엄 %와 원화 비용이 있다
- [ ] 김프 문구가 **사실 서술**이고 지시형이 0건이다
- [ ] **김프 차익거래 안내가 0건이다**
- [ ] `kimchiPremium: null`에서 적립 숫자가 유지된다
- [ ] 적립 완료 체크가 동작하고 자동 매칭이 반영된다
- [ ] 연속 주차·누적액이 표시된다
- [ ] **미실행 표시에 비난 문구가 0건이고 점수·등급이 0건이다**
- [ ] 적립 완료만 낙관적 갱신이다
- [ ] 설정 저장 후 "다음 계획부터 반영" 안내가 나온다
- [ ] 온보딩에서 월 적립액 하나만 묻는다
- [ ] `excluded[]`에 따라 국내주식 제외가 표시된다
- [ ] **`Z ≥ 7`에서 매도 지시 문구가 0건이다**
- [ ] 375px에서 body 가로 스크롤이 0이다

## Open Questions

- 적립 상세를 **자산 탭 안**에 둘지 **홈에서 push**할지. 3탭 IA에서 별도 탭은 없다 → **홈 블록 → push**가 기본안.
- 밴드 표가 "정적이라 즉시 렌더"라면 **밴드 설정을 클라이언트가 알아야** 한다. 서버 `bandConfig`를 받아야 하므로 완전히 정적이지는 않다.
- `Z ≥ 7` 0x가 장기간 이어지면 화면이 계속 "적립 없음"이다. 그때 무엇을 보여줄지.
