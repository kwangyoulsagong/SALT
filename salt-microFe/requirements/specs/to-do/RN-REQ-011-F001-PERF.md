## Summary

모바일 청구서의 급소는 **3선 그래프 렌더**, **거래 목록 스크롤**, **업로드가 JS 스레드를 막는 것** 셋이다.

## 예산 (저가 Android 실기기)

| 지점 | 예산 | 비고 |
|---|---|---|
| 자산 탭 → 청구서 세그먼트 | **200ms** | 캐시 히트 |
| 캐시 첫 페인트 | **200ms** | persist 읽기 포함 |
| 데이터 도착 | 1.2s | 집계 1콜 350ms + 네트워크 |
| **3선 그래프 렌더** | **300ms** | 다운샘플링된 점 |
| 기간 전환 (캐시 히트) | **150ms** | 쿼리 키 분리 |
| 기간 전환 (캐시 미스) | 1s | |
| 거래 목록 첫 페인트 | 300ms | |
| **거래 목록 스크롤** | **60fps** | `FlatList` |
| 다음 페이지 | 400ms | 커서 |
| 전후 90일 차트 BottomSheet | 400ms | |
| CSV 업로드 (10,000행) | **15s** | BFF 12s + 모바일 네트워크 |
| 폴링 | 2초 간격 · 최대 60초 | |
| persist 읽기 | **100ms** | 초과 시 크기 제한 |

## 급소 1 — 3선 그래프

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | 점 수를 확인한다. 서버 다운샘플링 값이 모바일에 과하면 **추가로 줄인다**(화면 폭 기준 150~200점) | Must |
| FR-2 | `react-native-svg` 기반이면 **path 문자열을 미리 계산**하고 `memo`한다. 매 렌더마다 만들지 않는다 | Must |
| FR-3 | 기간 전환 시 **차트 컴포넌트를 언마운트하지 않고 데이터만 교체**한다 | Must |
| FR-4 | 언마운트 시 정리한다. 기간을 여러 번 바꿀 때 메모리가 새면 안 된다 | Must |
| FR-5 | crosshair 터치 처리가 **프레임을 막지 않게** 값 조회를 O(log n) 이진 탐색으로 한다 | Should |
| FR-6 | 차트 렌더 시간을 측정하고 300ms 초과 시 점 수를 줄인다 | Must |
| FR-7 | `react-native-skia`를 쓸지 결정 전에 **번들 증가분을 측정**한다. `RN-REQ-002` Phase 2 판정에 영향한다 | Must |

## 급소 2 — 거래 목록

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | `FlatList`(또는 `FlashList`). **`ScrollView`에 거래 100건을 넣지 않는다** | Must |
| FR-11 | 행 컴포넌트를 **`memo`로 감싼다.** 리스트 행은 부모 갱신마다 전부 리렌더되고 그 비용이 측정 없이도 확실하다 | Must |
| FR-12 | `keyExtractor`를 `transactionId`로. **index 금지** | Must |
| FR-13 | `getItemLayout`을 줄 수 있으면 준다(행 높이가 고정이면) | Should |
| FR-14 | 다음 페이지 로드 중 **기존 행을 리렌더하지 않는다** | Must |
| FR-15 | 스크롤 프레임을 측정하고 **60fps 유지를 기록**한다 | Must |

## 급소 3 — 업로드가 JS 스레드를 막지 않게

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | **파일 내용을 읽지 않는다.** URI를 넘긴다. 읽으면 20MB가 JS 힙에 올라오고 스레드가 막힌다 | Must |
| FR-21 | 업로드 중 앱 메모리 증가분을 측정한다. **파일 크기에 비례하면 FR-20 위반** | Must |
| FR-22 | 업로드 중 화면이 반응한다. 취소 버튼이 눌린다 | Must |
| FR-23 | 진행률 갱신을 **프레임 단위로 버퍼링**한다. 바이트마다 setState하면 스레드가 막힌다 | Must |

## 캐시와 첫 페인트

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-30 | 화면 진입 시 **캐시를 먼저 그린다.** 네트워크를 기다리지 않는다 | Must |
| FR-31 | persist 읽기가 **100ms 이내**다. 초과 시 저장 범위를 줄인다(기본 window만) | Must |
| FR-32 | 갱신 중에는 인라인 스피너만. **전체 스켈레톤으로 되돌리지 않는다** | Must |
| FR-33 | persist 저장 시 `series`가 큰 window를 제외할지 판단한다 | Must |

## Acceptance Criteria

- [ ] 세그먼트 전환이 200ms 이내다 (측정값 기록)
- [ ] 캐시 첫 페인트가 200ms 이내다
- [ ] persist 읽기가 100ms 이내다
- [ ] **3선 그래프 렌더 < 300ms** (측정값 기록)
- [ ] 점 수가 모바일 화면 폭 기준으로 조정된다
- [ ] path 계산이 `memo`된다
- [ ] 기간 전환 시 차트가 언마운트되지 않고 데이터만 교체된다
- [ ] 언마운트 시 차트가 정리된다 (메모리 누수 0건)
- [ ] 차트 라이브러리 번들 증가분이 기록되어 있다
- [ ] 거래 목록이 `FlatList`이고 행이 `memo`이고 key가 `transactionId`다
- [ ] **거래 목록 스크롤이 60fps다** (측정값 기록)
- [ ] 다음 페이지 로드가 기존 행을 리렌더하지 않는다 (Profiler)
- [ ] **업로드 시 파일 내용을 읽지 않는다** (앱 메모리 증가분이 파일 크기에 비례하지 않음)
- [ ] 업로드 중 화면이 반응하고 취소가 눌린다
- [ ] 진행률 갱신이 프레임 단위로 버퍼링된다
- [ ] 갱신 중 전체 스켈레톤으로 되돌아가지 않는다
- [ ] **폴링 중단 조건 4개가 있다**
- [ ] 폴링 중 차트가 다시 만들어지지 않는다
- [ ] 폴링 횟수 분포가 측정되어 있다
- [ ] 언마운트 시 차트·구독·타이머가 정리된다
- [ ] 거래 목록 페이지 수 상한이 있다
- [ ] **저가 Android 백그라운드 복귀 후 강제 종료가 0건이다**
- [ ] 청구서 화면 번들 비중이 기록되어 있다
- [ ] 측정이 릴리스 빌드 + 기준 기기로 수행되었다
- [ ] 로그에 금액이 0건이다

## Open Questions

- 차트 라이브러리 선택. `react-native-svg`(가볍다) vs `react-native-skia`(빠르지만 번들이 크다). **다운샘플링된 150~200점이면 SVG로 충분**할 가능성이 높다 → 측정 후 결정.
- persist에 `series`를 넣을지. **넣지 않고 오프라인에서는 요약만** 보여주는 것이 크기 문제를 없앤다 → 사용성 판단 필요.
- 거래 목록 페이지 수 상한. 무한 스크롤에서 200건이면 메모리가 문제되지 않을 가능성이 높다.
