## Summary

모바일 F000의 급소는 **시세 목록 100행 × WS 초당 수십 회 갱신 × blink 애니메이션**이다. JS 스레드가 하나이므로 웹보다 위험하다.

## 예산 (저가 Android 실기기)

| 지점 | 예산 | 비고 |
|---|---|---|
| **콜드 스타트 → 첫 화면** | **2s** | 캐시 렌더 |
| 웜 스타트 | 600ms | |
| 탭 전환 | 200ms | |
| 시세 목록 첫 페인트 | **300ms** | 캐시 히트 |
| **시세 목록 스크롤** | **60fps** | 100행 + WS 갱신 + blink |
| **변동률 blink** | **60fps** | 2초 애니메이션 |
| 종목 상세 push | 300ms | |
| 차트 첫 렌더 | 400ms | 5분봉 30개 |
| 필터 BottomSheet 열기 | 200ms | |
| 온보딩 단계 전환 | 150ms | |
| WS 재연결 | 1s | 포그라운드 복귀 |
| 입력 → 화면 반영 | 100ms | |

## 급소 1 — 시세 목록 100행 × WS

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | **`FlatList`(또는 `FlashList`)** 를 쓴다. `ScrollView`에 100행을 넣지 않는다 | Must |
| FR-2 | 행 컴포넌트를 **`memo`로 감싼다.** 리스트 행은 예방적 메모가 정당한 자리다 | Must |
| FR-3 | `keyExtractor`를 심볼로. **index 금지** — 정렬·필터 5종이 있어 전부 재마운트된다 | Must |
| FR-4 | `getItemLayout`을 준다(2줄 카드 높이 고정) | Must |
| FR-5 | **WS 메시지를 프레임 단위로 버퍼링**한다. 초당 수십 회 setState하면 스레드가 막힌다 | Must |
| FR-6 | 가격 변경을 **행 단위로 격리**한다. 한 종목 가격이 바뀔 때 100행이 리렌더되면 안 된다 | Must |
| FR-7 | **보이는 행만 갱신**한다. `viewabilityConfig`로 화면 밖 행의 갱신을 건너뛴다 | Must |
| FR-8 | blink는 **`react-native-reanimated`로 UI 스레드**에서 돌린다. JS 스레드에서 돌리면 스크롤과 경쟁한다 | Must |
| FR-9 | blink가 `transform`/`opacity`만 쓴다 | Must |
| FR-10 | 스크롤 중 blink가 프레임을 떨어뜨리지 않는지 측정한다 | Must |
| FR-11 | **100행을 다 받을지 페이징할지 측정 후 결정**한다. 데이터 사용량과 스크롤 성능을 함께 본다 | Must |

## 급소 2 — 콜드 스타트

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | **Hermes를 켠다.** 사전 컴파일로 파싱 비용이 사라진다 | Must |
| FR-21 | 스플래시 → 첫 화면까지 **네트워크를 기다리지 않는다.** 캐시를 먼저 그린다 | Must |
| FR-22 | `src/app`의 프로바이더에서 무거운 초기화를 하지 않는다 | Must |
| FR-23 | **WS를 첫 화면 렌더 후에 연결**한다. 시작 경로에 소켓 핸드셰이크를 넣지 않는다 | Must |
| FR-24 | 폰트·아이콘을 번들에 넣고 런타임 다운로드를 하지 않는다 | Must |
| FR-25 | secure store 읽기가 시작을 막지 않게 한다. **비동기로 처리**하고 그동안 스플래시를 유지 | Must |
| FR-26 | 콜드 스타트를 저가 Android 실기기에서 측정하고 기록한다 | Must |

## Acceptance Criteria

- [ ] **콜드 스타트가 저가 Android에서 2s 이내다** (측정값 기록)
- [ ] Hermes가 켜져 있다
- [ ] 첫 화면이 네트워크를 기다리지 않는다
- [ ] WS가 첫 화면 렌더 후에 연결된다
- [ ] secure store 읽기가 시작을 막지 않는다
- [ ] 시세 목록이 `FlatList`이고 행이 `memo`이고 key가 심볼이다
- [ ] `getItemLayout`이 있다
- [ ] **시세 목록 스크롤이 60fps다** (측정값 기록)
- [ ] **변동률 blink가 60fps다** (측정값 기록)
- [ ] WS 메시지가 프레임 단위로 버퍼링된다
- [ ] 한 종목 가격 변경이 100행을 리렌더하지 않는다 (Profiler)
- [ ] 보이는 행만 갱신된다
- [ ] blink가 UI 스레드에서 돌고 `transform`/`opacity`만 쓴다
- [ ] 스크롤 중 blink가 프레임을 떨어뜨리지 않는다
- [ ] 100행 vs 페이징 결정이 측정 근거와 함께 기록되어 있다
- [ ] 차트가 종목 상세에서만 마운트된다
- [ ] 차트 인스턴스가 재사용되고 언마운트 시 정리된다
- [ ] 실시간 캔들 갱신이 버퍼링된다
- [ ] 스크롤 중 차트가 터치를 가로채지 않는다
- [ ] 차트 번들 증가분이 기록되어 있다
- [ ] **백그라운드에서 WS가 끊긴다**
- [ ] 포그라운드 복귀 재연결이 1s 이내다
- [ ] 유령 구독이 0건이다
- [ ] 재연결 백오프가 동작한다
- [ ] 이미지 캐시 상한이 있고 크기가 고정이다
- [ ] 언마운트 시 구독·타이머·차트가 정리된다
- [ ] **저가 Android 백그라운드 복귀 후 강제 종료가 0건이다**
- [ ] **앱 번들 ≤ 4MB** (측정값 기록)
- [ ] 가격 셀에 `accessibilityLiveRegion`이 0건이다
- [ ] 감소된 모션에서 blink가 느려진다
- [ ] 폰트 확대에서 목록 행이 잘리지 않는다
- [ ] 측정이 릴리스 빌드 + 기준 기기로 수행되었다

## Open Questions

- **100행을 다 받을지 페이징할지.** 스크롤은 `FlatList`로 60fps가 나올 가능성이 높지만 데이터 사용량과 WS 구독 수가 늘어난다 → 측정 후 결정(FR-11).
- `getItemLayout`과 폰트 확대의 충돌(FR-72). 고정 높이를 포기하면 스크롤 성능이 떨어진다 → **확대 배율을 감지해 분기**하는 것이 기본안.
- blink를 `reanimated`로 구현하면 번들이 늘어난다. 증가분을 측정해야 한다.
