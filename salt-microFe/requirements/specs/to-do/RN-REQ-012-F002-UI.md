## Summary

웹은 세금을 **별도 zone**으로 두지만 **RN에는 zone 개념이 없다.** 모바일에서는 `자산` 탭 내부 스택이다. 3열 비교표는 **세로 스택**이고, 슬라이더는 터치 조작이라 웹보다 정밀도가 낮다 — 숫자 직접 입력이 필수다.

## FSD 배치

| 레이어 | 슬라이스 | 컴포넌트 |
|---|---|---|
| `pages` | `tax` | `TaxScreen` — 자산 탭 스택에서 push |
| `widgets` | `asset-workspace` | 세금 세그먼트에서 요약 → `TaxScreen` push |
| `features` | `solve-harvest` · `simulate-crypto-scenario` · `edit-law-config` · `download-evidence` | 웹과 같은 슬라이스 이름 |
| `entities` | `tax` | 웹과 **같은 컴포넌트 이름**, RN 구현 |
| `src/native` | `fileShare` | 증빙 ZIP 공유 시트 |

## 화면 구조 — 모바일은 세로다

```
자산 탭 → 세금 세그먼트 (요약)
  미국주식 D-111 · 크립토 D-113 · 국내주식 비과세
  [세금 마감 콕핏 열기] → push

TaxScreen (스택)
┌─ D-Day 칩 3개 (가로 스크롤)          ← 즉시 렌더
├─ 법령 상태 배지
├─ 세그먼트: 미국주식 | 크립토 | 국내주식   ← 자산군을 세그먼트로. 한 화면에 3카드를 쌓지 않는다
│
│ [미국주식]
│   실현손익 · 공제 · 과세표준 · 예상세금
│   환율 함정 경고 (있으면)
│   [손실 수확 계산하기] → BottomSheet
│
│ [크립토]
│   취득가액 이동평균 / FIFO (2행)
│   3열 → 세로 3카드 스택
│     ① 연내 매도 · 세금 0원
│     ② 연말 보유(스텝업) · 절세 5,728,800원
│     ③ 내년 매도 · 차익만 과세
│   연말 시가 슬라이더 + 숫자 입력
│   손익분기 연말시가 콜아웃
│
│ [국내주식]
│   "소액주주 양도차익 비과세. 계산 대상 아님."
│   거래세 · 배당 · 금융소득 경계
│
├─ 증빙 아카이브 → [ZIP 공유]
├─ 계산 전제 (접힘 → 펼침)
└─ 면책 (하단 고정)
```

## Requirements

### A. 내비게이션

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | 세금은 **자산 탭 내부 스택**이다. **탭을 4개로 늘리지 않는다** | Must |
| FR-2 | 자산 탭의 세금 세그먼트는 **D-Day 요약만** 보여주고 상세는 push한다 | Must |
| FR-3 | 푸시 알림(`tax_deadline`)이 이 화면으로 **딥링크**한다. 딥링크 파라미터를 신뢰하지 않고 진입 후 서버로 재검증한다 | Must |
| FR-4 | 뒤로가기가 자산 탭으로 돌아간다. 딥링크 진입 시에도 스택이 올바르게 구성된다 | Must |

### B. 자산군을 세그먼트로

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | 자산군 3개를 **세그먼트로 전환**한다. 한 화면에 3카드를 쌓으면 스크롤이 너무 길어진다 | Must |
| FR-11 | 세그먼트 전환은 **이미 받은 데이터로** 한다. 전환마다 서버를 부르지 않는다(집계 1콜) | Must |
| FR-12 | 국내주식 세그먼트는 **비과세를 명시**하고 양도차익을 표시하지 않는다 | Must |
| FR-13 | 세그먼트에 `accessibilityRole="tablist"`와 선택 상태를 준다 | Must |

### C. D-Day

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | D-Day 칩 3개를 **가로 스크롤**로 배치한다. 좁은 화면에서 줄바꿈하지 않는다 | Must |
| FR-21 | `daysRemaining`을 **클라이언트에서 재계산**한다(기기 시간대 KST 기준) | Must |
| FR-22 | 미국주식 칩에 마지막 매도일과 권고일을 둘 다 표시한다 | Must |
| FR-23 | D-14 이내면 강조. **압박 문구 금지** | Must |
| FR-24 | `accessibilityLabel`로 "미국주식 2026년 12월 29일까지 111일 남음" | Must |

### D. 3열 → 세로 3카드

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-30 | 3열을 **세로 카드 3개**로 스택한다. 가로 표는 모바일에서 읽을 수 없다 | Must |
| FR-31 | 각 카드에 시나리오 이름을 명시한다. 웹의 열 머리말을 카드 제목으로 옮긴다 | Must |
| FR-32 | **대칭 렌더.** 추천 배지·강조 색이 없다 | Must |
| FR-33 | 스크린리더 순서가 ①②③이다 | Must |

### E. 슬라이더 — 터치는 정밀도가 낮다

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-40 | 슬라이더 옆에 **숫자 직접 입력**(`TextField`)을 둔다. 터치로 −40%~+80%를 정밀 조작할 수 없다 | Must |
| FR-41 | 슬라이더 조작 중 **서버 요청 0건.** 클라이언트 재계산 | Must |
| FR-42 | 재계산은 `scenarioParams`만 쓴다. **하드코딩 상수 0건** | Must |
| FR-43 | 슬라이더 값 변경을 **프레임 단위로 버퍼링**한다. 터치 이벤트마다 setState하면 JS 스레드가 막힌다 | Must |
| FR-44 | 놓을 때 서버와 대조하고 불일치 시 서버 값으로 덮는다 | Must |
| FR-45 | 손익분기 연말시가를 슬라이더 위에 표시한다 | Must |
| FR-46 | 슬라이더 터치 타깃이 **44×44 이상**이다 | Must |

### F. 손실수확 솔버

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-50 | 솔버는 **버튼 → `BottomSheet`** 로 결과를 보여준다. 화면에 인라인으로 쌓지 않는다 | Must |
| FR-51 | 후보 3개를 세로 카드로. **대칭 렌더, 추천 배지 없음** | Must |
| FR-52 | 종목 목록을 접어서 보여준다. 후보마다 종목이 여러 개다 | Must |
| FR-53 | `isOptimal: false`면 근사임을 표시한다 | Must |
| FR-54 | `caveats`에 재매수 취득가액 경고를 포함한다. **없으면 후보를 렌더하지 않는다** | Must |
| FR-55 | **매도 유도 CTA 금지.** "이 조합 확인"까지 | Must |

### G. 증빙

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-60 | ZIP은 **서명 URL을 받아 OS 공유 시트**로 넘긴다. 앱 메모리에 파일을 올리지 않는다 | Must |
| FR-61 | 파일 접근 권한을 요청할 때 **사유를 명시**한다 | Must |
| FR-62 | URL 만료(5분)를 안내하고 만료 시 재발급 버튼을 준다 | Must |
| FR-63 | 스냅샷 실패 시 **적색 배너 + 수동 입력 폼** | Must |

### H. 오프라인

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-70 | 마지막 성공 응답을 캐시하고 **"오프라인 · {시각} 기준" 배너**를 붙인다 | Must |
| FR-71 | 오프라인에서 **솔버·슬라이더 대조·법령 편집을 시도하지 않는다.** 버튼을 비활성하고 사유를 표시한다 | Must |
| FR-72 | 슬라이더 자체 재계산은 오프라인에서도 동작한다(클라이언트 계산이므로). 다만 **대조가 안 되므로 그 사실을 표시**한다 | Must |
| FR-73 | 오프라인 큐를 만들지 않는다 | Must |

## UX 상태

- **Loading**: D-Day 즉시 + 세그먼트 스켈레톤
- **Empty (계좌 미연결)**: 온보딩 안내. **D-Day는 보여준다**
- **Offline**: FR-70~72
- **Warning**: 원장 불일치 · 환율 결측 · lot 재계산 중 · D-14 이내
- **Error (스냅샷 실패)**: 적색 배너 + 수동 입력
- **Optimistic update**: 없음

## Acceptance Criteria

- [ ] 세금이 자산 탭 내부 스택이고 **탭이 3개다**
- [ ] 자산 탭 세금 세그먼트가 D-Day 요약만 보여준다
- [ ] 푸시 알림이 이 화면으로 딥링크하고 진입 후 서버 재검증이 일어난다
- [ ] 딥링크 진입 후 뒤로가기가 자산 탭으로 간다
- [ ] 자산군이 세그먼트로 전환되고 전환 시 서버 호출이 0건이다
- [ ] 국내주식 세그먼트에 양도차익 표시가 0건이다
- [ ] D-Day 칩이 가로 스크롤이고 줄바꿈하지 않는다
- [ ] `daysRemaining`이 기기 시간대 KST로 재계산된다
- [ ] D-14 이내에서 압박 문구가 0건이다
- [ ] 3열이 세로 카드 3개이고 추천 배지가 0건이다
- [ ] 스크린리더 순서가 ①②③이다
- [ ] 슬라이더 옆에 숫자 직접 입력이 있다
- [ ] **슬라이더 조작 중 서버 요청이 0건이다**
- [ ] 슬라이더 재계산에 하드코딩 상수가 0건이다
- [ ] 슬라이더 값이 프레임 단위로 버퍼링된다
- [ ] 놓을 때 서버 대조가 일어난다
- [ ] 슬라이더 터치 타깃이 44×44 이상이다
- [ ] 솔버가 `BottomSheet`로 열린다
- [ ] 후보에 추천 배지가 0건이고 재매수 경고가 있다
- [ ] 매도 유도 CTA가 0건이다
- [ ] ZIP이 OS 공유 시트로 넘어가고 앱 메모리에 올라가지 않는다
- [ ] 파일 권한 요청에 사유가 있다
- [ ] 오프라인 배너가 시각과 함께 표시된다
- [ ] 오프라인에서 솔버·대조·편집 버튼이 비활성이고 사유가 표시된다
- [ ] 오프라인 큐가 0건이다
- [ ] 터치 타깃 전부 44×44 이상
- [ ] **폰트 최대 확대에서 금액이 잘리지 않는다**
- [ ] VoiceOver·TalkBack으로 D-Day·3카드·계산 전제·면책이 낭독된다

## Open Questions

- 자산군 세그먼트가 **또 하나의 탭 계층**이 아닌가. 세그먼트는 같은 화면 안의 필터로 취급하고 데이터를 한 번에 받는 것이 기본안이지만, "탭을 줄인다"는 결정과의 정합을 재확인해야 한다.
- 계산 전제 표를 모바일에서 어떻게 보여줄지. 접힘 → 펼침이 기본안.
- 슬라이더 대신 **미리 정의된 시나리오 버튼**(−20%/0/+20%/+50%)이 모바일에서 더 나을 수 있다. 사용성 검증 필요.
