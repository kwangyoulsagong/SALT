## Summary

대화의 **SSE 구독·재연결·취소**가 이 REQ의 핵심이다. 그리고 홈은 **읽기 전용**이고 격자는 **저장 실패해도 동작**해야 한다.

## SSE 구독

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | 구독은 `features/ask-coach`의 훅이 담당한다. 컴포넌트가 `EventSource`를 직접 만들지 않는다 | Must |
| FR-2 | 흐름: `POST /messages` → `messageId` → `GET /stream?messageId` 구독 | Must |
| FR-3 | `message.delta`를 **마지막 말풍선에만** 누적한다. 목록 전체를 다시 그리지 않는다 | Must |
| FR-4 | 토큰을 **프레임 단위로 버퍼링**해서 반영한다. 토큰마다 setState하면 리렌더가 폭발한다 | Must |
| FR-5 | `message.card`를 받으면 **완성 객체로 한 번에** 붙인다 | Must |
| FR-6 | `message.done`에서 스트리밍 상태를 해제하고 `explanationSource` 배지를 결정한다 | Must |
| FR-7 | `message.error`를 받으면 **`fallbackText`를 렌더**하고 배지를 붙인다. 빈 화면 0건 | Must |
| FR-8 | 언마운트 시 구독을 해제한다. **유령 구독 0건** | Must |
| FR-9 | 취소 버튼이 구독을 끊는다. **서버로 종료가 전파**되어야 한다 | Must |

## 재연결 — 중복 생성을 막는다

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | `EventSource`는 자동 재연결한다. **같은 `messageId`로 다시 붙는다** | Must |
| FR-11 | `Last-Event-ID`를 서버가 받으므로 **그 이후 델타부터** 온다. 클라이언트가 중복을 걸러야 할 필요가 없다 | Must |
| FR-12 | 다만 **방어적으로 중복 델타를 검사**한다. 같은 이벤트 id가 두 번 오면 무시한다 | Must |
| FR-13 | **재연결 시 `POST /messages`를 다시 부르지 않는다.** 부르면 메시지가 두 개 생긴다 | Must |
| FR-14 | 재연결 실패가 반복되면(3회) 구독을 끊고 재시도 버튼을 준다 | Must |
| FR-15 | 재연결 중 화면에 "연결 중"을 표시한다 | Must |

## 대화 상태

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | 메시지 목록은 **역순 커서 페이징**이다. 위로 스크롤하면 과거를 불러온다 | Must |
| FR-21 | 새 메시지가 오면 **아래로 자동 스크롤**한다. 단 사용자가 위를 보고 있으면 스크롤하지 않고 "새 메시지" 버튼을 준다 | Must |
| FR-22 | 전송 실패 시 **입력을 보존**한다. 입력창을 비우지 않는다 | Must |
| FR-23 | 전송 중 입력을 비활성하지 않는다. 다음 질문을 미리 쓸 수 있게 | Should |
| FR-24 | 대화 목록은 `lastMessageAt` 내림차순 커서 | Must |
| FR-25 | 삭제는 `useDialog().confirm`. **자동 삭제 0건** | Must |
| FR-26 | 추천 질문 Chip을 누르면 **그 문구를 입력에 채우고 즉시 전송**한다 | Must |

## 홈 — 읽기 전용

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-30 | **홈에서 mutation을 호출하지 않는다.** 적립 완료·피드백 같은 액션을 두지 않는다 | Must |
| FR-31 | 블록을 누르면 **해당 탭으로 이동**한다. 홈에서 끝나는 액션이 없다 | Must |
| FR-32 | 블록 순서를 **코드로 고정**한다. 배열 순서를 데이터로 받지 않는다 | Must |
| FR-33 | 금액 `null`을 `0`으로 표시하지 않는다 | Must |
| FR-34 | AI 추천 블록에 **게이트를 적용**한다(`renderable`) | Must |
| FR-35 | 온보딩 미완료면 **블록 대신 온보딩 카드**를 렌더한다. 블록별 빈 상태를 각각 보여주지 않는다 | Must |
| FR-36 | 총자산 환율 기준 툴팁 문구를 `shared/i18n`에서 가져온다 | Must |

## Acceptance Criteria

- [ ] SSE 구독이 훅으로 감싸져 있고 컴포넌트가 `EventSource`를 직접 만들지 않는다
- [ ] `POST` → `messageId` → `GET stream` 흐름이 동작한다
- [ ] **델타가 마지막 말풍선에만 누적된다** (Profiler로 목록 전체 리렌더 0건 확인)
- [ ] 토큰이 프레임 단위로 버퍼링된다
- [ ] 카드가 완성 객체로 한 번에 붙는다
- [ ] `done`에서 스트리밍 해제 + 배지 결정
- [ ] `error`에서 `fallbackText`가 렌더되고 빈 화면이 0건이다
- [ ] 언마운트 시 구독이 해제된다 (유령 구독 0건)
- [ ] 취소 버튼이 구독을 끊고 서버로 전파된다
- [ ] **재연결 시 `POST /messages`를 다시 부르지 않는다** (메시지 중복 생성 0건)
- [ ] 중복 델타가 방어적으로 걸러진다
- [ ] 재연결 3회 실패 시 구독을 끊고 재시도 버튼이 나온다
- [ ] 재연결 중 "연결 중"이 표시된다
- [ ] 메시지 목록이 역순 커서 페이징이다
- [ ] 새 메시지 자동 스크롤이 되고, 위를 보고 있으면 "새 메시지" 버튼이 나온다
- [ ] 전송 실패 시 입력이 보존된다
- [ ] 삭제 시 confirm이 뜨고 자동 삭제가 0건이다
- [ ] 추천 질문 Chip이 즉시 전송된다
- [ ] **홈에 mutation 호출이 0건이다**
- [ ] 블록을 누르면 해당 탭으로 이동한다
- [ ] 블록 순서가 코드로 고정된다
- [ ] 금액 `null`이 `0`으로 표시되지 않는다
- [ ] AI 추천 블록에 게이트가 적용된다
- [ ] 온보딩 미완료 시 카드 1개만 나온다
- [ ] 격자 저장 실패 시 기본 배치로 동작한다
- [ ] 격자 저장이 1초 디바운스된다
- [ ] 손상된 배치가 기본으로 폴백되고 개발 로그에 남는다
- [ ] 1280px 미만에서 격자가 마운트되지 않는다
- [ ] 격자 판단이 마운트 후에 일어난다 (하이드레이션 경고 0건)
- [ ] 키보드 대체 수단이 있다
- [ ] 추천 질문 4개가 `shared/i18n`에 있다
- [ ] 금지 표현 검사가 동작한다
- [ ] 매핑 없는 서버 코드가 원문으로 노출되지 않는다
- [ ] 개발 환경에서 LLM 답변 스캔 경고가 나온다
- [ ] 면책이 답변마다 붙는다
- [ ] **"주문하기" 버튼·거래소 링크가 0건이다**
