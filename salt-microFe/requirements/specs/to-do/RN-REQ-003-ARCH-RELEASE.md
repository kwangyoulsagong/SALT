## Summary

iOS와 Android 릴리스 절차를 정의한다. 이 제품은 **비공개·초대제**이므로 공개 스토어 출시가 아니라 **내부 배포**가 기본이다. 그 제약이 릴리스 방식을 결정한다.

## 이 제품의 배포 제약이 먼저다

글로벌 플랜 1-1절: **앱스토어 출시 없음, 공개 URL 없음, 검색 노출 없음, 초대제(본인 + 최대 10명), 무료.**

→ **공개 스토어 심사를 통과할 필요가 없다.** 그러면 배포 경로가 달라진다.

## 배포 경로 후보 4개를 비교했다

| | A. TestFlight + Play 내부 테스트 | B. 공개 스토어 출시 | C. Ad Hoc / APK 직접 배포 | D. Expo Go |
|---|---|---|---|---|
| 심사 | **TestFlight 경심사 / Play 없음** | 정식 심사 1~3일 | 없음 | 없음 |
| 대상 인원 | TestFlight 최대 100(내부)/10,000(외부) · Play 내부 100 | 무제한 | iOS는 기기 UDID 등록 100 | 무제한 |
| 초대 방식 | **이메일·링크 초대** | 공개 | 기기 등록·파일 전달 | 링크 |
| 푸시 알림 | **✓** | ✓ | ✓ | 제한적 |
| 네이티브 모듈 | ✓ | ✓ | ✓ | **✗ 커스텀 불가** |
| OTA | ✓ | ✓ | ✓ | 해당 없음 |
| 만료 | TestFlight 빌드 90일 | 없음 | 프로비저닝 1년 | 없음 |
| 심사 리스크 | 낮음 | **"투자 조언" 심사 위험** | 없음 | 없음 |

### B를 버린 이유 — 가장 중요한 판단

공개 스토어 출시는 **글로벌 플랜 1-1절 위반**이다. 그리고 심사 리스크가 실재한다: 금융·투자 앱은 심사에서 **사업자 자격 증빙**을 요구받을 수 있고, 이 제품은 추천을 한다. **비공개를 유지하는 것이 법적 포지셔닝의 일부**다(1-2절 Non-Goals).

### D를 버린 이유
Expo Go는 **커스텀 네이티브 모듈을 쓸 수 없다.** `expo-secure-store`(토큰) · 푸시 · 딥링크가 필요하고 `prebuild`를 쓰기로 했다(`RN-REQ-001`). 개발 중 편의로만 쓴다.

### C를 버린 이유
iOS Ad Hoc은 **기기 UDID를 하나씩 등록**해야 하고 프로비저닝 프로파일이 1년마다 만료된다. 지인 10명의 기기 정보를 받아 관리하는 마찰이 크다. Android APK 직접 배포는 되지만 iOS와 절차가 갈라진다.

### A가 우리에게 맞은 이유
**초대제와 배포 방식이 일치한다.** TestFlight는 이메일·링크로 초대하고, Play 내부 테스트도 테스터 목록으로 관리한다. 초대 코드(F000)와 같은 모델이다. 심사는 TestFlight 경심사뿐이고 공개 노출이 없다.

## Requirements

### A. 배포 경로

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | iOS는 **TestFlight**로 배포한다. 공개 App Store 출시를 하지 않는다 | Must |
| FR-2 | Android는 **Play 내부 테스트 트랙**으로 배포한다. 공개 출시를 하지 않는다 | Must |
| FR-3 | 테스터 목록을 초대 코드 발급 대상과 **일치시킨다**. 앱을 받을 수 있는 사람 = 초대 코드를 가진 사람 | Must |
| FR-4 | **TestFlight 빌드는 90일 후 만료된다.** 분기마다 새 빌드를 올리는 것을 일정에 넣는다 | Must |
| FR-5 | 스토어 등록 정보에 **투자 조언·수익 보장 표현을 쓰지 않는다.** 설명에 면책을 포함한다 | Must |

### B. 서명과 자격

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | iOS: Apple Developer 계정 + 번들 ID + 푸시 인증서(APNs). **EAS가 서명을 관리**하게 한다 | Must |
| FR-11 | Android: 업로드 키를 **EAS에 위임**하거나 안전한 곳에 보관한다. **키를 잃으면 같은 앱을 업데이트할 수 없다** | Must |
| FR-12 | 서명 키·인증서를 레포에 커밋하지 않는다. `.gitignore` 확인 | Must |
| FR-13 | 권한 요청 문구(카메라·알림·파일)를 최소화하고 사유를 명시한다. **CSV 업로드가 파일 접근을 요구**한다 | Must |

### C. 릴리스 체크리스트 (매 릴리스)

| ID | 항목 | 왜 |
|---|---|---|
| FR-20 | **네이티브 변경이 있는가?** 있으면 스토어 빌드, 없으면 OTA | `RN-REQ-002` FR-8 |
| FR-21 | **버전 게이트를 올려야 하는가?** OTA 번들이 새 네이티브 API를 쓰면 올린다. **이 판정을 사람이 잊는다** | `RN-REQ-002` FR-42 |
| FR-22 | **금액·세금 계산이 바뀌었는가?** 바뀌었으면 점진 롤아웃 필수 | `RN-REQ-002` FR-3 |
| FR-23 | **번들 크기를 기록했는가?** Phase 2 판정의 근거다 | `RN-REQ-002` FR-10 |

| FR-26 | **확신 표현·목표주가·인격 평가가 0건인가?** 문구 검수 | 동일 |
| FR-27 | **추천 카드 3종 세트 게이트가 동작하는가?** 하나를 제거해 미렌더 확인 | 동일 |
| FR-28 | **iOS·Android 둘 다 실기기에서 스모크했는가?** | — |
| FR-29 | **롤백 경로를 확인했는가?** | `RN-REQ-002` FR-7 |

| 추적성 | 릴리스별 체크리스트 + 번들 크기 + 콜드 스타트 측정값 |

## Acceptance Criteria

- [ ] iOS가 TestFlight로, Android가 Play 내부 테스트로 배포된다
- [ ] 공개 스토어 출시가 0건이다
- [ ] 테스터 목록과 초대 코드 발급 대상이 일치한다
- [ ] 서명 키·인증서가 레포에 0건이다 (`git ls-files` 확인)
- [ ] 권한 요청 문구에 사유가 있고 요청 권한이 최소다
- [ ] 릴리스 체크리스트 10항목이 문서로 존재하고 1회 실행되었다
- [ ] OTA와 스토어 빌드의 판단 기준이 체크리스트에 있다
- [ ] 런타임 버전이 다른 OTA가 적용되지 않는다 (시뮬레이션 확인)
- [ ] 낮은 네이티브 버전에서 업데이트 안내 화면이 뜬다
- [ ] 롤백을 1회 실행 검증했다
- [ ] 스토어 등록 정보에 투자 조언·수익 보장 표현이 0건이고 면책이 포함된다

## Open Questions

- Apple Developer 계정 보유 여부와 연 $99 비용. **없으면 iOS 배포가 시작되지 않는다.** 착수 전 확인.
- Google Play 개발자 계정 보유 여부($25 일회).
- TestFlight 내부 테스터(100명, 심사 없음)와 외부 테스터(10,000명, 경심사)의 구분. **내부 테스터만 쓰면 심사가 아예 없다** — 지인 10명이면 내부로 충분한지 확인 필요.
- Play 내부 테스트의 테스터 상한과 초대 방식(이메일 목록 vs 링크).
- 세금 마감(12/29~31)과 스냅샷(1/1 00:10)이 걸린 시기의 릴리스 동결 기간을 언제로 잡을지.
