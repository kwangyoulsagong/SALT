## Summary

F004 모바일의 급소는 **폴링·LLM이 배터리와 데이터를 먹는 것**이다. 렌더 부하는 낮다(계산이 전부 서버이고 리스트가 짧다).

## 예산 (저가 Android 실기기)

| 지점 | 예산 | 비고 |
|---|---|---|
| 코치 탭 전환 | **200ms** | 캐시 히트 |
| 캐시 첫 페인트 | **200ms** | persist 읽기 포함 |
| 데이터 도착 | 800ms | `detail` 450ms + 네트워크 |
| 카드 펼침(근거·성적·실패) | **100ms** | 이미 받은 데이터 |
| 성적표 화면 push | 400ms | |
| preflight (버튼 → BottomSheet 결과) | **500ms** | |
| 피드백 (낙관적) | **0ms 체감** | |
| 재생성 (202) | 400ms | 이후 폴링 |
| **`explain`** | **20s 상한** | 취소 가능 |
| 리스트 스크롤 (익절·후보) | 60fps | 짧다 |

## 급소 1 — 폴링이 배터리를 먹는다

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | **`AppState`가 백그라운드면 폴링을 멈춘다.** 화면이 안 보이는데 2초마다 요청하면 배터리와 데이터를 먹는다 | Must |
| FR-2 | 복귀 시 **한 번 조회**한 뒤 필요하면 재개한다. 백그라운드에 있던 시간만큼 폴링을 몰아 하지 않는다 | Must |
| FR-3 | 최대 15회(30초). 초과 시 중단 + 재시도 버튼 | Must |
| FR-4 | 중단 조건 5개(완료·실패·언마운트·최대·백그라운드) | Must |
| FR-5 | `AbortSignal` 연결 | Must |
| FR-6 | 폴링 횟수 분포를 측정한다 | Must |

## 급소 2 — LLM 20s

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | **`explain`을 자동 호출하지 않는다** | Must |
| FR-11 | 진행 중 **취소 버튼**을 준다. 모바일에서 20s는 길다 | Must |
| FR-12 | **백그라운드 전환 시 취소**한다 | Must |
| FR-13 | 진행 중 화면이 반응한다. 다른 조작이 막히지 않는다 | Must |
| FR-14 | 진행 표시를 명확히 한다(`Spinner` + "해설을 만들고 있습니다") | Must |
| FR-15 | 실패 시 규칙 문장으로 즉시 대체. 재시도를 자동으로 하지 않는다 | Must |

## Acceptance Criteria

- [ ] 코치 탭 전환이 200ms 이내다 (측정값 기록)
- [ ] 캐시 첫 페인트가 200ms 이내이고 persist 읽기가 100ms 이내다
- [ ] 갱신 중 전체 스켈레톤으로 되돌아가지 않는다
- [ ] **백그라운드에서 폴링이 멈춘다**
- [ ] 복귀 시 한 번 조회 후 재개한다 (몰아 하기 0건)
- [ ] 폴링이 최대 15회이고 중단 조건 5개가 있다
- [ ] **폴링 횟수·데이터량이 측정되어 있다**
- [ ] **`explain`이 자동 호출되지 않는다**
- [ ] `explain`에 취소 버튼이 있고 백그라운드 전환 시 취소된다
- [ ] `explain` 중 화면이 반응한다
- [ ] `explain` 진행 표시가 명확하다
- [ ] 실패 시 규칙 문장으로 즉시 대체되고 자동 재시도가 0건이다
- [ ] 카드 펼침이 다른 섹션을 리렌더하지 않는다 (Profiler)
- [ ] 피드백 낙관적 갱신이 카드만 리렌더한다
- [ ] preflight가 BottomSheet 안에 격리된다
- [ ] 리스트 key에 index가 0건이다
- [ ] 언마운트 시 폴링·타이머·구독이 정리된다
- [ ] `explain` 진행 중 언마운트 시 요청이 취소된다
- [ ] persist 크기가 제한된다
- [ ] **저가 Android 백그라운드 복귀 후 강제 종료가 0건이다**
- [ ] **`generation-status`를 폴링하고 `detail`은 완료 시 1회 받는다**
- [ ] `scoreboard`가 미리 받아지지 않는다
- [ ] 코치 화면 번들 비중이 기록되어 있다
- [ ] 폴링 중 `accessibilityLiveRegion`이 0건이다
- [ ] `explain` 진행이 스크린리더에 알려진다
- [ ] 측정이 릴리스 빌드 + 기준 기기로 수행되었다

## Open Questions

- 폴링 대신 **푸시로 완료를 알릴 수 있다.** F007의 푸시 인프라를 쓰면 폴링이 사라지고 배터리·데이터가 절약된다 → **F007 이후 검토할 만한 개선**.
- `detail`을 persist할지(`RN-REQ-022` Open Question). 추천은 시점이 중요하다.
- `explain`을 아예 만들지 않으면 FR-10~15가 전부 사라진다.
