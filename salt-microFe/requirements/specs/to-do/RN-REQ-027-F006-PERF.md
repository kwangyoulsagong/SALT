## Summary

모바일 F006의 급소는 **대화 스트리밍이 JS 스레드를 막는 것**과 **SSE가 배터리를 먹는 것**이다. JS 스레드가 하나이므로 웹보다 위험하다.

## 예산 (저가 Android 실기기)

| 지점 | 예산 | 비고 |
|---|---|---|
| **콜드 스타트 → 홈** | **2s** | 캐시 렌더 |
| 홈 캐시 첫 페인트 | **200ms** | persist |
| 홈 데이터 도착 | 1.2s | 집계 450ms + 네트워크 |
| **탭 전환** | **200ms** | 3탭 |
| 코치 탭 첫 페인트 | 400ms | 과거 대화 + 브리핑 |
| **첫 토큰 도착** | **1s** | SSE |
| **델타 반영** | **60fps** | 프레임 버퍼링 |
| **대화 스크롤 (메시지 200)** | **60fps** | `FlatList inverted` |
| 과거 메시지 로드 | 500ms | 커서 |
| 자산 탭 세그먼트 전환 | 100ms | |
| Pull-to-refresh | 1.2s | |

## 급소 1 — 델타 반영이 JS 스레드를 막는다

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | 토큰을 **프레임 단위로 버퍼링**한다. 토큰마다 setState하면 스레드가 막힌다 | Must |
| FR-2 | **마지막 말풍선만** 갱신한다. 리스트 전체를 다시 그리지 않는다 | Must |
| FR-3 | 말풍선을 `memo`로 감싼다 | Must |
| FR-4 | 스트리밍 중 **다른 섹션(추천 카드·헤더)이 리렌더되지 않는다** | Must |
| FR-5 | 자동 스크롤을 프레임 단위로. 매 델타마다 `scrollToEnd` 0건 | Must |
| FR-6 | 델타 반영 프레임을 실기기에서 측정한다 | Must |
| FR-7 | **SSE 파싱(문자열 처리)이 프레임을 먹지 않게** 한다. 부분 라인 버퍼를 효율적으로 다룬다 | Must |

## 급소 2 — 대화 리스트

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | **`FlatList inverted`**. `ScrollView`에 메시지 200개를 넣지 않는다 | Must |
| FR-11 | `keyExtractor`를 `messageId`로. index 0건 | Must |
| FR-12 | 말풍선이 **가변 높이**라 `getItemLayout`을 줄 수 없다. **`estimatedItemSize`(FlashList) 또는 측정 기반**으로 | Must |
| FR-13 | 페이지 크기 30. **메모리에 무한히 쌓지 않는다** — 오래된 페이지를 버리거나 상한을 둔다 | Must |
| FR-14 | 이미지·카드가 포함된 말풍선의 높이를 고정하거나 미리 계산한다 | Should |
| FR-15 | 스크롤 프레임을 메시지 200개 기준으로 측정한다 | Must |

## 급소 3 — SSE와 배터리

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | **백그라운드에서 스트림을 닫는다.** 열어두면 배터리와 데이터를 먹는다 | Must |
| FR-21 | 재연결 백오프로 무한 재시도를 막는다 | Must |

| FR-23 | 언마운트 시 닫는다. **유령 연결 0건** | Must |

| FR-25 | **SSE는 압축되지 않으므로 토큰 수가 곧 대역폭**이다. 긴 답변의 데이터량을 측정한다 | Must |

## Acceptance Criteria

- [ ] **콜드 스타트 → 홈이 2s 이내다** (측정값 기록)
- [ ] 홈 캐시 첫 페인트 200ms, persist 읽기 100ms 이내
- [ ] 갱신 중 전체 스켈레톤이 0건이다
- [ ] **탭 전환이 200ms 이내다**
- [ ] 토큰이 프레임 단위로 버퍼링된다 (토큰마다 setState 0건)
- [ ] **델타가 마지막 말풍선에만 반영된다** (Profiler)
- [ ] 말풍선이 `memo`로 감싸져 있다
- [ ] 스트리밍 중 다른 섹션이 리렌더되지 않는다
- [ ] 자동 스크롤이 프레임 단위다
- [ ] **델타 반영이 60fps다** (측정값 기록)
- [ ] SSE 파싱이 프레임을 먹지 않는다
- [ ] 대화 목록이 `FlatList inverted`이고 key가 `messageId`다
- [ ] 가변 높이 처리가 되어 있다
- [ ] 페이지 크기 30이고 메모리 상한이 있다
- [ ] **대화 스크롤이 60fps다** (메시지 200개, 측정값 기록)
- [ ] **백그라운드에서 스트림이 닫힌다**
- [ ] 재연결 백오프가 동작하고 유령 연결이 0건이다
- [ ] 스트림 지속 시간·데이터량이 측정된다
- [ ] **WS와 SSE를 동시에 열지 않는다**
- [ ] 콜드 스타트 경로에 SSE 연결이 없다
- [ ] 탭 전환 시 이전 탭 구독이 정리된다
- [ ] 세그먼트 전환 시 서버 호출이 0건이다
- [ ] 언마운트 시 스트림·타이머·구독이 정리된다
- [ ] persist 크기가 제한된다
- [ ] **긴 대화 후 백그라운드 복귀 시 강제 종료가 0건이다**
- [ ] SSE 폴리필 번들 증가분이 기록되어 있다
- [ ] 스트리밍 중 스크린리더가 매 토큰 낭독하지 않는다
- [ ] 폰트 확대에서 리스트 높이가 틀어지지 않는다
- [ ] 측정이 릴리스 빌드 + 기준 기기로 수행되었다

## Open Questions

- **WS와 SSE 동시 사용(FR-33).** 코치 탭에서 시세 WS를 끊으면 홈으로 돌아왔을 때 시세가 오래됐다 → 재연결 비용과 배터리 사이의 균형을 측정으로 정해야 한다.
- 가변 높이 리스트에서 `FlashList`의 `estimatedItemSize`가 충분한지. 카드가 포함된 말풍선은 훨씬 크다.
- SSE 폴리필의 번들·성능 영향. 직접 구현이 더 가벼울 수 있다.
