## Summary

청구서의 급소는 **3선 그래프(수천 점)** 와 **큰 CSV 업로드**다. 그리고 폴링이 방치되면 서버 CPU를 먹는다.

## 예산

| 지점 | 예산 | 비고 |
|---|---|---|
| 청구서 첫 페인트 (스냅샷 히트) | **400ms** | BFF 350ms |
| 3선 그래프 렌더 | **200ms** | 다운샘플링된 `series` |
| 청구서 전체 완료 | 800ms | |
| 기간 탭 전환 | **300ms** | URL 변경 → 서버 재조회 |
| 편향 아코디언 펼침 | 100ms | 거래 목록 첫 페이지 |
| 거래 목록 다음 페이지 | 250ms | 커서 |
| 전후 90일 차트 모달 | 400ms | |
| CSV 업로드 (10,000행) | **13s** | BFF 12s + 클라이언트 |
| 계산 완료 폴링 | 2초 간격 · **최대 60초** | |
| 청구서 클라이언트 JS 증가분 | **60KB gzip 이하** | 차트 제외 |

## 급소 1 — 3선 그래프

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | `lightweight-charts`를 **`next/dynamic` + `ssr: false`** 로 마운트한다. 초기 번들에 넣지 않는다 | Must |
| FR-2 | **차트 인스턴스를 재사용**한다. 기간 탭 전환 시 새로 만들지 않고 데이터만 교체한다 | Must |
| FR-3 | 언마운트 시 `remove()`를 호출한다. 안 하면 기간을 여러 번 바꿀 때 메모리가 샌다 | Must |
| FR-4 | `series` 길이를 확인한다. **서버가 다운샘플링하지만 상한을 검증**하고 초과 시 클라이언트에서 자른다(마지막 방어) | Must |
| FR-5 | 3선을 한 차트에 그린다. 차트 3개를 만들지 않는다 | Must |
| FR-6 | 차트 렌더 시간을 측정하고 200ms 초과 시 점 수를 줄인다 | Must |

## 급소 2 — CSV 업로드

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | 파일을 **읽지 않는다.** `FormData`에 `File` 객체를 그대로 넣는다. `FileReader`로 내용을 읽으면 20MB가 메모리에 올라온다 | Must |
| FR-11 | 크기·확장자·MIME 검사는 **`File` 메타데이터만** 본다 | Must |
| FR-12 | 업로드 중 브라우저 메모리 증가분을 측정한다. **파일 크기에 비례하면 FR-10 위반**이다 | Must |
| FR-13 | 업로드 중 화면이 멈추지 않는다. 메인 스레드를 막는 작업 0건 | Must |
| FR-14 | 실패 행 CSV는 **서버가 만든 URL로 다운로드**한다. 클라이언트에서 생성하지 않는다 | Must |

## 급소 3 — 폴링

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | **중단 조건 없는 폴링을 만들지 않는다.** 완료·실패·언마운트에서 멈춘다 | Must |
| FR-21 | 최대 30회(60초). 초과 시 중단 + 재시도 버튼 | Must |
| FR-22 | 탭이 백그라운드면 멈춘다 | Should |
| FR-23 | 폴링 요청에 `AbortSignal`을 연결한다 | Must |
| FR-24 | 폴링 중 화면이 리렌더되지만 **차트를 다시 만들지 않는다**(FR-2) | Must |

## 리렌더

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-30 | 편향 아코디언 펼침이 **다른 아코디언을 리렌더하지 않는다.** 각 항목이 자기 상태를 갖는다 | Must |
| FR-31 | 거래 목록 페이징이 **기존 행을 리렌더하지 않는다.** 키가 안정되어야 한다(index 금지) | Must |
| FR-32 | 기간 탭 전환은 URL 변경 → 서버 재조회다. **클라이언트 필터링으로 흉내내지 않는다**(데이터가 다르다) | Must |
| FR-33 | `memo`·`useMemo`를 **예방적으로 붙이지 않는다.** 측정 후 필요한 곳만 | Must |

## Acceptance Criteria

- [ ] 청구서 첫 페인트 p95 < 400ms (측정값 기록)
- [ ] 3선 그래프 렌더 < 200ms (측정값 기록)
- [ ] 차트가 `ssr: false`로 마운트되고 초기 번들에 없다
- [ ] 기간 탭 전환 시 차트 인스턴스가 **재사용**된다 (새로 만들지 않음, 로그 확인)
- [ ] 언마운트 시 `remove()`가 호출된다 (메모리 프로파일로 누수 0건)
- [ ] `series` 길이 상한이 검증된다
- [ ] 차트가 1개다 (3개 0건)
- [ ] **업로드 시 `FileReader`가 0건이다** (파일 내용을 읽지 않는다)
- [ ] 20MB 업로드 중 브라우저 메모리 증가분이 파일 크기에 비례하지 않는다 (측정값 기록)
- [ ] 업로드 중 화면이 멈추지 않는다
- [ ] 실패 행 CSV가 서버 URL로 다운로드된다
- [ ] **폴링에 중단 조건 3개가 있다**
- [ ] 폴링이 최대 30회이고 초과 시 중단 + 재시도 버튼이 나온다
- [ ] 폴링 요청에 `AbortSignal`이 있다
- [ ] 폴링 중 차트가 다시 만들어지지 않는다
- [ ] 아코디언 펼침이 다른 항목을 리렌더하지 않는다 (Profiler)
- [ ] 거래 목록 페이징이 기존 행을 리렌더하지 않는다
- [ ] 리스트 key에 index가 0건이다
- [ ] 예방적 `memo`·`useMemo`가 0건이다 (측정 근거 없는 것)
- [ ] 클라이언트 JS 증가분 ≤ 60KB gzip (차트 제외, 측정값 기록)
- [ ] 차트가 별도 청크다 (번들 분석 첨부)
- [ ] `"use client"`가 잎 3개(그래프·업로드·키 폼)에 한정된다
- [ ] 원장 건강도 배너가 Suspense 밖이다
- [ ] Suspense 경계 5개 이하
- [ ] 스켈레톤 높이가 실제와 같다 (CLS 측정)
- [ ] 첫 블록/전체 완료 시각이 기록되어 있다
- [ ] 관측 항목 7종이 있다

## Open Questions

- 3선 그래프를 `lightweight-charts`로 할지 경량 SVG로 할지. **다운샘플링된 200~400점이면 SVG로도 충분**하고 번들이 훨씬 작다 → 측정 후 결정.
- 차트 인스턴스를 기간 탭 간에 재사용할 때 트랙 3개의 데이터 교체가 깔끔한지 확인 필요.
- 폴링 대신 SSE/알림으로 완료를 받으면 폴링 관련 요구(FR-20~24)가 전부 사라진다 → `BFF-REQ-011` Open Question과 연결.
