## Summary

모바일에서 이 기능은 **주간 알림 → 숫자 하나 → 체크**의 3동작이다. 웹의 밴드 표를 그대로 옮기지 않고, **바텀시트**로 접는다. 렌더 게이트는 웹과 **동일하게** 집행한다.

## 컴포넌트 (packages/ui-native + apps/mobile)

| 슬라이스 | 컴포넌트 |
|---|---|
| `entities/plan` | `WeeklyPlanCard` · `PlanItemRow` · `BandGaugeNative` · `AccumulationStreak` |
| `entities/indicator` | `TrackRecordSheet` · `IndicatorStaleBadge` |
| `entities/fx` | `KimchiPremiumRow` |
| `features/complete-weekly-plan` | `CompleteButton`(햅틱) |
| `features/edit-plan-settings` | `PlanSettingsScreen` |
| `widgets/home-briefing` | ② 블록 |
| `screens` | `PlanDetailScreen` |

## 화면 구조

```
홈 ② 블록 (카드)
  이번 주 적립
  475,000원                          >
  BTC 375,000 · VOO 100,000

PlanDetailScreen (push)
┌ 475,000원                     (32sp, 굵게)
│ 이번 주 적립
├ BTC   기본 125,000 × 3.0배 = 375,000원
│   MVRV Z −0.3 · 극단 저평가
│   [근거 보기]  → 바텀시트
├ VOO   기본 200,000 × 0.5배 = 100,000원
│   CAPE 40.6 · 98.8 퍼센타일
│   [근거 보기]
├ 김프 +1.2% · 약 4,500원이 프리미엄 비용
├ ─────────────────────────────
│ [이번 주 적립 완료]          (하단 고정)
└ 12주 연속 · 누적 4,120,000원 · 1주 미실행

근거 바텀시트 (스냅 50% / 90%)
  밴드 표 (5행, 현재 행 강조)
  실패 이력
    ✅ 2011·2015·2018·2022 바닥 4/4 적중
    ❌ 2025-10 톱 미검출 (이후 −52%)
```

## Requirements

### A. 한 숫자와 레이아웃

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | 총액을 **32sp 이상**으로 가장 크게 표시한다 | Must |
| FR-2 | 금액은 서버가 준 1,000원 단위 정수를 그대로 쓴다 | Must |
| FR-3 | `[이번 주 적립 완료]`는 **하단 고정**이고 `safeAreaInsets.bottom`을 존중한다 | Must |
| FR-4 | 자산 5종 이하가 일반이다. **FlatList 가상화는 10종 초과 시에만** | Should |
| FR-5 | 한 손 조작을 위해 주요 액션이 화면 하단 1/3에 있다 | Should |

### B. 렌더 게이트 (웹과 동일)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | `renderable: false`면 **배수·근거·밴드 강조를 트리에서 제외**한다 | Must |
| FR-11 | 대신 회색 박스 + 사유 + **"정상 동작입니다"** | Must |
| FR-12 | 게이트 차단 시에도 **기본액은 표시**한다 | Must |
| FR-13 | 홈 ② 블록에도 동일 게이트가 적용된다 | Must |
| FR-14 | 게이트 판정 로직은 **`packages/core` 공유 셀렉터**를 쓴다. RN 전용 복제가 0건이다 | Must |
| FR-15 | **우회 prop이 0건**이다 | Must |
| FR-16 | `trackRecordId`가 있으면 `[근거 보기]`가 **반드시** 노출된다 | Must |

### C. 바텀시트 (밴드 + 실패 이력)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | 밴드 표는 5행 고정, **현재 밴드 행을 배경색 + 좌측 마커 + 텍스트 "현재"** 로 표시 | Must |
| FR-21 | 실패 이력의 `hits`/`misses`가 **같은 시각적 비중**이다 | Must |
| FR-22 | 최소 항목: MVRV Z 바닥 4/4, **2025-10 톱 미검출(−52%)** | Must |
| FR-23 | 시트 스냅 50%/90%. 드래그·백드롭 탭·백 제스처로 닫힌다 | Must |
| FR-24 | Android 하드웨어 백 버튼이 시트를 먼저 닫는다 | Must |
| FR-25 | 시트 내부 스크롤과 시트 드래그가 충돌하지 않는다 | Must |
| FR-26 | 시트 열림 시 포커스가 시트로 이동하고 배경은 접근성 트리에서 제외된다 | Must |

### D. 김프와 지표 상태

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-30 | 프리미엄 % + **원화 비용**을 한 줄로 | Must |
| FR-31 | `level` 3단계를 **색 + 텍스트** 동시 표기 | Must |
| FR-32 | 문구는 사실 서술. **지시형·차익거래 안내가 0건** | Must |
| FR-33 | `kimchiPremium: null`이면 줄만 숨기고 적립 숫자는 유지 | Must |
| FR-34 | `staleDays >= 3`이면 배지 + "밴드 조정 없음" 안내 | Must |
| FR-35 | 지표 전체 실패 시 기본액만 표시하고 화면이 깨지지 않는다 | Must |

### E. 적립 완료

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-40 | 체크 시 **가벼운 햅틱**(`impactLight`) 1회. 성공 시 `notificationSuccess` | Should |
| FR-41 | 낙관적 갱신 + 실패 시 롤백 + 토스트 | Must |
| FR-42 | 버튼은 요청 중 disabled. **더블 탭이 2회 전송되지 않는다** | Must |
| FR-43 | 완료 후 버튼이 "완료됨" 상태로 바뀌고 다시 누를 수 없다 | Must |
| FR-44 | 원장 자동 매칭으로 이미 완료면 진입 시부터 완료 상태다 | Must |

### F. 알림 진입

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-50 | 주간 적립 푸시를 탭하면 **`PlanDetailScreen`으로 직행**한다 | Must |
| FR-51 | 콜드 스타트 딥링크에서도 같은 화면에 도착한다 | Must |
| FR-52 | 푸시 본문에 **금액을 넣지 않는다**. 잠금화면 노출 위험 | Must |
| FR-53 | 알림 문구에 비난·독촉이 0건이다 | Must |

### G. 금지

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-60 | **`Z >= 7`(0x)에서 매도 문구가 0건**이다. "이번 주 신규 적립 지시 없음" | Must |
| FR-61 | 미실행 주차에 **점수·등급·벌점·이모지 평가가 0건**이다 | Must |
| FR-62 | 거래소 앱으로 보내는 딥링크·주문 유도가 0건이다 | Must |
| FR-63 | 적립 금액을 `AsyncStorage`에 캐시하지 않는다 | Must |

## UX 상태

- **Loading**: 금액 자리 스켈레톤. 카드 높이 고정
- **Empty**: "월 얼마씩 넣을 계획인가요?" 1필드 온보딩
- **Blocked**: 회색 박스 + 사유 + "정상 동작입니다" + 기본액
- **Degraded**: 기본액 + "밴드 조정 없음(지표 조회 실패)"
- **ZeroWeek**: "이번 주 신규 적립 지시 없음" + 밴드 설명
- **Offline**: 마지막 화면 상태 유지 + 상단 오프라인 배너. **체크 버튼 disabled**
- **Error**: 재시도 버튼

## Acceptance Criteria

- [ ] 총액이 32sp 이상으로 가장 크게 표시된다
- [ ] 완료 버튼이 하단 고정이고 safe area를 존중한다
- [ ] **`renderable:false`에서 배수 노드가 트리에 없다**
- [ ] 차단 사유에 "정상 동작입니다"가 있다
- [ ] 차단 시에도 기본액이 표시된다
- [ ] 홈 블록에도 게이트가 적용된다
- [ ] **게이트 셀렉터가 `packages/core` 공유고 RN 복제가 0건이다**
- [ ] 우회 prop이 0건이다
- [ ] 밴드 표의 현재 행이 색 + 마커 + "현재" 텍스트로 표시된다
- [ ] **hits와 misses가 같은 비중이고 2025-10 톱 미검출이 있다**
- [ ] 시트가 드래그·백드롭·백 제스처로 닫힌다
- [ ] Android 백 버튼이 시트를 먼저 닫는다
- [ ] 시트 내부 스크롤이 드래그와 충돌하지 않는다
- [ ] 김프 줄에 % + 원화 비용이 있고 지시형이 0건이다
- [ ] `kimchiPremium: null`에서 적립 숫자가 유지된다
- [ ] `staleDays >= 3`에서 배지와 폴백 안내가 나온다
- [ ] 체크에 햅틱이 있고 더블 탭이 1회만 전송된다
- [ ] 자동 매칭 완료가 진입 시 반영된다
- [ ] **푸시 탭이 콜드 스타트에서도 PlanDetailScreen으로 간다**
- [ ] **푸시 본문에 금액이 없다**
- [ ] **`Z >= 7`에서 매도 문구가 0건이다**
- [ ] 점수·등급·비난 문구가 0건이다
- [ ] 거래소 주문 딥링크가 0건이다
- [ ] `AsyncStorage`에 적립 금액이 없다
- [ ] 글꼴 200%에서 금액이 잘리지 않는다
- [ ] iOS·Android 양쪽에서 위 항목이 모두 통과한다

## Open Questions

- 밴드 표를 바텀시트에 넣으면 "항상 볼 수 있게"라는 웹 FR-22와 강도가 달라진다. 시트를 **기본 50% 노출 상태**로 열어둘지, 탭으로만 열지.
- 푸시에 금액을 넣지 않으면 알림만 보고는 행동할 수 없다. 알림 가치와 잠금화면 노출을 어디서 절충할지.
