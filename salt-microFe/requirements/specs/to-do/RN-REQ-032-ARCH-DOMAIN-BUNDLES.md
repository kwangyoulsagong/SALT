## Summary

RN 앱은 코드가 없다(`apps/mobile` 없음, RN-REQ-001~031 전부 to-do). 바뀌는 코드는 0 이지만, **착수 전 문서가 새 도메인 구조와 어긋난다.**
이 REQ 가 어긋남을 정리하고, 기존 RN REQ 머리에 "2026-10-30 — RN-REQ-032 로 대체되는 부분" 블록을 단다.

| FR | 내용 |
|---|---|
| FR-1 | 서비스 번들 이름 = 도메인 이름(`ADR-005`). Phase 2 첫 분리 후보는 조건(RN-REQ-002 FR-20) 충족 시 정하고, `tax` 를 후보에서 지운다 |
| FR-2 | 하단 탭 4개 — 웹 ~~`AppChrome`~~ **`AppNavigation`**(정정 2026-11-03) 과 같은 순서 · 이름 · 아이콘 토큰 — 한 벌은 `@repo/core/navigation` `APP_TABS` |
| FR-3 | 경계 — **네이티브**: 홈 · 저축(목표 · 적립 · 장면) · 가계부 입력. **웹뷰**: 금융 팁 · 투자 상세 · 코치 리포트. 근거: 입력 속도 · 위젯 · 공유 시트는 네이티브가 필요하고, 정보 화면은 웹과 한 코드 |
| FR-4 | 웹뷰로 쓰는 zone(`web-investment` 일부 · `web-tips`)은 휴대폰 폭 레이아웃 REQ 가 필요하다 — UA `SALTApp/` 일 때 768 미만 안내 끔(기존 규칙) + 레이아웃 실측 |
| FR-5 | 알림 — 도메인별 채널(Android) · 카테고리(iOS), 설정은 서버 `notification_pref` 와 동기 |
| FR-6 | 기존 RN REQ 18건(001 · 002 · 016~031) 머리에 대체 블록 추가(본문은 당시 기록으로 둠 — 2026-10-29 전수 조사와 같은 방식) |

## FR — v4 한 장 패널 (2026-11-13 · 전 영역 계획 `requirements/specs/in-progress/F017-v4-one-panel-global-plan.md`)

> 사용자 2026-11-13: *"리팩토링 스펙 RN 스펙도 새로 다시 써야겠다 UI 등등"*. 투자 상세는 앱에서 **웹뷰**(FR-3 그대로)라 패널 자체는 웹 한 코드(`FE-REQ-064` FR-8~13). 앱 몫은 그 웹뷰가 앱처럼 보이고 동작하게 하는 것.

|---|---|---|

| FR-8 | **스트림이 웹뷰에서도 끊기지 않게** — 해설 SSE 가 앱 백그라운드 → 복귀 때 다시 붙고(저장본이 있으면 바로 다 보임), 오프라인이면 시작하지 않고 "연결되면 이어서" 한 줄(`streaming-sse.md` §9) | to-do |
| FR-9 | **네이티브 연결 셋** — ① 종목 상세 웹뷰의 "거래 기록 · 내 선"은 네이티브 입력 시트로(입력 속도 — FR-3 근거와 같다) ② "내 선에 닿음" 알림은 도메인 채널(FR-5) — **알림만으로는 행동이 안 바뀐다는 실험 결과**(리서치 C · Fischbacher 2017)라 알림 문구에 "선을 정할 때의 이유"를 같이 싣고 효과를 본인 기록으로 잰다 ③ 웹뷰 안 "공유"는 네이티브 공유 시트 | to-do |
