## Summary

청구서 화면의 동작 규칙. **금액을 프론트에서 계산하지 않는다**는 원칙에 예외가 없고(세금과 달리 슬라이더가 없다), 대신 **렌더 게이트 3개**와 **자책 방지 정책**을 코드로 강제한다.

## 렌더 게이트 3개

| 게이트 | 조건 | 근거 |
|---|---|---|
| G-1 | `reconciliation.residual`이 없으면 **청구서를 렌더하지 않는다** | 잔차 노출은 정책이다 |
| G-2 | `topGains` 필드가 없으면 **청구서를 렌더하지 않는다** | 대칭 렌더는 정책이다. 손실만 보여주면 자책 도구가 된다 |
| G-3 | `benchmarkSymbol`이 없으면 **Do-Nothing 트랙을 렌더하지 않는다** | 정의를 툴팁으로 노출할 수 없으면 오해를 만든다 |

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | 게이트 3개를 `entities/invoice/lib/renderGate.ts`에 순수 함수로 둔다 | Must |
| FR-2 | 게이트 미충족 시 **회색 박스 + 사유**를 표시한다. 빈 화면으로 두지 않는다 | Must |
| FR-3 | 게이트에 **우회 플래그를 만들지 않는다** | Must |

## 금액은 계산하지 않는다

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | **프론트에 금액 계산 코드가 0건**이다. 반사실·귀속·편향 합계·수수료·잔차 전부 서버 값 | Must |
| FR-11 | 표시 포맷(천단위·부호·통화)만 한다. `shared/lib/formatKrw` | Must |
| FR-12 | 편향별 합계를 프론트에서 다시 더하지 않는다. 서버 값을 쓴다 | Must |
| FR-13 | 예외: **차트 축 스케일링**은 표시 계산이므로 허용한다 | Must |

## 자책 방지 정책 — 코드로 강제

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | 사용자 문구는 전부 `shared/i18n`에 있다 | Must |
| FR-21 | **금지 표현 검사**: "당신은" · "패닉셀러" · "실수" · "잘못" · "점수" · "등급" · "벌점" · "확실" · "무조건" | Must |
| FR-22 | 편향 라벨 코드를 **사실 서술 문구**로 매핑한다. 예: `panic_sell` → "매도 후 90일 내 가격이 회복된 거래" | Must |
| FR-23 | 매핑 없는 라벨 코드는 **렌더하지 않고** 개발 로그에 남긴다 | Must |
| FR-24 | `hasGains: false`면 **기계적 적립 트랙 비교 블록을 자동 노출**한다. 조건부 렌더가 아니라 기본 동작 | Must |
| FR-25 | 기간 내 거래 0건 문구는 **중립적**이다: "이 기간에는 아무것도 하지 않았습니다. 개입 손익 0원 — 이것도 좋은 결과입니다." | Must |

## 업로드 상태 관리

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-30 | 업로드는 `features/import-ledger`의 mutation이다. **재시도하지 않는다** | Must |
| FR-31 | 업로드 중 **취소 가능**(`AbortSignal`) | Must |
| FR-32 | 성공 시 청구서·원장건강도·포지션 쿼리를 **전부 무효화**한다 | Must |
| FR-33 | 부분 성공(`failed > 0`)도 성공으로 처리하고 실패 행을 보여준다. **전체를 실패로 만들지 않는다** | Must |
| FR-34 | 재업로드 시 `duplicated > 0`이 정상임을 안내한다. 오류로 표시하지 않는다 | Must |
| FR-35 | 업로드 후 lot 재계산·반사실 재계산이 비동기로 돈다. **"계산 중" 상태를 표시**하고 완료를 폴링하거나 알림으로 받는다 | Must |
| FR-36 | 파일 크기 상한(20MB)을 **클라이언트에서 먼저 검사**한다. 서버까지 보내고 413을 받지 않는다 | Must |
| FR-37 | 파일 확장자·MIME을 검사한다. CSV가 아니면 업로드하지 않는다 | Must |

## 거래소 키

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-40 | 키 등록은 mutation. **재시도하지 않는다** | Must |
| FR-41 | 입력한 secret을 **상태에 오래 보관하지 않는다.** 전송 후 즉시 비운다 | Must |
| FR-42 | secret 입력 필드에 `autoComplete="off"` + `type="password"` | Must |
| FR-43 | `403 SCOPE_NOT_ALLOWED`를 **오류가 아니라 안내**로 처리한다. 사용자가 잘못한 것이 아니라 정책이다 | Must |
| FR-44 | 키 삭제는 `useDialog().confirm` — `Promise<boolean>` | Must |

## Acceptance Criteria

- [ ] 렌더 게이트 3개가 순수 함수로 있고 우회 플래그가 0건이다
- [ ] `residual` 없으면 청구서가 렌더되지 않고 사유가 표시된다
- [ ] `topGains` 필드 없으면 청구서가 렌더되지 않는다
- [ ] `benchmarkSymbol` 없으면 Do-Nothing 트랙이 렌더되지 않는다
- [ ] **프론트에 금액 계산 코드가 0건이다** (반사실·귀속·합계·수수료)
- [ ] 편향 합계를 프론트에서 다시 더하지 않는다
- [ ] 사용자 문구가 전부 `shared/i18n`에 있다
- [ ] **금지 표현 검사가 동작한다** (위반 문구 삽입 시 실패)
- [ ] 편향 라벨이 사실 서술로 매핑된다
- [ ] 매핑 없는 라벨이 렌더되지 않는다
- [ ] `hasGains: false`에서 기계적 적립 비교가 자동 노출된다
- [ ] 거래 0건 문구가 중립적이다
- [ ] 업로드가 재시도되지 않고 취소 가능하다
- [ ] 업로드 성공 시 청구서·원장·포지션 쿼리가 무효화된다
- [ ] 부분 성공이 성공으로 처리된다
- [ ] `duplicated > 0`이 오류로 표시되지 않는다
- [ ] 업로드 후 "계산 중"이 표시되고 폴링에 중단 조건이 있다
- [ ] 20MB 초과 파일이 클라이언트에서 걸러진다
- [ ] CSV가 아닌 파일이 업로드되지 않는다
- [ ] secret이 상태에 남지 않고 필드가 `type="password"` + `autoComplete="off"`다
- [ ] `403 SCOPE_NOT_ALLOWED`가 안내로 처리된다 (오류 톤 0건)
- [ ] 키 삭제 시 confirm이 `Promise<boolean>`이다
- [ ] `window`가 URL 쿼리로 유지된다
- [ ] 거래 목록이 커서 페이징이다
- [ ] 낙관적 갱신이 0건이다
- [ ] 금액 `null`이 `0`으로 표시되지 않는다
- [ ] `narrative` null 시 그 영역이 렌더되지 않고 오류 표시가 0건이다

## Open Questions

- 계산 완료를 폴링으로 알지 알림으로 받을지(`BFF-REQ-011` Open Question). **폴링이 단순하지만** 반사실 계산이 1.5s이므로 몇 초 폴링이면 충분하다.
- 금지 표현 검사 구현 방법(`FE-REQ-019` Open Question과 동일).
- 편향 라벨 문구를 누가 검수할지. **사실 서술로 바꾸는 것이 이 기능의 정책 핵심**이므로 카피 리뷰가 필요하다.
