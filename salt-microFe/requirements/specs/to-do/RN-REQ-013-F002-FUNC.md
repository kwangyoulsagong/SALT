## Summary

모바일에서 세금 기능의 동작 규칙. 웹과 다른 것은 **오프라인**, **딥링크 재검증**, **프레임 예산 안에서의 재계산** 셋이다.

## 클라이언트가 계산하는 것 — 웹과 같다

| 계산 | 근거 | 제약 |
|---|---|---|
| `daysRemaining` | 서버 값은 캐시. 기기 시간대가 맞다 | 날짜만, 금액 아님 |
| 연말 시가 슬라이더 3열 | 실시간 조작 | `scenarioParams`로만. **프레임 예산 안에서** |

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | 재계산 로직을 **`packages/core`에서 웹과 공유**한다. 두 번 구현하면 값이 갈린다 | Must |
| FR-2 | `packages/core`의 재계산 함수는 **순수 TS**다. React·RN에 의존하지 않는다 | Must |
| FR-3 | 재계산은 `scenarioParams`만 쓴다. 하드코딩 상수 0건 | Must |
| FR-4 | 반올림은 `scenarioParams.roundingMode`를 따르고 **서버와 원 단위까지 일치**한다 | Must |
| FR-5 | 재계산을 **`InteractionManager` 또는 프레임 예산 안에서** 돌린다. JS 스레드가 하나다 | Must |
| FR-6 | 그 외 금액 계산 0건. 과세표준·세액·취득가액·솔버·환율 환산 전부 서버 | Must |

## 딥링크 — 신뢰하지 않는다

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | 푸시 알림(`tax_deadline`)이 `salt://tax?assetClass=us_stock&taxYear=2026`으로 진입한다 | Must |
| FR-11 | **딥링크 파라미터를 신뢰하지 않는다.** 진입 후 서버로 재조회해 검증한다 | Must |
| FR-12 | 알 수 없는 `assetClass`·`taxYear`면 기본값으로 진입하고 파라미터를 버린다 | Must |
| FR-13 | 로그인되지 않은 상태의 딥링크는 **로그인 후 그 화면으로 이어진다** | Must |
| FR-14 | 딥링크 진입 시 스택을 `자산 탭 → 세금`으로 구성한다. 뒤로가기가 앱을 닫으면 안 된다 | Must |

## 오프라인

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | 마지막 성공 응답을 캐시한다. 캐시 키는 `(userId, taxYear)` | Must |
| FR-21 | 오프라인에서 **캐시를 보여주되 "오프라인 · {시각} 기준" 배너**를 붙인다 | Must |
| FR-22 | 오프라인에서 **mutation을 시도하지 않는다.** 솔버·대조·법령 편집·수동 스냅샷 버튼을 비활성하고 사유를 표시한다 | Must |
| FR-23 | **오프라인 큐를 만들지 않는다.** 나중에 자동 전송되면 사용자가 결과를 확인하지 않은 채 상태가 바뀐다 | Must |
| FR-24 | 슬라이더 재계산은 오프라인에서도 동작한다(클라이언트 계산). 다만 **서버 대조가 안 됨을 표시**한다 | Must |
| FR-25 | 캐시 만료 정책: **금액 데이터는 24시간**. 그보다 오래되면 "데이터가 오래되었습니다"를 표시한다 | Must |
| FR-26 | D-Day는 캐시된 `lastTradeDate`로 **클라이언트에서 계산**하므로 오프라인에서도 정확하다 | Must |

## 문구 게이트 — 웹과 같은 정책

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-30 | 사용자 문구는 전부 `shared/i18n`에 있다. **웹과 같은 카탈로그를 `packages/core`에서 공유**한다 | Must |
| FR-31 | 금지 표현 검사를 카탈로그 단위로 한다: "확실"·"무조건"·"보장"·"100%"·"서둘러"·"지금 매도"·"이렇게 하세요"·"절세 전략" | Must |
| FR-32 | 서버 코드(`noteCode`·`caveatCodes`·`degradedReasons`)를 i18n 키로 매핑한다. **매핑 없는 코드는 렌더하지 않는다** | Must |
| FR-33 | `caveatCodes`에 재매수 취득가액 경고가 없으면 **솔버 후보를 렌더하지 않는다** | Must |
| FR-34 | `disclaimer`·`lawConfigShown`이 없으면 **세금 화면을 렌더하지 않는다** | Must |

## Acceptance Criteria

- [ ] 재계산 로직이 `packages/core`에서 웹과 공유된다 (중복 구현 0건)
- [ ] `packages/core`의 재계산 함수가 React·RN에 의존하지 않는다
- [ ] 하드코딩 세율·공제가 0건이다
- [ ] **재계산 결과가 서버와 원 단위까지 일치한다** (경계값 10케이스)
- [ ] 재계산이 프레임을 막지 않는다 (60fps 유지)
- [ ] 그 외 금액 계산이 0건이다
- [ ] 푸시 딥링크가 세금 화면으로 진입한다
- [ ] **딥링크 진입 후 서버 재검증이 일어난다**
- [ ] 알 수 없는 파라미터가 버려지고 기본값으로 진입한다
- [ ] 미로그인 딥링크가 로그인 후 그 화면으로 이어진다
- [ ] 딥링크 진입 후 뒤로가기가 자산 탭으로 간다 (앱 종료 0건)
- [ ] 오프라인에서 캐시가 표시되고 배너에 시각이 있다
- [ ] 오프라인에서 mutation 버튼이 비활성이고 사유가 표시된다
- [ ] **오프라인 큐가 0건이다**
- [ ] 오프라인에서 슬라이더가 동작하고 대조 불가 표시가 있다
- [ ] 캐시가 24시간 넘으면 "오래되었습니다"가 표시된다
- [ ] 오프라인에서 D-Day가 정확하다
- [ ] i18n 카탈로그가 웹과 공유된다
- [ ] 금지 표현 검사가 동작한다
- [ ] 매핑 없는 서버 코드가 렌더되지 않는다
- [ ] 재매수 경고 없으면 솔버 후보가 렌더되지 않는다
- [ ] `disclaimer`·`lawConfigShown` 없으면 화면이 렌더되지 않는다
- [ ] mutation 재시도가 0건, 솔버 캐시가 0건, 낙관적 갱신이 0건이다
- [ ] 백그라운드 복귀 시 stale 데이터가 재조회된다
- [ ] 금액 `null`이 `0`으로 표시되지 않는다

## Open Questions

- `packages/core`에 i18n 카탈로그를 넣을지. 문구는 플랫폼별로 달라질 수 있다(모바일이 더 짧다) → **키는 공유하고 값은 플랫폼별**이 기본안.
- 캐시 만료 24시간이 적절한가. 세금 값은 원장이 바뀌지 않으면 변하지 않으므로 더 길어도 된다. 다만 **D-Day는 매일 바뀐다** — 그건 클라이언트 계산이므로 문제없다.
- 백그라운드 복귀 재조회가 데이터 사용량을 늘린다. 세금 화면은 자주 보지 않으므로 문제가 아닐 가능성이 높다.
