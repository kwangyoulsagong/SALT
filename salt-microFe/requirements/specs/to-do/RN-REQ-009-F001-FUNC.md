## Summary

모바일 청구서의 동작 규칙. 렌더 게이트 3개와 자책 방지 정책은 웹과 **완전히 같다**(`packages/core`에서 공유). 다른 것은 **오프라인**, **파일 선택**, **백그라운드 전환** 셋이다.

## 렌더 게이트 — 웹과 공유

| 게이트 | 조건 |
|---|---|
| G-1 | `reconciliation.residual` 없으면 청구서 렌더 안 함 |
| G-2 | `topGains` 필드 없으면 청구서 렌더 안 함 |
| G-3 | `benchmarkSymbol` 없으면 Do-Nothing 트랙 렌더 안 함 |

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | 게이트 함수를 **`packages/core`에서 웹과 공유**한다. 두 번 구현하면 정책이 갈린다 | Must |
| FR-2 | 게이트 미충족 시 회색 박스 + 사유 | Must |
| FR-3 | 우회 플래그 0건 | Must |

|---|---|---|
| FR-10 | **금액 계산 코드 0건.** 반사실·귀속·편향 합계·수수료·잔차 전부 서버 값 | Must |
| FR-11 | 표시 포맷만. 포맷터를 `packages/core`에서 웹과 공유 | Must |

## 자책 방지 — 웹과 같은 카탈로그

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | 사용자 문구는 `shared/i18n`에. **키를 `packages/core`에서 웹과 공유**하고 값은 플랫폼별(모바일은 더 짧다) | Must |
| FR-21 | 금지 표현 검사: "당신은"·"패닉셀러"·"실수"·"잘못"·"점수"·"등급"·"벌점"·"확실"·"무조건" | Must |

## 파일 선택과 업로드

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-30 | OS 파일 선택기(`src/native/documentPicker`)로 CSV를 받는다. MIME 필터 | Must |
| FR-31 | **파일 내용을 읽지 않는다.** URI를 `FormData`에 넣는다 | Must |
| FR-32 | 크기(20MB)·확장자·MIME을 **선택 직후 검사**한다 | Must |
| FR-33 | 업로드는 mutation. **재시도 0회.** `AbortSignal`로 취소 | Must |
| FR-34 | 성공 시 청구서·원장·포지션 쿼리를 **전부 무효화** | Must |
| FR-35 | 부분 성공(`failed > 0`)을 성공으로 처리한다 | Must |
| FR-36 | 재업로드 `duplicated > 0`을 오류로 표시하지 않는다 | Must |
| FR-37 | **업로드 중 앱이 백그라운드로 가면 중단**된다. 재개하지 않고 사용자에게 알리고 재시도하게 한다 | Must |
| FR-38 | 업로드 후 계산이 비동기로 돈다. "계산 중" 표시 + 폴링. **앱이 백그라운드면 폴링을 멈춘다** | Must |

## Acceptance Criteria

- [ ] 게이트 함수가 `packages/core`에서 웹과 공유된다 (중복 구현 0건)
- [ ] 게이트 3개가 동작하고 우회 플래그가 0건이다
- [ ] **금액 계산 코드가 0건이다**
- [ ] 포맷터가 웹과 공유된다
- [ ] i18n 키가 웹과 공유된다
- [ ] 금지 표현 검사가 동작한다
- [ ] 편향 라벨이 사실 서술로 매핑되고 매핑 없는 코드가 렌더되지 않는다
- [ ] `hasGains: false`에서 기계적 적립 비교가 자동 노출된다
- [ ] OS 파일 선택기가 MIME 필터로 동작한다
- [ ] **파일 내용을 읽지 않는다**
- [ ] 20MB 초과가 선택 직후 걸러진다
- [ ] 업로드 재시도 0회, 취소 가능
- [ ] 업로드 성공 시 3개 쿼리가 무효화된다
- [ ] 부분 성공이 성공으로 처리된다
- [ ] `duplicated > 0`이 오류로 표시되지 않는다
- [ ] **업로드 중 백그라운드 전환 시 중단되고 알려진다**
- [ ] 폴링이 백그라운드에서 멈춘다
- [ ] 오프라인에서 캐시 + 배너가 표시된다
- [ ] 오프라인에서 mutation 버튼이 비활성이다
- [ ] **오프라인 큐가 0건이다**
- [ ] 캐시 24시간 초과 시 안내가 나온다
- [ ] 온라인 복귀 시 mutation 자동 재전송이 0건이다
- [ ] 캐시 없는 기간이 오프라인에서 "불러올 수 없습니다"다
- [ ] 거래 목록이 `useInfiniteQuery`다
- [ ] 낙관적 갱신 0건
- [ ] 백그라운드 복귀 시 stale 데이터가 재조회된다
- [ ] 폴링 중단 조건 4개가 있다
- [ ] **secret이 기기 저장소에 0건이다** (secure store 포함)
- [ ] `403 SCOPE_NOT_ALLOWED`가 안내로 처리된다
- [ ] 금액 `null`이 `0`으로 표시되지 않는다
- [ ] `narrative` null 시 오류 표시가 0건이다

## Open Questions

- i18n 값을 플랫폼별로 둘지 공유할지. **키는 공유, 값은 플랫폼별**이 기본안(모바일 문구가 짧다) — 그러면 금지 표현 검사를 두 카탈로그에 각각 돌려야 한다.
- 업로드 중 백그라운드 전환을 iOS 백그라운드 업로드로 처리할지. 복잡도가 크고 **10,000행이 10s면 사용자가 앱을 떠나지 않을 가능성이 높다** → 중단이 기본안.
- 캐시 24시간이 적절한가. 반사실 스냅샷은 주 1회 갱신이므로 더 길어도 된다.
