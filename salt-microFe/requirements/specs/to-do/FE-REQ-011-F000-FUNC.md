## Summary

수리 9건의 **동작 규칙**과 초대·온보딩의 상태 관리. 그리고 사용자 노출 문구를 `shared/i18n`으로 모으는 작업(현재 `constants/api.ts`에 섞여 있다).

## 상태 동기화 — 관심 종목

실시간 탭의 별 아이콘과 관심 종목 탭 목록이 **같은 상태를 봐야 한다.**

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | 관심 종목은 `entities/market/model`의 단일 소스다. 두 화면이 같은 쿼리를 구독한다 | Must |
| FR-2 | 추가/제거는 `features/toggle-watchlist`의 mutation이다. 성공 시 **관심 종목 쿼리를 무효화**한다 | Must |
| FR-3 | **낙관적 갱신을 허용한다.** 별 아이콘은 금액이 아니고 즉시 반응이 중요하다 | Must |
| FR-4 | 실패 시 낙관적 갱신을 되돌리고 토스트를 띄운다 | Must |
| FR-5 | 관심 종목 추가 상한이 있으면 서버가 판정한다. 프론트가 세지 않는다 | Must |

## WebSocket 마지막 수신 시각

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | WS 메시지 수신 시각을 `entities/market/model`에 저장한다 | Must |
| FR-11 | 헤더에 그 시각을 **상대 시간 또는 절대 시각**으로 표시한다 | Must |
| FR-12 | WS가 끊기면 **"연결 끊김"** 을 표시한다. 오래된 시각을 그대로 두면 사용자가 최신이라고 오해한다 | Must |
| FR-13 | 시각 갱신이 **테이블 전체를 리렌더하지 않는다.** 헤더만 갱신 | Must |
| FR-14 | 하드코딩 문자열 `"실시간 오늘 19:30 기준"`이 코드에 0건이다 | Must |

## 터치 선택

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | 행 선택에 `onClick`을 **추가**한다. `onMouseEnter`는 **유지**한다(PC hover 동작을 없애지 않는다) | Must |
| FR-21 | 키보드 선택(`onKeyDown` Enter/Space)을 추가한다 | Must |
| FR-22 | 선택된 행을 시각적으로 표시한다. hover와 선택을 **구분**한다 | Must |
| FR-23 | 터치 기기에서 hover가 sticky가 되지 않게 한다(`@media (hover: hover)`) | Must |

## 반응형 동작

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-30 | 모바일에서 `MarketPreview`를 **아래로 접는다.** 조건은 CSS 미디어 쿼리이고 **JS 분기를 만들지 않는다**(SSR 불일치 위험) | Must |
| FR-31 | JS로 뷰포트를 판단해야 하면 **마운트 후**에만 한다. 서버 렌더 결과가 달라지면 하이드레이션이 깨진다 | Must |
| FR-32 | 표 스크롤 위치를 종목 선택 시 유지한다. 선택마다 맨 위로 튀지 않게 | Should |

## 문구 정리 — `shared/i18n`으로 모은다

현재 `constants/api.ts`에 `HTTP_ERROR_MESSAGE`·`TOAST_MESSAGES`·`ERROR_MESSAGE`가 섞여 있다.

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-40 | 사용자 노출 문구를 전부 `shared/i18n`으로 옮긴다 | Must |
| FR-41 | `constants/api.ts`에는 **URL·상수만** 남는다 | Must |
| FR-42 | 오타 `덜 썻어요` → `덜 썼어요`를 i18n 카탈로그에서 고친다 | Must |
| FR-43 | **금지 표현 검사**를 카탈로그에 적용한다: "확실"·"무조건"·"보장"·"100%"·"당신은"·"점수"·"등급" | Must |
| FR-44 | 서버 `reasonCode`·`messageCode`를 i18n 키로 매핑한다. **매핑 없는 코드는 렌더하지 않는다** | Must |

## 초대·온보딩 상태

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-50 | 온보딩 단계를 서버 `onboarding/status`가 결정한다. **프론트가 판단하지 않는다** | Must |
| FR-51 | 코드 입력 중 `invite/check`를 **디바운스**해서 부른다(300ms). 타이핑마다 부르지 않는다 | Must |
| FR-52 | `invite/accept`는 mutation. **재시도 0회** — 코드가 소진된다 | Must |
| FR-53 | 성공 시 토큰을 저장하고 홈으로 이동한다. 저장 위치는 **쿠키**(`FE-REQ-008` 전환 후) | Must |
| FR-54 | 실패 `reasonCode` 3종을 각각 다른 문구로. **상한 초과는 서버가 노출하지 않으므로** 일반 실패로 처리한다 | Must |
| FR-55 | 비밀번호 입력은 `type="password"` + `autoComplete="new-password"` | Must |
| FR-56 | 온보딩 중 이탈 후 재진입 시 **완료한 단계를 건너뛴다** | Must |

## Acceptance Criteria

- [ ] 관심 종목이 단일 소스이고 두 화면이 동기화된다
- [ ] 별 아이콘에 낙관적 갱신이 적용되고 실패 시 되돌아간다
- [ ] WS 마지막 수신 시각이 헤더에 표시된다
- [ ] WS 끊김이 표시된다
- [ ] 시각 갱신이 테이블 전체를 리렌더하지 않는다 (Profiler)
- [ ] **하드코딩 `"실시간 오늘 19:30 기준"`이 0건이다**
- [ ] `onClick`이 추가되고 `onMouseEnter`가 유지된다
- [ ] 키보드 선택이 동작한다
- [ ] hover와 선택이 시각적으로 구분된다
- [ ] 터치 기기에서 hover가 sticky가 되지 않는다
- [ ] `MarketPreview` 접힘이 CSS 미디어 쿼리로 처리된다 (JS 분기 0건)
- [ ] 하이드레이션 경고가 0건이다
- [ ] 사용자 문구가 전부 `shared/i18n`에 있다
- [ ] `constants/api.ts`에 사용자 문구가 0건이다
- [ ] **`덜 썻어요`가 0건이다**
- [ ] 금지 표현 검사가 동작한다
- [ ] 매핑 없는 서버 코드가 렌더되지 않는다
- [ ] 온보딩 단계가 서버 응답으로 결정된다
- [ ] `invite/check`가 디바운스된다 (타이핑 5회 → 요청 1회)
- [ ] `invite/accept`가 재시도되지 않는다
- [ ] 실패 `reasonCode` 3종이 각각 다른 문구다
- [ ] 온보딩 재진입 시 완료 단계를 건너뛴다
- [ ] 회원가입·비밀번호·계정삭제 화면·훅이 0건이다
- [ ] 그 경로 직접 진입이 `/`로 리다이렉트된다
- [ ] 로그인 화면에 초대 안내가 있다
- [ ] **동면 API 호출이 0건이다** (BFF 410 로그 1주 검증)
- [ ] 변경 금지 목록 항목이 제거되지 않았다

## Open Questions

- 토큰 저장을 언제 쿠키로 옮길지(`FE-REQ-008` Open Question). F000에서 초대 화면을 만들 때 함께 하는 것이 자연스럽다.
- 관심 종목 낙관적 갱신을 허용하는 것이 "금액 화면 낙관적 갱신 금지" 원칙과 충돌하지 않는지. **별 아이콘은 금액이 아니므로** 허용이 맞다.
- `MarketPreview` 접힘을 CSS로만 처리할 수 있는지. 접힌 상태에서 차트를 마운트하지 않으려면 JS 판단이 필요할 수 있다 → **마운트 후 판단**(FR-31).
