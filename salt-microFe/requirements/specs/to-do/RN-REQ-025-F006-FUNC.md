## Summary

모바일 대화의 핵심 규칙은 **백그라운드 전환 처리**다. 앱이 백그라운드로 가면 스트림이 끊기고, 복귀 시 **중복 생성 없이** 이어야 한다.

## SSE — 백그라운드가 웹과 다른 점

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | **`EventSource`가 RN에 기본 내장되어 있지 않다.** 폴리필 또는 `fetch` + `ReadableStream` 직접 구현을 쓴다 | Must |
| FR-2 | 직접 구현이면 **헤더에 토큰을 붙일 수 있다.** 웹의 쿠키 문제가 없다 | Must |
| FR-3 | 앱이 **백그라운드로 가면 스트림을 끊는다.** OS가 곧 끊고, 남겨두면 배터리를 먹는다 | Must |
| FR-4 | 복귀 시 **같은 `messageId`로 재연결**한다. `Last-Event-ID`로 이어받는다 | Must |
| FR-5 | **재연결 시 `POST /messages`를 다시 부르지 않는다.** 메시지가 두 개 생긴다 | Must |
| FR-6 | 복귀 시 이미 완료됐으면 **전문을 한 번에** 받고 닫는다 | Must |
| FR-7 | 재연결 백오프(1s → 2s → 4s). 3회 실패 시 끊고 재시도 버튼 | Must |
| FR-8 | 언마운트·취소 시 스트림을 닫고 **서버로 종료를 전파**한다 | Must |
| FR-9 | 중복 델타를 방어적으로 검사한다 | Must |

## 스트리밍 반영

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | 델타를 **마지막 말풍선에만** 누적한다 | Must |
| FR-11 | 토큰을 **프레임 단위로 버퍼링**한다. **JS 스레드가 하나이므로 웹보다 중요하다** | Must |
| FR-12 | 카드는 완성 객체로 한 번에 붙인다 | Must |

| FR-15 | 자동 스크롤이 **매 델타마다 일어나지 않게** 프레임 단위로 | Must |

## Acceptance Criteria

- [ ] SSE 구현 방식이 확정되고 **헤더로 토큰을 보낸다**
- [ ] **백그라운드 전환 시 스트림이 끊긴다**
- [ ] 복귀 시 같은 `messageId`로 재연결되고 `Last-Event-ID`로 이어받는다
- [ ] **재연결 시 `POST /messages`가 다시 호출되지 않는다** (메시지 중복 0건)
- [ ] 복귀 시 완료됐으면 전문을 한 번에 받는다
- [ ] 재연결 백오프가 동작하고 3회 실패 시 버튼이 나온다
- [ ] 언마운트·취소 시 서버로 종료가 전파된다
- [ ] 중복 델타가 걸러진다
- [ ] **델타가 마지막 말풍선에만 반영된다**
- [ ] 토큰이 프레임 단위로 버퍼링된다
- [ ] 카드가 완성 객체로 붙는다
- [ ] `error`에서 `fallbackText`가 렌더된다
- [ ] 자동 스크롤이 프레임 단위다
- [ ] **오프라인에서 스트림이 시작되지 않고 입력이 보존된다**
- [ ] 오프라인에서 과거 대화가 캐시로 보인다
- [ ] **오프라인 큐가 0건이다**
- [ ] 홈 오프라인 배너가 있다
- [ ] 온라인 복귀 시 자동 전송이 0건이다
- [ ] **홈에 mutation 호출이 0건이다**
- [ ] 블록 순서가 코드로 고정된다
- [ ] 금액 `null`이 `0`으로 표시되지 않는다
- [ ] AI 추천에 게이트가 적용된다
- [ ] 딥링크가 재검증되고 뒤로가기가 앱을 닫지 않는다
- [ ] 추천 질문 4개가 `shared/i18n`에 있다
- [ ] 금지 표현 검사가 동작한다
- [ ] 매핑 없는 코드가 렌더되지 않는다
- [ ] 면책이 답변마다 붙는다
- [ ] **"주문하기" 버튼·`Linking.openURL` 거래소 링크가 0건이다**
- [ ] `POST /messages` 재시도가 0건이다
- [ ] 낙관적 갱신이 0건이다
- [ ] 백그라운드 복귀 시 홈이 재조회된다
- [ ] 대화 삭제 시 confirm이 뜨고 자동 삭제가 0건이다

## Open Questions

- **RN에서 SSE를 무엇으로 구현할지.** `react-native-sse` 폴리필 vs `fetch` + `ReadableStream`. **RN의 `fetch`가 스트림을 지원하는지** 확인 필요(Hermes/네이티브 네트워킹 구현에 따라 다르다) — **착수 전 필수 조사.**
- 백그라운드 전환 시 스트림을 끊으면 **긴 답변이 중간에 멈춘다.** 복귀 시 이어받지만 체감이 어떤지 확인 필요.
- iOS 백그라운드 짧은 유예(수 초)를 활용해 마무리할지. 복잡도가 크다 → **끊는 것이 기본안.**
