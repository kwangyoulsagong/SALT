## Summary

코치 화면 모바일 구현. 웹과 다른 점은 **카드에 3종을 다 넣으면 화면 두 개 길이가 된다**는 것이다. 그래서 **카드 안에 3종 요약을 넣고 상세는 접힘**으로 처리한다 — 단 **3종이 동시에 보인다는 정책은 지킨다**(요약 3개가 한 화면에 있다).

## FSD 배치

| 레이어 | 슬라이스 | 컴포넌트 |
|---|---|---|
| `pages` | `coach` | `CoachScreen` — 3탭 중 하나 |
| `widgets` | `coach-console` | 카드 + 리스크 + 후보 + 익절 + preflight + 성적표 + 행동기록 |
| `features` | `rate-recommendation` · `run-preflight` · `regenerate-coach` · `edit-coach-profile` | 웹과 같은 슬라이스 이름 |
| `entities` | `coach` | 웹과 **같은 컴포넌트 이름**, RN 구현 |

## 화면 구조 — 세로

```
코치 탭 (CoachScreen)
┌─ 생성 시각 + staleHours 배지 + [새로 생성]
├─ 추천 카드
│   ┌ renderable: true ────────────────────────┐
│   │ [매수] KRW-BTC        점수 72             │
│   │ 점수는 확률이 아닙니다                     │
│   │ ─────────────────────────────────────────│
│   │ 근거 3개 (요약)               [자세히 ▾]  │
│   │ 성적 42회 · 승률 57%          [자세히 ▾]  │
│   │ 틀렸던 때 1건                 [자세히 ▾]  │
│   │ ─────────────────────────────────────────│
│   │ [도움 됐음] [도움 안 됨]                   │
│   └──────────────────────────────────────────┘
│   ┌ renderable: false ───────────────────────┐
│   │ (회색) 이 신호의 과거 성적 데이터가        │
│   │ 아직 없어 추천을 표시하지 않습니다        │
│   │ (표본 3건) · 이것은 정상 동작입니다        │
│   └──────────────────────────────────────────┘
├─ 리스크 (severity 내림차순, 최대 3 + 더보기)
├─ 후보 (상위 3, 접힘)
├─ 익절 플랜 (보유 종목별, 세로 카드)
├─ [주문 전 계산] → BottomSheet
├─ [신호 성적표] → push (표는 가로 스크롤)
├─ 행동 기록 (사실 서술 + 청구서 링크)
├─ 국내주식 제외 안내
└─ 면책 (하단 고정)
```

## Requirements

### A. 게이트 — 컴포넌트가 강제한다

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | `RecommendationCard`가 `renderable: false`면 **카드 대신 `BlockedNotice`** 를 렌더한다 | Must |
| FR-2 | `BlockedNotice`에 사유 + **"이것은 정상 동작입니다"** | Must |
| FR-3 | **카드 안에 근거·성적·실패사례 3개 요약이 동시에 보인다.** 각각 `[자세히]`로 펼친다 | Must |
| FR-4 | **우회 prop이 0건이다** | Must |
| FR-5 | 홈 요약 카드에도 같은 게이트가 적용된다 | Must |
| FR-6 | 3종 요약이 **한 화면(스크롤 전)에 들어가야 한다.** 375×667에서 검수 | Must |

### B. 점수

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | 점수와 **`scoreNote`를 함께** 렌더한다. `scoreNote` 없으면 점수를 표시하지 않는다 | Must |
| FR-11 | `action` 4종을 **색 + 텍스트 + 아이콘 3중**으로. `Badge`로 구현 | Must |
| FR-12 | 점수에 `accessibilityLabel`("100점 중 72점") | Must |
| FR-13 | **게이지·프로그레스바로 100% 채우지 않는다.** 확률로 읽힌다 | Must |

### C. 성적표

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | 카드 안 배지: `42회 · 승률 57%`. 상세는 펼침 | Must |
| FR-21 | `lowSample: true`면 `표본 부족` 배지 + 승률 회색 | Must |
| FR-22 | 신호 유형별 표는 **별도 화면으로 push**한다. 좁은 화면에 표를 넣지 않는다 | Must |
| FR-23 | 표는 **가로 스크롤 컨테이너**에 둔다. 화면이 가로로 스크롤되지 않는다 | Must |
| FR-24 | 표에 스크린리더용 행·열 라벨을 준다 | Must |

### D. 익절 플랜

| ID | 요구사항 | 우선순위 |

| FR-30 | 보유 종목별 **세로 카드**. 3단계를 `KeyValueList`로 | Must |
| FR-31 | 현재가 대비 거리 %를 표시한다 | Must |
| FR-32 | **목표주가·수익률 예측 문구가 0건**이다 | Must |
| FR-33 | 보유 0건이면 "보유 종목이 없습니다" | Must |

## Acceptance Criteria

- [ ] `renderable: false`에서 카드 대신 `BlockedNotice`가 렌더된다
- [ ] `BlockedNotice`에 "이것은 정상 동작입니다"가 있다
- [ ] **카드에 근거·성적·실패사례 3개 요약이 동시에 보인다**
- [ ] **375×667 스크롤 전에 3종 요약이 들어간다**
- [ ] 우회 prop이 0건이다
- [ ] 홈 요약 카드에도 게이트가 적용된다
- [ ] `scoreNote`가 함께 보이고, 없으면 점수가 렌더되지 않는다
- [ ] `action` 4종이 3중 표기다
- [ ] 게이지·프로그레스바 표현이 0건이다
- [ ] `lowSample`에서 배지 + 회색 처리
- [ ] 성적표 표가 별도 화면이고 **가로 스크롤 컨테이너**에 있다
- [ ] 화면이 가로로 스크롤되지 않는다
- [ ] 익절 3단계와 거리 %가 표시된다
- [ ] **목표주가·수익률 예측 문구가 0건이다**
- [ ] preflight가 `BottomSheet`이고 입력이 `Keypad`다
- [ ] **preflight에 게이트·차단이 0건이다**
- [ ] **"주문하기" 버튼과 거래소 딥링크가 0건이다**
- [ ] 행동 기록이 사실 서술이고 **인격 평가가 0건이다**
- [ ] 청구서 링크가 자산 탭으로 이동한다
- [ ] 피드백 사유 4종이 `BottomSheet`로 나온다
- [ ] 피드백만 낙관적 갱신이다
- [ ] `staleHours > 24`에서 배지 + 버튼이 나온다
- [ ] 쿨다운 중 버튼 비활성 + 남은 시간
- [ ] 429가 남은 시간으로 표시된다
- [ ] 성향 6항목이 있고 저장 후 재조회된다
- [ ] **면책 하단 고정이고 `disclaimer` 없으면 화면이 렌더되지 않는다**
- [ ] 국내주식 제외가 표시된다
- [ ] LLM 실패 시 배지가 나온다
- [ ] AI 생성물이 `colors.ai.*` + `Badge tone="ai"`로 구분된다
- [ ] 오프라인 배너 + mutation 버튼 비활성
- [ ] **오프라인 큐가 0건이다**
- [ ] 터치 타깃 44×44 이상
- [ ] **폰트 최대 확대에서 카드가 깨지지 않는다**
- [ ] VoiceOver·TalkBack으로 카드 3종이 낭독된다
- [ ] **확신 표현이 0건이다**

## Open Questions

- **3종 요약이 375×667 스크롤 전에 들어가는가.** 안 들어가면 정책("동시에 보인다")과 화면 크기가 충돌한다 → **요약을 더 짧게** 하거나 정책 해석을 조정해야 한다. 사용성 검증 필요.
- 성적표를 push할지 인라인 접힘으로 할지. push가 화면을 짧게 유지하지만 왕복이 늘어난다.
- `Keypad`가 `@repo/ui-native`에 있는지(`RN-REQ-001` FR-22 목록에는 없다) → **추가 필요**.
