## Summary

모바일 코치의 동작 규칙. 게이트·금지 표현·주문 미실행은 **웹과 완전히 같고 `packages/core`에서 공유**한다. 다른 것은 오프라인과 백그라운드 처리다.

## 게이트 — 웹과 공유

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | 게이트 함수를 **`packages/core`에서 웹과 공유**한다 | Must |
| FR-2 | 서버 `renderable`을 쓰고, **방어적으로 재확인**한다(3종 중 하나가 없으면 렌더하지 않고 개발 로그) | Must |
| FR-3 | **우회 prop·플래그가 0건이다** | Must |
| FR-4 | `disclaimer` 없으면 화면 렌더 안 함. `scoreNote` 없으면 점수 렌더 안 함 | Must |
| FR-5 | `blockedReason` 3종을 i18n 키로 매핑 | Must |

## 계산하지 않는다

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | **점수·승률·MDD·`distancePct`·preflight를 계산하지 않는다** | Must |
| FR-11 | 표시 포맷터를 `packages/core`에서 웹과 공유한다 | Must |
| FR-12 | `staleHours`는 서버 값을 쓴다. **기기 시계로 재계산하지 않는다** — 시계가 틀린 기기에서 배지가 잘못 뜬다 | Must |

## 문구 — 웹과 같은 정책

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | 사용자 문구는 `shared/i18n`. **키를 웹과 공유**하고 값은 플랫폼별(모바일이 짧다) | Must |
| FR-21 | 금지 표현 검사 11개: "확실"·"무조건"·"보장"·"100%"·"목표주가"·"예상 수익률"·"당신은"·"패닉셀러"·"실수"·"잘못"·"점수가 높으니" | Must |
| FR-22 | 서버 코드 4종(`factCode`·`conditionCode`·`reasonCode`·`blockedReason`)을 i18n 키로 매핑 | Must |
| FR-23 | 매핑 없는 코드를 원문으로 노출하지 않는다 | Must |
| FR-24 | 행동 기록을 **사실 서술로만** | Must |
| FR-25 | 익절 문구에 "목표주가"·"예상"을 쓰지 않는다 | Must |

## 주문을 실행하지 않는다

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-30 | **"주문하기"·"매수하기"·"매도하기" 버튼 0건** | Must |
| FR-31 | preflight 끝에 "직접 주문하세요" | Must |
| FR-32 | **거래소 앱 딥링크·`Linking.openURL` 0건.** 모바일에서는 특히 유혹이 크다(앱이 설치되어 있다) | Must |
| FR-33 | preflight에 차단 로직 0건 | Must |

## 쿨다운

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-40 | 쿨다운은 **서버 판정**. 기기 타이머를 신뢰하지 않는다 | Must |
| FR-41 | `retryAfterSeconds`로 로컬 카운트다운하되, 0이 되면 `generation-status`를 재조회한다 | Must |
| FR-42 | **앱이 백그라운드에 있던 동안 타이머가 멈춘다.** 복귀 시 `generation-status`를 재조회한다 | Must |
| FR-43 | 429를 받으면 타이머를 갱신한다. 오류 토스트 0건 | Must |
| FR-44 | 재생성 mutation 재시도 0회 | Must |
| FR-45 | 202 후 폴링. **중단 조건 5개**: 완료 · 실패 · 언마운트 · 최대 횟수 · **백그라운드 전환** | Must |

## Acceptance Criteria

- [ ] 게이트 함수가 `packages/core`에서 웹과 공유된다
- [ ] 방어적 재확인이 동작한다 (3종 중 하나 없으면 렌더 안 함 + 개발 로그)
- [ ] **우회 prop·플래그가 0건이다**
- [ ] `disclaimer`·`scoreNote` 없으면 렌더되지 않는다
- [ ] **점수·승률·MDD·`distancePct`·preflight 계산 코드가 0건이다**
- [ ] 포맷터가 웹과 공유된다
- [ ] `staleHours`가 서버 값이다 (기기 시계 재계산 0건)
- [ ] i18n 키가 웹과 공유되고 금지 표현 검사 11개가 동작한다
- [ ] 매핑 없는 코드가 원문으로 노출되지 않는다
- [ ] 행동 기록이 사실 서술이고 인격 평가가 0건이다
- [ ] 익절 문구에 "목표주가"·"예상"이 0건이다
- [ ] **"주문하기" 버튼과 거래소 딥링크·`Linking.openURL`이 0건이다**
- [ ] preflight에 차단 로직이 0건이다
- [ ] 쿨다운이 서버 판정이고 백그라운드 복귀 시 재조회된다
- [ ] 429가 타이머 갱신이고 오류 토스트가 0건이다
- [ ] **폴링 중단 조건 5개가 있다** (백그라운드 포함)
- [ ] **`explain`이 자동 호출되지 않는다**
- [ ] `explain`에 취소 버튼이 있고 백그라운드 전환 시 취소된다
- [ ] 진행 중 재클릭이 막힌다
- [ ] `explain` 실패 시 규칙 문장이 표시되고 오류 화면이 0건이다
- [ ] `[도움 안 됨]`이 사유 없이 전송되지 않는다
- [ ] 피드백이 낙관적 갱신이고 실패 시 되돌아간다
- [ ] 오프라인 배너 + mutation 버튼 비활성
- [ ] **오프라인 큐가 0건이다**
- [ ] 캐시 24시간과 `staleHours`가 문구로 구분된다
- [ ] 온라인 복귀 시 mutation 자동 재전송이 0건이다
- [ ] preflight가 버튼 클릭으로만 호출된다
- [ ] 성향 저장 후 코치 쿼리가 무효화된다
- [ ] 낙관적 갱신이 피드백만이다
- [ ] 백그라운드 복귀 시 stale 데이터가 재조회된다

## Open Questions

- 캐시 24시간과 `staleHours`(생성 후 경과)를 사용자가 혼동할 수 있다. **문구를 어떻게 구분할지** 카피 검토 필요.
- `explain` 20s를 모바일에서 기다리게 할지. **취소 버튼 + 진행 표시**가 기본안이지만, 아예 만들지 않는 것도 검토 대상(`FE-REQ-029` Open Question).
- i18n 값을 플랫폼별로 두면 금지 표현 검사를 두 카탈로그에 각각 돌려야 한다.
