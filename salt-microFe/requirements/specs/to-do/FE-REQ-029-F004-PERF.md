## Summary

코치 화면의 급소는 **LLM 경로(20s)** 와 **폴링이 방치되는 것**이다. 계산은 전부 서버이므로 렌더 부하는 낮다.

## 예산

| 지점 | 예산 | 비고 |
|---|---|---|
| 코치 탭 첫 페인트 | **400ms** | 최신 insight 읽기 |
| 추천 카드 페인트 | **400ms** | Suspense 밖 또는 첫 블록 |
| 성적표 표 | 600ms | |
| 익절 플랜 | 500ms | detail에 포함 |
| 행동 기록 | 500ms | detail에 포함 |
| 전체 완료 | 800ms | |
| preflight (버튼 → 결과) | **300ms** | |
| 피드백 (낙관적) | **0ms 체감** | |
| 재생성 (202) | 300ms | 이후 폴링 |
| 폴링 완료까지 | 최대 30초 | |
| **`explain`** | **20s 상한** | LLM. 예산이 아니라 상한 |
| 클라이언트 JS 증가분 | **40KB gzip 이하** | 차트 없음 (코치 리포트) |
| **패널 — 행 선택 → 판단 페인트** (2026-09-21) | **300ms** | BFF 200ms + 렌더 |
| **패널 — 모드 전환** | **50ms · 요청 0건** | 이미 받은 두 모드 |
| 상세 분석 페이지 첫 페인트 | 600ms | Hero · 차트 먼저 |
| 차트 오버레이 선 3개 | 추가 페인트 16ms 이내 | 기존 차트 위 |
| 패널 · 상세 클라이언트 JS 증가분 | **25KB gzip 이하** | 차트 라이브러리 추가 0 |

## 급소 1 — LLM 경로

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | **`explain`을 자동 호출하지 않는다.** 종목 전환마다 부르면 20s 요청이 쌓인다 | Must |
| FR-2 | 버튼 클릭으로만. 클릭 중 `Button loading`(흐려지지 않는다) | Must |
| FR-3 | `AbortSignal`로 화면 이탈 시 취소한다. **20s 요청이 남으면 서버 커넥션을 먹는다** | Must |
| FR-4 | 같은 종목 재클릭을 **막는다**(진행 중 버튼 비활성). 서버 5분 캐시가 있지만 요청 자체를 줄인다 | Must |
| FR-5 | `explain` 진행 중 다른 조작이 막히지 않는다. 화면이 멈추지 않는다 | Must |

## Acceptance Criteria

- [ ] 코치 탭 첫 페인트 p95 < 400ms (측정값 기록)
- [ ] **추천 카드가 가장 먼저 페인트된다**
- [ ] 전체 완료 p95 < 800ms
- [ ] **`explain`이 자동 호출되지 않는다** (종목 전환 시 요청 0건)
- [ ] `explain` 버튼이 `loading`이고 흐려지지 않는다
- [ ] `explain`에 `AbortSignal`이 연결되고 화면 이탈 시 취소된다
- [ ] 진행 중 재클릭이 막힌다
- [ ] `explain` 중 화면이 멈추지 않는다
- [ ] **폴링 중단 조건 4개가 있다**
- [ ] 폴링이 2초 간격 최대 15회다
- [ ] 폴링 요청에 `AbortSignal`이 있다
- [ ] 폴링 중 카드가 다시 만들어지지 않는다
- [ ] **폴링 횟수 분포가 측정되어 있다**
- [ ] Suspense 경계 5개 이하
- [ ] 스켈레톤 높이가 실제와 같다 (CLS 측정)
- [ ] 첫 블록/전체 완료 시각이 기록되어 있다
- [ ] **스트리밍 이득이 측정으로 판정되었다** (없으면 1콜 렌더로 되돌림)
- [ ] 피드백 낙관적 갱신이 카드만 리렌더한다 (Profiler)
- [ ] preflight 입력이 다른 블록을 리렌더하지 않는다
- [ ] 예방적 `memo`가 0건이다
- [ ] 리스트 key에 index가 0건이다
- [ ] 클라이언트 JS 증가분 ≤ 40KB gzip (측정값 기록)
- [ ] `"use client"`가 잎 4개(코치 리포트) + 5개(패널 · 상세, 2026-09-21)에 한정된다
- [ ] 늦게 오는 블록에 `aria-busy`가 있다
- [ ] 폴링 중 `aria-live`가 0건이다
- [ ] **게이트 미렌더율이 측정되어 있다**
- [ ] 패널 행 선택 → 판단 페인트 p95 < 300ms (측정값 기록)
- [ ] **모드 전환 시 네트워크 요청 0건 · 50ms 이내**
- [ ] 모드 전환 · 판단 도착이 시세 표를 리렌더하지 않는다 (Profiler)
- [ ] 판단 블록 스켈레톤 CLS 0
- [ ] 오버레이에 새 차트 라이브러리가 0이다
- [ ] 상세 분석 페이지 첫 페인트 p95 < 600ms, 해설 요청이 버튼 전 0건이다
- [ ] 패널 · 상세 클라이언트 JS 증가분 ≤ 25KB gzip

## Open Questions

- `detail`이 1회 호출이라 **스트리밍 이득이 작다**(FR-25). 측정 후 Suspense를 걷어낼 수 있다.
- `explain`을 아예 만들지 않을 수도 있다. **`detail`의 `explanation`(생성 시 저장)이면 충분**하고, 즉석 해설은 프리뷰용이었다 → PM 확인 필요.
- 게이트 미렌더율이 높으면 **화면이 거의 비어 보인다.** 그 경우 UI를 어떻게 할지는 UI REQ의 문제이지만 성능 측정이 그 신호를 준다.
