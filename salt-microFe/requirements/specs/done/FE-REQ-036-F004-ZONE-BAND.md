## Summary

코치의 **관찰 구간**(미보유 종목 — 과거 가격 분포의 하단 · 중앙 · 상단)을 차트 위 **옅은 띠 + 이름표**로 그린다.
상세 분석 차트(`TradingChart`)와 투자 화면 우측 패널 차트(`PreviewChart`) 둘 다. 함께 상세 차트의 확대 · 축소 ·
처음 보기 버튼을 한 덩어리 캡슐로 바꾼다.

## 왜 — 관찰된 문제

| # | 문제 | 근거 |
|---|---|---|
| 1 | 상세 차트의 구간이 **회색 점선 세 줄**이라 캔들 · 이동평균 사이에서 "구간"으로 안 읽힌다 | 2026-09-22 사용자 피드백("스마트 바이존 없는 거지?") — 실제로는 그려져 있었다 |
| 2 | **패널 차트에는 구간이 아예 없다.** 구간은 패널 아래 표(`ZoneSummary`)에만 있다 | `CoachPanel` → `MarketPreview` 가 차트에 아무것도 넘기지 않음 |
| 3 | 상세 차트 조작 버튼이 **떨어진 회색 네모 셋**(`IconButton tonal`)이라 차트보다 먼저 눈에 들어온다 | 2026-09-22 사용자 피드백("버튼들이 안 이쁘고") |
| 4 | `PreviewChart` 는 가격선을 y 범위에 넣는다 — 장기 모드 구간(1년 하위 20% ~ 상위 20%)을 넣으면 2.5시간 캔들이 한 줄로 납작해진다 | `FE-REQ-034` 문제 3 과 같은 원인. 상세는 고쳤고 패널은 선을 안 넘겨서 드러나지 않았다 |

## 설계 원칙

- **이름은 "관찰 구간"이다.** 사용자가 참고로 보여 준 화면은 "스마트 바이 존"이라는 이름표를 달았지만
  `FEATURE-004` FR-21 이 "매수존 · 매수 적정가 · 목표가" 문구를 금지한다(법적 포지셔닝 — 공통 수용 기준).
  이름표에 **`예측 아님`** 을 붙인다 — 칠한 띠는 선보다 "여기서 사라"로 읽히기 쉽다. 부추기는 이모지를 쓰지 않는다
- **관찰 구간만 띠가 된다.** 보유 종목의 내 규칙 가격(손실 제한 · 1차 익절 검토 · 추세 유지)은 뜻이 다른 세 가격이라
  그 사이를 칠하면 "이 안이 좋다"로 읽힌다 — 선만 그린다(지금 그대로)
- **색은 AI 액센트**(`tokens.colors.ai.primary`). 코치가 만든 것이라는 표시이고, 상승 빨강 · 하락 파랑을 피한다
- **가격 · 문구는 부르는 쪽 값 그대로.** 차트(`@repo/ui`)는 구간이 무엇인지 모른다

## Requirements

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | 관찰 구간 → 띠: 하단 ~ 상단을 옅게 칠한다(캔들 **아래**). 경계선 · 중앙선은 띠와 같은 색(`zone` 톤) | Must |
| FR-2 | 이름표: 띠 왼쪽 위 안쪽, 캔들 **위**, 흰 바탕 + 옅은 액센트. 문구 `관찰 구간 {하단} ~ {상단} · 예측 아님`. 띠가 이름표보다 얇으면 띠 바로 위(자리가 없으면 아래) | Must |
| FR-3 | 패널 차트에도 같은 띠 · 선. 모드 전환에 요청 0(같은 응답을 다르게 읽는다). 판단이 막혀도 그린다(`FE-REQ-026` FR-117 과 같다) | Must |
| FR-4 | 패널 차트 y 범위 = **캔들만**. 범위 밖 선은 그리지 않고, 띠가 창 밖이면 이름표를 가장자리에 `▲` / `▼` 와 함께 남긴다 | Must |
| FR-5 | 상세 차트 조작 버튼: 한 덩어리 캡슐(얇은 테두리 · 칸 사이 구분선 · 아이콘). 키보드 포커스 표시 · `aria-label` · `title` 유지 | Must |
| FR-6 | 범례 견본 색이 차트 선과 같다(`zone` 톤) | Must |
