## Summary

`FE-REQ-073` 작업 중 사용자 지적으로 `/m` 을 훑어 찾은 배터리 후보 둘. 간격 조회는 이미 TanStack 기본(화면이 안 보이면 멈춤)이라 손대지 않았다.

**불변식: 보는 사람이 없는 화면은 라디오를 쓰지 않는다** — 숨은 채 오래 있으면 실시간 소켓을 닫고, 돌아오면 바로 다시 연다.

## FR

| FR | 내용 |
|---|---|
| FR-1 | 실시간 소켓(`wsClient`)은 화면이 숨은 채 `HIDDEN_CLOSE_MS`(휴대폰 `/m` 10초 · 데스크톱 5분)가 지나면 닫고 재연결 0 · 숨은 동안 새 구독이 와도 열지 않음 · 다시 보이면 곧바로 연결하고 구독을 다시 보냄. 그 전에 돌아오면 그대로(짧은 앱 · 탭 전환에 다시 연결하지 않는다). 데스크톱 5분은 사용자 "desktop 은 괜찮다" — 동작을 거의 바꾸지 않는다 |
| FR-2 | 하단 탭 글래스 흐림(`blur(20px) saturate(180%)`)의 스크롤 비용을 잰다. 값은 사용자와 정한 디자인이라 **측정만** 하고 바꾸는 것은 사용자 결정 |

## 측정 (2026-11-21)

| 항목 | 값 |
|---|---|
| FR-1 실브라우저(390 · 휴대폰 종목 상세) | 숨김 10.0초에 닫힘 · 그 뒤 20초 받은 프레임 0 · 숨은 동안 새 소켓 0 · 다시 보이자 새 소켓 · 3초 안 7프레임 |
| FR-2 스크롤(390 · 가계부 지출 30건 · CPU 4배 느리게 · 3회) | GPU 작업 흐림 켬 128~135ms ↔ 끔 56~57ms(140프레임 — 프레임당 약 +0.55ms, 약 2.4배) · 버린 프레임 둘 다 0 · 래스터 · 레이아웃 차이 없음. 헤드리스 Chrome(소프트웨어 GPU)이라 절대값은 실기기와 다르고 비율만 본다 |
