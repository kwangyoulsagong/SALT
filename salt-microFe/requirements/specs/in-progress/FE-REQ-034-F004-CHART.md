## Summary

상세 분석 페이지(`/investments/[symbol]`, `FE-REQ-026` L)의 차트를 **프리뷰 차트(`PreviewChart`)에서 떼어내고
자체 구현한 트레이딩 차트로 바꾼다.** 프리뷰 차트는 투자 화면 우측 패널 전용으로 남긴다.

외부 차트 라이브러리를 쓰지 않는다. `lightweight-charts` 로 만든 `TradingViewChart` 는 사용처 없는 죽은 코드이고
이 REQ 에서 **의존성과 함께 지운다**(`FE-REQ-011` 죽은 코드 판정의 한 건을 닫는다).

## 왜 — 관찰된 문제

| # | 문제 | 근거 |
|---|---|---|
| 1 | 상세 차트가 **패널 프리뷰와 같은 컴포넌트**다. 30~60봉 · 고정 크기 · 확대/이동 없음 · 이동평균 없음 · 축 없음 — 한 종목을 오래 보는 화면의 차트가 아니다 | 슬라이스 6(`F004-fe-detail-page`) |
| 2 | 프리뷰 차트는 SVG 이고 **hover 한 번에 전체 캔들을 React 로 다시 그린다**(`setHoverIndex` → 캔들 · 거래량 노드 전부 재조정). 봉 수가 200으로 늘면 노드가 ~600개이고 포인터 이동마다 재조정된다 | `PreviewChart.tsx`. 도입 전 수치는 §측정 |
| 3 | 가격선을 y 범위에 넣어 **캔들이 납작해진다** — 축과 가격 라벨이 없어 선이 몇 원인지도 안 보인다 | 슬라이스 6 회고 |
| 4 | **실시간 캔들이 틱마다 새 봉을 붙인다.** WS 캔들 `timestamp` 는 ms 숫자, REST 캔들은 KST 문자열인데 `===` 로 비교해 한 번도 같지 않다 → 프리뷰 차트가 틱마다 한 칸씩 밀린다 | `useMarketPreviewChartRealtime.ts` · BFF `candleBuilder` |
| 5 | `lightweight-charts` 가 `apps/web` · `@repo/ui` 두 곳의 의존성에 있지만 import 하는 곳이 없다 | `grep` 0건(파일 하나 — 죽은 코드) |

## 설계 원칙

- **캔버스다.** `canvas.md` 도입 조건 중 "잦은 업데이트(포인터 · 실시간 틱)로 React 재조정 비용", "노드 수" 두 가지에
  해당하고, 개별 캔들의 DOM 접근성은 요구사항이 아니다. 대신 요약 · 범례 · 조작은 DOM 에 둔다(FR-60~)
- **레이어 두 장.** 캔들 · 거래량 · 축 · 선을 그리는 **기본 캔버스**와 십자선만 그리는 **오버레이 캔버스**. 포인터가
  움직이면 오버레이만 다시 그린다 — 캔들 수와 무관하게 O(1)
- **React 는 그리지 않는다.** 데이터 · 크기 · 뷰포트가 바뀌면 `requestAnimationFrame` 한 번으로 모아 그린다.
  포인터 · 휠 · 드래그는 React 상태를 거치지 않고 ref 로 처리한다. React 상태는 범례의 "가리킨 봉 번호" 하나다
- **엔진은 순수 함수.** 스케일 · 틱 · 이동평균 · 뷰포트 계산 · 실시간 병합은 DOM 없는 순수 함수로 두고 단위 테스트한다
- **색은 토큰.** 캔버스는 CSS 변수를 못 읽으므로 `@repo/tokens` 값을 직접 쓴다. 상승 빨강 · 하락 파랑

| FR-6 | **현재가 선**: 마지막 봉 종가에 가로 점선 + 가격축 위 배지(마지막 봉 색) | Must |

| FR-9 | y 범위 = 보이는 봉의 저가~고가 + 위아래 여백(비율 상수). 이동평균이 범위를 벗어나면 잘린다(범위를 늘리지 않는다) | Must |

## 성능 예산

| 항목 | 예산 | 측정 |
|---|---|---|
| 포인터 이동 1회 처리(오버레이 그리기 포함) | **≤ 2ms** 스크립팅 (200봉 · 1000봉 둘 다) | Playwright + `performance.now()` 계측 / CDP 트레이스 |
| 드래그 · 휠 중 프레임 | **60fps 유지**, 긴 작업(>50ms) 0 | `longtask` 관측 |
| 기본 캔버스 전체 다시 그리기 | 200봉 ≤ 4ms · 1000봉 ≤ 8ms | 엔진 벤치(단위 테스트 옆) |
| 실시간 틱 1회 | 기본 캔버스 다시 그리기 1회 이하(rAF 로 모음) | 틱 N 회 → 그리기 ≤ 프레임 수 |
| 번들 | 상세 지연 청크 증가 ≤ **15KB gzip** · 새 의존성 0 · `lightweight-charts` 제거 | `next build` + 청크 gzip |
| 메모리 | 마운트/언마운트 20회 후 캔버스 · 리스너 · 옵저버 잔존 0 | heap 스냅샷 · 리스너 수 |
| CLS | 0.01 이하(차트 자리 고정 높이) | `layout-shift` |

## UX 상태

- **Loading**: 차트와 같은 높이의 스켈레톤(범례 줄 포함)
- **Error**: "차트를 불러올 수 없습니다" + 높이 유지
- **Empty(봉 0)**: "표시할 시세가 없습니다" + 높이 유지
- **기간 전환 중**: 이전 봉을 유지하고(깜빡임 방지) 범례 옆 작은 로딩 표시

  읽고, 차트 표시용 가격 변환(스케일 · 이동평균)은 표시의 일부로 본다. PM 이 다르게 읽으면 서버가 지표를 내려줘야 한다
