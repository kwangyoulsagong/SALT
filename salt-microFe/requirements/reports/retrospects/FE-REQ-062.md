# FE-REQ-062 회고 — 화면 움직임

2026-11-26 `feat/fe-req-062-interaction-motion`.

## 잘 된 것

- **바닥값을 한 곳에** — 전환 없는 링크 372개 · 행을 그리는 자리 80곳 가까이를 화면마다 고치지 않고 데스크톱 전역 `:where()`(특이도 0) 한 곳에 뒀다. 컴포넌트가 정한 값이 늘 이겨서 기존 결정(목표 행 0.99 누름 · 휴대폰 규칙)은 그대로였다
- **원인 토큰을 지웠다** — `transition: all` 180개는 전부 속성 없는 옛 토큰 `vars.transitions` 하나에서 왔다. 토큰을 지우고 `motionBudget.test.ts` 로 다시 못 쓰게 했다(변이 3/3)
- **트레이스가 처음 구현을 뒤집었다** — SVG 드러남을 `clipPath` 사각형 `scaleX` 로 짰는데 "transform 이니 괜찮다"가 틀렸다. SVG 안 변형은 매 프레임 레이아웃(70 → 248). 바깥 `<svg>` `clip-path` 로 바꿔 전환 끈 상태와 같아졌다

## 아쉬운 것

- 처음 측정이 로그아웃 화면이었다 — 로그인 쿠키가 실리지 않은 채 15화면을 쟀다. 화면 한 장을 찍어 보고서야 알았다
- 필터 미끄러짐을 JS `click()` + 낡은 노드 참조로 재서 "안 움직인다"를 한 번 잘못 읽었다 — 실제 원인(대기 분기가 필터를 갈아 끼움)은 그 뒤 노드를 다시 찾아서 나왔다

- **1회차에서 done 을 선언했다** — 기능 동작만 보고 main 과 나란히 · 실패 분기 · 결함 훑기를 건너뛰었다. 사용자가 물어서야 2회차를 했고, 거기서 `RolledText` 쉼표 결함(조용히 글자를 바꿈)이 나왔다
