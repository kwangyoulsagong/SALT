# FE-REQ-044 회고 — 그래픽 · 모션 · 마이크로 인터랙션 (2026-09-30)

## 왜 이렇게 됐나

사용자가 참고한 국내 금융 앱들처럼 그래픽 애니메이션을 "무조건" 넣자고 했고, 곧바로 범위가 온보딩 → 모든 페이지 → 상태 문구
("거래 기록이 등록됐어요")로 넓어졌다. 페이지를 먼저 조사해 자리 40곳의 배치표를 만들고, **아무것도 안 보이던 완료 순간**부터(A),
그다음 조작 반응(B), 마지막으로 남은 한 줄 · 등장(C) 순으로 나눴다. 그래픽은 앱에 흩지 않고 DS 에 뒀다(사용자 지시).

## 잘한 것

- **번들을 재서 잡았다.** `motion/react` 가 네임스페이스로 다시 내보내 모든 페이지 첫 로드가 +45 kB(예산 40 kB 초과)였다.
  동적 `LazyMotion` 으로 바꿔도 줄지 않자 청크 내용을 열어(`drag` 17 · `layoutId` 18회) 원인을 찾았고 `framer-motion` 의 `m` 으로 +20~25 kB.
  같은 실수를 ESLint 가 막는다
- **서버 HTML 은 마지막 프레임.** 그래픽이 JS 를 기다리지 않는다(`curl` 로 확인)
- **바뀐 순간에만 튄다.** 별 · 체크를 `useChangedAfterMount` 로 — 처음부터 켜진 것 20개가 페이지 열 때마다 튀지 않는다
- **이전 결정을 지켰다.** 막힌 판단 안내(정보 아이콘 · 오류처럼 보이면 안 됨) · 등락률 깜빡임(성능 규칙상 변경 금지) · 개별 안무 길이는 그대로.
  색 대비 수정은 사용자 승인 뒤 해당 요소만

## 아쉬운 것

- 로그인 뒤 화면(거래 저장 · 분석 완료 · 별 · 실시간 점 · 숫자 굴리기)은 BFF 가 있어야 떠서 코드로만 확인했다
- 처음 스크린샷을 너무 일찍 찍어 "그래픽이 안 보인다"로 잘못 읽을 뻔했다 — 애니메이션은 프레임 연속(60 · 350 · 3000ms)으로 봐야 한다
- 404 를 `EmptyState` 로 만들었다가 `main` 중복 · `h1` 없음(axe)으로 다시 짰다 — 페이지 단위 화면은 처음부터 axe 를 돌렸어야 했다
- 일괄 치환으로 FR-33 이 한때 "완료"로 적혔다 — 상태 칸은 항목별로 고친다

## Action

- `QA-001` 로컬 풀스택에서 로그인 뒤 화면 10곳(체크리스트 미검증 표) 실측
- 남은 기존 axe 대비 3건(홈 절약 팁 · "내 코치 리포트" 링크) — 사용자 결정 받기
- RN 모션: 같은 `tokens.motion` 을 `reanimated` 로(`RN-REQ`)
