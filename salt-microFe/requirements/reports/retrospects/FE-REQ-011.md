## 2. 잘 된 것

- **헤더를 `RealtimeAsOf` 로 떼었다.** 기준 시각이 바뀔 때 100행이 다시 그려지지 않는다(FR-13).
- **REQ 를 그대로 따르지 않은 판단마다 근거가 코드 옆에 있다.** 낙관적 갱신 거부(FR-3)는
  `useToggleWatchlist` 주석, 수신 시각 위치(FR-10)는 `a76cec1` 본문, 선택 무색(FR-22)은
  `05b0427` 사용자 결정. 다음 사람이 같은 판단을 처음부터 하지 않는다.
- **끊김 표시를 검증하다 BFF 버그를 찾았다.** WS 를 죽였는데 죽지 않았다 — `16f7eba`(SIGTERM
  뒤 생존). 화면 검증이 다른 영역의 결함을 드러낸 사례다.

## 3. 틀렸던 것

### 하드코딩 시각을 지우고 끊김 상태는 보지 않았다 — `a76cec1`

09-18 `350f3e7` 이 "19:30 기준"을 WS 수신 시각으로 바꿨다(FR-14). 그런데 BFF 가 죽어도 초록 점과
마지막 시각이 그대로 남아 **멈춘 값을 실시간으로** 보여 줬다. 표가 언마운트될 때 리스너만 떼고
서버에 해제를 보내지 않은 것도 같은 자리였다.

> **Action:** 수신 시각을 표시하는 곳은 **연결 상태와 짝으로** 만든다. 시각만 있으면 거짓이 된다.

### 버튼이 반응하니 동작한다고 읽었다 — `85913fc`

`MarketOrder.Ascending` 이 빈 문자열이라 서버가 내림차순으로 답했다. 버튼 색은 바뀌었고 에러도
없었다. 응답 해시를 비교해서야 오름차순 = 내림차순임을 알았다(루트 market-table §2).

> **Action:** 필터 · 정렬 버튼은 **응답이 달라지는지**(해시 비교)로 검증한다.

### 폰에서 탭한 행이 선택된 것처럼 남았다 — `85913fc`

hover 색이 터치 기기에서 sticky 가 됐다(FR-23). `(hover: hover)` 안으로 옮겼다. `aria-selected` 가
첫 행에 멈춘 것(`memoKey` 누락)도 같은 커밋에서 고쳤다.

### 별 토글 실패가 조용하다

낙관적 갱신을 하지 않기로 하면서 FR-4 의 토스트도 같이 빠졌다. 실패하면 무효화 후 별이 제자리로
돌아갈 뿐 사용자에게 이유가 없다. 체크리스트 FR-4 미충족.

> **Action:** 낙관적 갱신을 거부해도 **실패 알림은 별개 요구**다. 2026-09-21 개정 FR-5(409 인라인
> 안내)를 만들 때 같이 닫는다.
