- 원 아래 select 대신 칩 묶음(`CategoryChips`) 하나로 세 입력이 같은 분류 고르기를 쓴다.

## 2026-11-04 — F4b

- **잘 된 것**: 보여 줄 대상을 서버 값(`stage` · `closable` · `reviewQuestions`)으로만 갈라 화면에 날짜 비교 · 임계 상수가 0. 분류 칩은 새로 짜지 않고 엔티티로 내렸다(구조 커밋 따로).
- **실수**: 닫은 시각(UTC 문자열)을 앞 10자로 잘라 날짜로 보일 뻔했다 — 하루 어긋날 수 있어 문장에서 날짜를 뺐다. 마감 버튼이 카드 폭으로 늘었다(스크린샷으로 발견).
- **확인 요령**: 전체 페이지 캡처가 패널 등장 애니메이션을 다시 틀어 패널이 비어 보였다 — 뷰포트 캡처 · 계산 스타일로 정상 확인. 캡처가 비면 코드보다 캡처 방식을 먼저 의심한다.
- Action: 실화면 스크립트는 `networkidle` 대신 `load` + 선택자(dev 서버 첫 컴파일 · 장시간 연결).

## 2026-11-04 — 확인 단계 결함

- 숫자 칸 묶음(`useNumberFields`)의 초기값은 첫 마운트 한 번뿐인데, 칸 목록은 서버 응답을 따라 늘어난다 — "첫 값"과 "새로 생긴 칸"이 다른 길이었다. 같은 꼴(목록마다 숫자 칸)인 저축 나눠 넣기 · 저울은 칸이 사용자 입력에서 시작해 해당 없음(확인함).
- Action: 서버 목록에서 칸이 생기는 화면은 칸 채우기를 effect 한 길로(`fillIfEmpty`).

## 2026-11-04 — F4c

- **잘 된 것**: 기분 칩 · 만족 칩을 엔티티로 처음부터 내려 입력 폼과 묻기 카드가 같이 쓴다(S1b 분류 칩 교훈).
- **판단**: 달력 요일 자리를 프론트가 날짜로 세지 않게 서버 `weekday` 로 받았다. 막대 높이(그 줄 최대 대비)는 표시 비율일 뿐 계산 결과를 만들지 않는다.
- **실수**: 실화면 스크립트가 시드와 어긋난 칸(지출 있는 날)을 눌러 멈췄고, 첫 실행이 답을 저장해 둘째 실행이 카드를 못 찾았다.
- **Action**: 실화면 스크립트는 시작할 때 상태를 되돌린다 — 두 번 돌려도 같게.
- **확인 단계 실수**: 그림으로 전하는 칸 · 막대를 `aria-label` 만으로 처리했다(역할 없는 요소라 안 읽힘). **Action**: 표시 전용 시각 요소는 숨긴 글자 + `ariaSnapshot` 확인.

## 2026-11-04 — 가계부 S1d(F4d)

- **잘 된 것**: 날짜 칸 min · max 를 서버 값(`today` · `startMax`)으로 — 화면이 날짜를 더하지 않는다. 끝 날 상한은 서버 거절 코드를 한 줄로.
- **판단**: 끝난 카드를 다른 색 · 다른 모양으로 가르지 않고 아래 묶음으로만. 단계 배지도 같은 색 하나.
- **실수**: 처음 계약은 기간 상한 일수 둘(`periodDaysMax` · `startAheadDaysMax`)을 줘 화면이 날짜를 더해야 했다 — 쓰기 전에 `startMax` 날짜로 바꿨다. 첫 실화면 스크립트가 응답 기록을 켜지 않아 콘솔 400 둘의 주소를 못 남겼다.
- **Action**: 실화면 스크립트는 처음부터 `response` ≥ 400 기록.
