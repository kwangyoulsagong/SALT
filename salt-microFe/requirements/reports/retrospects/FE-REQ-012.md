# FE-REQ-012 회고 — F000 API 호출 계약

- 작성: 2026-09-22 (머지 후 백필)
- 체크리스트: `requirements/reports/checklists/FE-REQ-012.md`
- 전 영역 기록: 루트 `requirements/reports/checklists/F000-watchlist-tab.md` · `F000-invite-onboarding.md` ·
  `F000-realtime-reliability.md` · 회고 `requirements/reports/retrospects/F000-watchlist-tab.md`

## 1. 무엇을 했나

`period` 오타를 세 영역에서 같이 고쳤고(`545bda4`), 신규 호출 다섯을 붙였다 — 뉴스 `bde1c81` ·
관심 종목 `8dd0a2a` · 보유 요약 `e43f619` · 온보딩 `bfe19ba` · 목표 저장 `b89f40c`. WS 절은
#43 `a76cec1` 이 닫았다. 호출 진입점 `apiFetch` 는 #40 `3a736de` 에서 생겼다.

## 2. 잘 된 것

- **오타를 교정하지 않고 422 로 막았다**(`545bda4`). 교정하면 오타가 영구화된다. 배포 순서와 롤백
  순서를 커밋 본문에 적었다 — 한 커밋에 세 영역이 들어간 대가를 문서로 치렀다.
- **`apiFetch` 가 나중에 번들 회귀의 해법이 됐다.** MSW 경쟁(`3a736de`) 때문에 만든 단일 진입점이
  있었기에 axios 를 걷어낼 대상이 이미 있었다(`ac86d55`).
- **WS 구독을 참조 카운트로 바꿨다**(`a76cec1`). 화면을 떠나면 해제가 실제로 전송되는 것을
  브라우저에서 확인했다 — "리스너를 뗐다"와 "서버가 멈췄다"는 다르다.

## 3. 틀렸던 것

### 토큰을 쓰는 코드가 없었다 — `bfe19ba`

`ACCESS_TOKEN_KEY` 를 읽는 `authHeader()` 는 있는데 쓰는 코드가 없었다. `useSignIn` 은 `USER_KEY`
만 저장해서 **`/api/app/*` 호출이 전부 401** 이었고, 화면은 그것을 "데이터 없음"으로 그렸다.
빌드 · 타입체크 · lint 를 통과한 채였다. `shared/api/authToken.ts` 에 `writeSession` 을 두고
로그인 · 초대 수락이 같이 쓴다.

> **Action:** 인증이 붙는 호출을 추가하면 **로그인 직후 그 호출 1건이 200** 인지를 체크리스트
> 항목으로 둔다. 401 을 빈 상태로 그리는 화면은 이 결함을 숨긴다.

### MSW 워커보다 먼저 나간 요청이 404 였다 — `3a736de`

첫 방문은 우연히 통과하고 리로드에서 깨졌다(워커 기동 2초 전 요청 3건). 렌더를 막는 표준 레시피는
SSR 마크업을 어긋나게 하므로 요청 쪽에서 기다리게 했다.

> **Action:** dev 에서 조회가 깨지면 **리로드로 재현**해 본다. 첫 방문만 보면 경쟁을 놓친다.

### 목표 저장이 `console.log` 였다 — `b89f40c`

FR-36 은 Should 였고 "끊겨 있으면 잇는다"였다. 확인해 보니 끊겨 있었다. 폼은 완성돼 있었다.

### 같은 axios 회귀를 반복했다 — `ac86d55`

앞 슬라이스 회고가 두 번 적은 실수를 온보딩 호출 셋이 되풀이했다(`/home` 166 kB).

> **Action:** lint 규칙(`no-restricted-imports`)으로 올린다 — `FE-REQ-010` 회고와 같은 항목.
