# FE-REQ-034 (F004 CHART) — 회고

- 날짜: 2026-09-22 · 브랜치 `feat/fe-detail-trading-chart` · 체크리스트 `requirements/reports/checklists/FE-REQ-034.md`

## 1. 무엇을 했나

상세 분석 차트를 투자 화면 프리뷰(SVG)에서 떼어 외부 라이브러리 없는 캔버스 차트로 바꿨다. 캔들 · 이동평균 4개 ·
거래량 · 축 · 십자선 · 이동/확대 · 실시간. 만들다가 **기존 버그 둘**을 찾았다 — 프리뷰가 틱마다 봉을 붙이던 것,
일봉 시각이 NaN 이던 것.

## 2. 잘 된 것

- **엔진을 순수 함수로 먼저 쓰고 테스트부터 돌렸다.** 뷰포트 식의 부호가 두 군데 뒤집혀 있었는데 화면을 띄우기 전에
  테스트가 잡았다
- **캔버스 두 장 + React 는 그리지 않는다.** 십자선 200회 이동에 기본 캔버스 다시 그리기 0, 1000봉에서도 이동당 0.57ms
- **전후를 같은 조건으로 쟀다.** `main` 과 브랜치를 각각 worktree 프로덕션 빌드로 띄워 CDP 지표로 비교 — 켜진 dev
  서버를 건드리지 않았다
- **실측이 실제 결함 다섯 개를 찾았다**: 버튼이 최고가 표시를 가림 · 가장자리 표시 겹침 · 375px 범례가 한 줄에
  한 항목 · 세로 스크롤 뒤 탭이 십자선을 고정(`pointercancel`) · Suspense 가 그리기를 300ms 늦춤. 타입 · lint ·
  단위 테스트는 전부 통과한 상태였다
- 커밋을 버그 수정 · 죽은 코드 제거 · 기능으로 나눠 되돌리기 지점이 각각 하나다

## 3. 틀렸던 것 · 헷갈렸던 것

- **`getBoundingClientRect` 를 포인터마다 불렀다.** 직전 범례 갱신이 DOM 을 더럽혀 강제 레이아웃이 났다. 캐시로
  고쳤는데, 남은 레이아웃은 범례 리플로 자체라 `contain` 으로도 줄지 않았다 — 측정 후 되돌렸다
- **`next/dynamic` 을 "지연 로딩 = 공짜"로 봤다.** Suspense 대체 화면을 걷을 때 React 18 이 최대 300ms 를 몰아
  기다린다. 청크를 미리 받는 것으로는 안 줄었고, Suspense 를 거치지 않게 바꿔야 줄었다(p95 337 → 40ms)
- 메모리 측정에서 캔버스가 2·4·6개 남아 누수로 봤다 — **Playwright 가 클릭한 요소 핸들**이었다. 힙 보유 경로를
  따라가 보고서야 알았다. 도구가 측정 대상을 붙잡을 수 있다

## 4. 남은 기술부채

- `candleTime`(병합 · 파싱)에 상시 테스트가 없다 — `apps/web` · `@repo/core` 에 러너가 없다. RN 도 같은 병합이 필요하니
  `@repo/core` 로 옮기면서 러너를 붙이는 것이 맞다 → **`FE-REQ-035` 에서 닫힘**
- 서버 차트 응답 지연 요동(0.02~2.9초)이 상세 첫 페인트 예산을 좌우한다 — 프론트로는 못 줄인다
- 서버 일봉/분봉 응답의 시각 키가 다르다(`date` / `timestamp`). 프론트가 맞추고 있다 — 서버 계약을 하나로
- `TradingChart` 는 `PreviewChart` 와 캔들 그리기를 공유하지 않는다(SVG vs 캔버스). 프리뷰를 캔버스로 옮길지는
  패널 성능이 문제로 관측될 때
