# FE-REQ-060 회고

## 1단계 가계부 — 2026-11-19

- **REQ 가 "서버 필드를 더한다"고 미리 경고한 칸이 이미 있었다** — 날마다 합은 달력 칸(`calendar.days[].spent`)에. 계약을 바꾸기 전에 응답 타입부터 읽는다
- **"그 밖" 묶음 합 · 예산 입력 중 합은 화면 금액 계산이 된다** — 서버 행을 다 보이고, 합은 저장한 값(서버 `total`)만. 막대 길이 비율만 화면
- **같은 꼴은 한 번에** — 회색 상자(모서리 12 · weakFill)가 12곳. 화면에서 보인 둘만 고치면 다음 화면에서 또 나온다
- 숨은 요소가 글자 크기 측정을 부풀렸다(768 미만 안내 · 접힌 칸) — 보이는 요소만 센다
- 첫 숫자를 서버가 받아 넘기는 화면은 브라우저 요청 실패만으로 실패 장면이 안 나온다 — 서버 첫 조회를 비우고(틀린 쿠키) 브라우저 요청을 실패시켜 만든다

## 2단계 저축 — 2026-11-19

- **REQ 가 "서버 필드를 더한다"고 미리 경고한 칸이 이번엔 정말 없었다** — 1단계 회고대로 응답 타입부터 읽고, 목록 응답 모양(배열)을 바꾸지 않고 새 경로로 더했다(BREAKING 0 · 쿼리 2회)
- **같은 글자 두 번은 데이터가 만든다** — 이름을 템플릿 이름 그대로 둔 목표("비상금")에서만 보였다. 실화면 데이터에 기본값 그대로인 행을 한 줄 넣는다
- 패널 제목을 붙이며 안쪽 상자 제목이 남았다 — 상자 컴포넌트를 제목 있는 칸에 넣을 땐 `bare` 를 먼저 찾는다
- 넓은 칸에 "이름 ↔ 값 양 끝" 배치를 그대로 옮기면 M1 증상이 다시 난다 — 넓은 칸은 이름 위 · 값 아래
- 서버 시험 변이 하나가 살아남았다 — 다 찬 목표는 구간이 원래 비어 "진행 중만" 규칙을 가르지 못했다. 경계 데이터는 규칙만 다르게 만드는 값(멈춘 목표 + 계획 달)으로

## 3단계 금융 팁 — 2026-11-20

- **틀을 입히자 번들이 34 kB 늘었다** — `PageFrame` 하나 때문에 `ui` 배럴의 클라이언트 모듈이 공개 글에 실렸다. 화면 재배치 단계에도 main 과 나란히 빌드해 첫 로드를 잰다(이번엔 마지막 빌드에서야 봤다)
- 스펙이 "기준 실측"으로 적은 칸(썸네일)이 우리 데이터엔 없었다 — 그림을 지어내지 않고 정정 · 범위 밖으로. 착수 때 응답 타입부터 읽는다는 2단계 교훈이 이번에도 맞았다
- 1920 에서 값이 멀리 떨어지는 결함이 2단계에 이어 또 났다 — 넓은 칸 목록은 처음부터 글 단 + 짧은 값 칸 폭으로 묶는다
- 이동 경로의 지금 화면 = 제목(같은 글자 두 번)을 고치려다 되돌렸다 — 다른 zone 상세가 모두 같은 꼴이라 한 화면만 다르면 더 나쁘다. 바꾸려면 `BackNav` 규칙에서 한 번에

### 3단계 확인 2회차

- 1회차에 "빈 상태"만 실데이터로 봤다 — 카드 0장 · 목표 0개 계정이었다. 그래서 긴 제목(내 숫자 글)에서만 나는 넘침, 목표가 있어야 나는 자기 글 권하기를 놓쳤다. 임시 계정에 데이터를 먼저 만든 뒤 실화면
- 움직임 장치를 2단계에서 붙였는데 3단계에서 또 빠졌다 — 새 행 · 새 칸이면 누름 · 등장을 체크리스트 칸으로
