# BFF-REQ-039 회고 (2026-09-29)

- **슬라이스 2 문서가 "BFF 가 걸러 내지 않는다"고 적었는데 틀렸다.** 위험 예산 · 미러 뷰모델은 필드를 골라 옮긴다 — 서버 필드 추가는 화면에 닿지 않았다. `basis` 만 zone · exitPlans 통째 전달이라 닿았다(모르는 값까지). 서버 슬라이스 체크리스트의 "BFF 무변경"은 코드 확인이 아니라 추정이었다
- 서버 기본값(`trendOpen: true` = 게이트 없음)이 화면 사실("200일선 위")로 읽히는 자리를 찾아 막았다 — 판정용 기본값과 표시용 사실은 다르다

## Action

- 서버에서 응답 필드를 더하는 슬라이스는 BFF 뷰모델에서 그 필드명을 grep 해 "옮겨지는가"를 체크리스트에 적는다

## FR-6 거래소 투자유의 · 주의 (2026-09-30)

- BFF 가 `renderable` 을 **막는 쪽으로만** 고칠 수 있게 했다 — 서버 게이트가 빠져도 유의 종목 판단이 새지 않는다. 여는 쪽 경로는 여전히 0
- 주의 코드는 원문 5종 화이트리스트 — 업비트가 코드를 늘려도 화면이 모르는 코드를 원문 그대로 보여 주지 않는다
- Action: `getPreview` 서비스 테스트 하네스(백엔드 호출 목) — 이번엔 뷰모델 함수만 테스트했다

## FR-7 재료 정지 (2026-10-07)

- 서버 막힘 사유가 하나 늘 때마다 BFF 유니온 · core 유니온 · 문구 표 세 곳을 같이 고친다. 이번엔 한 커밋에 묶어 갈라지지 않았다
- Action: 판단 막힘 사유도 목표 비중처럼 "모르는 값 → 기본 사유" 매핑을 둘지 검토(지금은 서버 값을 그대로 옮긴다)
