# BFF-REQ-010 회고 — F000 성능 (시세 개요 · WS)

- 작성: 2026-09-22 (머지 후 백필)
- 체크리스트: `requirements/reports/checklists/BFF-REQ-010.md`
- 근거: 루트 `requirements/reports/checklists/F000-realtime-reliability.md` · `F000-market-table.md`

## 1. 무엇을 했나

이 REQ 만을 위한 브랜치는 없다. 실시간 신뢰성(#43)과 시세 표(#44) 슬라이스가 각자의 증상을 쫓다가
A절(FR-1~4)과 WS절(FR-10~15)을 **측정으로 판정**했다. 결과는 "만들 것"보다 "걷어낼 것"이 많았다 —
가격 캐시 덧씌우기 제거(`d959e39`), throttle 불필요 판정.

## 2. 잘 된 것

- **측정이 요구사항을 뒤집었다.** FR-4 는 히트율을 "재라"였고, 재 보니 0% 라 캐시를 지웠다.
- **만들지 않은 것에 재검토 조건을 붙였다.** throttle — 14.8~19.5건/초 · 심볼당 ≤2.6건/초,
  "10배가 되면 다시 본다".
- **수정 전/후를 같은 스크립트로 쟀다.** 두 소켓 A 5 → 56, 서버 꺼짐 0 → 19.5건/초, SIGTERM 40초
  생존 → 0.2초. 커밋 본문에 수치가 있어 FR-63 이 저절로 채워졌다.

## 3. 틀렸던 것

### 규칙 문서가 틀린 사실을 전제했다 — `d959e39`

`performance-bff.md` §4 는 시장 개요 가격을 "worker 인메모리 캐시(현행 유지)"로 적었다. 그 캐시는
워커 프로세스에서만 차고 REST 에서는 늘 비어 있다. `d959e39` 에서 "BFF 캐시 없음"으로 고치고
프로세스 경계 주의를 붙였다. 관심 목록 보정(`a7090cb`)은 같은 캐시를 아직 읽는다 — 서버 값으로
떨어져 겉보기 정상이라 남겼다(루트 market-table §5, FR-30 미충족).

> **Action:** `watchlist` 뷰모델을 다시 만질 때 보정 경로를 지운다. 캐시를 읽는 코드를 넣으면
> **그 프로세스에서의** 히트율을 먼저 잰다(§4 에 반영됨).

### 시세가 조용히 멈추는 경로가 셋, 죽지 않는 프로세스가 하나 — `0483f14` · `16f7eba`

토큰 키잉(두 번째 탭이 첫 탭을 굶김) · Upbit 구독 대체(추가분만 보내면 나머지가 끊김) · 서버
장애 시 0건. 셋 다 에러 없이 0건을 보냈다. Upbit 구독 대체는 문서가 아니라 8초짜리 실험이
알려줬고, SIGTERM 뒤 생존은 프론트 "연결 끊김"을 검증하려고 WS 를 죽였는데 **죽지 않아서** 드러났다.

> **Action:** WS 변경은 "보냈다"가 아니라 **"받는다"를 스크립트로 잰다.** 재현 스크립트는
> 스크래치패드에만 있다(루트 realtime §5) — 레포로 옮긴다.

### FR-2 가 다른 REQ 와 동시에 만족될 수 없었다

"정리 전과 바이트 동일"은 서버가 `periodChange` 를 더한 순간(`4b72c9e`, `SRV-REQ-009` FR-20)부터
성립하지 않는다. BFF 는 서버 응답과 바이트 동일로 판정을 바꿨다.

> **Action:** FR-2 문구를 "BFF 가 서버 응답을 바꾸지 않는다"로 개정할 후보.
