## 1. 무엇을 했나

D·E·F절(뉴스 `bde1c81` · 관심 종목 조립 `a7090cb` · `period` 422 `545bda4`)을 #41 에서,
G절(proxy 3경로 제거 · 온보딩 3라우트 · rate limit, `a4f9cee`)을 #42 에서 닫았다.
A절(동면 410) · B절(홈 조립) · C절(알림)은 손대지 않았다.

## 2. 잘 된 것

- **판정 규칙을 import 없는 순수 함수로 뗐다**(`bb48a3d`). 서비스를 import 하면 Upbit 소켓이
  열리는 구조가 테스트를 막고 있었다. 러너가 이때 처음 생겼고 0 → 23 → 28건이 됐다.
- **`priceStale` 을 캐시 적중이 아니라 값의 나이로 판정했다**(`a7090cb`). 임계값 60초는 실측
  (표본 40 · 최대 4.8초, 12.4배)이 근거다. 캐시 적중 설계는 코드를 쓰기 전에 버렸다.
- **BFF 가 초대 판정을 하지 않는다**(`a4f9cee`). `reasonCode` 를 그대로 올리고, `quota` 만
  서버와 **두 겹으로** 지운다 — 무인증 경로라 한쪽이 틀려도 새지 않게.

## 3. 틀렸던 것

### 관심 목록을 한 페이지만 읽었다 — `e9deb23`

별 아이콘이 이 응답으로 "담겨 있나"를 판정하므로 101번째부터 **담겨 있는데 빈 별**이 된다.
페이지를 끝까지 읽게 했다(상한 10페이지는 루프 방지).

> **Action:** 응답을 "포함 여부 판정"에 쓰는 소비처가 있으면 페이징 상한을 체크리스트 항목으로 둔다.

### 보유 평가 갱신 경로를 아무도 부르지 않았다 — `e43f619`

워커는 관심 목록 쪽 `update-prices` 만 밀어 넣어 `portfolio_holdings.current_value` 가 생성 이후
0 이었다. 홈 "주식" 섹션을 붙이려다 드러났다. 같은 페이로드를 두 곳에 `allSettled` 로 보낸다.

> **Action:** 내부(`internal`) 엔드포인트는 **호출자가 누구인지**를 REQ 나 체크리스트에 적는다.

### upstream 4xx 보존이 컨트롤러마다 따로다

관심 목록은 새 컨트롤러에서 409 를 처음부터 보존했지만(`a7090cb`), 시세 개요는 모든 실패를 500 으로
바꾸다 #44 에서야 고쳐졌다(`d959e39`). 규칙은 이미 있었다(`backend-integration.md` "backend가 4xx를
주면 가능한 원 status/message를 보존한다"). `error.middleware` 가 `AppError` 가 아닌 것을 전부 500 으로
만들어 **컨트롤러마다 지켜야 하는 구조**다.

> **Action:** 문장 규칙을 공통 헬퍼(upstream 오류 → `AppError`)로 올린다.

### 체크리스트 안에 옛 상태가 남았다

§2 "남은 것"이 FR-60~64 를 미완으로 적은 채 §6 에서 pass 로 닫혔다. 한 문서가 두 상태를 말한다.

> **Action:** 절을 추가할 때 앞 "남은 것" 표에서 닫힌 행을 지운다(또는 취소선).
