# BFF-REQ-008 회고 — F000 화면 계약

- 작성: 2026-09-22 (머지 후 백필)
- 체크리스트: `requirements/reports/checklists/BFF-REQ-008.md`
- 전 영역 기록: 루트 `requirements/reports/checklists/F000-watchlist-tab.md` · `F000-invite-onboarding.md`

## 1. 무엇을 했나

신규 계약 8개 중 8개를 열었다 — 관심 목록 3(`a7090cb`) · 뉴스(`bde1c81`) · 보유 요약(`e43f619`)을
#41 에서, 온보딩 3(`a4f9cee`)을 #42 에서. 제거 목록(`register` · `users/password` ·
`users/account` proxy)도 `a4f9cee` 에서 닫았다(**BREAKING**). 동면 410(FR-11)은 남았다.

## 2. 잘 된 것

- **뷰모델이 화면이 쓰는 것만 싣는다.** 뉴스는 `content` 를 담지 않고 `viewCount` 는 서버가 줄
  때만 키를 만든다(테스트 2건). 보유 요약은 이름 조회가 실패해도 금액을 내려보내고
  `namesDegraded` 로 이유를 알린다.
- **`nextStep` 을 서버 값이 아니라 정규화한 `steps` 에서 다시 찾는다.** 어긋나면 화면이 "이미
  끝낸 단계로 가라"고 말한다. 빠진 단계는 미완료로 채워 스테퍼가 항상 세 칸이다(테스트 5건).
- **REQ 와 다르게 한 판단을 체크리스트에 남겼다.** 뉴스를 무인증으로 연 이유(서버 `/news` 공개,
  같은 패널의 차트 · 심리도 공개)가 §3 에 있어 다음 사람이 되묻지 않는다.

## 3. 틀렸던 것

### FR-13(`packages/core` 공유)을 처음부터 지킬 수 없었다

`bff` 가 pnpm workspace 밖이라 뷰모델 타입을 import 할 수 없다. 프론트가
`entities/*/model/types.ts` 에 같은 모양을 **다시 선언**한다. 지금은 손으로 맞추고 있고,
한쪽만 바꾸면 타입체크가 잡지 못한다.

> **Action:** `FE-REQ-024` 에서 합칠 때까지 계약 변경 커밋은 **양쪽 타입 파일을 같은 커밋에서** 고친다.

### 계약 변경이 fix 커밋 본문 한 줄에만 있었다

`0483f14`(#43)가 WS `connected` 메시지에서 `userId` 를 뺐고, `d959e39`(#44)가 시세 개요의 서버
4xx 를 500 대신 그대로 내려보내게 바꿨다. 둘 다 화면이 받는 계약인데 커밋 본문 외에는 기록이
없다 — 이 REQ 체크리스트에도 없다. 소비처가 0건(전자)이거나 개선(후자)이라 문제는 없었다.

> **Action:** BFF ↔ 프론트 응답이 바뀌면 fix 커밋이어도 이 체크리스트에 한 줄 남긴다
> (`pr-convention.md` §5 "계약 변경은 눈에 띄게").

### 체크리스트 §1 이 옛 상태를 말한다

§1 표가 온보딩 3경로를 "미구현"으로, 제거 목록을 "손대지 않았다"로 적은 채 아래 절에서
닫혔다. `BFF-REQ-007` 체크리스트와 같은 모양이다.

> **Action:** 절을 추가할 때 앞 표의 상태 칸을 같이 고친다.
