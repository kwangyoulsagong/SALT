## Summary

BFF가 얹는 지연을 20ms 이하로 유지하고, **자산군 3종을 서버 1회 호출로 받아 블록으로 나누는 것**이 이 REQ의 핵심 절약이다.

## 예산

| 엔드포인트 | 예산 | 내역 |
|---|---|---|
| `GET /api/app/tax/deadlines` | **100ms** | 서버 300ms 타임아웃, 실제 ~50ms |
| `GET /api/app/tax/cockpit` (집계) | **700ms** | 서버 600ms + BFF 20ms + 여유 |
| 블록 엔드포인트 각각 | 100~400ms | 소스에 따름 |
| `POST /api/app/tax/harvest-solve` | **600ms** | 서버 500ms + 20ms |
| `POST /api/app/tax/crypto-scenario` | 250ms | |
| `GET /api/app/tax/fx-trap` | 350ms | |
| `POST /api/app/tax/archive/download` | 250ms | 서명 URL만. **파일이 통과하지 않는다** |
| **BFF가 얹는 지연** | **20ms 이하** | 초과 시 조립 코드 문제 |

## 절약 1 — 서버 호출 1회를 블록 3개가 공유한다

`GET /api/tax/cockpit`이 자산군 3종을 함께 준다. 블록 함수 3개가 각각 부르면 **서버 부하가 3배**다.

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | 요청 스코프 캐시로 서버 호출을 **1회로 합친다** | Must |
| FR-2 | 캐시는 요청 안에서만 산다. **글로벌 캐시가 아니다** — 세금 값은 매번 최신이어야 한다 | Must |
| FR-3 | 웹이 블록 엔드포인트 4개를 각각 부르면 **서버 호출이 4회** 된다. 그 경우 요청 스코프 캐시가 작동하지 않는다 → **측정 후 판단**: 서버 부하가 문제면 웹도 집계 1콜로 바꾼다 | Must |

## 절약 2 — 솔버를 첫 페인트에서 뺀다

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | 솔버(500ms)를 **집계 엔드포인트에 포함하지 않는다** | Must |
| FR-11 | 솔버는 사용자가 요청할 때만 부른다. 화면은 "손실 수확 계산하기" 버튼을 준다 | Must |
| FR-12 | 솔버 결과를 **캐시하지 않는다.** 연말에는 보유가 자주 바뀐다 | Must |

## 절약 3 — 파일을 통과시키지 않는다

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | 증빙 다운로드는 **서명 URL만** 전달한다. 파일이 BFF를 통과하면 메모리를 먹는다 | Must |
| FR-21 | ZIP 생성을 BFF가 하지 않는다. 서버 또는 스토리지가 담당 | Must |

## 병렬화와 타임아웃

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-30 | 집계는 **`Promise.allSettled`** 로 병렬이다. `await` 연쇄 0건 | Must |
| FR-31 | 서버 호출마다 타임아웃. **블록 예산보다 짧게** | Must |
| FR-32 | 집계 총 타임아웃 = 가장 느린 블록 예산 + 100ms | Must |
| FR-33 | 재시도는 조회에만 1회. mutation 0회 | Must |

## 응답 크기

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-40 | `crypto.holdings[]`는 보유 종목 수만큼이다. **lot 개별 row가 없음을 확인**한다 | Must |
| FR-41 | 솔버 후보 3개 × 종목 목록. 종목 상한 초과 시 서버가 자른 것을 그대로 전달한다 | Must |
| FR-42 | `archive.files[]`를 페이징한다. 연도 × 소스 × 종류로 늘어난다 | Should |
| FR-43 | 쓰지 않는 필드를 빼서 전달한다 | Should |

## 관측성

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-50 | 측정: 블록별 `unavailable` 발생률, 서버 호출 지연 분포, 타임아웃 발생률, **솔버 호출 수와 지연**, `deadlines` 엔드포인트 p95 | Must |

## Acceptance Criteria

- [ ] 자산군 3블록이 서버를 1회만 부른다 (요청 로그)
- [ ] 요청 스코프 캐시가 요청 간에 공유되지 않는다
- [ ] 웹 블록 엔드포인트 사용 시 서버 호출 수가 측정되어 있다
- [ ] 솔버가 집계에 포함되지 않는다
- [ ] 솔버 결과가 캐시되지 않는다
- [ ] 증빙 파일이 BFF를 통과하지 않는다 (메모리 사용량 확인)
- [ ] `Promise.all`이 0건이다
- [ ] 서버 호출 전부에 타임아웃이 있다
- [ ] mutation 재시도가 0건이다
- [ ] `GET /api/app/tax/deadlines` p95 < 100ms (측정값 기록)
- [ ] 집계 p95 < 700ms (측정값 기록)
- [ ] **BFF가 얹는 지연 < 20ms** (측정값 기록)
- [ ] 응답에 lot 개별 row가 0건이다
- [ ] 로그에 세금 금액이 0건이다
- [ ] 관측 항목 5종이 있다

## Open Questions

- FR-3의 판단: 웹 블록 엔드포인트 4개가 서버를 4회 부르는 것이 허용 가능한가. 사용자 ≤10명이면 문제가 아닐 가능성이 높지만, **서버 콕핏 조회가 600ms이므로 4회면 서버 CPU가 2.4s를 쓴다.** 측정 필요.
- 증빙 ZIP 생성 위치(서버 vs 스토리지).
