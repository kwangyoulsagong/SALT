# BFF 성능 규칙

## 0. 조건

BFF는 계산하지 않는다. **지연의 원인은 거의 항상 (a) 서버 호출을 직렬로 했거나 (b) 실패를 기다렸기 때문**이다.

## 1. 예산

| 엔드포인트 | 예산 | 비고 |
|---|---|---|
| 홈 집계 (`/api/app/home`, 모바일) | **400ms** | 5블록 병렬 |
| 홈 블록 개별 (웹) | 100~400ms | 블록별 예산은 소스에 따름 |
| 청구서 (스냅샷 히트) | 300ms | 미스 시 1.5s |
| 세금 콕핏 | 600ms | |
| 주간 계획 | 250ms | 전부 캐시 히트여야 한다 |
| 김프 | 실시간, 30초 캐시 | |
| 코치 상세 | 400ms | 최신 insight 읽기 |
| 코치 대화 첫 토큰 | 1s | SSE |
| 시장 개요 (`limit=100`) | 300ms | 가격 캐시 |
| 프록시 통과 | +20ms 이하 | BFF가 얹는 지연 |

**BFF가 얹는 지연이 20ms를 넘으면 조립 코드에 문제가 있다.**

## 2. 병렬화 — 1번 규칙

```ts
// ❌ 직렬. 5블록이면 5배 느리다
const a = await backendApi.get('/portfolio', t);
const b = await backendApi.get('/plan/weekly', t);

// ✅ 병렬 + 실패 격리
const r = await Promise.allSettled([...]);
```

- **`await`를 연달아 쓰는 조립 코드를 만들지 않는다.** 의존 관계가 없으면 병렬이다
- **`Promise.all`을 쓰지 않는다.** 하나가 실패하면 전부 버린다. 조합 응답은 `allSettled`
- 의존 관계가 있으면(A의 결과로 B를 부른다) **서버에 조합 엔드포인트를 요청한다.** BFF에서 체인을 만들면 지연이 누적된다

## 3. 타임아웃 — 없으면 예산이 무의미하다

- 서버 호출마다 타임아웃을 준다. **블록 예산보다 짧게**
- 타임아웃된 블록은 `status: 'unavailable'`이다. 전체를 실패시키지 않는다
- 재시도는 **조회에만**, 최대 1회. mutation은 재시도하지 않는다(중복 생성)
- 홈 집계의 총 타임아웃은 **가장 느린 블록 예산 + 100ms**로 상한을 둔다

## 4. 캐시

| 대상 | 정책 |
|---|---|
| 시장 개요 가격 | worker가 갱신하는 인메모리 캐시 (현행 유지) |
| 김프 | TTL 30초 |
| 지표·환율 | 서버가 이미 일 1회 갱신 → BFF에서 다시 캐시하지 않는다 |
| 홈 조립 결과 | **캐시하지 않는다** |
| LLM 해설 | 서버가 스냅샷에 저장한다. BFF에서 캐시하지 않는다 |

**BFF 캐시를 늘리기 전에 서버 캐시를 확인한다.** 두 곳에 두면 무효화가 두 배로 어려워진다.

## 5. 응답 크기

- 반사실 `series`는 기간 `all`이면 수천 개다. **표시 해상도로 다운샘플링**해서 준다 (서버가 하면 더 좋다)
- 시장 개요는 `limit=100`이고 행마다 5컬럼이다. 쓰지 않는 필드를 빼서 전달한다
- 거래 목록에 전후 90일 가격 배열을 담지 않는다. 별도 엔드포인트

## 6. WebSocket

- 구독은 **화면이 보는 종목만**. 100종목 전부를 항상 구독하지 않는다
- 클라이언트 연결이 끊기면 상위 구독을 정리한다. 안 하면 유령 구독이 쌓인다
- 가격 갱신을 **throttle해서 내려보낸다.** 초당 수십 회를 그대로 밀면 프론트가 리렌더로 죽는다
- worker는 직접 실행될 때만 시작한다. import side effect로 interval이 중복 생성되지 않게 한다

## 7. SSE

- 스트림당 메모리를 잡는다. 동시 스트림 상한을 두고 초과 시 거부한다
- **클라이언트 종료를 서버로 전파**한다. 안 하면 유령 LLM 호출이 남는다(`streaming-sse.md` §4)
- 압축과 프록시 버퍼링을 끈다

## 8. 측정

- 요청 로깅에 이미 `duration`이 있다. **엔드포인트별 p95를 예산과 대조**한다
- 관측 항목: 블록별 `unavailable` 발생률, 서버 호출 지연 분포, 타임아웃 발생률, SSE 첫 토큰 지연, 동시 스트림 수
- 느리다는 보고에 추측으로 답하지 않는다. **어느 블록이 느린지 먼저 본다**
- 성능 수정 커밋에 before/after 수치를 남긴다
