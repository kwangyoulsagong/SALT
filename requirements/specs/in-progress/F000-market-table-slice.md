## Summary

**투자 화면 시세 표의 버튼이 실제로 동작하게 한다.** 기간 7버튼은 서버가 `period` 를 읽지
않아 전부 같은 목록을 돌려줬고, "오름차순"은 빈 문자열을 보내 "내림차순"과 같은 목록을 받았다.
화면은 에러 없이 버튼 색만 바꿨다. 같은 슬라이스에서 투자 화면이 1280px 에서 가로로 밀리던
레이아웃 결함(사용자 보고)과 프리뷰 가로 스크롤(뉴스 제목 · 차트)을 닫았다.

## Background

- 2026-09-21 사용자 결정: **Investment 쪽부터 계속**(`F000-realtime-reliability` 에 이어서).
- 영역을 넘는 이유: **계약 변경이 있다.** 서버 응답 항목에 `periodChange` 가 생겼고(추가 ·
  하위 호환) 모르는 `period` 가 422 다. BFF 는 그 422 를 500 으로 바꾸고 있었고, 프론트는
  새 필드를 읽는다. 커밋은 영역별로 나눴다 — 서버 → BFF → 프론트(기능) → 프론트(레이아웃).

| BFF | `BFF-REQ-010` | FR-1 · FR-2(다르게) · FR-3 · FR-4 | p95 측정 · 덧씌우기 제거(히트율 0%) · `limit=100` 유지 |

| 프론트 | `FE-REQ-010` | FR-50(다르게) · FR-51 · FR-54(확장) | 1280px 가로 스크롤 · 프리뷰 가로 스크롤 |

## Acceptance Criteria

- [x] 기간 7버튼의 응답 목록이 서로 다르다 (BFF 경유 해시 7개 전부 다름)
- [x] 오름차순과 내림차순의 목록이 다르다
- [x] 기준 시세가 없는 종목은 "—" 이고 24시간 값으로 채우지 않는다
- [x] 모르는 `period` 가 BFF 를 거쳐 **422** 로 온다 (500 아님)
- [x] 기간 모드에서 변동률이 깜박이지 않는다
- [x] 선택 행의 `aria-selected` 가 선택을 따라간다 · 보라색을 다시 켜지 않는다
- [x] 1920·1440·1280·1024·375 에서 문서 가로 스크롤 0
- [x] 프리뷰(뉴스 제목 · 차트)가 가로로 스크롤되지 않는다
- [x] 세 영역 빌드·타입체크·lint·테스트 통과
