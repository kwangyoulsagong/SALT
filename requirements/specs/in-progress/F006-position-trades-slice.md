## 판단 — 리뷰가 볼 곳

1. **평단은 FIFO 그대로**(사용자 결정 2026-11-18) — 스펙 "이동평균"과 코드 FIFO 가 어긋나 있었다. 바꾸면 기존 보유 평단 · 실현 손익이 바뀐다. 스펙을 정정
2. **불변식 한 줄로 셋을 막음** — 옛 검사 "지금 보유 ≥ 매도"는 과거 날짜 매도 · 매수 수량 줄이기 · 매수 삭제를 통과시켰다(수정 · 삭제엔 검사가 없었다). `LedgerChange.ts` 가 거래일 → 같은 시각 매수 먼저 → id 로 걸어 최저 보유를 본다. **이미 음수인 옛 원장**은 더 나빠지지만 않으면 받는다 — 아니면 그 사람은 문제 기록을 고치는 것밖에 못 한다
3. **쓴 뒤 다시 읽어 검사 → 던져 롤백** — 미리보기의 가상 순서와 DB 순서가 같은 시각 · 같은 방향일 때만 다를 수 있다. 저장되는 것은 늘 DB 사실
4. **트랜잭션 자리** — 저장소에 `tx` 를 넘기지 않고 연결 고르기 맥락(`routedClient` — 화면 · 배치 풀 나눔과 같은 자리)에 "열린 트랜잭션"을 얹었다(`runInTransaction`). 저장소 0줄 변경 · 국내 주식 평가(시세 읽기)는 커밋 뒤. 잠금 `pg_advisory_xact_lock(사람 · 자산군 · 종목)` — 동시 매도 둘 → 하나만(실측)
5. **남의 거래 403 → 404**(`DB-REQ-022` FR-74) — 존재를 떠볼 수 없게. `findOwned` 하나로
6. **수정에 모르는 키는 400** — 서버 `strict` · BFF 도 먼저 400. 조용히 버리면 "바꿨는데 안 바뀐" 성공이 된다
7. **FE** — 목록 경로 `/portfolio/transactions`(3탭 IA 없음) · 삭제 확인은 시트 안 한 줄(앱에 `DialogProvider` 없음) · 시트는 `<form>` 이 아니다(`SearchField` 가 자기 `<form>` 을 가져 겹쳤다) · 좁은 화면 훅을 `@repo/web-shared/lib` 로 내림(두 번째 소비처)
8. **같은 원인** — 상세 화면 기록 폼(`useRecordTrade`)이 포지션을 무효화하지 않았다 → `positionAll` 더함
