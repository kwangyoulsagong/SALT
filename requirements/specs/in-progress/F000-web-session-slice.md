## Summary

사용자가 "코치가 안 뜬다"고 했고, 원인은 코치가 아니었다. **로그인이 MSW 목이었다** —
`POST /api/v1/auth/login` 목이 `token: "mock-jwt-token"` 을 주고 화면은 그 문자열을 세션으로
저장했다. `/api/app/*` 는 그 토큰을 거부하므로 코치 · 관심 목록 · 포트폴리오가 전부 401 이었고,
화면은 그것을 "데이터 없음" 또는 "지금 판단을 불러올 수 없습니다"로 그렸다.

두 번째 원인은 **토큰 갱신이 없었다는 것**이다. 서버 액세스 토큰은 15분이고 리프레시 토큰은
저장만 되고 아무도 쓰지 않았다. 초대 경로로 만든 진짜 세션도 15분 뒤 같은 상태가 됐다.

## 범위

| REQ | FR | 내용 |
|---|---|---|
| `FE-REQ-011` | FR-62 · FR-63 | 만료 시 갱신 · 실패 시 로그인 이동 · 로그인 화면 초대 안내 |
| `FE-REQ-012` | (호출 배치) | `login` · `refresh` 행 추가 — 표에 없던 두 호출 |
| `FE-REQ-028` | FR-61 | `401` → refresh → 실패 시 로그인(F004 에도 같은 문장이 있었다) |

## 판단 — 리뷰가 볼 곳

1. **갱신을 `apiFetch` 에 얹은 것** — 호출하는 쪽에 두면 새 슬라이스가 잊고, 잊은 화면은 15분 뒤
   조용히 빈다. 규칙은 `@repo/core/auth` 에 두어 **테스트가 붙고**(9개) RN 이 같은 것을 쓴다
2. **갱신 호출을 `shared/api` 에 둔 것** — FSD 등록표는 토큰 갱신을 `auth` 슬라이스 책임으로
   적는다. 그런데 부르는 쪽이 `shared` 이고 `shared` → `entities` 는 훅이 막는다. 주입으로
   뒤집으면 등록을 잊은 화면에서 갱신이 사라진다. 토큰 읽기·쓰기가 이미 여기 있다
3. **목을 지운 것(BREAKING)** — 개발에서도 로그인에 BFF · 서버가 필요해진다. 목을 남기면
   그것이 계약으로 남고, 같은 사고가 또 난다
4. **실패 문구를 폼 위 한 줄로 둔 것** — 서버가 "없는 이메일"과 "틀린 비밀번호"를 구분하지 않으므로
   (계정 존재 여부 노출) 어느 필드가 틀렸는지 우리도 모른다
