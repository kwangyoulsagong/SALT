## 판단 — 리뷰가 볼 곳

1. **LLM 0** — F008 해설에서 템플릿이 LLM 글을 이겼고(FR-49 20:20 · O3 20:0) 같은 날 작성기 공통 결함 셋이 나왔다. 대화 답에 LLM 다듬기를 붙이려면 같은 블라인드 A/B 를 먼저 지난다. 이벤트 계약(`message.delta` · `done.source`)은 LLM 이 붙어도 그대로
2. **어떤 재료를 읽나는 도메인 표**(`ANSWER_MATERIALS`) — 질문마다 필요한 것만(위험 → 위험 예산 하나). 재료 하나 실패 = 그 문장만 "불러올 수 없어요" + `gaps`, 0 을 쓰지 않는다
3. **스펙 정정 셋** — ① 두 스트림 경합은 advisory lock 대신 `status = 'streaming'` 조건부 UPDATE(규칙 답이라 LLM 비용이 없다 — 늦은 쪽은 저장본을 보낸다) ② 재기동 정리(FR-8)는 부팅 워커 대신 목록을 읽는 자리에서 ③ 칩 "지금 팔아야 하나?" 는 검사기 명령형(`-아야`)에 걸려 "지금 팔 때인가?"
4. **이번 주 얼마** — 적립 계산(F003)이 없다. 지어내지 않고 "아직 없다" + 한 번 거래 손실 한도(있으면 금액)로 사이즈 계산을 가리킨다
5. **칩 표식** — 칩으로 물으면 저장 문장 앞에 칩 코드를 보이지 않는 구분자로 감춘다. 스트림이 같은 분류를 다시 얻고(칩이 이긴다), 목록 응답은 벗겨서 보낸다

### 판단 — 리뷰가 볼 곳

1. **게이트는 한 곳** — 코치 상세의 추천 조립을 `application/lib/recommendationCard.ts` 로 옮겨 상세 · 대화 답 · 브리핑이 같이 쓴다(동작 변경 0). 두 번째 소비처가 생긴 날 옮기지 않으면 게이트가 두 벌이 된다
2. **막힌 카드 = 내용 없는 게이트 칸**(`DB-REQ-022` FR-12 정정) — `null` 로 두면 FEATURE-006 UX 의 "사유 회색 상자"를 못 그린다. 행동 · 종목 · 점수 · 근거는 싣지 않는다(시험 · 실 DB 키 5개)
3. **카드는 팔기 · 이번 주 금액 질문에만** — 위험 · 복기 답에 추천을 끼우면 묻지 않은 매매 얘기가 된다(`ANSWER_MATERIALS` 표)
4. **복사본이 진실** — 저장 추천은 사용자당 한 행이 덮어써진다. `insight_id` 는 추적용(SET NULL)
5. **SSE 카드 id = 문장 수** — 마지막 문장까지 받고 끊긴 재연결도 카드를 받는다(실호출 확인)
6. **브리핑은 저장하지 않는다** — 화면을 열 때마다 대화 행이 생기지 않게. 위치는 지난 대화 다음 · 이번 질문 앞(오늘의 첫 메시지)
7. **새 답 따라가기** — 맨 아래(80px 안)를 보던 사람만, 내가 보낸 질문은 늘 따라감, 위를 읽던 사람은 자리 + "새 답 보기"
