## 판단 — 리뷰가 볼 곳

1. **목표 시계는 BFF 가 조립한다** — 가계부 서비스가 저축 서비스를 부르면 서비스 간 동기 호출이 생기고(`msa-services.md` §5 "동기 호출 사슬 금지"의 첫 고리), 서버 주소를 서버 코드에 박게 된다(§6). 저축이 "지출 X 원이면 가장 가까운 목표가 며칠 늦어지나"를 답하는 조회를 열고(`SRV-REQ-045` FR-17 이 원래 그렇게 적었다), BFF 가 저장 응답과 나란히 부른다. 예산 300ms 를 넘으면 `goalClock: { state: "pending" }` — 저장은 기다리지 않는다
2. **착지 구간 발행은 지출을 적을 때 하루 한 번** — 계산 기준은 **그날 시작**(어제까지 + 오늘 포함 남은 날, 리뷰 반영 2026-11-04) — 조회(GET)는 쓰지 않는다(저축 S1a 판단 5 와 같은 원칙). `(user, month, issued_on)` 유일 + `ON CONFLICT DO NOTHING`(오류 코드 분기 0). 화면은 발행 기록을 읽지 않고 늘 지금 기준으로 다시 계산한다 — 발행 기록은 "지난달 같은 날짜 적중"과 채점(`FC-REQ-024`)의 근거
3. **봉투 예산은 달마다가 아니라 "지금 예산" 하나** — 매달 다시 만드는 입력 피로를 막는다. 바꾸면 이번 달부터 적용, 지난달 화면도 지금 예산으로 본다(달별 이력은 S1b 월 마감과 같이 — 마감한 달의 예산을 그때 붙잡는다)
4. **할부는 별도 표 대신 `expense.installment_months`** — 원거래 = 그 행이고 월 청구는 계산값(`DB-REQ-038` FR-5 도 "저장 안 함")이라 표 하나를 더 둘 이유가 S1a 엔 없다. 리볼빙(원금이 바뀐다)이 들어오는 S1b 에 표를 연다
5. **분류 제안은 규칙만, LLM 0** — 금액은 정규식으로 확정, 분류는 낱말 표 → 최근 같은 가맹점의 분류. LLM 은 "선택"(`SRV-REQ-046` FR-3)이고, 붙이면 결제 문자에서 마스킹한 뒤의 가맹점이 밖으로 나간다 — 보낼 필드 공개(`FEATURE-015` FR-5) 화면이 생긴 뒤에
6. **기본 분류 12개는 코드 표** — 사용자 분류 표(`DB-REQ-038` FR-2)는 S1b. 분류 키는 `text` + 도메인 검증(CHECK 를 두면 사용자 분류를 들일 때 마이그레이션이 깨진다)
