## Summary

**서버 · BFF 가 끝난 주문 전 계산에 화면을 붙인다.** `/trade-preflight`(슬라이스 10 에서 손절 칩 ·
총자산 대비 최대 손실이 생겼다)와 BFF `POST /api/app/trade-preflight` 는 2026-09-22 에 있었고, 웹 소스에서
preflight 를 부르는 곳이 0건이었다. 상세 분석 오른쪽 열 수익 플랜 다음에 상주 카드를 둔다(PC), 좁은 폭(앱 웹뷰)은
여는 줄 + 바텀시트. Hero 에 [주문 전 체크] 해시 링크. 후속(사용자 승인 2026-10-29 "필드에 추가" · "남은것 다 해"): 서버 목표 도달 시 손익(`SRV-REQ-025` FR-65) · 자산군을 시세로(FR-66) · BFF `assetType` 한 줄 · 국내 주식 상세에도 같은 카드.

사용자 결정(2026-10-29): 같은 페이지의 F009 거래 기록 폼(사이즈 계산)과 겹치지만 **스펙대로 따로** 만든다 —
주문 전 체크는 "사기 전" 계산기(금액 칩 · 손절 칩 · 목표가 · 손익비), 거래 기록은 "이미 한 거래"를 적는 폼이다.

## 판단 — 리뷰가 볼 곳

1. **계산하지 않는다.** 손절 칩은 비율(−0.05)을 그대로 보내고 가격 환산 · 최대 손실 · 비중 · 손익비 · 상한 판정은 전부
   서버 값이다. FR-154 의 "목표 도달 시" 금액이 서버 응답에 없어 처음엔 비웠고(프론트가 곱하면 공통 수용 기준 3 위반),
   사용자 승인으로 서버에 필드를 더했다. **부호를 그대로 둔다** — 손익비처럼 0 으로 막으면 잘못 적은 목표가가 숨는다
2. **Hero 는 해시 링크 하나다.** 머리는 서버 컴포넌트라 기능 배럴을 값으로 부르면 클라이언트 경계가 늘어난다
   (`performance-frontend.md` §7). 카드가 문서의 링크 누름을 듣고, 넓은 화면은 브라우저 스크롤 + 제목 포커스, 좁은 폭은
   기본 이동을 막고 시트를 연다. `hashchange` 가 아닌 이유 — 같은 링크 두 번째 누름은 해시가 안 바뀐다
3. **"총자산"이라 부르지 않는다.** 서버 분모는 같은 자산군 보유 평가금 + 이번 금액이다. 문구는 응답 `assetType` 으로 "보유 코인 전체" · "보유 국내 주식 전체"
4. **진입가는 현재가로 한 번만 채운다.** 따라가면 틱마다 다시 계산되며 결과 줄이 흔들린다. 실시간 값이 없으면 공개 시세 —
   실측에서 WS 값이 오지 않아 진입가가 비고 계산이 시작되지 않았다
5. **실패하면 이전 결과를 두지 않는다.** `keepPreviousData` 그대로면 500 뒤에 이전 입력의 값이 지금 값처럼 남는다
6. 비율은 소수 2자리 — 정수 반올림이면 상한 60% 를 60.4% 로 넘었는데 "60%" 가 되어 배지와 어긋난다
