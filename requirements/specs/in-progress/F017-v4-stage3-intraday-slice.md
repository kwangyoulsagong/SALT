## 판단 — 리뷰가 볼 곳 (3a)

1. **1시간봉 → 5분봉으로 되돌림** — 처음엔 5분봉 이력이 없어(서버 보관 30일) FR-9 H1 선례대로 1시간봉 `base-rate@2` 를 등록했다.
   사용자 "5분봉으로 다 해야" — 이력을 **우리가 쌓고 백필**하면 FR-7 원문(30분 ±3% · VI) 그대로 된다. `@2` 는 실행 전 철회(DB 등록 0 · 결과 0), `@3` 새로 등록
2. **이력은 예측 표에 지우지 않고** — 코인은 forecast 가 업비트 5분봉을 2024-11 부터 받는다(서버 표는 30일 그대로 — 300종목 × 2년이면 서버 표가 6천만 행).
   국내는 서버 5분봉 보관을 400일로(`exceptAssetType`) + KIS 일별분봉 1년 백필(기획 원문 FR-21 로 되돌림) + forecast 가 옮겨 쌓는다
3. **조건 출처를 결과 전에 고정** — FR-7 넷 + `@1` 이 미룬 장중 조건(리서치 §3-3 K5 · K7 · C4 · C6). C5(거래량 시계)는 정의가 없어 뺐다(`@4` 후보)
4. **통계는 하루 한 번 · 문턱은 5분마다** — 통계(코인 6천만 칸)는 60일 구간으로 나눠 읽는다(덧댄 21일 · 쿨다운으로 경계 이중 계산 0).
   문턱은 최근 33일만 읽어 1초 안. 문턱 행 as_of = 마지막 통계 as_of(뷰가 그것으로 고른다). 서버는 15분 넘게 묵은 문턱을 안 본다
5. **두 키를 단위로 가른다** — `v_base_rate.horizon_unit`(day · hour). 점검 한 줄(하루)은 `@1` 그대로, 시나리오 1h · 4h 만 `@3` — 둘 다 "지평 1"이라 섞이면 1시간을 하루로 읽는다
6. **평소 행 = 정각 칸만** — 5분마다 겹치는 라벨로 평소 표본이 12배 부풀지 않게
7. **국내는 유니버스 약 50종목** — 전 종목 5분봉 1년은 KIS 240만 호출(초당 2건 → 2주). 나머지 종목 1h · 4h 칸은 국내 평소

## 판단 — 리뷰가 볼 곳 (3b)

1. **사전은 새로 짓지 않았다** — `news-reaction@2` 사전으로 DART 보고서 이름도 분류(54%). 사전을 고치면 태그와 창이 다른 종류를 셈한다
2. **DART 게시 시각 결함을 @2 로** — 1년 백필분의 '처음 본 시각'이 백필 날이라 한 해가 하루에 몰렸다(3,458/3,461). 접수일 끝(23:59:59 KST)으로 —
   그날 반응은 post1 에서 빠지는 보수적 선택. @1 은 전부 below_min 이라 본 숫자 0, 그 행은 지움
3. **공시 제목 → DART 행 대신 쓰기** — 같은 공시다. 뉴스 제목은 대신 쓰지 않는다(다른 사건일 수 있다)
4. **근거 단계는 안 바꾼다** — '미리 움직인 폭'은 늘 받치지 않는 근거(supports false). 비교 칸 문구만 바뀐다
