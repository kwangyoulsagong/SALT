## Summary

F009(1인 펀드매니저 코치)의 준수율 · 미러는 기존 성적표와 같은 숫자를 쓴다. 그 숫자의 **이름 · 기간 · 출처가 틀리면**
F009 가 틀린 숫자를 더 크게 보여 준다. 그래서 코드 진단 C01~C06
(`requirements/reports/feature-audits/2026-09-24-ai-investment-deep-research.md` §5)을 먼저 고친다.
새 REQ 를 만들지 않고 **F004 · F008 기존 REQ 를 개정**한다(`FEATURE-009` 슬라이스 표 0행).

## 범위와 진행

## 판단 — 리뷰가 볼 곳

1. **C04 는 별칭 없이 이름을 바꿨다** — 서버 FR-30("이름 변경 0건")의 두 번째 예외. 옛 이름을 남기면 거짓 이름이 계약에 남는다. 소비처가 같은 레포에 전부 있다
2. **C04 는 계산을 바꾸지 않았다** — 진짜 MDD 는 판단 표본(겹치는 기간)으로는 못 구한다. 사용자 거래 곡선이 생기는 F009 슬라이스 1 에서 별도 필드로
3. **C05 는 말을 채점에 맞췄다, 채점을 말에 맞추지 않았다** — 25분 전략을 채점하려면 분봉 채점이 새로 필요하고 표본 20 이 쌓일 때까지 단타가 전부 막힌다(사용자 결정). `validity.code` **값**이 바뀌어 프론트 i18n 을 같은 커밋에서 바꿨다

4. **C06 은 기존 행을 추정하지 않고 쓴 쪽으로 갈랐다** — 쓰는 코드가 워커 · 시드 둘뿐이고 시드가 표식을 남겼다. 열에 기본값이 없다(출처를 빼먹은 새 코드가 실측으로 들어가지 않게). 로컬 개발은 `JUDGMENT_COUNT_SYNTHETIC=true` 로만 합성 표본을 센다
