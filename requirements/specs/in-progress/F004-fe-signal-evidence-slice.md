## Summary

**성적표 그룹 하나를 펼치는 화면.** 서버는 2026-09-23(슬라이스 11)부터 성적표 그룹마다 관찰 기간 수익률 분포
(`returnDistribution`)와 맞았던 때 · 틀렸던 때(같은 상한 3)를 주고 있었는데(`SRV-REQ-025` FR-53), BFF 가 "화면이 아직
안 쓴다"며 분포를 버리고 있었고 화면은 코치 리포트 성적표 패널(최근 빗나간 판정 3)뿐이었다. F004 FR-33 · 34 의 마지막
조각. 사용자 "새브랜치 파고 다음꺼 진행" — 마스터 인덱스의 "다음 F004 는 주문 전 체크 화면과 성적표 · 추천 근거 상세".

## 판단 — 리뷰가 볼 곳

1. **빠진 구간을 0 으로 채우지 않는다.** 구간 하나라도 없거나 횟수가 음수 · 소수면 BFF 가 분포 전체를 `null` 로 둔다.
   0 으로 채우면 "그 구간에서 끝난 판단이 없었다"는 주장이 되고, 화면은 이유 한 줄("분포를 아직 받지 못했어요")을 쓴다
2. **분포는 지난 표본의 모양이다.** "이 구간에 들 확률" · 기대 수익 문구 0, 막대 아래 "다음 판단이 어느 구간에 들지 알려
   주지 않아요". 기간은 그룹이 말한다(단타 하루 · 장기 30일) — 스펙 초안의 "30일 수익률" 고정은 단타 표본에 거짓이라 서버가 이미 고쳤다
3. **맞았던 때 · 틀렸던 때는 같은 컴포넌트 하나를 두 번 그린다.** 크기 · 위계 · 순서가 코드상 같을 수밖에 없다. 화면이
   고르거나 자르지 않는다(서버가 같은 상한 · 최근 순)
4. **추가 요청이 없다.** 성적표와 같은 응답(`/coach/scoreboard`)에서 그룹을 고른다 — 리포트에서 넘어오면 캐시로 바로 그린다.
   그룹별 경로를 BFF 에 새로 만들지 않았다
5. **세로 `BarChart` 를 쓰지 않았다.** `@repo/ui/barChart` 는 칸 아래 이름이 말줄임이라 390 폭(칸 47px)에서 "−20 ~ −10%" 가
   잘린다. 가로 막대(이름 칸 고정) + 같은 값의 `sr-only` 표
6. **표본 부족이면 비율 셋(적중률 · 평균 · 가장 나빴던 한 번)을 감춘다** — 성적표와 같은 서버 판정. 분포 횟수와 사례는
   채점된 사실이라 그대로 둔다
