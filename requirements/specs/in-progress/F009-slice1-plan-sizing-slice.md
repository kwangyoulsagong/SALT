## Summary

"이 크기가 내 예산에서 몇 %인가"를 서버가 계산하고, 사용자가 적은 계획을 저장하고, 예산 게이지 셋을 준다.
**화면은 없다** — 슬라이스 3(`BFF-REQ-038` · `FE-REQ-039`)이 붙인다. 기획 `FEATURE-009` 슬라이스 표 1행.

|---|---|---|
| DB | `salt-server/requirements/specs/in-progress/DB-REQ-031-F009-SCHEMA.md` | FR-1~7 (`realized_vol` FR-8 은 슬라이스 2) |
| 서버 | `salt-server/requirements/specs/in-progress/SRV-REQ-038-F009-RISK.md` | FR-1~8 (판정 · 미러 FR-9 슬라이스 4, 복기 FR-10 슬라이스 6) |
| BFF · 프론트 | — | 변경 없음. 새 서버 경로를 부르는 곳이 아직 없다 |

## 판단 — 리뷰가 볼 곳

1. **월 손익을 평단 없이 시가 평가 항등식으로** — 지금 평가 − 월초 평가 − 순유입. 월초 보유 종목의 월초 종가가 없으면 합을 만들지 않는다
2. **거래에 연결된 계획의 채점 기준(손절가 · 계획 수량 · 오를 확률) 잠금** — 결정 뒤 기준을 옮기면 준수율이 자기 채점이 된다. 쓰기 조건으로 걸어 경합도 막는다
3. **`preflight` 를 고치지 않고 `sizing` 을 나란히 둔 것** — 특성화 테스트가 고정한 `number` 산술을 깨지 않으려고. 두 계산이 공존한다(슬라이스 3 에서 화면이 어느 쪽을 부를지 정한다)
4. **실현 변동성 원천이 없는 채로 계약을 연 것** — `insufficient_data` 로 흐르고 슬라이스 2 가 메서드 하나를 바꾼다
5. **비율 예산의 분모 = 코인 보유 평가금액** — 현금 · 주식 기록이 없어서. 화면이 분모를 밝혀야 한다
