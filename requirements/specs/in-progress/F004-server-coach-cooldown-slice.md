## Summary

코치 서버 후속 중 **마이그레이션이 필요한 두 축**을 닫는 슬라이스다. 슬라이스 11 · 12 가 스키마 변경을
섞지 않으려고 미뤄 둔 것이다.

- **프로필 축** — `defaultMode` · `notificationLevel` 을 실제로 저장한다. 종목 판단은 `mode` 가 없으면 사용자 기본 모드를 따른다
- **쿨다운 축** — 수동 재생성은 202 로 받고 뒤에서 생성한다. 5분 안에 다시 누르면 429 + 남은 초. 생성 상태 경로가 생겼고
  워커 생성도 기록한다

## 판단 — 리뷰가 볼 곳

1. **`generate` 를 202 로 바꿨다 (BREAKING)** — BFF 는 1s 타임아웃으로 202 를 기대한다(`BFF-REQ-025` FR-3).
   소비처는 BFF 프록시뿐이고 본문을 읽는 곳이 없다(grep 확인). 되돌리려면 커밋 `d0f7c4c` 하나를 revert 한다
2. **기록을 받는 순간 만든다** — 끝날 때 쓰면 생성 중에 온 두 번째 요청이 쿨다운을 통과한다. 그래서 상태에 `running` 을
   더했다(`DB-REQ-017` "다르게")
3. **쿨다운 기준 = 받아들인 수동 요청** — 거부는 늘리지 않고(연타가 벌이 되지 않게) 실패는 건다(실패 연타 방지). 워커는 제외
4. **쿨다운은 에러가 아니라 결과 타입** — `ErrorKind` 를 늘리지 않았다. 429 로 옮기는 것은 컨트롤러
5. **프로필은 고른 값만 저장** — 고른 적 없으면 `null`, 응답만 기본값을 채운다

## 커밋
