## Summary

판정 AI 리서치(`requirements/reports/research/2026-09-27-ai-judgment-upgrade.md` §6-4 1~2단계 · §10 슬라이스 1). 코치 규칙 점수는 가중을 전부
손으로 정했고 **한 번도 채점된 적이 없다.** 이 슬라이스는 두 가지를 만든다.

1. **지금 규칙이 맞는지 과거로 잰다** — 결과를 보기 전에 판정 규칙을 사전등록하고, 구현된 규칙을 그대로 재현해 항목별 IC 를 잰다.
   사용자 결정(2026-09-27): 고래는 가중을 먼저 올리지 않고 **긴 이력으로 잰 뒤** 근거가 나오면 올린다. 대형 체결 이력은 **1년**.
2. **앞으로는 매일 불변으로 남긴다** — 추적 종목 × 두 모드 판단을 항목 기여 · 재료 발생 시각 · 국면 태그와 함께 원장에 쓴다.
   과거로 못 재는 항목(단타 1시간봉 RSI · 업비트 대형 체결)은 여기서 8주 뒤(2026-11-23) 같은 프로토콜로 잰다.

## 판단 — 리뷰가 볼 곳

1. **사전등록을 결과보다 먼저 커밋했다** — 판정 규칙(CI 가 0 을 포함하면 가중 0, 반대편이면 부호 반전)을 바꾸려면 새 키가 필요하고, 작업은
   같은 키에 다른 내용이 오면 실패한다. 첫 실행이 등록 단계에서 두 번 실패했는데(판단 5) **결과는 계산 전**이었다
2. **구현된 규칙을 그대로 재현했다** — RSI 단순 합 · 손실 0 이면 1 로 나누기 · 공포탐욕 0 무시까지. 고치면 "지금 규칙"이 아니라 "고친 규칙"을 잰다.
   특성화 테스트 값이 서버와 같다(`tests/domain/test_rule_items.py`)
3. **가중은 이 슬라이스에서 바꾸지 않았다** — 판정대로 바꾸면 화면 판단이 바뀌고, 성적표(`symbol_judgment_snapshots`)에 규칙 버전 열이 없어
   v1 · v2 표본이 섞인다. 바꾸는 커밋은 사용자 결정 뒤 별도로(아래 "다음")
4. **원장에 판정 열이 없다** — 슬라이스 0 회고 Action. 라벨은 읽는 쪽이 가격으로 만들어 경계를 바꿔도 행을 다시 쓰지 않는다. UPDATE 는 트리거가 막는다
5. **push 전 마이그레이션을 고쳤다** — `rule_ic.mode` CHECK 에 도전자 `any` 가 빠져 있었다. 새 마이그레이션 대신 원 파일을 고치고 로컬 DB 는
   제약 · `_prisma_migrations` 체크섬을 손으로 맞췄다. 다른 DB 에는 아직 적용된 적 없다
6. **대형 체결은 화면이 부를 때만 저장되고 있었다** — 4개월 15종목 291행 · 저장 시각이 체결 시각이 아님 · 같은 체결 반복 저장 · 10건 상한.
   워커 수집으로 바꿨고, 실 DB 첫 실행에서 재개 지점을 "마지막 대형 체결"로 잡은 결함이 드러나 "지난 회차에 훑은 체결"로 고쳤다
7. **항목 기여는 응답에 싣지 않는다** — `dualDecision` 이 `ModeDecision` 을 통째로 내보내므로, 기여는 `scoreModeDecision` 이 따로 돌려준다.
   BFF · 프론트 계약 무변화
