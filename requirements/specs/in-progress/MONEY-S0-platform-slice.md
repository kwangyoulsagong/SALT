## 판단 — 리뷰가 볼 곳

1. **아웃박스를 Spring Modulith 발행 기록 대신 서비스 스키마마다 직접 뒀다**(`SRV-REQ-044` FR-1 정정) — 서비스마다 DB 계정 · 트랜잭션이 따로라 공용 표 하나로는 업무 쓰기와 한 트랜잭션이 될 수 없다. Modulith 는 경계 검증에만
2. **한 프로세스 안에서도 서비스마다 DB 풀 · 계정 · 트랜잭션 매니저가 따로** — 코드가 남의 표 이름을 적어도 DB 가 42501 로 막는다. 비용: 서비스 수만큼 풀(지금 5개짜리 하나)
3. **오류 바디를 Express 실제 응답(골든 4)과 바이트까지 맞췄다** — BFF 무변경이 합격 기준이라 "같은 모양"이 아니라 같은 바이트
4. **BFF 스위치는 서버 호출 한 곳(`backendApi`) 인터셉터에만** — 서비스 26곳 무변경. 그림자는 GET · HEAD 만, 기록에 값 0
5. **RabbitMQ 유지**(사용자 질문 "왜 카프카 안 씀?" → 그대로 가기로) — 작업 큐 · 재시도 · 데드레터가 기본이고 양이 적고 재생은 DB 재조회로. 바꿀 조건 FR-9 그대로, 바꿀 때 릴레이 · 구독 어댑터 둘만
