## Summary

사용자 "새 브랜치 파고 다음꺼 진행" — 마스터 인덱스 §4-1 순위 2 의 다음 줄(`FEATURE-011` FR-14 미래 휴장일).

FR-14 는 슬라이스 0 부터 "부분"이었다. 1순위 출처인 KIS 휴장일 조회(`CTCA0903R`)가 이 앱 키(모의투자용, 실전 키 전환 없음 —
사용자 결정 2026-10-29)로 `EGW02004` 거부라, 달력은 일봉 역산(지난날) + 09:10 관측(오늘)만 있었다. 그래서

- 평일 휴장 **전날** 장 상태가 다음 개장을 휴장일 09:00 으로 냈다(12-24 → 12-25, 12-30 → 12-31)
- 평일 아침 09:10 전에는 오늘이 달력에 없어 `calendarKnown = false` — 화면 장 상태 줄에 "달력 추정"이 매일 아침 붙었다

**KRX 연간 휴장일 공시를 서버 상수 표(`KRX_NOTICE_CLOSURES`)로 두고 3순위 출처 `krx_notice` 로 오늘 ~ 표 끝을 채운다.**
실제 체결 출처(`candles` · `probe`)가 공시보다 우선이다 — 공시 뒤 임시공휴일은 그날 09:10 관측이 덮는다.

## 판단 — 리뷰가 볼 곳

1. **출처를 코드 상수로 둔 판단.** 무키 대안은 없었다 — 공공데이터포털 특일 API 는 키가 필요하고(없음) KRX 고유 휴장(연말 · 근로자의 날)을
   따로 더해야 한다. 거래소 공시는 1년에 한 번이라 상수 + 만료 경고(31일 전)로 충분하다고 봤다. 다음 해 공시를 놓치면 그 해는 지금처럼
   "추정"으로 돌아갈 뿐 틀린 휴장을 내지 않는다(표 밖 날짜는 쓰지 않는다)
2. **표가 맞다는 근거는 실측이다.** 2026-01-01~10-29 줄 15개가 저장 일봉 역산과 날짜까지 같다(제헌절 7-17 · 지방선거 6-3 포함).
   동기화가 매일 같은 대조를 돌려 어긋나면 경고한다. 남은 미래 줄은 12-25 · 12-31 · 2027-01-01(신정 — 다음 해 공시 전이지만 법정 공휴일)
3. **예측이 같은 표를 읽는다 — 서버만 바꾸면 조용히 깨진다.** 미래 개장일이 들어오면 예측의 "마지막 아는 거래일"이 12-30 이 돼
   `presumed_weekdays`(원천 멈춤 → 평일을 거래일로 가정 → 게이트 소등)가 꺼진다. 그래서 같은 PR 에서 예측 읽기를 실행 날짜까지 자른다.
   **서버 커밋만 먼저 머지하지 않는다**
