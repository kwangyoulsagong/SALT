## Summary

사용자 "새 브랜치 파고 다음꺼 진행"(§4-1 순위 3 F008 FR-73 줄 — `SRV-REQ-050` → `BFF-REQ-050` → `FE-REQ-059`). 구현 중 사용자 추가 요구 둘:
"스트리밍도 제대로 안 되는 느낌 — 그냥 정보 짝 나와, 스트리밍 제대로 만들어" · "클로드 코덱스가 들어왔으니 더 정확하게 — 더 분석 잘하니까".

- **라우팅** — 서버 맥에 로컬 CLI 가 있고 허용 사용자(비우면 소유자)이고 웹이면 로컬 CLI, 아니면 Gemini. 격리 · 상한 · 실패 시 Gemini 한 번 → 템플릿
- **진짜 스트리밍**(`SRV-REQ-050` FR-13) — 전엔 템플릿을 한 틱에 쏟고 끝에 통째 교체였다. 로컬 Claude 는 줄 형식 토큰 스트림 → 문장마다 검사 → 통과한 것만 즉시. 검사 전 원문 0 은 그대로
- **깊은 분석**(FR-14) — 근거끼리의 방향 · 판단이 약해지는 조건. 검증기는 문장 단위 · 금액 방향 없음 · 권유 확장

## 판단

1. **템플릿 선흘림을 공급자에 따라 나눈다** — 토큰 스트림이 없는 Gemini · Codex 에서 선흘림을 없애면 수 초 빈 화면이다. 흐를 수 있는 공급자만 흘린다
2. **Codex 는 스트리밍 대상이 아니다** — `codex exec --json` 이 메시지를 끝에 한 번 준다(실측). 같은 줄 형식 · 같은 검사, 예전 길
3. **과거 성적 숫자는 해설 문장에 넣지 않는다** — 성적은 4요소 한 벌로만(F009 FR-33), 카드가 이미 그린다. 깊이는 숫자를 늘리지 않고 근거 사이 관계로
4. **토큰 상한은 Gemini 만** — 로컬은 구독. 토큰 상한에 닿아도 로컬은 쓴다(`geminiAllowed: false`)
