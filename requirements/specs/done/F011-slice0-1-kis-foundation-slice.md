## 판단 — 리뷰가 볼 곳

1. **시세를 `MarketAsset` 이 아니라 `kr_stock_quotes` 에** — 코인 경로 8곳이 자산군을 안 거른다(상폐 처리가 국내 주식을 6시간마다 끔 · 업비트 호출 · 비소유자 노출). 기획 정정
2. **허용 목록 + 레포 grep** — 주문 TR 을 "막는" 대신 조회 TR 만 부를 수 있게. 거부 목록은 새 주문 TR 을 못 막는다
3. **원시 SQL 시각 = `timestamptz → UTC`** — DB 세션이 `Asia/Seoul` 이라 `::timestamp` 는 9시간 어긋난다. 첫 판에서 실제로 났고(일봉 `00:00Z`) 로컬 행을 바로잡았다
4. **KIS 업무 오류는 HTTP 500** — 메시지 코드가 있으면 재시도하지 않는다(`EGW00201` 만). 첫 판은 거부된 TR 을 3번씩 다시 불렀다
5. **한도는 앱 키 단위, 페이서는 프로세스 단위** — 초과를 받으면 프로세스가 1→8초 물러선다. 개발 서버 5개가 동시에 돌던 상태에서 이것이 없으면 회차당 재시도 40~120 · 종목 실패
6. **동시 6 + 페이서** — 순차 호출은 지연 × 건수(현재가 50종목 38초). 출발 간격은 페이서가 지키고 동시성은 매달린 요청만 묶는다
7. **휴장일** — KIS 조회가 이 키로 거부(`EGW02004`). 지난날은 일봉 역산(실제 체결 기록) · 오늘은 09:10 관측 · 미래는 `calendarKnown=false` 로 숨기지 않는다
8. **SSE 인증** — 기획의 내부 토큰 대신 사용자 JWT + 소유자. 소유자 전용이라 새 비밀값이 필요 없다
9. **5분봉 병합** — 재시작으로 버킷 중간부터 받으면 덮어쓰기가 앞부분을 지운다. 시가 유지 · 고저 넓은 쪽 · 거래량 큰 쪽
10. **5분봉 보관 30일** — 기획은 1년 백필이지만 정리 작업이 5분봉 30일을 자산군 구분 없이 지운다. 코인과 같은 보관으로 맞췄다
11. **고정 속도 vs 적응형** — 적응형은 실패 0 이지만 2~2.7배 느려 버렸다. 고정의 실패는 다음 회차가 메운다
12. **시세 창 16:00 까지** — 시간외 단일가 동안 KIS 현재가 · 체결이 시간외 값이라 정규장 값을 덮었다. 18:00 까지는 별도 필드(슬라이스 6)와 함께
