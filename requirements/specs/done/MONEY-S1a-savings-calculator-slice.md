## 판단 — 리뷰가 볼 곳

1. **옛 `/api/goals*` 를 Kotlin 으로 다시 만들지 않고 은퇴시킨다**(`msa-services.md` §7 의 ①~③ 대신 "가져오기 → 소비처 전환 → 410"). 옛 계약의 소비처는 셸 목표 화면 · 홈 카드 · 온보딩 프로브 셋뿐이고 셋 다 이 슬라이스에서 새 계약으로 옮긴다 — 아무도 안 부를 경로의 골든 · 그림자는 비용만 있다. 쓰기 경로가 둘(Express · Kotlin)인 기간을 0 으로 만드는 것이 데이터 갈라짐을 막는 유일한 방법이다
2. **데이터 이동은 관리자 SQL 한 번**(`salt-platform/db/savings-import.sql`) — Flyway 는 `svc_savings` 로 돌아 `public` 을 읽을 권한이 없다(그게 S0 의 요점). INSERT 만 · 다시 돌려도 같은 결과 · 행 수 대조 · 되돌리기 스크립트
3. **기준선 숫자를 비워 둔다** — 원문 대조 전 통계를 금액으로 내리면 "미확인" 표시를 달아도 화면엔 숫자가 남는다. 템플릿은 7종 + `baseline: null` + `reason`. FEATURE-012 열린 질문이 닫히면 채운다
4. **계산 계약을 하나 더 열었다** — `POST /api/savings/calculate`(저장 없음). 만들기 화면이 디바운스로 부르는 자리(FE FR-3)인데 SRV 스펙 API 목록에 없었다
5. **도달 구간은 상태가 바뀔 때만 발행** — 만들기 · 적립에서 `projection_issued` + 이벤트. 조회(GET)는 쓰지 않는다. **정정 2026-11-03(`c82be47c`)**: 화면은 발행 기록을 읽지 않고 늘 지금 기준으로 다시 계산한다 — 발행 기록은 채점 보관용(낡음 · 목록/상세 불일치 · `degraded` 가림, 코드 리뷰)
