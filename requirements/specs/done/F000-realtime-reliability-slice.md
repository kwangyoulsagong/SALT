## Summary

**투자 화면의 실시간 시세가 조용히 멈추는 경로를 닫는다.** 앞선 두 슬라이스가 기능을
열었다면 이것은 이미 있는 기능이 **에러 없이 틀린 것을 보여주는 자리**를 막는다 — 멈춘
시세를 초록 점과 "기준 시각"으로 그리는 헤더, 두 번째 탭을 열면 굶는 첫 탭, 서버가 꺼지면
0건을 보내는 WS, 기동 때마다 429 가 수백 건 쌓이는 캔들 수집.

## Background

- 2026-09-21 사용자 결정: **다음 단계는 Investment 쪽부터**. 후보였던 동면 410·알림 2종은 뒤로 미뤘다.
- 영역을 넘는 이유: 시세 경로가 서버(Upbit REST) → BFF(Upbit WS 중계) → 프론트(WS 구독)로
  한 줄이고, 증상(헤더가 멈춤)은 프론트에서 보이는데 원인은 세 영역에 나뉘어 있었다.
  **계약 변경은 없다**(`connected` 메시지의 `userId` 제거 — 소비처 0건). 그래서 커밋을
  영역별로 나눴고, 되돌릴 때 영역 하나만 revert 할 수 있다.

## 범위 — 각 REQ 의 어느 FR 인가

| 영역 | REQ | FR | 내용 |
|---|---|---|---|
| 서버 | `SRV-REQ-006` | 체크리스트 §12-3 정정 · §15 | 거래소 호출 출발 간격 제한. "캔들 수집 실패 0건"을 **재현되는 사실**로 만든다 |
| BFF | `BFF-REQ-010` | FR-11 (판정) · FR-12 · FR-15 (측정) | 연결 키 · Upbit 전체 집합 구독 · 서버 장애 격리 · 종료 처리 |
| 프론트 | `FE-REQ-011` | FR-10 · FR-11 · FR-12 · FR-13 | 연결 상태 · "연결 끊김" · 헤더만 리렌더 |
| 프론트 | `FE-REQ-012` | FR-24 · FR-25 · FR-26 | 유령 구독 0 · 재연결 백오프 + 끊김 표시 · 캔들 동작 유지 |

## 범위 밖

| 항목 | 왜 |
|---|---|
| 동면 route 410 · 홈 조립 · 알림 2종 | 사용자 우선순위(Investment 먼저). `SRV-REQ-009` FR-7·8 · `BFF-REQ-007` A·B·C절 |
| BFF 가격 throttle (`BFF-REQ-010` FR-11) | 실측 18.9건/초 · 심볼당 최대 2건/초. 프론트가 이미 프레임 단위로 묶는다. **만들지 않는다는 판정**이다 — 체크리스트 §3 |
| WS 토큰 검증 | BFF 는 토큰을 해석하지 않는다(`bff-architecture.md` §6). 시세는 공개 데이터 |
| `upbit-ws.service` 가 import 시 연결하는 것 | `websocket-worker.md` 위반이지만 WS·워커 두 프로세스가 각자 쓰는 싱글턴이라 구조 변경이다. 별 작업 |
| 온보딩 화면 브라우저 실측 (앞 슬라이스의 남은 항목) | Chrome 확장이 연결되지 않았다. 투자 화면은 Playwright 로 봤다 |

## Acceptance Criteria

- [x] 콜드 스타트에서 Upbit 429 **0건** · 캔들 수집 실패 **0건**
- [x] 같은 토큰 두 소켓이 둘 다 받고, 하나를 닫아도 다른 하나가 계속 받는다
- [x] 서버가 꺼진 상태에서 새 WS 프로세스가 화면 요청 심볼을 전달한다
- [x] Upbit 구독 요청이 항상 전체 집합이다
- [x] SIGTERM 을 받은 WS 프로세스가 즉시 끝나고 클라이언트가 close 를 받는다
- [x] BFF 가 끊기면 헤더가 "연결 끊김 · 재연결 중"이고 기준 시각을 쓰지 않는다
- [x] 재기동하면 헤더와 수신이 복구된다
- [x] 표가 언마운트되면 `unsubscribe` · `unsubscribe_candle` 이 전송된다
- [x] 로그·환영 메시지에 토큰 원문이 없다
- [x] 세 영역 빌드·타입체크·lint·테스트 통과
