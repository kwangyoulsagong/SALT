## 판단 — 리뷰가 볼 곳

1. **S1g = 이야기 카드 하나** — 셋 중 Should 는 이야기 카드뿐이고, 지금까지 쌓인 기록(분류 · 스티커 · 챌린지 · 기분)을 읽기만 해 새 원장이 없다. 사람 장부는 새 원장 · 민감 정보 분류(Could), 리볼빙은 규정 원문 대조가 먼저 — S1h
2. **줄은 사실만 · 값이 없으면 빠진다** — 쓴 돈(건수 · 적은 날 · 대략 포함) · 가장 많이 쓴 분류(몫 %) · 가장 많이 쓴 달(해 카드 · 달이 둘 이상) · 안 쓴 날 · 챌린지 한 날 · 아낀 돈 · 기분을 남긴 지출 수. **점수 · 순위 · 지난번 대비 · 칭찬 0**, 기분은 수만(어떤 기분 · 만족 점수 0 — 민감 정보). 0 인 줄은 내밀지 않는다("0일"이 평가처럼 읽힌다). 안 쓴 날은 달력과 같은 답 — 스티커 뒤 그날 지출을 적었으면 빠진다
3. **새 표 0 · 쿼리 6 · 인덱스 하나** — 카드는 저장하지 않고 그때 계산한다(기록을 고치면 카드도 따라온다). 지출은 (날짜, 분류, 정밀도)로 묶은 한 문장(해 카드도 날 수 × 분류 수 행) + 스티커 · 챌린지 날 · 아낀 돈 합 · 기분 수 + 분류 표. 아낀 돈은 챌린지 id 로만 읽던 표라 V7 에 `(user_id, saved_on)` 인덱스
4. **볼 수 있는 날 = 월 마감과 같은 규칙** — 지난 기간은 바로, 이번 기간은 마지막 3일부터(`MonthCloseRules.CURRENT_MONTH_LAST_DAYS` 를 그대로 — 도메인 테스트가 두 답이 같은지 본다). 아직이면 `readyOn` 만(재료 쿼리 0), 오지 않은 기간은 400 `STORY_PERIOD_FUTURE`
5. **금액 가림은 화면 몫 · 기본 가림** — 서버는 금액을 그대로 준다(본인 화면이다). 공유는 남에게 가는 것이라 "금액 보이기"를 **꺼진 채** 시작하고, 화면 카드와 공유 이미지가 **같은 문장 · 같은 가림 상태**를 쓴다(`storyText` 한 곳) — 보이는 그대로 나간다. 가린 자리는 "가린 금액"으로 읽힌다
6. **공유 이미지 = 누를 때 화면 밖 캔버스 한 번** — 카드는 DOM(선택 · 읽기 · 접근성). PNG 는 공유를 누를 때 화면 밖 캔버스에 카드의 계산된 색 · 글꼴로 그려 파일로 내보낸다(새 라이브러리 0). 파일 공유를 받는 브라우저면 공유 시트, 아니면 저장. `canvas.md` 의 "카드에 캔버스 금지"는 렌더링 규칙이라 내보내기 한 줄을 더했다
