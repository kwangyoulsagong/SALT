## Summary

`FE-REQ-074` 검증 2회차에서 찾음 · 사용자 "베스트 케이스로". 업비트 등락 · 고저는 **당일**(한국 시각 오전 9시에 넘어감) 기준 — 전일 종가 대비다.
진짜 24시간은 거래대금 · 거래량뿐이다. 계약 필드 이름(`change24h` · `high24h` · `low24h`)은 그대로 두고(서버 · BFF · 웹 · 예측 · DB 열까지 걸린다)
뜻을 적은 곳 — LLM 프롬프트 · AI 입력 공개 · 화면 이름표 · 주석 — 을 고쳤다. 값 · 채점 변화 0(과거 검산은 원래 일봉 종가 / 전일 종가).

| 영역 | REQ | 무엇 |
|---|---|---|
| 서버 | `SRV-REQ-061` | 해설 프롬프트 "전일 대비 변동률" · AI 입력 공개 · 문장 검사 `wrong_change_window`(지난 24시간에 붙인 등락) · `toQuote` 창 표 |
| 웹 | `FE-REQ-075` | 코인 상세 "당일 범위 · 24시간 거래대금" · 검색 설명 · 요약 기준 `CryptoDay` · 칩 · 관찰 항목 이름 |
| BFF | — | 주석 하나(계약 변경 0) |

## 판단

1. **필드 이름은 바꾸지 않는다** — 이름 바꾸기는 계약 BREAKING(DB 열 · 예측 · 웹소켓)인데 값은 맞다. 대신 원천 어댑터 한 곳에 창 표
2. **프롬프트만 고치지 않고 문장 검사도** — 모델이 습관으로 "24시간 동안 3% 올랐어요"를 쓸 수 있다. 저장된 실문장 50개에 대 오탐 0 을 확인하고 넣었다
3. **저장된 해설은 다시 만들지 않는다** — 실측 결과 틀린 창을 쓴 저장 문장 0
