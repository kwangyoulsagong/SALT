# F016 단계 B — 국내 소식 · 수급 — 회고

슬라이스 `requirements/specs/done/F016-B-kr-news-flows-slice.md` · 체크리스트 `requirements/reports/checklists/F016-B-kr-news-flows.md`.

## 잘 된 것

- **실측이 설계를 바꿨다** — 시황 제목 TR 은 종목 칸을 비우면 시장 전체를 주고, 날짜 · 시각으로 쪽을 넘긴다. 기획의 "종목마다 5분"이 "시장 전체 한 번"이 돼
  호출이 약 24분의 1이 됐고 관심 종목 · 공시도 같이 걸렸다. 외국인 · 기관 장중 추정은 모의 키가 거부한다는 것도 코드 전에 알았다 — 원천 없는 칸을 만들지 않았다
- 업종 지수는 기존 지수 TR · 파서를 그대로 썼다(새 파서 0). 프로그램 매매 금액 단위(원)가 투자자 TR(백만 원)과 다르다는 것을 실측 행을 테스트에 그대로 넣어 고정했다
- 실화면을 처음부터 너비 넷 + 390 웹뷰 + 실패 · 빈 · 비소유자 · 만료 세션 표로 돌렸다(단계 A 확인 2회차 교훈)

## 아쉬운 것 · 배운 것

- **시세 사슬 끝에 "정각 판정"을 붙였다가 회차를 놓쳤다** — 사슬 한 회차가 1분을 넘기면(장중 초과가 많을 때) 사슬 끝 유스케이스가 늦은 시각을 본다.
  박자는 cron 이 정하고, 유스케이스 안에서 "지금 분"을 다시 판정하지 않는다. 같은 모양(사슬 끝 + 분 판정)은 시간외 단일가(`isKrAfterHoursPollMinute`)에도 있다 — 아래 다음
- **장중 작업에 저녁 작업의 양보 규칙을 가져왔다** — "초과 한 번이면 양보"는 18:40 투자자 동향(한가함)엔 맞지만 장중(초과율 40%+)엔 매 회차 0/50 이었다. 성공 0 회차가 로그 없이 지나가 원인을 늦게 찾았다 → 회차마다 한 줄
- 맥 슬립(12:08~13:08)이 cron 회차를 지워 첫 진단이 늦었다 — 장중 실측은 `caffeinate` 로 붙잡고 한다(메모리에 있던 것)
- 시황 제목 첫 수집은 한 쪽뿐이라 배포 당일 오전 소식은 비었다(삼성전자 11:52 전 제목 없음). 지난 30일을 거슬러 받지 않는 것은 맞지만, 그날 하루치는 받을 수도 있었다 — 쪽 상한(5)으로는 안 닿는다
- **레이어 훅 사후 실행이 검사 없이 통과했다** — 훅은 `tool_name: "Write"` 와 본문을 받아야 검사하는데 `file_path` 만 넣어 23파일 전부 exit 0 이었다. 체크리스트에 "위반 0"을 적었고 확인 2회차에서야 알았다. 사후 실행은 **위반 하나를 넣어 exit 2 가 나는지(음성 대조)를 먼저** 본다
- 단계 A 가 "단계 B 에서"로 넘긴 행(VI 30건 초과 세기)을 처음 보고 때 빠뜨렸다 — 착수 때 앞 단계 체크리스트의 "단계 B" 행을 grep 해 범위에 넣는다
- 제공처 이름이 "공시"인 행이 칩 "공시"와 겹쳐 보였다 — 실화면에서 처음 봤다
