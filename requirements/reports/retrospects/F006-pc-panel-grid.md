# F006 PC 격자 — 회고

2026-11-19 · `feat/f006-pc-panel-grid`

## 잘 된 것

- 9월에 만들어 두고 한 번도 실제 화면에 붙지 않은 공용 컴포넌트(`MovableGrid`)를 저장 계약과 함께 붙이자 숨은 결함이 셋 나왔다(가지 id 겹침 · 칸 넘침이 메뉴를 자름 · `Menu` 두 줄 꺾임). 셋 다 같은 브랜치에서 규칙으로 고쳤다
- 413 계약을 실측하다 서버 · BFF 모두 "본문이 너무 큼"이 500 이던 것을 찾았다 — 경계 값을 계약 바깥(100kb)까지 재서 나왔다
- 같은 원인 회색 글자 한 줄(PR #205 가 별칭 `ds.` 를 놓침)을 axe 로 찾아 값 grep 으로 전수 확인했다

## 아쉬운 것

- 첫 변이에서 시험 둘이 결함을 못 잡았다 — 가지 id 시험은 모듈 카운터가 이미 커진 상태라 원래 코드로도 통과했고, 재귀 상한 시험은 다른 검사가 같은 결과를 냈다. 시험이 "결과"만 보고 "원래 결함이 나는 조건"을 만들지 않았다
- zone 빌드 사본(`apps/_b-*`)이 turbo 작업 공간 이름과 겹쳐 전체 검사가 한 번 막혔다 — 사본은 빌드 직후 지우고 검사를 돌린다
- zsh 반복문에서 변수가 낱말로 안 나뉘어 장면 스크립트가 조용히 아무것도 안 했다(오류 없이 "console errors: []" 만) — 장면마다 결과 줄이 있는지 본다

## Action

- 변이 시험은 "고친 줄을 원래 코드로 되돌린 것"으로 한다(임의 값이 아니라) — 이번 M1 처럼
- 공용 컴포넌트를 처음 실제 화면에 붙일 때 메뉴 · 넘침 · 포커스를 실화면에서 먼저 본다
