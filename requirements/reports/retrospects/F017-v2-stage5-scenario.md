# F017 v2 단계 5 시나리오 — 회고

## 잘된 것
- 좋은 숫자를 셋 번 의심했고 셋 다 결함이었다 — 셔플 무효(기준 둔함 + 셔플 샘), 피처 누수 여부(없음 — 미룬 라벨), "59% vs 41%"(늘 안 오른다와 같음). 하나라도 그냥 넘겼으면 화면이 실력 없는 확률이나 오도하는 성적을 말했다
- 사전등록을 결과 뒤에 고치지 않았다 — @1 은 무효로 기록, @2 는 같은 기간을 봤다는 사실을 등록에 적고 화면을 라이브 증명 뒤로 미뤘다

## 문제
- 첫 가설(셔플만 샘)로 @2 초안을 썼다 — 진단이 뒤집었다. 커밋 전이라 막았다. **진단 → 등록** 순서를 지킨다
- 사전등록 기준 (4)를 '늘 오른다' 하나로 둔 게 결함이었다 — 오른 비율이 50% 가 아니면 공짜로 넘는다. 라벨 r > 0 에 그대로가 섞이는 것도 등록 때 보지 못했다
- 라이브 표본을 모델 버전(커밋 해시)으로 세게 짰다 — 배포마다 0. 키로 세게 고쳤다
- 시험 route mock 을 서버 모양으로 써 화면에 'undefined' — mock 은 BFF 출력 모양으로

## 액션
- 확률 시험 사전등록의 기준은 늘 둘 — '피처 없는 같은 모델'(보정까지 같은) · '늘 많은 쪽'. 라벨은 그대로를 따로(예측 규칙 후보 — `modeling-evaluation.md` 개정은 @3 와 같이)
- @3 는 전진 시험만(같은 기간 세 번 봄) — 사용자 결정
