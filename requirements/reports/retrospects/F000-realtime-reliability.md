# F000 실시간 시세 신뢰성 — 회고

- 브랜치: `feat/f000-realtime-reliability` (PR #43, 머지 `2127b3a`)
- 날짜: 2026-09-21
- 체크리스트: `requirements/reports/checklists/F000-realtime-reliability.md`
- 슬라이스: `requirements/specs/in-progress/F000-realtime-reliability-slice.md`

## 1. 무엇을 했나

투자 화면 시세가 **에러 없이 멈추는** 경로 넷을 닫았다 — 기동 때 쌓이는 Upbit 429(`a78ec49`),
두 번째 탭이 첫 탭을 굶기는 연결 키 · 대체형 구독 · 서버 장애 시 0건(`0483f14`), SIGTERM 뒤
살아남는 WS 프로세스(`16f7eba`), 멈춘 값을 "실시간"으로 그리는 헤더(`a76cec1`). 계약 변경이
없어 커밋을 영역별로 나눴고, 영역 하나만 revert 할 수 있다.

## 2. 잘 된 것

**수정 전 값을 먼저 쟀다.** 체크리스트 §2 의 표가 전부 before/after 짝이다 — 같은 토큰 두 소켓
A 5 · B 35 → 56 · 43, B 를 닫은 뒤 A **0** → 41, 서버 꺼짐 0 → 19.5건/초. 고쳤다는 주장이
재현 스크립트에 붙어 있다.

**"만들지 않는다"를 판정으로 남겼다.** `BFF-REQ-010` FR-11 throttle 은 실측 18.9건/초 · 심볼당
≤2.6건/초라 만들지 않았고, "수치가 10배가 되면 다시 본다"는 재검토 조건까지 적었다(§3).

**주장하지 않을 것을 구분했다.** SSR 에서 Next 가 WS 를 여는 문제는 수정 전 코드로 재현하지
못해 "사고를 막았다고 주장하지 않는다"로 적었다(§5).

**고친 자리를 호출부가 아니라 한도의 주인에 뒀다.** 레이트리밋은 프로세스 전체의 것이라
유스케이스 넷이 아니라 `UpbitClient` 에서 출발 간격을 건다(`a78ec49`).

## 3. 틀렸던 것

### 앞선 체크리스트의 "캔들 수집 실패 0건"이 거짓이었다 — `a78ec49`

`SRV-REQ-006` 체크리스트 §12-3 은 한 회차 기동만 보고 0건이라 적었다. 2026-09-18 콜드 스타트는
429 **985건** · 캔들 수집 실패 2건이었고, 983건을 재시도가 줍고 있었다. 재시도는 이미 맞은 429 를
줍는 장치라 레이트리밋 대책이 아니다. 125ms 출발 간격으로 170초 실측 0 · 0 이 됐다(§2, SRV §15).
1초 창 묶음은 27건이 남아 버렸다 — 도착이 몰린다.

> **Action:** 외부 호출 규칙(`salt-server/.claude/rules/workers-external.md` · `ddd-infrastructure.md`
> §6)에 "재시도는 한도 준수가 아니다 — 한도는 **보내기 전에** 지킨다"를 넣는다. 2026-09-22 현재
> 두 문서는 재시도 정책만 말한다.

### 종료 처리 버그를 검증 도구가 찾았다 — `16f7eba`

"연결 끊김" 표시를 보려고 WS 를 죽였는데 **죽지 않았다.** `wss.close()` 는 기존 연결을 닫지 않고
콜백은 연결이 다 끝나야 불려서, SIGTERM 40초 뒤에도 175건을 보내고 있었다. 재배포나 `tsx watch`
재시작 뒤에도 브라우저가 옛 코드 프로세스에 붙어 있었다는 뜻이다.

> **Action:** 없음 — 기능 검증 과정에서 잡혔다. 다만 "프로세스 종료"는 테스트가 없어 회귀하면
> 다시 브라우저로만 드러난다.

### 증상과 원인이 다른 영역에 있었다

헤더가 멈추는 것은 프론트에서 보였지만 원인 셋이 BFF 였다. 프론트만 고쳤으면 "연결 끊김"
문구는 나오지만 두 번째 탭 · 서버 장애 문제는 남았다(§6). Upbit 구독이 **대체형**이라는 것도
문서가 아니라 8초 실험이 알려줬다 — 추가분만 보내던 코드는 타입 · 테스트를 다 통과했다.

> **Action:** `bff/.claude/rules/websocket-worker.md` 는 2026-09-22 현재도 "현재 구독 상태를
> 기준으로 **diff 를 계산한다**"고 적혀 있다 — Upbit 에서는 diff 만 보내면 나머지가 끊긴다.
> "상대 구독 의미(추가형/대체형)를 실측으로 확인하고, 대체형이면 전체 집합을 보낸다"로 고친다.

## 5. 다음에 보완할 규칙 · 문서

- **체크리스트의 "0건"은 회차를 적는다.** 한 번의 운 좋은 기동이 사실로 기록됐다 — 수치 옆에
  관찰 시간·회차를 두는 형식(§2 서버 표처럼)을 기본으로 한다.
- 외부 호출 규칙에 "보내기 전 한도 준수"를, WS 연동 규칙에 "구독 의미 실측"을 넣는다(위 Action).
- Playwright 검증 스크립트를 스크래치패드가 아니라 레포에 남길 자리를 정한다. 지금은 재현 수단이
  세션과 함께 사라진다.
