# 회고 — 가계부 S1e + F4e

## 잘 된 것
- 여섯 갈래에서 새 입력 화면이 필요 없는 것 하나(고정비)를 골라 하루 안에 서버 · BFF · 화면 · 이벤트까지 닫았다. 분류 표를 건드리는 둘(사용자 분류 · 통장 쪼개기)과 규정 확인이 먼저인 것(리볼빙)을 섞지 않았다.
- 후보를 저장하지 않아 지출 지우기 · 고치기와 맞출 상태가 없다. 저장한 것은 사용자가 정한 것(숨김)과 한 번만 낼 것(증가 기록)뿐.
- "매주 가는 카페"를 경계 표에 먼저 넣고 사슬 규칙(앞 고리 = 비슷한 금액의 바로 앞)을 정했다 — 규칙이 사례보다 먼저 나왔다.
- 템플릿으로 옮기면 후보에서 빠지는 것을 새 상태 없이(이름 = 가맹점 키) 했다.

## 아쉬운 것
- 사용자 입력(가맹점)에 조사를 붙인 문구를 썼다 — 실화면에서 "SKT 요금를"로 보고서야 고쳤다.
- FE 주석에 FR 번호를 스펙 확인 없이 적었다(FR-10 은 다른 요구) — 문서 단계에서 발견.
- 종단 테스트 이름의 `%` 가 컴파일 경고(-Werror)로 막혔고, 새 테스트를 `@TestConfiguration` 과 클래스 사이에 끼워 넣어 컴파일이 깨졌다.

## Action
- 사용자 입력이 들어가는 문구는 조사를 붙이지 않는다(문구 검사 때 `${…}[은는이가을를]` 를 grep).
- 코드 주석에 FR 번호를 적기 전에 그 REQ 의 FR 표를 연다.
