# 회고 — 가계부 S1f + F4f

## 잘 된 것
- 다섯 갈래 중 분류 표를 건드리는 둘만 묶었다. 통장 쪼개기를 분류가 아니라 "템플릿인가"로 가르자 내 분류와 서로 엮이지 않았고, S1e "매달 적기로"가 그대로 급여 통장으로 간다.
- V1 이 남겨 둔 자리(`category` 열 CHECK 없음)를 그대로 썼다 — 지출 원장 열 변경 0, 키는 이름이 아닌 난수라 이름 바꾸기가 지난 지출을 건드리지 않는다.
- 묶음 · 고를 수 있나 · 순서를 `CategoryBook` 한 곳에 두고 경계 표 테스트를 먼저 썼다. 흔한 길(기본 분류 · 봉투)은 쿼리 수를 늘리지 않았다.
- 월 화면은 받은 분류 표로 이름을 그려 서버 HTML 부터 맞다 — "내 분류" 대체 글이 서버 HTML 에 0.

## 아쉬운 것
- jOOQ 에서 식을 SELECT 와 GROUP BY 에 같이 쓸 때 상수가 바인드 변수가 되는 것을 몰라 종단 테스트 22건이 한꺼번에 깨졌다.
- 이 레포에 prettier 설정이 없는데 파일 단위로 돌려 손대지 않은 파일이 바뀌었다(메모리에 "파일 단위 prettier 금지"가 있었다).
- V6 주석의 슬라이스 경로를 `in-progress/` 로 썼다가 `done/` 으로 고치느라 로컬 DB 에서 V6 를 되돌리고 다시 적용했다.

## Action
- jOOQ 로 같은 식을 SELECT · GROUP BY 에 쓰면 상수는 `DSL.inline`.
- 프론트 서식은 손으로 — `prettier --write` 를 파일에 돌리지 않는다.
- 마이그레이션 주석의 루트 슬라이스 경로는 처음부터 `done/`(슬라이스는 끝나면 그리로 간다).
