# F004 슬라이스 15 — FE 코치 리포트 — 회고

영역 회고: `salt-microFe/requirements/reports/retrospects/FE-REQ-026.md` · `FE-REQ-027.md` · `FE-REQ-028.md`

- 첫 화면이 "전부 막힘"이라는 것을 알고 만들었다 — 막힘 안내가 오류처럼 보이지 않게(회색 · 다시 시도 없음) 먼저 잡았다
- 사본 타입에서 필드를 **빼는 것**이 가장 싼 게이트였다(후보 목록). 화면 코드에 "그리지 말 것" 주석을 두는 것보다 확실하다
- 폴링 완료 판정은 처음에 "워커 행이면 계속 기다림"이었다 — 테스트를 쓰다 30초 타임아웃으로 끝나는 날이 보여 `settled` 를 더했다
- 효과가 `accepted` 변화에도 돌아 **요청 전 응답**을 첫 폴링으로 셀 뻔했다 — 처리한 응답 시각을 ref 로 기억해 막았다

## Action

- 사용자 스크린샷으로 로그인 상태 화면 · 재생성 · 쿨다운 실측 → 체크리스트 갱신
- 후보 목록 게이트 계약 — PM · BFF 에 질문(FEATURE-004 · BFF-REQ-023 에 기록)
- `staleHours` 임계가 필요하면 서버가 `isStale` 을 준다 — PM 판단

## 후속 (2026-09-23)

- 사용자가 같은 디자인 지적을 여러 번 했다. **참고 화면을 열어 재기 전에는 만들지 않는다**(메모리 `design-reference-standard`)
- 목은 계약이 된다 — 가짜 지출 조회가 진짜 보유 목록을 가렸고, 수화 불일치를 숨기고 있었다
- SEO 를 하며 번들이 +51 kB 됐다가 닫혔다. 서버 컴포넌트의 배럴 import 는 눈에 안 보이는 비용이다 — 빌드 수치를 매번 본다
