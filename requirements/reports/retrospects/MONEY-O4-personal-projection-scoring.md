# MONEY-O4 개인 재무 구간 채점 — 회고 (2026-11-18)

## 잘 된 것

- REQ 문장(이벤트 구독 · 비밀 솔트)을 그대로 짓지 않고 이유부터 다시 읽었다 — 이벤트 본문에 원 사용자 id · 금액이 있어 구독하면 FR-5 를 어기고, 예측은 배치라 상시 소비자도 없다. 레포 규칙(export 뷰 · S3d 해시 식)이 이미 답이었다
- 금액을 스키마 밖으로 내보내지 않으려 가계부 판정을 뷰에서 했고, 판정식이 두 벌이 된 대가를 Kotlin 시험으로 묶었다
- 서비스 시험 DB 가 forecast 마이그레이션 파일을 직접 읽어 GRANT 까지 운영과 같게 했다
