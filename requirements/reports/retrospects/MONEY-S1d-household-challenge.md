# 회고 — 가계부 S1d + F4d

## 잘 된 것
- 일곱 갈래를 다시 나눠 서비스 둘에 걸친 쓰기(아낀 돈 → 저축 목표)를 혼자 두었다. 판단 하나가 리뷰에서 묻히지 않는다.
- 두 서비스 쓰기를 보상 단계 없이 닫았다 — 받는 쪽(저축)이 출처 id 로 멱등, 보내는 쪽(가계부)은 조건부 UPDATE, 순서는 BFF. 재시도가 곧 복구다.
- 금액을 화면 본문에서 받지 않고 원천 기록(가계부)에서 읽었다 — BFF 테스트가 본문 금액 99,999,999 를 무시하는지 본다.
- "실패 없음"을 문서가 아니라 DB CHECK · 응답 낱말 테스트 · 같은 색 카드로 막았다.

## 아쉬운 것
- 종단 테스트가 저축 목표 id 를 응답 최상위(`id`)에서 읽어 경로가 `/goals//…` 가 됐고, 플랫폼이 그 경로에 **401** 로 답했다 — 테스트 실수지만 화면 쪽이었다면 로그아웃으로 읽혔을 응답이다. BFF 에 빈 목표 400 을 넣었다.
- 빈 이름 거절을 도메인 코드로 기대했는데 요청 형식 검사(`@NotBlank`)가 먼저 막았다 — 테스트 기대를 계층에 맞췄다.
- 응답 낱말 금지 검사가 응답 틀(`"message":"success"`)에 걸렸다 — `data` 만 본다.
- 실화면 첫 실행에서 콘솔 400 둘이 났고 다시 재현하지 못했다. 응답 기록 없이 콘솔만 본 첫 스크립트라 어느 요청인지 남지 않았다.

## Action
- 실화면 스크립트는 처음부터 `response` 기록(상태 ≥ 400 의 메서드 · 주소 · 본문 앞부분)을 켠다 — 콘솔 글자만으로는 어느 요청인지 못 찾는다.
- 경로 조각이 사용자 입력이면 BFF 에서 빈 값을 400 으로 막는다(플랫폼은 `//` 에 401).
- 서비스 둘에 걸친 쓰기는 같은 꼴로 — BFF 순서 · 받는 쪽 출처 멱등 · 금액은 원천에서(`bff-architecture.md` §5 에 한 줄).
