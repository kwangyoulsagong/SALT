# F011 국내 탭 요약 띠 회고 (2026-11-02)

## 잘 된 것
- 서버 응답 열 이름을 코인과 같게 두고 뜻을 `changeBasis` · `kind` 로 따로 실어, 프론트 칸 컴포넌트가 prop 셋만 늘었다.
- KIS 응답 원문을 한 번 찍어 고가 · 저가 · 거래대금(이미 오던 값)을 찾았고, 원/달러 TR 을 착수 첫 시간에 찔러 막힌 것을 확인했다.

## 어긋난 것
- 스펙 넷이 출처를 적지 않은 칸(원/달러) · 이미 성립한 FR(5분봉 대상) · 워크스페이스 밖 BFF 의 "같은 타입" · 유니버스 해석 비용을 모른 쿼리 예산을 갖고 있었다.
- 첫 커밋에 앞서 `git rm` 한 프론트 삭제 6개가 DB 커밋에 섞였다 — 커밋 전 `--cached --stat` 를 보고 push 전에 다시 나눴다.
- 프로덕션 빌드가 dev 서버의 `.next` 를 덮어 실화면 오류가 났다(빌드 뒤 dev 재기동으로 해결).

## Action
- 요약 · 표 칸 스펙엔 칸마다 "출처(TR · 테이블)" 열을 둔다
- `git rm` 은 그 영역 커밋 직전에 한다 — 먼저 해 두면 다음 커밋에 섞인다
- 실화면 전 `pnpm --filter web build` 를 했으면 `ops/salt.sh restart web`

## 후속 (2026-11-02)
- 첫 보고 때 실화면을 1600 한 폭만 봤다. 블록을 옮긴 슬라이스는 그 블록의 미디어 쿼리 숨김 조건과 네 폭(1024 · 1280 · 1440 · 1600) 넘침을 재야 한다 — 일정이 1280 에서 사라진 퇴행을 그렇게 찾았다.
- 다른 기능(F008) REQ 를 정정하면 그 기능 기획서 이력도 같이 — 영역 FEATURE 만 적고 빠뜨렸다.

- 원/달러를 "실전 키 때 닫힘"으로 남겼다가 사용자가 "안되는것들은 빼 실전키 안할거니까"로 정리했다 — 실전 키 미사용은 이미 내려진 결정이었다. 막힌 원인이 기존 결정이면 미검증 행이 아니라 범위 제외로 적는다.
