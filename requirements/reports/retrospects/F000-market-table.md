# F000 시세 표 필터·기간 변동률·레이아웃 — 회고

- 브랜치: `feat/f000-market-table` (PR #44, 머지 `f85f982`) · 후속 `fix/f000-market-table-viewport` (PR #47, 머지 `847ab21`)
- 날짜: 2026-09-21
- 체크리스트: `requirements/reports/checklists/F000-market-table.md`
- 슬라이스: `requirements/specs/in-progress/F000-market-table-slice.md`

## 1. 무엇을 했나

기간 7버튼과 오름차순이 **색만 바뀌고 목록은 같았다** — 서버가 `period` 를 읽지 않았고
`MarketOrder.Ascending` 이 빈 문자열이었다. 서버가 기간을 해석해 `periodChange` 를 주고(`4b72c9e`),
BFF 가 422 를 500 으로 바꾸던 것과 빈 캐시 덧씌우기를 걷어냈고(`d959e39`), 프론트가 새 필드를
읽게 했다(`85913fc`). 같은 브랜치에서 1280px 가로 밀림(`decbd23`)을, 후속 PR 에서 세로 스크롤
(FR-53, `0455fac`)을 닫았다.

## 2. 잘 된 것

**"동작한다"를 응답 해시로 판정했다.** 에러가 없는 결함이라 볼 방법이 해시 비교 하나였다.
변경 전 7개 동일 → 변경 후 7개 전부 다름 · 1m asc 도 별도 해시(체크리스트 §2).

**없는 값을 다른 값으로 채우지 않았다.** 기준 시세가 없으면 `periodChange: null` → 화면 "—".
"1년" 버튼이 24시간 값을 보여주는 쪽이 더 나쁘다는 판단이 서버 · 프론트 둘 다에 있다(`4b72c9e`·`85913fc`).
모르는 `period` 도 조용히 실시간으로 떨어지지 않고 422 다.

**앞 회고의 Action 을 닫았다.** 관심 종목 탭 회고가 "`market-overview.service` 캐시가 REST
프로세스에서 조용히 no-op 이다 — 히트율을 관측하라"고 남겼다. 이번에 재서 **0 / 100** 을 확인하고
캐시를 지웠으며 `performance-bff.md` §4 를 "BFF 캐시 없음"으로 고쳤다(`d959e39`).

**원인이 같은 결함 셋을 한 커밋에 묶었다.** 2컬럼 상자 · 뉴스 제목 · 차트 폭이 모두 "세로
FlexBox 자식은 내용 폭"이었다(`decbd23`). 영역별 커밋 넷은 되돌릴 때의 결과까지 §1 표에 적혀 있다.

## 3. 틀렸던 것

### 2026-09-18 반응형 판정이 틀렸다 — `decbd23` · `c9bfc26`

`FE-REQ-010` FR-51(`body` 가로 스크롤 없음)을 375/390/1440 만 보고 닫았다. 1280 에서 문서 폭
1368~1420, 1024 에서도 밀렸다(§2 결함 확인). 사용자 보고로 드러났다. 검수 뷰포트를 5개
(1920·1440·1280·1024·375)로 넓히고 판정을 정정했다(§3 FR-51 · FR-54).

> **Action:** 3뷰포트 검수는 **양 끝만 본다** — 2컬럼이 접히기 직전 폭(1280·1024)을 빼먹는다.
> 2026-09-22 현재 `salt-microFe/.claude/rules/` 에 검수 뷰포트 목록이 없다. 5뷰포트를 규칙으로 둔다.

### 머지 시점에 FR-53 이 미충족이었다 — 후속 PR #47 `0455fac`

PR #44 머지 때 체크리스트는 FR-53 을 **미충족**(표 `80vh` 가 y=315 에서 시작, 900px 화면에서 문서
1195px)으로, "`calc(100vh - N)` 여부 사용자 판단 대기"로 두었다. 같은 날 `max(320px, 100dvh − 395px)`
로 닫았다. 미충족을 표에 적고 머지한 것은 규칙대로지만, 그 대가가 **395px 상수**로 남았다(§4).

> **Action:** 없음 — 규칙대로 기록했고 같은 날 닫혔다.

### 고치는 도중에 같은 결함을 하나 더 만들었다 — `decbd23`

차트 폭을 재는 상자가 세로 FlexBox 자식이라 **재야 할 대상의 폭을 따라갔다**(§6). 넘침을 고치는
측정 장치가 넘침의 원인과 같은 성질이었다.

### 검증 환경이 결함처럼 보였다

dev 서버 둘(3000 · 3100)이 같은 `.next` 를 써서 청크가 깨지고 표가 0행이 됐다(`Unexpected token '}'`).
관심 종목 탭 회고 §4-bis("dev 서버 도는 중 `next build` 로 `.next` 를 깨뜨렸다")와 같은 종류다.

> **Action:** 로컬 실행 메모에 "web dev 서버는 하나만, `.next` 를 공유하는 프로세스를 동시에 띄우지
> 않는다"를 적는다. 두 번 같은 원인으로 시간을 썼다.
