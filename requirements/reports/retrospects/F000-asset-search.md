# F000 슬라이스 — 종목 검색 · 추적 자산 상한 — 회고

영역 회고(주): `salt-server/requirements/reports/retrospects/SRV-REQ-008.md` · `bff/.../BFF-REQ-007.md` · `salt-microFe/.../FE-REQ-010.md` · `FE-REQ-011.md`

## 요약

- **스펙은 한 달 전에 4영역에 다 있었고 코드는 0건이었다** — 그 사이 Q2 가 닫혀 "크립토만 검색" 문장이 낡았다. 스펙을 그대로 구현하지 않고 닫힌 결정을 먼저 반영했다(FR-87 개정)
- **스펙과 코드 관례가 어긋난 곳은 관례를 따르고 스펙을 고쳤다** — `SRV-REQ-009` FR-30 의 422 · 50자 · `change24h` 는 서버 DTO 전부(Zod 400) · 국내 검색(30자) · 국내 등락(전일 대비)과 맞지 않았다. 각각 근거를 FR 행에 남겼다
- **단위 테스트로는 안 보이는 결함을 실화면이 잡았다** — 응답 순서에 따라 별이 "제거"로 굳는 것(표 행 `memoKey`). 첫 실패를 dev 첫 컴파일 지연으로 넘기려 했다가, 대기 없이 반복하자 재현됐다
- **같은 줄을 고치다 기존 결함을 봤다** — BFF 접근 로그가 라우터 아래 요청을 전부 `/` 로 찍고 있었다(`req.url` 은 끝난 시점에 상대 경로). 검색어 가림을 확인하려고 로그를 읽어서 드러났다
- `FE-REQ-011` FR-7(보유 ★ 해제 금지)을 "관심 종목 탭은 남음"으로 적으려다, 서버가 이미 보유 집합을 읽고 있어 행에 `isHeld` 하나로 닫았다

## 실수

- dev 서버(3100)를 띄운 채 `pnpm build` 를 돌려 `.next` 를 덮었다 — 다음 실화면이 500. 코드 결함으로 오인할 뻔했다
- 실검증 스크립트 한 번에 설정 · 측정 · 정리를 반복(loop)하는 명령이 권한에 막혔다 — 단계를 나눠 돌렸다

## Action

- 실화면 확인 중에는 빌드를 돌리지 않는다. 빌드가 필요하면 dev 를 먼저 끄거나 다른 `distDir` — 메모리 `local-fullstack-run` 에 한 줄
- 엔티티 표가 바깥 상태(별 · 선택)를 `render*` 로 받으면 `memoKey` 에도 그 상태를 넣는다 — `TableRow` 는 `memoKey` 만 비교한다. 같은 구조인 `WatchlistTable`(관심 목록 행 자체가 상태라 지금은 안전)도 새 바깥 상태를 꽂을 때 같은 확인
- 새 경로를 확인할 때 로그 한 줄을 실제로 읽는다 — 접근 로그 결함은 그렇게만 보였다
