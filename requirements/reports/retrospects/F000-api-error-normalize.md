# F000 슬라이스 — 웹 API 에러 모양 하나 — 회고

영역 회고: `salt-microFe/requirements/reports/retrospects/FE-REQ-012.md` (주) · 파일만 걸친 13곳은 각 회고 2026-10-28 절

## 요약

- **마스터 인덱스의 "다음 후보"가 이미 닫혀 있었다** — `AssetType` 3값은 F011 슬라이스 0 · 3 이 넓혔고 문서만 그대로였다. 후보를 고르기 전에 코드부터 봤기에 빈 작업을 피했다
- **같은 판정이 11번 복사돼 있으면 그중 하나(전역)는 다르다** — 훅들은 4xx 를 안 불렀지만 기본값을 쓰는 시세 쿼리 전부가 4xx 를 두 번 더 불렀다. 실측으로 4 → 2 요청, 실패 표시 4.2 → 1.0초
- **429 를 재시도 대상에서 뺀 것은 동작 변경이다** — 전에는 전역에서 1초 뒤 다시 불렀다. 서버가 정한 시각을 앞당기는 재시도였다
- 실측 중 서버의 **모르는 코인 차트 500** 을 봤다 — 어제 404 로 고친 가격 · 감성과 같은 원인인데 차트 경로만 남았다. 서버 범위라 기록만 했다
- 포트 3000 은 다른 프로젝트(vite)였다 — 띄우기 전 `lsof` 로 확인하고 3100 을 썼다

## Action

- 사용자 지시 시: 서버 차트 경로 Upbit 404 → `MARKET_SYMBOL_NOT_FOUND` 404 (`SRV-REQ-009` 후속)
- 새 슬라이스 API 는 `throw await readApiError(response, "<이름>")` — `api-convention.md` 에 적었다. 클래스를 새로 만들면 리뷰에서 막는다
