# F010 슬라이스 0 — 성적표 신뢰성 — 회고

영역 회고: `salt-server/requirements/reports/retrospects/SRV-REQ-024.md` · `salt-forecast/requirements/reports/checklists/FC-REQ-001.md` §미검증

- **가장 큰 결함은 리서치가 아니라 실 DB 한 줄이 찾았다.** 감사는 "5분봉 RSI 가 잡음"이라 했는데, 실제로는 지표가 **한 번도 계산된 적이 없었다**(캔들 `5m` · `1d` 를 지표 이름 `m5` · `h1` 로 조회). 코드만 읽으면 "지표가 있다"고 믿게 된다 — 성적 · 판단을 다루는 슬라이스는 시작할 때 `SELECT count(*)` 를 먼저 친다
- 그 결과 지금까지 쌓인 live 판단 표본은 전부 "지표 없는 판단"이었다. 표본을 지우지 않고 남긴 것은 맞지만, 성적표에 **"이 표본은 지표 없이 낸 판단"** 표식이 없다. 슬라이스 1(원장 통합)에서 판단 시점의 재료 스냅샷을 행에 같이 남겨야 이런 표본을 나중에 가를 수 있다
- 채점 경계를 바꾸면(0 → 0.1%) 기존 행을 **재판정하는 마이그레이션**이 규칙을 SQL 로 한 번 더 적는다. 규칙이 두 곳이다 — 다음부턴 `return_rate` 만 저장하고 `outcome` 은 읽을 때 정책 함수로 만드는 쪽이 낫다(지금은 SQL 집계가 `outcome` 컬럼을 센다)
- "표본 1건이면 통과"(FR-32) 같은 임시안은 계약 enum 에 흔적이 없어 폐기할 때 BFF 가 모르는 사유를 "계약 깨짐"으로 처리한다. 사유 enum 을 늘리는 변경은 **서버 · BFF · core 를 같은 커밋 묶음**에서 — 이번엔 지켰다
- 병렬 에이전트(예측 · 요구사항)와 같은 브랜치에서 작업하면 마스터 인덱스처럼 **한 파일을 둘이 만지는 지점**이 생긴다. 이번엔 인덱스 편집을 에이전트 종료 뒤로 미뤘다. 다음엔 시작 전에 "누가 어느 파일"을 적는다
- zsh 에서 `echo ======` 가 `=cmd` 확장으로 죽어 조사 명령 절반이 조용히 빠졌다 — 구분선은 `-----`

## Action

- 슬라이스 1: 판단 · 추천 행에 재료 스냅샷(지표 주기 · 값 · 결측 목록) 저장 → "지표 없는 표본" 필터
- 슬라이스 1: `outcome` 을 저장 컬럼이 아니라 읽기 시 정책 함수로(집계는 `return_rate` 경계로)
- 머지 뒤 워커 1회차 로그에서 `추천 스냅샷` · `지표 m5/h1/d1` 행 수 확인
