# MONEY-S1b — 회고

## 잘된 것

- 남은 FR 을 "원천이 있는가"로 갈랐다 — 물가 · 제도 · 공동 · 가계부는 다른 서비스 · 데이터가 먼저라 빼고, 이 서비스 안에서 닫히는 일곱만 끝까지(서버 · DB · BFF · UI · 화면)
- 재미 넷 중 둘(도장 · 엽서)은 표를 만들지 않았다 — 계산값을 저장하지 않으면 갈라질 자리가 없다
- 실측이 결함 하나(저울 확정 뒤 성공 문구 사라짐), 줄인 모션 측정이 "스크린샷만 찍고 검증했다고 쓸 뻔한 것"을 막았다

## 문제

- 스펙 FR-19(목록 쿼리 3회)를 구현 뒤 문서 쓸 때 봤다 — 착수 때 FR 표의 성능 줄을 먼저 읽는다
- 독립 리뷰가 10건을 찾았다: 형식 검증이 도메인 사유 코드를 가림 · 같이 보이는 두 숫자(상환 · 이자)가 다른 값에서 나옴 · 기한 목표 확정 · 잠금 전 읽기 · 상수 복사 · 집계 세 벌. 전부 테스트가 통과한 뒤에 나왔다
- 규칙 문서(`motion.md`)와 스펙 문서가 코드 수정 커밋에 섞였다 — `git add <영역>/` 대신 경로로 스테이징

- **문제(셸 경유 실측)**: 리뷰 3번(상환 · 이자 불일치)을 고치며 "이자 = 올린 상환 × n − 원금"으로 바꿨더니 금리 0% 에 이자 8원이 나왔다 — 리뷰 지적을 고친 코드도 경계값(0%)으로 다시 잰다. 이자는 정확값, ~~차액은 마지막 달(실제 상환 방식)~~ 총액을 n 달에 나눔(재정정 `af797be0`)
- 테스트 스크립트를 문자열 치환으로 고치다 다른 단계 금액까지 바뀌어 거짓 실패가 났다 — 상태가 쌓이는 실측 스크립트는 단계마다 지금 값을 읽어 정한다

- **문제(두 번째 리뷰)**: 셸 실측 결함을 "마지막 달이 차액"으로 고친 것을 리뷰(high)가 다시 8건 잡았다(나머지에 따라 거절 · 1개월 두 금액 · 대출 실패가 꺼내기를 지움 · NaN). 고친 코드에도 리뷰를 다시 돌린다 — 이번엔 돌렸고 그래서 잡혔다

- 3차 리뷰(재설계분) 7건: 6건 수정 · 1건 사실 아님. 4차 9건: 3차 수정이 X.5원 꼬리 오차를 되살렸다 — 서로 당기는 지적은 경계 테스트부터. 5차 10건: 4차 입구 검사가 화면 퇴행(문구 없음 · 입력칸)을 만들었다 — 서버 계약을 바꾸면 화면 문구 · 입력을 같은 커밋 묶음에서. 6차 9건: 한 호출처만 고치면 같은 원인이 다른 호출처에 남는다. 7차 10건: 6차가 더한 이유 값이 이벤트 계약에 없어 적립이 500 — 값을 더하면 계약 · 종단까지. 8차 9건: 한 칸만 막아 같은 공용 함수를 쓰는 칸이 다 남았다 — 원인 함수에서.
- **문제(전체)**: 리뷰를 8번 돌았고 그중 상당수가 직전 수정이 만든 결함이었다. 대출 분할 · 입력 정리처럼 경계가 많은 칸은 처음에 불변식 · 경계 테스트 표부터 쓰고 구현한다 규칙 문서(중간 반올림 금지)가 S1a 부터 코드와 어긋나 있던 걸 이번에 적었다
