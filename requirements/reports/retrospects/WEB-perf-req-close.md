# 데스크톱 기능 닫기 — 성능 · 마이그레이션 REQ 정리 회고

2026-11-19 · `feat/web-perf-close`

## 잘 된 것

- 9월 문서를 "만들 목록"으로 읽지 않고 FR 마다 지금 코드와 대조했다 — 18개 문서의 FR 대부분이 나중 결정(LLM 0 · 홈 카드 · 알림 Kotlin · 예측 배치 · 스냅샷 원장)으로 이미 대체돼 있었고, 실제로 남은 일은 결함 하나 · 작은 수정 넷 · 측정이었다
- 대조 중 피드백 행이 최신 추천을 가리는 잠복 결함을 찾았다 — 웹이 안 부르는 경로라 화면 확인으로는 영영 안 나왔을 것이다. 같은 원인 조회 셋(최신 · 이력 · 점수 재료)을 한 번에 막았다
- 측정 없이 넣은 memo 를 측정 근거가 없어 다시 뺐다 — 규칙(§0)대로. 대신 "뺀 상태로 긴 프레임 0"을 실측으로 남겼다
- 로그아웃 측정에서 차이가 안 보이자(위젯을 안 불러서) 실로그인으로 다시 재서 거래 시트 효과(−8.6 kB)를 확인했다

## 아쉬운 것

- 첫 zone 빌드를 dev 서버가 쓰는 폴더에서 돌려 투자 zone dev 를 잠깐 500 으로 만들었다 — 메모에 "복사본에서"라고 적혀 있었는데 측정을 서두르다 놓쳤다
- 서버 쪽 Bash 일괄 수정이 권한 분류기에 막혀 같은 수정을 편집 도구로 다시 했다 — 여러 곳을 한 번에 바꾸는 파이썬 치환은 서버 코드에 쓰지 않는다

## Action

- zone 운영 빌드는 처음부터 `rsync … apps/<zone>-perfcopy/` 사본에서 `npx next build` — dev 가 도는 폴더에서 `pnpm --filter <zone> build` 를 부르지 않는다
- 오래된 성능 REQ 를 닫을 때는 "FR 대조(충족 · 대체 · 남은 일) → 남은 일만 구현 · 실측" 순서를 그대로 쓴다 — 대조 없이 문서대로 만들면 이미 대체된 설계를 다시 짓는다
