# 회고 — 가계부 S1g + F4g

## 잘 된 것
- 셋 중 Should 하나만 잘랐다. 이야기 카드는 지금까지 쌓은 기록을 읽기만 해 새 표 · 이벤트 · 쓰기 경로가 0 이었고, 인덱스 하나로 끝났다.
- 줄을 고르는 규칙(값이 없으면 빠짐 · 같은 합이면 표 순서 · 스티커 뒤 지출 날 빠짐)을 `StoryRules` 한 곳에 두고 경계 표 테스트부터 썼다. 볼 수 있는 날은 월 마감 상수를 그대로 써서 두 화면이 같은 날에 열린다.
- 화면 카드와 공유 이미지가 같은 함수(`storyText`)에서 문장을 받는다 — "보이는 그대로 나간다"가 구조로 지켜진다.
- 실데이터 카드 값을 손으로 다시 계산해 맞췄다(59.5% → 59).

## 아쉬운 것
- 첫 실화면에서 같은 이름 영역 둘이 또 나왔다(S1f 확인 단계와 같은 종류) — 영역 이름을 페이지 제목에서 그대로 가져왔다.
- 문장 조각을 줄로 묶는 곳에 `flatMap` 을 써서 줄이 한 줄로 납작해질 뻔했다(타입은 통과 — 쓴 직후 다시 읽어 잡음).
- V7 주석 경로를 또 `in-progress/` 로 썼다 — S1f Action 에 적어 둔 것을 지키지 못해 로컬 V7 을 되돌리고 다시 적용했다.

## Action
- `nav` · `section` 의 `aria-label` 은 그 페이지 `h1` 과 다른 낱말로 — 쓸 때 접근성 트리에서 같은 이름을 grep.
- 마이그레이션 첫 줄을 쓰기 전에 직전 V 파일 머리를 복사해 시작한다(경로가 `done/` 으로 따라온다).

## 2026-11-05 — 확인 단계

- 첫 실화면은 공유 시트를 "받음 · 닫음 · 실패" 셋으로 흉내 냈지만, 실패 뒤 사용자가 무엇을 얻는지는 묻지 않았다 — 실패 문장만 맞추고 끝났다. 코드를 다시 읽어 거절 → 저장으로 고쳤다.
- "FR-4 전부 닫힘"을 이번 슬라이스 몫만 보고 썼다 — 다음 슬라이스(S1h)의 짝 경로를 세지 않았다.
- **Action**: 실패 분기는 "문장이 맞나"가 아니라 "사용자가 원하던 것을 다른 길로 얻나"로 확인한다. 영역 REQ 를 "전부 닫힘"이라 쓰기 전에 남은 슬라이스의 짝 FR(서버 · FE)을 grep 한다.
