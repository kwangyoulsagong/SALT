# F000 관심 종목 탭 — 회고

- 브랜치: `feat/f000-watchlist-tab`
- 날짜: 2026-09-18
- 체크리스트: `requirements/reports/checklists/F000-watchlist-tab.md`

## 1. 무엇을 했나

`/investments` 의 "관심 종목" 탭이 눌러도 빈 화면이었다. 서버에 watchlist CRUD 가 있고
BFF 가 프록시하는데 **화면이 그 경로를 부르지 않았다.** 그 한 줄을 서버 → BFF → 프론트로
이었고, 커밋 네 개로 나눴다(슬라이스 문서 · 서버 · BFF · 프론트).

## 2. 잘 된 것

**영역별 REQ를 슬라이스 문서로 다시 묶은 것.** F000 의 REQ 는 종류별(UI·FUNC·API·PERF)로
쪼개져 있어서 "관심 종목 탭"이라는 하나의 가치가 REQ 세 개에 흩어져 있었다. 어느 FR 이
범위이고 어느 FR 이 아닌지를 먼저 적으니 커밋 경계와 "미충족" 표가 그것을 그대로 따랐다.

**계약의 소유자를 층마다 다르게 둔 것.** 서버는 도메인 계약(`priceUpdatedAt` 을 주고
신선도 판정은 부르는 쪽에 맡긴다), BFF 는 화면 계약(`priceStale` 불리언 하나로 접는다),
프론트는 표시만 한다. 덕분에 "지연"의 정의를 바꿀 때 고칠 자리가 BFF 한 곳이다.

**별 동기화를 코드가 아니라 쿼리 키로 푼 것.** 두 탭이 같은 키를 보고 mutation 이 그 키만
무효화한다. 동기화 코드가 0줄이다.

## 3. 틀렸던 것

### 번들을 53 kB 키웠다가 측정으로 잡았다

위젯 `model/index.ts` 에 `previewParams` 를 올렸는데 그 파일이 `@/entities/market` barrel 을
import 한다. barrel 을 쓰는 `MarketBoard` 는 페이지가 정적으로 가져오므로, **프리뷰·차트가
전부 First Load 에 들어왔다** — `/investments` 125 → 178 kB.

`FE-REQ-009` 회고가 같은 함정을 이미 기록했고(`ui/index.ts` 주석), 그 주석은
**"dynamic 으로 부르는 잎을 barrel 에 올리지 마라"** 였다. 내가 올린 것은 잎이 아니라
상수 파일이었고, 그래서 그 경고를 내 상황에 연결하지 못했다.

> **Action:** 규칙 문장을 "잎"이 아니라 **"무엇을 import 하는 파일이냐"** 로 다시 쓴다 —
> *barrel 에 올리는 파일이 무거운 barrel 을 import 하면 그 무게가 전파된다.*
> `fsd-widgets.md` 또는 `performance-frontend.md` §7 에 한 줄로 넣을 값이 있다.

### API 응답만 봤으면 통과로 읽었을 결함이 있었다

주식에 업비트 로고 URL 을 붙여 `logos/AAPL.png` 404 가 화면에 깨진 이미지로 나갔다.
JSON 만 보면 `logoUrl` 에 문자열이 들어 있으니 정상으로 보인다. **브라우저를 열어야만
보이는 것이 있다.**

> **Action:** 화면이 붙는 슬라이스의 체크리스트에는 **스크린샷 근거**를 필수로 둔다.
> 이 레포는 이미 `FEATURE-000` 검증 계획 1번이 before/after 스크린샷을 요구한다 —
> 신규 화면에도 같은 것을 적용한다.

### `priceStale` 을 캐시 적중으로 판정하려다 되돌렸다

처음 설계는 "실시간 캐시에 있으면 fresh, 없으면 stale" 이었다. 그런데 **구독을 부르는 것은
`price-updater.worker` 이고 그건 별도 프로세스**라, REST 만 띄우면 캐시가 비어 전부 "지연"이
된다. 코드를 쓰기 전에 `market-overview.service` 가 같은 캐시를 쓰는 것을 읽다가 발견했다.

기존 코드(`market-overview.service`)는 **지금도 그 문제를 안고 있다** — REST 프로세스에서
`getPriceCache()` 가 비어 있으면 보정이 조용히 no-op 이 된다. 실패가 아니라 "보정이 안 된"
상태라 아무도 모른다.

> **Action:** `BFF-REQ-010`(F000 PERF)에서 **캐시 적중률을 관측 항목으로** 넣는다.
> 0% 가 정상으로 보이는 코드가 이미 하나 있다.

## 3-bis. 범위가 두 번 넓어졌다 — 그때마다 드러난 것

사용자가 "미충족 다해"로 범위를 넓히면서 `FE-REQ-010` 의 나머지 수리 9건까지 닫았다.
그 과정에서 **죽어 있던 경로 셋**이 드러났다. 셋 다 "화면이 없어서 아무도 안 불렀다"가
원인이다.

| 죽어 있던 것 | 어떻게 드러났나 |
|---|---|
| `ListWatchlist` 가 `Decimal` 을 문자열로 내보냄 | 탭을 채우려고 처음 소비했을 때 |
| `/portfolio/internal/update-prices` 를 아무도 안 부름 | 홈 "주식" 섹션이 0원만 나와서 |
| 목표 추가 제출이 `console.log` | FR-9 이 "연결됐는지 검증하라"고 해서 |

> **소비처가 없는 계약은 검증되지 않는다.** 세 경로 다 빌드·타입체크·lint 를 통과하고
> 있었고 테스트도 막지 못했다. 화면을 붙이는 순간 전부 드러났다.

### UI 는 스크린샷으로만 잡힌다

두 번 사용자가 화면을 보고 되돌리라고 했다 — **선택 행의 보라색**(팔레트 밖 색을 `@repo/ui`
변형에서 가져왔다)과 **뉴스 제목이 안 잘리는 것**(링크를 감싸면서 `<a>` 가 `inline` 이라
`width:100%` 가 내용 폭이 됐다). 둘 다 타입체크·lint·테스트를 통과한다.

> **Action:** 화면이 붙는 커밋은 스크린샷을 근거로 남긴다. "API 응답이 맞다"는 화면이
> 맞다는 뜻이 아니다 — 주식 로고 404 도 같은 종류였다.

### 번들은 두 번 깨졌고 두 번 측정이 잡았다

`previewParams` 를 barrel 에 올려 `/investments` 를 125 → 178 kB 로, 새 호출에 `axios` 를
써서 `/home`·`/goals/addgoals` 를 +23·+35 kB 로 만들었다. 둘 다 **기능은 정상**이라
측정하지 않았으면 그대로 머지됐다.

> **Action:** `pnpm build` 의 Route 표를 커밋 전에 한 번 본다. 이미 `FE-REQ-009` 회고가
> 같은 말을 했고 이번에 두 번 더 필요했다 — 규칙이 아니라 **습관의 문제**다.

## 4-bis. 도구가 만든 오차

- **3px 초과로 보이던 것이 측정 도구의 테두리였다.** iframe 에 `border: 2px` 를 줬고
  그만큼 뷰포트가 줄었다. 테두리를 없애자 375px 에서 정확히 0 이 됐다.
- **포트 3000 을 다른 프로젝트가 점유**하고 있었다. 우리 Next 는 `[::1]:3000` 에만 붙어서
  `curl`(IPv4)은 남의 앱을, 브라우저(IPv6)는 우리 앱을 받았다 — 같은 URL 이 다른 답을 줬다.
- **`next build` 를 dev 서버가 도는 중에 돌려 `.next` 를 깨뜨렸다.** 500 이 떴고 원인을
  찾는 데 시간이 들었다.

> **Action:** 검증 환경의 오차를 결과에 섞지 않는다. "화면이 이상하다"를 만나면
> **코드를 의심하기 전에 무엇을 보고 있는지** 확인한다.
