# F011 슬라이스 0 · 1 회고 — 국내 주식 시세 기반 + 실시간 (2026-10-07)

## 결과가 기대와 달랐나

- 기획은 국내 주식 시세를 `MarketAsset` 에 넣는다고 했다. 코인 쿼리를 따라가 보니 자산군을 거르는 곳이 거의 없었다 —
  넣었으면 업비트 상폐 처리가 6시간마다 국내 주식을 끄고 비소유자 시장표에 섞였을 것이다. 표를 나눴다
- KIS 휴장일 조회가 이 키로 거부됐다(`EGW02004`). 같은 키로 시세 · 분봉 · WS 는 된다 — 일봉 역산으로 지난 휴장을 맞췄다(2026년 14일 전부 일치)
- 문서상 20건/s 한도가 이 키에는 맞지 않았다. 6건/s 에서도 50건 묶음마다 초과가 났다
- 9/30 부터 남은 개발 서버 5개가 같은 키를 쓰고 있었다. 처음엔 초과 응답이 내 코드 탓인 줄 알고 속도를 낮춰 봤는데 오히려 나빠졌다 — 측정이 오염돼 있었다
- 원시 SQL 시각이 9시간 어긋났다. DB 세션 시간대가 `Asia/Seoul` 이었다. API 응답을 눈으로 보다 잡았다(`00:00Z` 일봉)

## 잘한 것

- 마스터 파서를 공식 파이썬 결과와 숫자로 대조했다(거래정지 · 관리 수 · 삼성전자 시총) — 필드 인덱스 off-by-one 을 실물로 잡았다
- 주문 TR 을 거부 목록이 아니라 허용 목록 + 레포 grep 테스트로 막았다
- 5분봉을 KIS 1분봉과 종가 대조해 수용 기준을 숫자로 닫았다(30봉 0.0000%)
- 순차 → 동시 6 으로 바꾼 뒤 실패가 늘자 원인을 프로세스 목록까지 따라갔다

## 아쉬운 것

- 처음 마이그레이션을 정밀도 규칙(`Decimal(38,10)`) 확인 없이 만들었다 — 커밋 전 로컬에서 다시 만들었다
- 거부된 TR 을 재시도 3회씩 불렀다(KIS 가 업무 오류를 500 으로 준다는 걸 몰랐다)
- 장 마감 보정 · 5분봉 1년 백필 · provider 상태 지표는 이번에 못 했다
- 미래 휴장(10/9 한글날)은 당일 09:10 전까지 모른다

## Action

- 영역 회고: `salt-server/requirements/reports/retrospects/SRV-REQ-040.md` · `DB-REQ-033.md`
- 원시 SQL 로 시각을 쓰는 다른 곳이 있는지 grep(`::timestamp`) — 같은 9시간 문제가 숨어 있을 수 있다
- KIS 고객센터에 휴장일 조회 TR 권한 문의(사용자) — 풀리면 미래 휴장이 닫힌다
- 개발 서버는 띄운 세션이 끈다(메모리 규칙) — 이번 세션 끝에 내가 띄운 서버를 끈다
