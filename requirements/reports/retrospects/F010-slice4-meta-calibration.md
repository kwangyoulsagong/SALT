# F010 슬라이스 4 회고 — 메타 모델 · 보정 (2026-09-29)

영역 회고: `salt-forecast/requirements/reports/retrospects/FC-REQ-011.md`

## 결과가 기대와 달랐다

리서치는 메타 모델 + Beta 보정으로 "확률 표시 자격"을 기대했다. 순위(AUC 0.65)는 나왔지만 확률로는 그 시점 기저율을 못 이겼다(BSS CI 0 포함).
라벨 분산의 대부분이 **시점**(시장 전체가 익절에 닿기 쉬운 날인가)이고, 종목 간 순위 정보(RES)가 보정 비용(REL)보다 작았다. 규칙 점수 혼자는
이 라벨에 거의 정보가 없었다(AUC 0.525) — 1차 신호가 약하면 메타라벨링의 이점이 작다는 리서치의 경고가 그대로다.

사전등록 넷 중 셋(국면 게이트 · 이벤트일 축소 · 보정 확률)이 "못 넘음"이다. 이 기능의 가치가 "새 숫자를 보이는 것"보다
"보일 자격이 없는 숫자를 막는 것"에 있다는 슬라이스 1 의 결론이 한 번 더 확인됐다.

## 잘 된 것

- BSS 하한을 기준으로 먼저 적어 두어, AUC 0.65 앞에서 "확률을 내도 되지 않나" 대화가 필요 없었다
- 셔플 점검 실패 → 사전등록대로 원인부터 → 진단 3종을 코드에 넣어 재현
- 서버 · BFF · 화면을 건드리지 않았다 — 채택 전에는 계약도 만들지 않는다

## 아쉬운 것

- 셔플 점검을 풀링 AUC 로 정의한 등록 문구 오류(결론은 BSS 로도 같다)
- 첫 리포트를 코드 커밋 전에 만들어 실행 해시가 틀렸다 → 재실행

## `@2` 뒤

사용자 "베스트 케이스로" → 원인 진단에서 나온 가설 하나로 `@2` 를 결과 전에 등록해 다시 쟀다. 종목 간 순위 정보는 실재했지만 확률로는 역시
기저율을 못 이겼다. 두 번 다 문턱을 만지지 않았다. 확률은 새 표본(라이브 원장)이 생길 때까지 등록하지 않는다.
