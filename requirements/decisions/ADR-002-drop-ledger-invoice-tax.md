# ADR-002 — 원장 · 청구서 · 세금(F001 · F002)을 제품에서 뺀다

- 상태: **채택 (사용자 결정)**
- 날짜: 2026-09-21
- 대체하는 것: 글로벌 플랜 §0(네 가지 중 "마감일"·"회계") · §3("회계에 걸어야 하는 이유") · §4(자산군 3개 세금 엔진) · §9~10(P1·P2 순서와 12/29 하드 마감)
- 영향 목록: 아래 §4

## 1. 결정

**FEATURE-001(개입 청구서 · 원장)과 FEATURE-002(연말 세금 마감 콕핏)를 제품 범위에서 뺀다.**
영역 REQ 40건(`DB-005`~`012` · `SRV-012`~`019` · `BFF-011`~`018` · `FE-014`~`021` ·
`RN-008`~`015`)과 PM 기획서 2건을 **삭제한다**(사용자 결정 — 보관 폴더를 두지 않는다).

> 사용자 결정(2026-09-21): *"이런 기능은 없애도 되자나 우린 돈을 잘 버는 걸 도와주는 거지"*

## 2. 왜

- **제품의 한 줄이 바뀌었다.** 글로벌 플랜 §0 은 SALT 를 추천 · 한 숫자 · 마감일 · 회계
  네 가지로 정의했다. 사용자가 고른 것은 **"돈을 잘 벌게 돕는 것"** 이고, 세금 마감과
  과거 개입의 회계는 그 목표의 주변부다 — 잃은 것을 세고 새는 것을 막는 쪽이다.
- **두 기능이 가장 비싼 선행 조건을 요구했다.** 둘 다 결제일 · 환율 · 자산군 3종이 들어간
  수기 원장(`F001`)을 전제한다. 그런데 F001 영역 REQ 20건은 2026-09-08 "계좌 연동 제외"
  결정 **전** 설계(CSV · 업비트 키 · KIS)로 쓰여 있어 착수 가능한 상태가 아니었다
  (2026-09-21 감사). 다시 쓰고 만들고 나서야 세금 · 청구서가 시작된다.
- **코드가 없다.** 서버에 `ledger` · `counterfactual` · `tax` 모듈이 없고,
  `apps/web-tax` 는 zone 자리표시 화면 하나다. 지금 빼는 비용이 가장 싸다.

## 3. 버리는 것과 남기는 것

| | 판정 |
|---|---|
| 반사실 3트랙 · 거래별 가격표 · 잔차 0 항등식 (F001) | **버린다** |
| 세금 D-Day · 손실 수확 솔버 · 환율 함정 · 크립토 스텝업 · 증빙 (F002) | **버린다** |
| 결제일 · 거래 환율 · 신고 잔고 · 수기 현재가 (원장 확장 필드) | **버린다** |
| **보유 기록** | **남긴다 — 기존 `PortfolioTransaction` 그대로.** AI 코치(비중 · 손절 · profit-plan)와 포지션 화면이 평단 · 수량을 필요로 한다. 서버 `POST/PATCH/DELETE /api/portfolio/transactions` 가 이미 있다. 원장 확장(결제일 · 환율 · 반사실)은 하지 않는다 |
| 알림 "세금 D-Day" | **버린다.** F006 FR-50 의 2종 중 하나가 빠져 **1종(지표 · 추천 갱신)** 이 된다 |
| 홈 블록 ④ 세금 D-Day · ⑤ 청구서 한 줄 | **버린다.** 홈 블록 구성은 F006 에서 다시 정한다 |
| 자산 탭 세그먼트 `청구서` · `세금 요약` | **버린다.** 자산 탭은 `포지션` 중심이 된다 |
| `apps/web-tax` zone · `/tax` rewrite | **이 ADR 로는 지우지 않는다.** Multi-Zones(ADR-001)의 유일한 zone 경계가 세금이었다. zone 을 걷을지 다른 경계로 쓸지는 아키텍처 결정이라 별도로 한다 — §5 |

## 4. 영향 목록

| 문서 | 바뀌는 것 |
|---|---|
| 글로벌 플랜 §0 · §3 · §4 · §9 · §10 | 이 ADR 이 대체한다고 머리에 적는다. 본문은 기록으로 둔다 |
| 마스터 인덱스 매트릭스 | F001 · F002 행을 **폐기**로. P1 · P2 가 비고 P3(F003 · F004 · F006)가 다음이 된다 |
| `FEATURE-006` | 홈 블록 · 자산 세그먼트 · 알림 2종 · 온보딩 "계좌 연결" 단계 |
| `FEATURE-000` | FR-34/35(`AssetType` 3값 · KIS)의 근거가 세금 규칙 차이였다 — 열린 질문으로 |
| `FEATURE-003` · F003 REQ | "원장 sync 자동 매칭"(`FE-REQ-023` FR-33 등) — 원장이 없으므로 수동 체크만 |
| `FEATURE-007` · F007 REQ | 세금 D-Day 푸시 |
| F006 영역 REQ | 위와 같은 항목을 각 REQ 머리에 표시 |

## 5. 열어 둔 것

- **`apps/web-tax` zone.** 세금이 빠지면 zone 이 서비스할 경로가 없다. 선택지: ① zone 을
  걷고 단일 앱으로(ADR-001 의 Multi-Zones 구조는 유지 가능 — zone 이 하나일 뿐) ② 다른
  기능을 zone 으로. 결정 전까지 코드는 그대로 둔다.
- **자산군 3종(`AssetType` · KIS).** 세금 차이가 주된 근거였다. AI 코치가 국내 · 미국 주식을
  다룰지에 따라 남기거나 뺀다.

## 6. 되돌리려면

REQ 42건은 git 이력에만 있다. 이 ADR 이 들어간 커밋의 부모에서 꺼낸다
(`git log --diff-filter=D --name-only -- '*F001*' '*F002*'`). 되살리면 F001 영역 REQ 는 **수기 원장 기준으로
다시 써야 한다**(2026-09-21 감사 결과 — CSV · API 키 전제가 남아 있다).
