# FEATURE-009: 1인 펀드매니저 코치 — 계획 · 사이즈 · 행동 미러 · 복기

## TL;DR

- **다음에 만들 것은 "더 잘 맞히는 AI"가 아니라 "내 행동과 내 위험을 숫자로 보여주는 코치"다.** 개인투자자 손익의 원인은 종목 선택이 아니라 행동(회전율 · 처분효과 · 추격 · 물타기 · 사이즈)이고, 이 증거는 대규모 계좌 데이터로 여러 나라에서 재현됐다. 근거: `requirements/reports/research/2026-09-24-fund-manager-coach.md` §2.
- 사용자가 **이미 적는 것**(종목 · 평단 · 수량 — 수동 입력, 계좌 연동 없음) 위에 **최대 2개**(손절가 · 한 줄 이유)를 선택으로 더 받고, 나머지는 전부 서버가 계산한다: 이 크기가 내 손실 예산에서 몇 %인지, 지금 변동성이면 비중이 얼마가 맞는지, 계획을 지켰는지, 익절은 며칠 · 손절은 며칠 들고 있었는지, 그냥 들고 있었으면 얼마였는지, 실수에 얼마를 썼는지.
- **앱은 사용자를 통제 · 차단하지 않는다**(2026-09-08 사용자 결정 — 서약 카드 · 쿨다운 타이머 제외). 개입은 **측정 · 미러 · 계산기 · 기록**까지다. 알림은 정보이고, 어떤 입력도 강제하지 않는다 — 손절가를 안 적으면 R 지표가 "계산 불가"로 보일 뿐이다.
- Codex Astra 조사(같은 날)와 한 몸이다: 신뢰성 수정 **C01~C06** 이 먼저고(`feature-audits/2026-09-24-ai-investment-deep-research.md`), 판단 기록 **W06** · 금액 시뮬레이터 **W03** · 위험 지도 **W02** · 논지 모니터 **W05** 는 이 기획서의 FR 로 흡수한다(`specs/in-progress/ai-investment-workbench-design.md`). 리서치 메모 **W01** · 전략 연구실 **W04** 는 `FEATURE-008` 쪽이다.
- 숫자는 서버 · 문장은 LLM(템플릿 기본) · 주문 경로 없음 · 명령형 0건 · 3종 고지 상시. **개인 보유 · 평단 · 수량은 LLM 프롬프트에 넣지 않는다**(한국 유사투자자문 "개별성" 선 — 리서치 §5).
- **쉬워야 한다**(사용자 요구 2026-09-24). 새 화면을 늘리지 않는다 — 기존 종목 상세 · 포지션 · 코치 리포트 안에 카드로 들어간다. 거래 1건 입력 30초 이내. 예쁘고 접근성이 쉬운 UI — 참고 화면 실측 · `packages/ui` 토큰 · WCAG AA.

## 배경과 문제

- SALT 는 "시장이 어떻게 될까"에는 정직한 답을 갖췄다(변동 범위 + 채점 + 기준 대비 + 빗나간 사례, `FEATURE-008`). **"내가 어떻게 행동하고 있나 · 얼마를 걸어야 하나"에는 아직 답이 없다.** 코드 인벤토리(리서치 §1-2): 포지션 사이징 없음 · 포트폴리오 위험 없음 · 일지 없음 · 계획 대비 실행 없음 · 벤치마크 대비 없음 · 회전율 없음. `riskTolerance` 는 저장만 되고 아무 데서도 읽지 않는다.
- 지금 행동 코치(`behavior.ts`) 는 과매매 · 패닉 · 추격 3규칙을 **알림**으로 준다. 실험 증거는 "알림만 주는 조건은 처분효과 감소 효과가 0" 이다(리서치 §2-3). 효과가 있었던 것은 **본인 데이터 피드백**(2주 후에도 유지) · **매입가 표시 제거**(−25%) · **미래 지향 프레이밍** · **벤치마크 대비**다. 이 기획서는 알림을 미러로 바꾼다.
- 사용자 요구(2026-09-24): *"진짜 돈 잘 벌 수 있게 도와주는 펀드 매니징 같은 느낌"*, *"사용자가 진짜 쉽게 사용할 수 있도록"*, *"UX UI 진짜 이쁘고 접근성 쉽고"*, *"계좌 연동은 안 하잖아, 우리는 다 사용자 수동으로 입력"*.
- 펀드매니저가 실제로 하는 일의 순서는 **위험 예산 → 사이징 → 규칙 → 기록 → 복기**다. 예측은 그 안의 한 입력이다.

## 목표

1. 사용자가 거래를 적을 때 **"이 크기가 맞나"** 를 서버 숫자로 본다(손실 예산 · 변동성 타깃 · 분수 켈리).
2. 계획(손절 · 이유)을 적은 거래는 **지켰는지**가 자동으로 채점되고, 지킨 거래와 안 지킨 거래의 성과가 나란히 보인다.
3. 처분효과 · 회전율 · 실수 비용 · 벤치마크 대비를 **본인 데이터**로 보여 준다. 남의 통계가 아니다.
4. 결정과 결과를 분리해 기록하고(W06), 월 1회 복기 리포트를 서버 수치 + 템플릿 문장으로 낸다.
5. 위 전부를 **추가 입력 2개 이내 · 새 화면 0개**로 한다.

## 사용자 시나리오

1. **거래 입력**(기존 폼 — 종목 · 매수/매도 · 수량 · 단가 · 날짜). 아래에 접힌 "계획(선택)" — `손절가` · `이유 한 줄`. 적으면 폼 옆에 즉시:
   `이 거래 최대 손실 −420,000원 · 내 월 손실 예산의 28% · 지금 변동성(연 52%)이면 참고 비중 24%(현재 31%)`. 안 적으면 그 자리에 `손절가를 적으면 손실 크기를 계산해요`.
2. **종목 상세**(`/investments/KRW-BTC`) 우측, 변동 범위 카드 아래 **"내 계획"** 카드: 손절 · 이유 · D+N · 손절까지 거리(원) · 4주 안 손절 도달 확률(F008 FR-7, 소유자) · `계획 세부 →`.
3. **포지션 화면** 상단 **리스크 게이지** 3개: `이번 달 낙폭 예산 −1,500,000 중 −620,000 사용(41%)` · `현재 집중도 BTC 71% (내 상한 60%)` · `연 회전율 3.2배 · 올해 수수료 184,000원`. 그리고 **매입가 숨김** 토글 — 켜면 평단 · 손익률이 사라지고 "오늘 처음 본다면?" 한 줄만 남는다.
4. **코치 리포트**(`/coach/report`) 에 **"내 거래 미러"** 섹션:
   - `익절은 평균 3.1일, 손절은 평균 19일 들고 있었어요 · 이익 실현 비율 62% vs 손실 실현 38%`(처분효과)
   - `그냥 들고 있었으면 +4.2% · 실제 −1.8% · 차이의 대부분은 수수료와 3번의 추격 매수`(벤치마크)
   - `계획을 적은 거래 14건 중 11건 지킴(79%) · 지킨 거래 평균 +1.9% · 안 지킨 거래 평균 −4.4%`
   - `실수 태그 비용: 추격 −310,000 · 물타기 −280,000 · 계획 외 −95,000`
   - `유형별 기대값: 급등 추격 −0.8R(표본 12) → 엣지 없음 표시`
   각 줄은 표본 수와 함께, 표본 20 미만은 `표본 부족` 배지.
5. **매도 입력** 때 프레이밍 한 줄(차단 아님): `이 종목을 오늘 처음 본다면 살까요? · 계획 손절 88,300,000 vs 지금 91,200,000 · 그냥 들고 있었으면 대비 +2.1%`. 입력은 그대로 진행된다.
6. **월초** 코치 리포트에 **월간 복기** 카드: 위 미러 요약 + IPS 이탈(상한 초과 일수) + "이번 달 한 가지" — 서버가 가장 비용이 큰 태그 하나를 고르고 템플릿 문장으로 쓴다.
7. **처음 한 번** 코치 대화에서 IPS 3문항: 월 허용 손실(원 또는 %), 1회 거래 최대 손실, 한 종목 상한. 답하지 않으면 게이지가 `기준을 정하면 보여요` 상태다. 언제든 설정에서 바꾼다.

### B. 포지션 사이즈 계산(W03 흡수)

| ID | 요구사항 | 우선 | 상태 |
|---|---|---|---|
| FR-4 | 거래 입력 폼에서 `종목 · 수량 · 단가 · 손절가` 가 있으면 서버가 계산한다: (a) **최대 손실 원화** = 수량 × (단가 − 손절가) + 수수료 · 갭 가정, (b) 1회 예산 대비 % · 월 예산 잔여 대비 %, (c) **예산 기준 참고 수량 상한** = min(1회 예산 ÷ (단가 − 손절가 + 단위 비용), 종목 상한 수량, 가용 현금 수량). 진입가 ≤ 손절가면 "손절가가 진입가보다 높아요" 상태 | Must | 서버 완료(S1) · 가용 현금 제외 |
| FR-5 | **변동성 타깃 참고 비중** = 목표 변동성 ÷ 종목 실현 변동성(EWMA 또는 GARCH, `salt-forecast` 가 일 1회 계산해 `forecast` 스키마에 적재). 현재 비중과 나란히. "비중을 줄이세요"가 아니라 두 숫자만 | Must | 서버 완료(S1 · S2) — EWMA 값 · 기준에 지는 종목은 `insufficient_data` |
| FR-6 | **분수 켈리**(선택 펼침): 사용자가 승률 · 손익비를 적으면 1/4 · 1/2 · 풀 켈리를 표시. 기본 표시는 1/4. 엣지 추정 오차 경고 문장 고정. 입력이 없으면 섹션 자체가 없다 | Should | 서버 완료(S1) |
| FR-7 | **N연패 시 낙폭** = 참고 수량 기준 "이 크기로 5번 연속 손절이면 −X원(예산의 Y%)" | Should | 서버 완료(S1) |
| FR-8 | 모든 금액은 서버 Decimal. 프론트는 표시. 음수 · NaN · 통화 혼합 · 현금 초과 차단(W03 수용) | Must | 서버 완료(S1) |

## UX 상태

- **Loading**: 카드 자리 스켈레톤(숫자 자리 고정 폭). 계산 결과는 입력 후 300ms 디바운스.
- **Empty(기준 없음)**: `기준을 정하면 보여요` + [3문항 답하기 →] (FR-2). 게이지는 회색 윤곽만.
- **Empty(표본 부족)**: 지표 자리 그대로 두고 `표본 부족 · 12 / 20` 배지. 값은 흐리게 표시(숨기지 않는다 — 성적을 숨기지 않는 원칙).
- **Insufficient data**: `손절가를 적으면 계산해요` · `변동성 데이터 준비 중(asOf …)`.
- **Error**: 카드 단위 격리. 미러 한 줄이 실패해도 나머지 줄은 보인다.
- **Unauthorized**: 코치 리포트 · 포지션 자체가 인증 뒤라 별도 상태 없음. 소유자 전용 줄(도달 확률) 은 비소유자 응답에 **없다**.
- **Success**: 계산 결과 `aria-live="polite"`. 저장 성공은 토스트 1줄, 모달 없음.

## 정책과 제약

### 보장하는 것 · 보장하지 않는 것 (사용자 질문 2026-09-24 "어느 정도 수익 보장은 해줘야")

| 보장한다 | 보장하지 않는다 · **문구로도 쓰지 않는다** |
|---|---|
| **손실 상한 계산** — "이 크기면 최악 −X원 · 내 예산의 Y%"는 산술이다. 계획을 지키면 예산 밖으로 나가지 않는다 | 수익 · 수익률 · 목표 달성. 자본시장법은 투자자문 · 유사투자자문 모두에서 **손실 보전 · 이익 보장 문구를 금지**한다(2025 일제검사 주요 적발 사유). SEC 도 같은 문구를 AI-washing 으로 집행 |
| **성적 공개** — 코치 판단 적중률 · 빗나간 사례 · 기준 대비를 매주 채점해 숨기지 않는다 | "AI 가 예측" · 합산 수익률 · 미실현 수익률 · 기간 · 표본 없는 적중률 |
| **벤치마크 대비 가시화** — "그냥 들고 있었으면"보다 나빠지고 있는지 매달 본인 숫자로 보인다 | 시장을 이긴다는 약속. 액티브 펀드 67% 가 지수를 못 이긴다(리서치 §6-4) |

- **통제 · 차단 · 타이머 · 약속 강제 없음**(2026-09-08 결정). 모든 판정은 정보 라벨, 사용자가 수정 가능.
- **계좌 연동 없음 · 전부 수동 입력**(2026-09-24 사용자). 실시간 체결 감지는 설계에 없다. 판정은 일 1회 배치 + 입력 시점 계산.
- **숫자 서버 · 문장 LLM(템플릿 기본)** · **개인 보유 · 금액은 LLM 프롬프트 금지**.
- **명령형 0건 · 한 점 목표가 0건 · 확신 표현 0건**. "비중을 줄이세요" 대신 "참고 비중 24% · 현재 31%".
- 성적 · 지표는 **숨기지 않는다**. 표본 부족은 흐리게 + 배지.
- 소유자 전용: F008 의 도달 확률만. 나머지 미러 · 계산은 모든 계정(본인 데이터라 개별성이 아니라 **본인 기록의 통계**다 — 자문이 아니다. Open Question 참조).

## 이벤트/상태 흐름

```
[사용자 거래 입력 + 계획(선택)] → POST /coach/plans + POST /portfolio/transactions
        └→ 즉시 POST /coach/size-check (예산 · 변동성 → 숫자 라인)
[매일 배치] forecast.realized_vol 갱신 → 준수 판정(TradePlan × 종가 × 거래) → DecisionOutcome(청산분)
        → 미러 집계(처분효과 · 벤치마크 · 회전율 · 태그 비용) → 읽기 뷰
[매월 1일] 월간 복기 생성(수치 → 템플릿) → 코치 리포트 카드
[사용자 태그 수정] → 원본 판정 보존 + 수정 레코드
```

- [ ] 거래 1건 + 계획 입력이 30초 이내(실측, 5회 평균). 추가 입력 필드 2개 이하, 전부 선택.

- [ ] 예산 3문항이 비어 있으면 게이지 · 사이즈 % 가 `기준을 정하면 보여요` — 0 · 기본값 표시 0건.
- [ ] 사이즈 계산 결과가 서버 Decimal 과 일치(프론트 재계산 0건). 진입가 ≤ 손절가 · 현금 초과 · 음수 차단.
- [x] 변동성 타깃 비중은 `forecast.realized_vol` 이 있을 때만, 없으면 `insufficient_data`(0 아님). (S2 — 서버 리더 실 DB 확인, HTTP 본문은 S3)
