# FEATURE-006: 코치 대화 & 3탭 IA

> **FEATURE-005를 대체한다.** 2026-09-09 사용자 결정으로 IA가 바뀌었다. FEATURE-005의 5탭안은 폐기하고 홈 블록 요구사항만 이 문서로 흡수한다.
>
> **2026-09-21 개정.** `ADR-002`(원장 · 청구서 · 세금 제거)와 스토리보드 갭 감사
> (`pm/requirements/reports/feature-audits/2026-09-21-storyboard-gap.md`)의 결정 D5 · D6 · D7 · D8 · D9와
> 기본안 B6 · B7 · B12 · B13 · B14 · B16 · B19를 반영했다. 홈은 **3블록**, 자산 탭은 `포지션` / `시장` / `관심 종목`,
> 알림은 **1종**이다. 청구서 · 세금에 걸린 문장은 전부 지우거나 바꿨다.

## TL;DR

- **대화가 제품의 핵심이다.** 코치와 자연어로 주고받는 것이 SALT의 중심이 된다. 서버에 `ai-coach`(점수 엔진 + LLM explainer) · `signal-performance` · `profit-plan` · `behavior-coach`가 이미 있고 화면만 없었다.
- **탭을 3개로 줄인다.** `홈` / `코치` / `자산`. 사용자 명시: *"너무 많은 탭은 별로"*.
- **PC는 탭이 아니라 이동식 격자다.** 코치 탭을 `MovableGrid`(이진 트리 분할)로 한 화면에 놓는다. 자산 탭 `시장`은 지금 2컬럼 그대로다(D7).
- 홈은 **3블록, 읽기 전용**: 총자산 → 이번 주 적립 → AI 추천. 그 아래 기존 목표 카드 · `AnalysisGraph` · `TipsApp`은 그대로다(D6). *(2026-09-21 개정 — 5블록 중 ④ 세금 D-Day · ⑤ 청구서는 ADR-002로 소멸)*
- 자산 탭은 `포지션` / `시장` / `관심 종목`(D7). 포지션은 보유 · 평가금 흐름 · 리스크 레이더 · **거래 기록 입력**이다(B13 · B14).
- 알림은 **1종(지표 · 추천 갱신)**(D5). 설정은 **한 화면**(D9).
- 추천은 어디에 렌더되든 **근거·과거 적중률·실패사례 3종**이 함께 붙는다. 하나라도 없으면 렌더하지 않는다.

## 배경과 문제

### 왜 5탭에서 3탭으로

FEATURE-005(2026-09-08)는 5탭(`홈`·`코치`·`청구서`·`세금`·`포지션`)을 제안했다. 하루 뒤 사용자가 그것을 되돌렸다 — *"너무 많은 탭은 별로"*.

실제로 5탭에는 문제가 있었다.

| 탭 | 방문 빈도 | 판정 |
|---|---|---|
| 홈 | 매일 | 유지 |
| 코치 | 매일 | 유지 |
| 청구서 | 주 1회 (월요일 변동분) | **상시 탭을 차지할 이유가 없다** |
| 세금 | 연말 + 5월 | **1년에 두 번 쓰는 것이 탭 하나를 차지한다** |
| 포지션 | 매일 | 유지 |

청구서·세금·포지션은 **모두 "내 자산에 대한 사실"** 이다. 하나로 묶인다.

> **2026-09-21 이후.** 청구서 · 세금이 `ADR-002`로 빠졌다. 자산 탭에 남는 것은 `포지션`과, 지금 `/investments`에
> 있는 **시장**(실시간 표 + 우측 AI 코치 패널)과 **관심 종목**이다(D7). "내 자산에 대한 사실"과 "시장에 대한 사실"을
> 한 탭의 세그먼트로 둔다 — 둘 다 종목 → 상세 분석 페이지로 이어진다.

### 왜 대화가 핵심인가

레퍼런스 앱이 오픈 API + LLM으로 "대화하듯 거래"를 내놓은 것을 보고 사용자가 판단했다: **우리는 이미 AI 코치가 있으니 그게 우리 핵심이다.**

그리고 대화는 이 제품의 구조와 맞는다.

- SALT의 결정은 네 개(얼마 넣을까 / 지금 뭘 할까 / 내 포트폴리오가 위험한가 / 내가 뭘 잘못했나)다. **네 개 다 질문 형태다.** *(2026-09-21 개정 — "언제까지 팔아야 하나(세금)"는 ADR-002로 빠지고 리스크 질문으로 바뀌었다)*
- 화면을 여러 개 만들어 답하는 대신, **묻고 답하는 하나의 화면**이 더 짧은 경로다.
- 근거·적중률·실패사례 3종은 **대화 안에서 카드로** 렌더하기에 적합하다.

### 왜 PC는 격자인가

모바일은 화면이 하나뿐이라 탭이 맞다. PC는 넓은데 탭으로 나누면 **한 번에 하나만 본다.** 사용자가 PC에서 원하는 것은 "코치 대화를 보면서 동시에 포지션과 추천 카드를 보는 것"이다.

`@repo/ui/movableGrid`가 이미 있다(이진 트리 분할, 끌어서 이동·크기 조절, 구분선 `role="separator"` + 화살표 키).

## 목표

1. 탭을 **3개로 고정**하고 그 밖의 화면은 탭 내부 이동으로만 존재하게 한다.
2. **코치 대화 화면**을 만들고 그것을 제품의 중심에 둔다.
3. 홈 첫 화면(스크롤 전)에서 총자산·이번 주 적립·AI 추천이 보이게 한다.
4. 홈은 계산하지 않는다 — 각 기능의 요약 필드만 조립한다.
5. PC에서 여러 패널을 동시에 볼 수 있게 한다.
6. 보유 자산을 원화로 합산해 하나의 숫자로 보여준다(서버 계산).
7. **보유 기록을 앱 안에서 직접 적고 고칠 수 있게** 한다 — 코치의 비중 · 손절 · 익절 계산이 이 기록에 기댄다(ADR-002 §3).
8. 알림 · 설정 · 검색 · 상세를 **탭을 늘리지 않고** 도달 가능하게 한다.

## 사용자 시나리오

### 모바일

1. 앱을 연다. 홈 첫 화면:
   - `총자산 187,420,000원` `+2,140,000 (+1.16%) 오늘`
   - `이번 주 적립 475,000원` — BTC 375,000 · VOO 100,000
   - `AI 코치 — 매수 · KRW-BTC · 점수 72` [근거 보기]
2. 아래로 스크롤하면 기존 목표 카드 · 투자 요약(`AnalysisGraph`) · 금융 팁(`TipsApp`)이 지금 모습 그대로 있다. 상단 헤더의 벨에 안 읽은 알림 수가 붙어 있다.
3. `AI 코치` 블록을 누르면 **코치 탭**으로 간다. 대화 화면이고 첫 메시지가 오늘의 추천 카드다.
4. `"지금 팔아야 하나?"` 라고 입력한다. 답이 **토큰 단위로 흐른다.** 답 안에 추천 카드가 붙고, 카드에는 근거·적중률·실패사례가 전부 있다.
5. `"왜 그렇게 생각해?"` 라고 되묻는다. 근거가 더 펼쳐진다.
6. `자산` 탭으로 간다. 세그먼트 3개: `포지션` / `시장` / `관심 종목`. 포지션에서 [거래 기록 추가]를 눌러 어제 산 BTC를 적는다. 저장 전에 **서버가 계산한 평단 전후**가 보인다.
7. `시장`에서 종목을 누르면 **상세 분석 페이지**로 push된다(내용은 F004).

### PC

1. 한 화면에 패널 여러 개가 놓여 있다.
   ```
   ┌────────────────┬───────────────┐
   │  코치 대화      │  추천 카드     │
   │                ├───────────────┤
   │                │  포지션 요약   │
   └────────────────┴───────────────┘
   ```
2. 패널 머리말을 끌어 자리를 바꾸고, 구분선을 끌어 크기를 조절한다.
3. 대화를 보면서 포지션 숫자가 동시에 보인다.
4. `자산 → 시장`은 격자가 아니라 **지금의 2컬럼**(실시간 표 + 우측 AI 코치 패널)이다(D7).

## UX 상태

- **Loading**: 블록별 스켈레톤. 총자산만 마지막 캐시값을 회색으로 먼저. 대화는 과거 메시지를 먼저 그리고 진행 중 응답에 `Spinner`.
- **Empty (온보딩 미완료)**: 온보딩 카드 1개.
- **Empty (대화 없음)**: FR-21의 브리핑 카드 + FR-22의 추천 질문 Chip. **빈 입력창만 보여주지 않는다.**
- **Partial (일부 블록 실패)**: 그 블록만 "지금 불러올 수 없습니다" + 재시도.
- **Blocked (3종 세트 미충족)**: 카드 대신 회색 박스 — "이 신호의 과거 성적 데이터가 아직 없어 추천을 표시하지 않습니다(표본 N건)". **이게 정상 동작임을 명시.**
- **Degraded (LLM 실패)**: 규칙 기반 문장 + `해설 생성 실패, 규칙 기반 설명` 배지.
- ~~Degraded (원장 불일치)~~: 청구서 · 세금 블록이 없어 소멸(ADR-002).
- **Empty (보유 0건)**: 포지션 Hero 대신 첫 기록 안내(FR-78). 총자산 블록도 "보유 기록이 없습니다" — `0원`이 아니다.
- **Empty (알림 없음)**: "새 알림이 없습니다". 벨 배지 숨김.
- **Offline (모바일)**: 캐시 + `마지막 갱신 시각`. 금액 화면은 "오프라인 · 시각 기준" 배너.
- **Optimistic update**: 없음. 홈은 읽기 전용이고 대화는 서버 응답이 내용이다. 거래 기록 · 설정 저장도 서버 응답 후 갱신한다. **읽음 처리만** 예외로 즉시 반영하고 실패 시 되돌린다(금액이 아니다).

## 정책과 제약

- **홈에 블록을 추가하지 않는다.** 새 기능이 생기면 기존 3블록 중 하나를 대체하거나 탭 내부로 들어간다.
- **탭을 4개로 만들지 않는다.**
- 홈은 계산하지 않는다. 계산은 각 컨텍스트(`portfolio` · F003 · F004).
- **대화가 주문을 실행하지 않는다.** 어떤 표현으로 요청해도 계산과 근거까지다.
- **3종 세트 게이트에 우회 플래그를 만들지 않는다.**
- 총자산 환율 기준(현재 환율)을 툴팁으로 명시. ~~세금 계산 기준과의 비교~~는 ADR-002로 소멸.
- **포지션의 모든 숫자(평단 · 손익 · MDD · 레이더)는 서버가 계산한다.** 프론트는 표시만.
- **FEATURE-000의 변경 금지 목록을 침범하지 않는다.** 홈 목표 진행 카드 · `AnalysisGraph` · `TipsApp` · 실시간 테이블은 이 IA 안에서 자리를 찾는다 — **삭제하지 않는다.**

> **FEATURE-005와의 차이:** FEATURE-005 FR-10은 `TipsApp`·`Goals`·`MarketIntelligencePreview`·`InvestmentFilterTabs` **삭제**를 요구했다. FEATURE-000 개정(같은 날)이 그것을 **변경 금지 목록으로 뒤집었다.** 이 문서는 FEATURE-000을 따른다 — 삭제하지 않고 3탭 안에 배치한다. **2026-09-21 확정(D6 · D7):** 목표 카드 · `AnalysisGraph` · `TipsApp`은 **홈 3블록 아래** 지금 모습 그대로, 실시간 테이블은 **`자산 → 시장`** 에 지금 2컬럼 그대로.

## 검증 계획

1. **탭/블록 스냅샷 테스트**: 순서와 개수 고정.
2. **부분 실패**: 3개 소스를 하나씩 실패시키는 3케이스 + 전체 실패 1케이스.
3. **스트리밍 순서**: 네트워크 스로틀 하에 블록 페인트 순서 확인.
4. **뷰포트 검수**: 375×667 / 390×844 / 1440 / PC 격자.
5. **대화 E2E**: 추천 질문 4개 각각 → 답변 도착 → 카드 렌더 확인.
6. **렌더 게이트**: 3종 각각 제거한 3케이스 + 전부 있는 1케이스.
7. **LLM 폴백**: 타임아웃·에러·빈 응답 3케이스.
8. **재연결 멱등**: 스트림 중 연결 끊고 재연결 → 메시지 1건 확인.
9. **주문 유도 방어**: "사줘"·"팔아줘"·"자동으로 해줘" 등 10개 프롬프트에 주문 실행 0건.
10. **카피 전수 검수**: 확신 표현·목표주가·인격 평가.
11. **접근성**: 탭바 role/aria, 대화 `role="log"`, 스크린리더로 총자산·추천 카드 낭독.
12. **성능**: 홈 첫 블록·전체, 코치 첫 토큰, 탭 전환, 대화 스크롤.
13. **변경 금지 검증**: FEATURE-000 목록 항목의 존재와 시각 동일성.
14. **거래 기록 왕복**: 매수 → 미리보기 평단 = 저장 후 평단, 과매도 거부, 수정 · 삭제 후 재계산.
15. **알림 읽음**: 3건 생성 → 1건 읽음 → 배지 2 → 모두 읽음 → 배지 0.
16. **ADR-002 잔재 스캔**: `grep -rn "/tax\|청구서\|세금 D-Day"` 화면 코드 0건.

## Open Questions

- **대화가 어디까지 답하는가.** "이 종목 어때?"에 개별 미국 주식 신규 매수 추천을 하면 1-3절 위반이다. **프롬프트 가드와 후처리 필터를 어떻게 설계할지** 확정 필요. 기본안: 미보유 개별 종목 질문은 "보유 종목의 비중·손절" 또는 "지수/ETF 단위"로 되돌린다(세금은 ADR-002로 빠졌다). 감사 Q3와 연결된다.
- **대화 컨텍스트 범위.** 매 질문마다 포트폴리오·지표·성적표를 전부 프롬프트에 넣으면 비용과 지연이 커진다. **어떤 질문에 어떤 컨텍스트를 붙일지 라우팅**이 필요하다.
- 대화 히스토리 보존 기간. 무한히 쌓이면 모바일 메모리와 프롬프트 비용 문제가 된다.
- ~~`자산` 탭 세그먼트 3개가 또 다른 탭 아닌가~~ → **2026-09-21 해소.** `시장`은 실시간 WS 화면이라 포지션과 한 번에 받을 수 없다. 세그먼트마다 경로를 두고 같은 zone 안 soft navigation으로 전환한다(FR-19).
- PC 격자의 기본 배치(패널 구성과 비율)를 무엇으로 할지. 사용자가 바꾼 배치를 저장할지.
- ~~목표 저축(`goal`)을 3탭 어디에 둘지~~ → **2026-09-21 해소(D6).** 홈 3블록 아래 지금 자리 그대로.
- **Q1 — `apps/web-tax` zone.** 세금이 빠져 zone이 서비스할 경로가 없다. 걷을지 다른 경계로 쓸지는 **이 문서가 정하지 않는다**(감사 Q1 · ADR-002 §5). 그때까지 코드는 두되 **진입 링크만** 뺀다(FR-4).
- **Q2 — 자산군 3종.** 거래 기록 시트의 첫 단계(자산군)와 총자산 환율 환산이 여기에 달려 있다. 자산군이 크립토 하나로 줄면 시트의 첫 단계와 환율 툴팁이 사라진다.
- **추천 질문 Chip 교체 문구.** "세금 언제까지?" 대신 "내 포트폴리오 위험한가?"로 둔 것은 이 문서의 판단이다(리스크 레이더가 근거). 사용자 확인 필요.
- **알림 켜기/끄기와 `notificationLevel`(F004)의 관계.** 둘 다 "알림"이다. 기본안: `alertsEnabled`는 **생성 여부**, `notificationLevel`은 코치가 **어떤 강도의 갱신을 알릴지**. 하나로 합칠 수 있으면 합친다 — F004와 같이 정한다.
- **리스크 레이더 축 정의 · 상한을 어디에 둘지.** 기본안: 서버 설정 파일(환경별). 사용자 편집 없음 — 설정 화면에 노출하지 않는다.
