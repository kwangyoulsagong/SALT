# FEATURE-007: 모바일 앱 (React Native · iOS + Android)

> **2026-09-21 개정.** `ADR-002`(원장 · 청구서 · 세금 제거)와 스토리보드 갭 감사
> (`pm/requirements/reports/feature-audits/2026-09-21-storyboard-gap.md`)의 결정 D5 · D6 · D7 · D9와 기본안 B21을 반영했다.
> 세금 D-Day 푸시 · 세금 화면 · 청구서 · CSV/계좌 연결을 지웠다. 푸시는 **1종(지표 · 추천 갱신)**, 앱 IA는 웹과 같은
> **3탭(홈 3블록 / 코치 / 자산 = 포지션 · 시장 · 관심 종목)** 이다. 모바일이 필요한 이유도 "마감일"에서 "바뀐 판단이 도달하는 것"으로 바꿨다.

## TL;DR

- **판단이 바뀐 순간이 도달해야 한다.** 코치 추천이 바뀌거나 밸류에이션 밴드가 바뀌어 이번 주 적립액이 달라지면, 웹을 열 때까지 기다리지 않고 알림이 간다. 푸시는 **이 1종뿐**이다(D5). *(개정 2026-09-21 — 세금 마감 알림은 ADR-002로 삭제)*
- `salt-microFe/apps/mobile`에 **React Native** 앱을 만든다. iOS와 Android를 하나의 코드로.
- IA는 웹과 같다 — **3탭**(`홈`/`코치`/`자산`). 홈은 3블록 + 기존 블록(D6), 자산은 `포지션` / `시장` / `관심 종목`(D7). 세금 · 청구서 화면은 없다.
- **비공개·초대제이므로 공개 스토어 출시를 하지 않는다.** iOS는 TestFlight, Android는 Play 내부 테스트.
- **웹 디자인 시스템을 재사용할 수 없다.** vanilla-extract는 RN에서 동작하지 않는다 → `packages/tokens` 추출 + `packages/ui-native` 신설.

## 배경과 문제

### 왜 모바일이 필요한가 — 결정에 시점이 있다

이 제품이 답하는 결정은 전부 시점이 있다. *(개정 2026-09-21 — "언제까지 팔아야 하나(세금 D-Day)" 행 삭제, ADR-002)*

| 결정 | 시점 | 모바일이 필요한 이유 |
|---|---|---|
| 이번 주 얼마 넣을까 | 월요일 아침 · 밴드가 바뀐 주 | 데스크톱 앞이 아니다. 밴드가 바뀌면 푸시가 온다 |
| 지금 뭘 할까 | 코치 추천이 바뀔 때 | 알림을 받고 즉시 본다 |
| 내가 뭘 잘못했나 | 매매 직후 | 거래소 앱에서 나온 직후다 — 거래 기록을 바로 남긴다 |

두 번째가 결정적이다. 추천이 바뀐 사실은 **바뀐 그날** 봐야 의미가 있고, "웹에 들어와서 확인하세요"로는 늦는다. 단, 알림은 **1종**으로 제한한다 — 가격 급등락 · 뉴스로 알림을 만들지 않는다(FOMO 방지, D5 · B19).

### 왜 PWA로는 안 되는가

**iOS의 웹 푸시 제약**이 핵심 기능을 막는다. 홈 화면 추가를 사용자에게 요구하는 것도 초대제 10명에게조차 마찰이다. 상세 비교는 `RN-REQ-001`.

### 왜 React Native인가

- 기존 React/TypeScript 역량을 그대로 쓴다.
- `entities`/`model`·BFF 뷰모델 타입·포맷터를 **`packages/core`로 공유**할 수 있다.
- Flutter는 Dart를 새로 배워야 하고 도메인 타입까지 두 번 정의하게 된다.

## 목표

1. **지표 · 추천 갱신 알림(1종)이 도달**하게 한다. *(개정 2026-09-21 — 세금 D-Day 삭제)*
2. iOS·Android에서 3탭 IA를 웹과 같은 정보 구조로 제공한다(홈 3블록 + 기존 블록 · 코치 · 자산 3세그먼트 · 상세 분석 push · 설정 한 화면).
3. **스토어 심사 없이 배포**할 수 있게 한다 (OTA).
4. 웹과 **시각·문구가 갈라지지 않게** 한다 (토큰 공유).
5. 오프라인에서 마지막 상태를 볼 수 있게 한다.

## 사용자 시나리오

1. 초대 링크로 TestFlight(또는 Play 내부 테스트) 초대를 받아 앱을 설치한다.
2. 앱을 열면 **초대 코드**를 입력한다. 그다음 **첫 보유 기록 입력**(건너뛰기 가능), **월 적립액**(실제로 저장). 3스텝으로 끝난다. *(개정 2026-09-21 — 계좌 연결 삭제, B12)*
3. 홈에 **총자산 → 이번 주 적립 → AI 추천** 3블록이 보이고, 그 아래 기존 목표 카드 · 투자 분석 · 금융 팁이 그대로 있다(D6).
4. **월요일 아침, 푸시가 온다** — `BTC 밸류에이션 밴드가 바뀌었습니다 · 이번 주 적립을 확인하세요`. 금액은 없다.
5. 알림을 누르면 적립 상세로 **딥링크**한다. 배수와 근거 · 실패 이력이 보인다. 업비트에서 산 뒤 [이번 주 적립 완료]를 누른다.
6. `코치` 탭에서 `"지금 BTC 비중 괜찮아?"` 라고 묻는다. 답이 흐르고 근거·적중률·실패사례가 붙은 카드가 온다. 종목을 누르면 **상세 분석 페이지**로 push된다.
7. 실제 매매는 거래소 · 증권사 앱에서 한다. 돌아와서 `자산 → 포지션`의 [거래 기록 추가]로 남긴다. SALT는 계산과 근거까지다.
8. 지하철에서 앱을 연다. 네트워크가 없다. **마지막 갱신 시각과 함께 캐시된 화면**이 보이고 금액에 "오프라인" 배너가 붙는다.
9. 며칠 뒤 계산 버그가 수정된 릴리스가 **스토어 심사 없이** 적용된다.

## UX 상태

- **Loading**: 스플래시 → 마지막 캐시를 먼저 그리고 갱신. **네트워크를 기다리지 않는다.**
- **Empty (온보딩 미완료)**: 초대 코드 화면.
- **Offline**: FR-30~33.
- **Blocked (버전 낮음)**: 업데이트 안내 화면. 진행 불가.
- **Blocked (3종 세트 미충족)**: 웹과 같은 회색 박스 + 사유.
- **Degraded (LLM 실패)**: 규칙 기반 문장 + 배지.
- **Error (푸시 권한 거부)**: 홈에 한 줄 안내 — "지표나 코치 추천이 바뀌면 알려 드릴게요 · 알림 허용". **반복해서 묻지 않는다.** *(개정 2026-09-21)*
- **Optimistic update**: 없음.

## 정책과 제약

- **공개 스토어 출시를 하지 않는다.** 글로벌 플랜 1-1절(비공개·초대제)이 배포 방식을 결정한다.
- **알림에 금액을 담지 않는다.**
- **주문을 실행하지 않는다.** 웹과 동일.
- **탭을 4개로 만들지 않는다.**
- **오프라인 큐를 만들지 않는다.**
- 웹과 **문구를 공유한다.** 확신 표현·목표주가·인격 평가 금지가 앱에도 그대로 적용된다.
- `MovableGrid`를 모바일에 만들지 않는다. **PC 전용**이다.

## 검증 계획

1. **실기기 스모크**: iOS 1대 + 저가 Android 1대. 3탭 순회 + 온보딩 완주.
2. **푸시 E2E**: 등록 → 발송 → 도달 → 딥링크 → 재검증. 두 플랫폼.
3. **중복 방지**: 같은 알림 생성 이벤트를 3회 흘려 기기당 발송 1건 확인. *(개정 2026-09-21)*
4. **알림 문구 검수**: 압박 표현·금액 노출.
5. **버전 게이트**: 낮은 버전 시뮬레이션 3케이스(네이티브 낮음 / OTA 런타임 불일치 / 정상).
6. **오프라인**: 기내 모드에서 홈 · 적립 상세 · 포지션 · 상세 분석 · 대화 각각. *(개정 2026-09-21)*
7. **접근성**: 스크린리더 낭독 + 폰트 최대 확대 + 터치 타깃 측정.
8. **성능**: 콜드/웜 스타트, 탭 전환, 리스트 스크롤, 대화 스트리밍 프레임. **릴리스 빌드로** 측정.
9. **보안**: 저장소 grep(토큰·키), 권한 목록, 알림 페이로드 캡처.
10. **배포**: TestFlight·Play 내부 테스트 각 1회 + OTA 1회 + 롤백 1회.
11. **문구 공유 검증**: 웹과 앱의 같은 화면 문구가 일치하는지(i18n 소스 하나).

## Open Questions

- **Apple Developer 계정($99/년)과 Google Play 개발자 계정($25)** 보유 여부. **없으면 배포가 시작되지 않는다.** 착수 전 확인 필수.
- 푸시 구현 방식 — Expo Notifications vs FCM/APNs 직접. **Expo를 쓰기로 한 이상 Expo Notifications가 기본안**이지만, 서버에서 직접 발송하려면 자격 증명 관리 방식이 갈린다.
- TestFlight 내부 테스터(100명, 심사 없음) vs 외부 테스터(경심사). **지인 10명이면 내부로 충분한지** 확인.
- 기준 저가 Android 기기를 무엇으로 정할지. 성능 예산의 측정 기준이 된다.
- 웹과 화면 로직이 두 번 구현된다. `packages/core`로 올릴 범위를 어디까지 할지 — **RN이 React Query를 쓰는지에 따라 `api` 공유 여부가 갈린다**(`RN-REQ-001` Open Question).
- 알림 설정을 서버에 둘지 기기에 둘지. 여러 기기가 있으면 서버가 맞다.
- ~~세금 마감 시기 릴리스 동결~~ → **닫힘 2026-09-21** — 세금이 없다(ADR-002).
- **주간 적립 전용 푸시가 없다**(D5 — 1종). 밴드가 바뀌지 않은 월요일에는 푸시가 없고 사용자가 앱을 열어야 한다. "월요일 아침 적립" 시점(배경 표 1행)을 푸시 없이 받아들일지. — 2026-09-21
- 홈 화면 위젯(iOS · Android)을 만들지. 1차는 범위 밖, 만들더라도 금액을 표시하지 않는다. — 2026-09-21
