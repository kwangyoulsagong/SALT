# DB-REQ-038 — 회고

## 2026-11-04 — 가계부 S1a

- jOOQ 생성기(H2 흉내)가 text 열 기본 키 · 유일 제약을 못 읽어 처음 빌드가 깨졌다. 제약을 `ALTER TABLE` 로 빼 `[jooq ignore]` 로 감쌌다 — `kotlin-platform.md` §4 의 인덱스 처리와 같은 방식이라 규칙 한 줄로 충분했다.
- 할부 표 · 사용자 분류 표 · 달별 예산을 미뤄 표 4개로 시작했다 — 미루는 이유를 슬라이스 판단에 적어 두었다.

## 2026-11-04 — 가계부 S1b

- 스펙의 "다음 예정일" 열을 두지 않고 `day_of_month` + 달마다 예정 행으로 — 저장한 다음 날짜는 고칠 때마다 다시 맞춰야 한다.
- 지출 FK 를 `SET NULL` 로 두면 CHECK(확인 ⇔ 지출)가 깨진다 — 막음으로 두고 유스케이스가 먼저 되돌린다.
- Action: 상태와 연결 열이 짝이면 CHECK 로 묶고, FK 동작은 그 CHECK 와 어긋나지 않게 고른다.

## 2026-11-04 — 가계부 S1c

- 민감 정보 두 표에 `COMMENT ON TABLE … 'sensitive'` — 카탈로그에서 찾을 수 있게. 생성기가 못 읽어 `[jooq ignore]` 안에 뒀다.
- 생성기 낱말과 겹칠 수 있는 열 이름(`day`)은 처음부터 피했다(`sticker_on`).

## 2026-11-04 — 가계부 S1d

- **잘 된 것**: "실패 없음"을 CHECK 로 — 화면 · 응답 어디서도 실패 상태를 만들 수 없다.
- **판단**: 스펙(`calendar_sticker` kind)을 따르지 않고 `challenge_day` 를 따로 — 적용된 V3 주석은 체크섬 때문에 못 고쳐 V4 머리와 이 REQ 에 남겼다.
- **Action**: 적용된 SQL 주석에 "다음 슬라이스에서 이렇게"를 쓰지 않는다 — 계획은 바뀌고 주석은 못 고친다.

## 2026-11-04 — 가계부 S1e

- **판단**: 후보 표를 두지 않았다 — 저장하는 것은 사용자가 정한 것(숨김)과 한 번만 낼 것(증가 기록)뿐. 표가 지출과 갈라질 길이 없다.
- **Action**: 없음 — V5 머리 주석에 "다음 슬라이스" 계획을 쓰지 않았다(S1d Action 지킴).

## 2026-11-05 — 가계부 S1f(`MONEY-S1f-household-categories-accounts`)

- **판단**: 사용자 분류를 지출 표 열이 아니라 새 표로 — 키만 지출에 남기고 이름 · 묶음은 한 행. 지우기는 보관이라 지난 지출이 이름을 잃지 않는다.
- **실수**: V6 머리 주석에 루트 슬라이스 경로를 `in-progress/` 로 적어 로컬 적용 뒤 고쳤다(체크섬 — push 전이라 되돌려 다시 적용).
- **Action**: 마이그레이션 주석의 슬라이스 경로는 처음부터 `done/`.

## 2026-11-05 — 가계부 S1g(`MONEY-S1g-household-story`)

- **실수**: V7 머리 주석의 슬라이스 경로를 또 `in-progress/` 로 썼다(S1f Action 을 못 지킴) — 로컬에서 되돌려 다시 적용.
- **Action**: 새 V 파일은 직전 V 파일 머리를 복사해서 시작한다.
