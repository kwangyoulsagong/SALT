# SRV-REQ-038 회고

## 슬라이스 1 (2026-09-24)

- 월 손익을 "실현 + 미실현"으로 나누면 평단을 되살려야 한다. **시가 평가 항등식**(지금 − 월초 − 순유입)으로 바꾸자 평단이 필요 없어졌고 전량 매도 종목도 자연히 들어왔다
- 잠금 규칙은 검사만으로는 거짓이다 — 검사와 쓰기 사이에 연결이 끼면 뚫린다. 조건을 **쓰기 문장**에 넣고, 가짜 저장소에 "끼어들기" 훅을 둬서 재현했다
- 없는 값(`realized_vol`)을 위해 없는 테이블을 조회하지 않았다. 포트만 먼저 열고 `null` → `insufficient_data` 로 흐르게 했다 — 슬라이스 2 는 메서드 하나만 바꾼다
- 기획서의 응답 필드 이름(`*Pct`)이 기존 계약 규칙(`*Rate`, 소수)과 달랐다. 초안 이름을 따르지 않고 기획서를 고쳤다

## Action

- 슬라이스 2: 월초 종가를 `v_daily_close` 로 바꿀지 판단 — 지금은 간격 무관 첫 캔들

## 슬라이스 4 (2026-09-27)

- 판정 · 결과 · 미러가 각자 원가를 매기면 "준수 거래 평균"과 "태그 비용 합"이 서로 다른 원가에서 나온다. **되감기 한 번**(`tradeLedger`)을 먼저 만들고 셋이 그것만 보게 했다
- `portfolio` 의 FIFO 는 매수 기록 없는 매도의 원가를 0 으로 본다. 그대로 쓰면 미러가 조용히 좋아진다 — 결과를 만들지 않고 따로 셌다
- "KST 09:00 vs UTC 00:00" 을 사용자에게 선택지로 물었는데 **같은 시각**이었다(업비트 일봉 경계). 묻기 전에 데이터 경계를 먼저 확인했어야 했다
- 테스트 손계산에서 14일 13시간을 13일로 적어 한 번 틀렸다 — 코드가 아니라 기대값 쪽 실수. 날짜 차이는 손으로 쓰지 말고 시각 두 개를 적는다
- 저장할 표가 없는 미러를 배치 → 읽기 뷰로 하려면 마이그레이션이 필요했다. 요청 시 계산이 14ms 라 기획서를 바꿨다

## 슬라이스 5 (2026-09-27)

- 입력 중 태그 후보를 배치와 **같은 규칙**으로 내려고 가상의 매수 한 건을 장부 끝에 붙여 `replayLedger` 를 다시 돌렸다. 규칙을 한 벌 더 쓰지 않아 폼과 배치가 갈릴 자리가 없다
- 미리보기를 사이즈 계산 응답에 붙이면서 **실패 격리**를 유스케이스 안에 뒀다(`previewBehavior` 가 잡고 `null`). 보조 줄이 사이즈 결과까지 끌고 내려가지 않게
- 행동 알림을 끄는 일이 "워커 한 줄 지우기"가 아니었다 — 같은 저장 행을 코치 상세 · 행동 코치 · 추천 점수 감점이 읽고 있었다. 셋을 요청 때 판정으로 옮기고 나서야 쓰기 경로를 지울 수 있었다. 소비처를 grep 으로 먼저 다 찾은 덕에 점수 감점이 조용히 0 이 되는 회귀를 피했다

## 슬라이스 6 (2026-09-27)

- 보유 대비(TWR)와 IPS 이탈 일수가 **같은 일별 평가금**을 봐야 해서 거래를 일봉에 붙이는 루프를 `portfolioSeries` 로 뽑고 `benchmarkMirror` 를 그 위로 옮겼다. 리팩터 뒤 슬라이스 4 테스트 19개가 그대로 통과한 것이 값 불변의 근거다
- 월간 복기를 "미러 응답에 요약 필드"(슬라이스 5 Action)로 하지 않았다 — 사용자가 **월초 저장**을 골랐다(태그를 고쳐도 그달 숫자가 남게). 저장은 JSON 스냅샷 한 행이고 이미 있으면 계산하지 않는다. 배치 · 첫 조회 둘 다 같은 유스케이스라 경합은 유니크 제약이 정리한다
- 스냅샷을 `JSON.stringify` 모양으로 두고 응답 때 `Decimal` 로 되살려 미러 변환 함수를 그대로 썼다 — 두 섹션의 반올림이 갈라질 자리를 없앴다
- Brier 기준 가격을 처음엔 "적은 날 종가"로 쓰려다 멈췄다 — 적은 뒤에 움직인 몫이 채점에 섞인다. 적기 전 마지막 닫힌 봉으로 정했다(누출 규칙과 같은 원칙)
