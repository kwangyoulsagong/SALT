흐름 전체는 루트 회고 `requirements/reports/retrospects/F004-symbol-judgment.md` · `F004-zone-gauge.md`.

## 1. 무엇을 했나

`GET /api/ai-coach?symbol` 응답에 `modes.{scalp,longTerm}`(판단 · `validity` · 게이트 · `trackRecord` ·
`failureCases` · `zone`) · `gaugeTrackRecords` · `disclaimer` 를 더하고 `confidence` 를 뺐다. 새 엔드포인트는 없다.
체크리스트 집계 pass 9 · 미충족 1(FR-48) · 범위 밖 1(FR-49) · 미착수 27.

## 2. 잘 된 것

- **BREAKING 을 한 커밋에 가뒀다.** `confidence` 제거는 `1b8abd4`(`feat(srv)!`) 하나에 있고 커밋 본문이 소비처
  영향(BFF `mapDecision` 은 `undefined` 를 옮기고 프론트는 grep 0건)을 적었다.
- **하위 호환 필드를 남겼다.** `modeDecision` · `dualDecision` 은 그대로 두고 `confidence` 만 뺐다(FR-41).
- **표본 0 과 `null` 을 구분했다**(FR-43). `winRate: null` · `sample: 0` 이라 화면이 "표본이 쌓이는 중"과
  "0%"를 헷갈리지 않는다.
- `failureCases` 항목을 문구가 아니라 코드와 숫자(`event` = `<mode>.<action>`, `returnRate`)로 줬다 — 문구는 프론트
  i18n 이다(REQ Changelog).

## 3. 틀렸던 것

기록된 것 없음 — 두 슬라이스에서 이 REQ 몫의 계약을 되돌린 커밋은 없다.

다만 explain **요청** 스키마에서 필수 `confidence` 가 함께 빠졌다(`coach.dto.ts`, `1b8abd4`). FR-30 이 적은 예외는
"종목 경로의 `confidence`" 하나뿐이다. `z.object` 가 모르는 키를 버려서 보내던 쪽은 깨지지 않지만, 예외 목록에는 없다.

> **Action:** FR-30 예외 문장에 explain 요청의 `confidence` 제거(D3 · FR-102)를 한 줄 더한다.

## 슬라이스 11 (2026-09-23) — 성적표 그룹 · 표본 시드

- **계약의 리터럴이 거짓일 수 있다.** 스펙은 `horizonDays: 30` 이었는데 단타 관찰 기간은
  24시간이다. 그대로 구현하면 화면이 "30일 수익률 분포"를 단타 표본 위에 그린다. 스펙을
  따르는 것과 사실을 말하는 것이 갈릴 때는 **스펙을 고치고 왜인지 남긴다**
- **경계가 두 곳에 있으면 갈라진다.** 구간 경계를 도메인 배열에 두고 SQL 이 그 배열을
  `FILTER` 로 펼치게 했다. 검증은 경계값 11개에서 SQL 과 정책 함수가 같은 구간을
  고르는지 본 것이고, 이건 단위 테스트로는 못 잡는다(SQL 이 다른 구현이다)
- **시드가 판정을 흉내 내면 안 된다.** 수익률은 지어내도 되지만 적중·실패는 `judgeOutcome`
  을 부른다. 그러지 않으면 판정 규칙을 바꿀 때 시드만 옛 규칙으로 남는다
- 멱등성은 **앵커를 자정으로 내려서** 얻었다. `new Date()` 를 쓰면 유니크가 잡지 못해
  돌릴 때마다 표본이 늘고, 성적표 숫자가 실행 횟수에 따라 달라진다
- 기존 무인자 경로와 새 그룹 경로가 **소스가 다르다**(저장 추천 이력 + 현재가 / 확정 스냅샷).
  하위 호환 요구가 한 경로에 두 계약을 남겼다 — 옛 경로를 언제 걷을지는 BFF 가 새 표를
  쓰기 시작한 뒤에 정한다

- explain abort 실측은 관측성 계측과 함께

## 슬라이스 12 (2026-09-23) — 코치 상세

- **"미결 판단"이 사실은 스펙에 답이 있었다.** 슬라이스 11 은 저장 추천의 성적 출처를 미결로 넘겼는데,
  `DB-REQ-019` FR-45 가 "연결이 없는 행은 게이트가 차단하고 그것이 정상"이라고 이미 쓰고 있었다.
  질문을 넘기기 전에 **짝 REQ(DB · FUNC)의 매핑 절을 먼저 grep** 했으면 한 슬라이스 일찍 닫혔다
- **막히는 것이 결과인 슬라이스다.** 추천 블록이 지금 전부 `failure_cases_missing` 이다. 화면이 비어 보이는 것을
  피하려고 종목 판단 성적을 빌려 오면 `coach.sell` 카드에 `long_term.avoid` 의 실패가 붙는다 — 3종 세트의
  취지를 거꾸로 만드는 편법이라 하지 않았다
- **같은 숫자는 같은 함수로.** 성적 표본(`collectPerformanceSamples`) · 가격선 거리(`priceGap`) · 익절 계산
  (`calculateProfitPlan`)을 기존 화면과 공유했다. 상세가 따로 세면 두 화면이 같은 판단에 다른 승률을 말한다
- **기존 성적 정의의 구멍을 발견만 했다.** `signal-performance` 는 행동과 무관하게 "가격이 올랐으면 적중"이라
  매도 추천이 상승장에서 적중한다. 옮겨 쓰기만 했고 바꾸지 않았다 — 규칙 변경은 PM 판단이다
- 토큰 발급 스크립트가 세션 권한에서 막혔다. 유스케이스를 실제 어댑터로 부르는 것으로 SQL 경로는 확인했지만
  HTTP 200 은 못 봤다. **인증 실측은 BFF 경유가 정석**이고 그 슬라이스로 넘긴다

## Action

- PM: 저장 추천(`coach.<action>`)의 적중 규칙 — 매도 · 관망 · 리밸런싱이 무엇이면 "맞은" 것인가
- `generate` 슬라이스에서 후보 근거(`candidates[].reasons`)를 저장한다
- BFF `/api/app/coach/report` 로 상세를 붙이고 인증 경로 200 을 BFF 경유로 실측한다

## 슬라이스 13 (2026-09-23) — 쿨다운 · 프로필

- **비동기로 바꾸자 기록 시점이 판단이 됐다.** 끝날 때 쓰면 생성 중 두 번째 요청이 쿨다운을 통과한다. 받는 순간
  `running` 으로 쓰고 끝나면 닫는다 — 스펙의 상태 셋에 없던 값을 하나 더했고 그 이유를 스키마 주석에 남겼다
- **쿨다운 기준을 무엇으로 하느냐가 제품 동작이다.** 거부를 세면 연타가 벌이 되고, 실패를 빼면 실패를 연타로 반복한다.
  "받아들인 수동 요청"으로 정했다
- **관측 기록이 로컬 이상을 먼저 보여 줬다.** 워커 생성이 같은 시각에 두 번씩 찍혔다 — 로컬 서버 프로세스가 두 벌이었다.
  기록이 없을 때는 알 수 없던 사실이다
- 응답 필드 제거(`unsupportedPersistedFields`)와 상태 코드 변경(202)을 하기 전에 **소비처를 grep 으로 확인**했다.
  BFF 는 `?? []` · 프록시만이라 깨지지 않았다 — 확인했다는 사실을 커밋 본문에 남겼다
