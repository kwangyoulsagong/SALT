# SRV-REQ-063 회고 — 해설 지난 날

## 무엇이 결함이었나

"판단이 의미 있게 바뀔 때만 다시 만든다"(지문)는 LLM 호출을 아끼려는 맞는 결정이었는데, **날이라는 축이 빠져 있었다.**
판정이 며칠 같으면 −9.87% 날에도 그날 해설이 없고, 며칠 전 문장이 '최신'으로 보였다. 보존 5벌도 같은 전제(최신 하나만 쓴다) 위에 있었다.
재료도 같은 전제였다 — "오늘" 등락 하나라 큰 하락 다음 날 반등만 말했다.

## 배운 것

- **캐시 키를 정할 때 "사용자가 무엇을 날짜로 읽나"를 같이 본다** — 해설은 사람이 "그날의 해설"로 읽는다. 키에 날이 없으면 화면이 거짓 '최신'을 보인다
- **보존 개수는 읽는 쪽이 정한다** — 5벌은 "최신만 쓴다"일 때 맞았다. 지난 날을 읽는 쪽이 생기면 보존 규칙이 같이 바뀌어야 한다(같은 커밋)
- DB 세션 시간대가 `Asia/Seoul` 이고 열은 시간대 없는 UTC — raw SQL 에 `Date` 를 그대로 넘기지 않는다(문자열 → `AT TIME ZONE 'UTC'`)
