# SRV-REQ-054 회고

## 2026-11-09

- 뽑기 규칙은 실데이터를 돌려 보고 세 번 고쳤다 — 포털 본문 칸이 글자를 블록 없이 직접 품어 사진 설명만 남았고(판 1), 언론사 페이지의 관련 기사 목록이 80문단으로 붙었다(판 3). 합성 픽스처만으로는 둘 다 안 보였다 — **실측 25 + 25건을 먼저 돌리고 규칙을 정했어야 했다**
- 찾음을 영구 캐시하니 틀린 뽑기가 영구로 남을 뻔했다 → 판 번호 열(`extractor_version`)을 표에 두어 규칙을 고치면 저절로 다시 찾게 했다. 영구 캐시를 두는 표엔 처음부터 판 번호를 둔다
- 표를 만든 직후 열을 더해 로컬 마이그레이션을 두 번 다시 적용했다(커밋 전이라 가능) — 캐시 표 설계에서 "규칙이 바뀌면?"을 먼저 물었어야 했다
- 받는 주소가 남이 정한 값이라 SSRF 를 처음부터 넣었다 — 주소 문자열이 아니라 DNS 를 푼 주소로 판정해야 리다이렉트 · 재바인딩이 같이 막힌다

## 2026-11-09 확인 2회차

- 결함 다섯이 전부 "한 번 실측 · 한 번 테스트"로 지나간 자리에서 나왔다. SSRF 는 DNS 조회만 막고 숫자 주소 경로를 생각하지 않았다 — **방어는 들어오는 모든 길(첫 주소 · 리다이렉트 · 숫자 주소)을 표로 적고 시작한다**
- 꼬리 줄 규칙을 "120자 미만 + 낱말 포함"으로 넓게 잡아 본문을 지웠다 — 지우는 규칙은 지우면 안 되는 문장 표를 먼저 쓴다
- 검색 두 번을 더하면서 BFF 예산(15초)을 다시 계산하지 않아 회귀를 냈다(결함 4 — BFF 쪽) — 단계를 더하면 위층 예산을 같은 커밋에서 다시 셈한다
