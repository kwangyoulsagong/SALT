# SRV-REQ-052 — 회고

## 단계 D(2026-11-12)

- **잘 된 것**: 해설 스냅샷 틀(배치 · 라우팅 · 상한 · 원장)을 그대로 써서 새 것은 프롬프트 · 검사 · 고르기 셋뿐. 문장에 분해 숫자를 넣지 않기로 하자 지문이 사실 목록만이 되고 장중 몫 변화로 LLM 을 다시 부르지 않게 됐다
- **결함(실측에서)**: 해설 배치가 24시간 LLM 상한 300 을 다 써 한 줄 배치는 매 회차 "다음 회차"만 셌다(시도 0). 같은 상한을 나중에 붙인 배치가 나눠 쓸 땐 앞 배치가 몫을 남겨야 한다 → 예약 30(`SRV-REQ-025`)
- **판단**: 조용한 날 문장을 저장하지 않았다 — 규칙이 결정적이라 요청 때 같은 답 · LLM 0. 대신 정직률을 뷰로 못 잰다(서버 경계 표가 그 몫)
- **다음**: 다음 카드 날 워커 로그로 정기 회차 생성 확인 · 첫 나빠짐 판정(시도 10)

## 확인 2회차(2026-11-12)

- "테스트 다 통과 · 실문장 3건 통과"에서 멈췄다면 장중 10분마다 사라지는 한 줄을 냈다. **한 시간 뒤 같은 종목을 다시 본 것**이 결함을 냈다 — 시간에 따라 바뀌는 입력(회차 시각)이 있는 기능은 첫 확인과 한 회차 뒤 확인을 둘 다 한다
- 공급자 고르기를 다시 짠 것은 구현 전 "같은 일을 하는 코드가 있나"(체크리스트 §2-1)를 라우터 파일 이름만 보고 넘긴 탓 — 상태를 든 클래스까지 봤어야 했다
