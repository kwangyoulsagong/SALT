# SRV-REQ-040 회고 — 슬라이스 0 · 1 (2026-10-07)

- 외부 API 오류 객체가 요청 헤더(시크릿)를 들고 다닌다는 점을 클라이언트 설계 첫 줄에 뒀다. 원본을 밖으로 내보내지 않는 것이 마스킹보다 확실하다
- KIS 는 업무 오류도 HTTP 500 — `isRetryableHttpError`(5xx 재시도) 공용 규칙을 그대로 쓰면 틀린다. 클라이언트별 판정이 필요하다
- 한도가 앱 키 단위인 외부 API 는 프로세스 페이서만으로 못 지킨다. 초과 신호에 물러서는 감속이 있어야 개발 환경에서 안전하다
- 순차 호출은 지연 × 건수다. 페이서와 동시 상한은 다른 것을 지킨다(출발 간격 · 매달린 수)
- 후속(같은 날): 보정 · 백필 · provider · 지표 · WS 장애 테스트를 닫으며 버그 넷(빈 키 · degraded · 15:30 종가 · 시간외 덮어쓰기)을 잡았다. 실패 횟수 초기화 지점처럼 **"성공"의 정의**가 접속인지 메시지인지가 장애 경로를 바꾼다
- 적응형 속도는 측정으로 버렸다(실패 0 · 2~2.7배 느림). 스스로 메워지는 실패(다음 회차)는 속도와 바꿀 가치가 없었다
- 슬라이스 3(2026-10-08): "같은 화면"이 되려면 같은 데이터가 먼저다 — 당일 고가/저가는 KIS 응답에 있었는데 저장하지 않고 있었다. 화면 열을 먼저 정하고 서버 필드를 거꾸로 셌어야 했다. 필터 값은 코인 문자열(`""` · `7d`)을 그대로 받아 계약을 한 벌로 뒀다

- 로고(FR-32): 판정 결과를 주소가 아니라 **출처**로 저장해 키 교체가 DB 를 건드리지 않게 했다. 외부 일시 실패는 판정을 미뤄(`none` 으로 저장하지 않음) 30일짜리 오판을 막았다. 이미지 디코더를 의존성 없이 쓴 것은 범위(깊이 8 · 비인터레이스)를 좁혀서 가능했다

## 슬라이스 4 (2026-10-08)

- **잘 된 것**: 표본을 섞지 않는 방법을 스키마 변경 없이 찾았다 — `signal_type` 문자열 접두. 코인 행은 그대로라 마이그레이션 · 백필이 없고 성적표 SQL 하나만 비용 `CASE` 를 얻었다
- **시장이 닫힌다는 것 하나가 세 곳에 나왔다**: 여는 조건 · 신선도 · 채점 종가. 코인 상수(30분 · 사흘 · 만기 뒤 첫 종가)를 그대로 쓰면 저녁마다 막히고 금요일 만기가 월요일 종가가 된다
- **찾은 구멍**: 해설(`ExplainCoachDecision`)이 종목 코치와 따로 막음을 조립해, 국내 주식을 코인 성적 · 코인 신선도로 판정하고 비소유자에게 사실을 줄 뻔했다 — 막음 재료를 `materialGuards` 하나로 묶었다. 같은 판단을 내는 경로가 둘이면 규칙도 두 벌이 된다
- **아쉬운 것**: 커밋을 판단 단위로 나누려 공유 파일을 잠시 되돌렸다가 zsh 가 변수 경로를 쪼개지 않아 stash 한 번을 헛돌렸다. 커밋마다 워크트리 단독 컴파일 · 테스트로 확인해 깨진 커밋은 없다
