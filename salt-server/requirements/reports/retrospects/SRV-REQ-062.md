# SRV-REQ-062 회고 — 웹 푸시

## 잘 된 것

- 라이브러리 없이 JDK 암호로 — RFC 부록 A 시험 벡터를 먼저 걸어 첫 실행에 바이트가 맞았고, 실 FCM · 실 브라우저가 풀어 상호 운용까지 닫았다
- 보내기 포트를 빈으로 두어 종단 시험이 밖으로 나가지 않는다 — 컨텍스트를 하나로 지키려고 가짜를 `@Configuration` 으로(통합 시험 전부가 같이 읽음)

## 고친 것

- 처음엔 보내기 유스케이스 안에서 트랜잭션 유스케이스를 `new` 했다 — 프록시가 없어 `@Transactional` 이 빠진다. 둘을 빈으로 꺼냈다
- 처음엔 종단 시험 하나만 다른 속성 · `@Import` 로 컨텍스트를 하나 더 띄우려 했다 — 연결 상한 규칙(`ContentEndToEndTest` 머리)을 보고 공용 속성으로 옮겼다

- 버그 검증에서 넷 — 저장 관문이 길이 · 머리 바이트만 봐서 곡선 밖 점이 들어오고, 보내기에서 던지면 이미 표시한 같은 회차 남의 푸시까지 잃었다. "표시 먼저"(많아야 한 번)와 "회차 중 예외"가 만나는 자리를 처음엔 안 봤다 — 표시 뒤 단계는 하나도 던지면 안 된다
- 사람이 넣는 주소로 서버가 요청하는 기능엔 개수 상한도 같이 — 허용 목록만으로는 증폭을 못 막는다
