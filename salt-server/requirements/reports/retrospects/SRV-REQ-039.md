# SRV-REQ-039 회고 — 성적 4요소 claim (2026-10-07)

## 결과가 기대와 달랐나

- 성적 자리마다 모양이 달라 "기간 · 빗나간 수" 를 붙일 데이터가 서버에 없는 곳이 둘(변동 범위 창 · 사건 빗나간 수 전체)이었다 — forecast 쓰기 주인에게 열을 더해야 했다
- 화면 라벨 "틀렸던 때 N건" 이 사례 목록 상한(3)을 세고 있었다. 숫자 하나가 기간 · 분모 없이 나가면 이렇게 조용히 틀린다
- 필드를 골라 옮기는 DTO(목표 비중)가 하나 있어 단위 테스트는 다 통과했는데 실스택에서 claim 이 비었다

## 잘한 것

- 판단 · 추천 · 성적표가 이미 같은 요약 함수를 거쳐 한 곳 수정으로 세 자리가 맞았다
- 빈 칸을 지우지 않고 이유 코드로 보냈다 — 목표 비중 빗나간 수를 사후에 정의하지 않았다
- 실스택(로컬 JWT → BFF)으로 확인해 DTO 누락을 머지 전에 잡았다

## 아쉬운 것

- 금지어 부정형 처리를 처음에 "아니" 하나로 짰다 — 한국어 활용("아닙니다")을 스크래치로 돌려 보고서야 알았다
- 판단 · 추천은 로컬 표본이 없어 실데이터 화면을 못 봤다

## Action

- 응답 DTO 가 필드를 고르는 경로는 유스케이스 뷰 타입과 대조하는 테스트를 둔다(다음에 DTO 를 만질 때)
- 새 성적 숫자를 응답에 낼 때는 같은 커밋에 `claim` 을 붙인다 — 4요소 없는 성적 필드를 만들지 않는다
