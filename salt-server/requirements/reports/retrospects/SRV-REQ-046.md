# SRV-REQ-046 — 회고

## 2026-11-04 — 가계부 S1a

- **잘 된 것**: 저축 첫 판의 꼴(네 층 · Composition · Flyway · 아웃박스 · 종단 테스트)을 그대로 옮겨 도메인 테스트 19개가 첫 실행에 통과했다. 파서를 순수 함수로 둬 "원문 0"을 함수 경계로 증명할 수 있었다.
- **리뷰가 찾은 것(1회)**: 착지 발행이 "그날 첫 저장 시점"에 고정돼 그날 나머지 지출이 구간 밖으로 샜다(말일은 한 점). 표본 시작을 지출 날짜 최솟값으로 잡아 지난날 대략 합계 한 건이 14일 문턱을 0원 날로 넘겼다. 둘 다 "시점이 바뀌는 값"을 계산 기준으로 쓴 실수 — 하루 단위 발행이면 기준도 하루 시작이어야 한다.
- **남긴 것(리뷰 지적이지만 고치지 않음)**: 지우기 이벤트 없음(구독자 생길 때) · 그날 이미 발행했어도 착지를 다시 계산하는 쿼리 2회(쓰기 응답 몫, 실측 지연 문제 없음) · 쿼리 수 테스트 없음.
- **Action**: 리뷰는 슬라이스당 1회(메모 `feedback-code-review-once`). 착지 채점이 붙을 때 `spent_so_far` 뜻(그날 시작 합)을 채점 쪽 문서에 적는다.

## 2026-11-04 — 백테스트가 찾은 것

- 10 · 90% 구간을 "이름표대로 맞는지" 재 보지 않고 첫 판을 냈다. 흉내 표본 36개월에서 67.9% — 긴 기간 창 합이 겹쳐 퍼짐이 줄어든 탓. 요일 평균 합 + 7일 합 퍼짐으로 82.1%.
- 3개월만 보면 한 달 안 적중끼리 얽혀 숫자가 크게 흔들린다(꾸준형 54~58%) — 보정 판정은 긴 기간으로.
- Action: 구간 · 분위를 내는 계산은 첫 판에 백테스트를 같이 둔다. 고정비는 반복 템플릿(S1b)이 빼야 월세형이 좁아진다.

## 2026-11-04 — 가계부 S1b

- **잘 된 것**: S1a 엔진 주석의 약속("반복 템플릿이 예정으로 따로 더하게 되면 뺀다")을 엔진 인자 하나(`scheduled`)와 날별 합 `FILTER` 한 문장으로 닫았다 — 엔진 본문은 그대로라 백테스트가 안 흔들린다.
- **판단**: 워커를 일 1회 대신 매시 — 멱등이니 회차를 늘려 놓친 회차를 메웠다. 확인 · 건너뛰기 · 처음 닫기는 전부 조건부 한 문장(경합에 오류 코드 0).
- **실수**: `INSERT … SELECT` 에 시각을 문자열로 넘겨 `timestamptz` 캐스트가 빠졌다 — 종단 테스트가 잡았다. jsonb 본문을 문자열로 비교해 테스트가 틀렸다(공백) → JSON 으로 읽어 비교.
- **Action**: 손 SQL(`dsl.execute`)에 시각을 넘기면 `?::timestamptz`. 이벤트 본문 검사는 JSON 으로.

## 2026-11-04 — 가계부 S1c

- **잘 된 것**: 본인 지출일 때만 태그가 붙는 것을 `INSERT … SELECT … ON CONFLICT` 한 문장으로 — 소유 확인 조회 · 오류 코드 분기 0. 다음 날 답 · 넘김도 조건부 UPDATE 하나.
- **판단**: 기록 없는 날 ≠ 안 쓴 날 — 스티커는 사용자 표시로만, 그날 지출이 생기면 숨김(지우지 않음). 달력 칸 상태 · 요일을 서버가 줘 프론트 날짜 계산 0.
- **실수**: 400일 경계 테스트의 "바로 밖" 달이 경계일을 품고 있었다 — 테스트 값만 고쳤다.
- **Action**: 경계 표의 바깥 값은 경계에서 한 달 이상 떨어뜨린다.

## 2026-11-04 — 가계부 S1d

- **잘 된 것**: "실패 없음"을 상태 둘 + 단계 셋으로 나눴다 — 저장은 `active` · `ended`, 화면 단계는 서버 계산. 기간이 지난 것과 그만둔 것이 같은 끝이라 화면이 둘을 가를 길이 없다.
- **판단**: 챌린지 스티커를 `calendar_sticker` kind 대신 `challenge_day` 로 — 어느 챌린지 날인지와 같은 날 두 챌린지를 남긴다. 저축 적립은 부르지 않고 "보탰다"만 조건부 UPDATE.
- **실수**: 종단 테스트가 저축 목표 id 를 응답 최상위에서 읽어 경로가 `//` → 401. 빈 이름을 도메인 코드로 기대(형식 검사가 먼저). 낱말 금지 검사가 응답 틀 `success` 에 걸림.
- **Action**: 낱말 금지 검사는 `data` 에만. 다른 서비스 응답 모양은 그 컨트롤러 View 를 보고 읽는다.

## 2026-11-04 — 가계부 S1e

- **잘 된 것**: 후보를 저장하지 않고 표본에서 센다 — 지출 지우기 · 고치기와 맞출 상태가 없다. 월 화면과 쓰기가 같은 `FixedCostReader` 를 쓴다.
- **판단**: 사슬의 앞 고리를 "비슷한 금액의 바로 앞 지출"로 — 매주 카페가 한 달 간격 사슬을 만들지 못한다(경계 표에 먼저 넣고 규칙을 정했다).
- **실수**: 종단 테스트 이름의 `%` 가 -Werror 경고로 막혔다 · 새 테스트를 `@TestConfiguration` 과 클래스 사이에 넣었다 · jsonb 텍스트의 `": "` 공백을 모르고 문자열을 비교했다.
- **Action**: 아웃박스 본문 확인은 `payload->>'key'` 로 읽는다(문자열 전체 비교 금지).

## 2026-11-05 — 가계부 S1f(`MONEY-S1f-household-categories-accounts`)

- **잘 된 것**: `Category` 를 enum 에서 키 값으로 바꾸면서 이름(`Category.FOOD` · `entries` · `fromKey`)을 그대로 둬 호출처 대부분이 손대지 않았다. 묶음만 `CategoryBook` 으로 옮겼다.
- **판단**: 통장 쪼개기를 분류가 아니라 "템플릿인가"로 가른다 — 내 분류와 엮이지 않고 고정비 찾기의 "매달 적기로"가 그대로 급여 통장이다.
- **실수**: 같은 식을 SELECT · GROUP BY 에 쓰며 상수를 바인드 변수로 둬 Postgres 가 거절(종단 22건). 
- **Action**: jOOQ 로 같은 식을 두 자리에 쓰면 상수는 `DSL.inline`.

## 2026-11-05 — 가계부 S1f 확인 단계

- 종단 테스트에 없던 길(보관한 분류 템플릿 고치기)을 실스택으로 확인하고 같은 확인 단계에서 종단 테스트로 넣었다(30). Action: "그대로 두면 받는다" 같은 예외 길은 만드는 커밋에 종단 테스트를 같이.
