## Summary

`tax` 컨텍스트의 도메인 로직. 자산군 3종의 규칙이 완전히 다르므로 **엔진을 자산군별로 나눈다.** 이 REQ의 핵심은 **손실 수확 솔버**와 **환율 함정 탐지** — 둘 다 다른 앱에 없는 것이고, 계산 가능하며, 놓치면 그냥 돈이 새는 것이다.

## 자산군 3종 — 규칙이 다르다

| | 크립토 | 국내주식(소액주주) | 미국주식 |
|---|---|---|---|
| 양도차익 과세 | **2027-01-01 시행** 예정. 22%, 연 250만원 공제, 분리과세 | **비과세** | **과세 중.** 22%, 연 250만원 공제 |
| 손익통산 | 가상자산 내 통산 | 해당 없음 | **해외주식 전체 합산 + 실현손실만** |
| 귀속연도 기준일 | 양도일 | — | **결제일 (T+1)** |
| 연말 마감 | 2026-12-31까지 매도 = **비과세**(1회성) | — | **매년.** 12/30 매도 → 12/31 결제 |
| 취득가액 | 이동평균/FIFO. 2027 전 보유분은 **max(실제, 2026-12-31 시가)** | — | 결제일 기준환율 원화 환산 |
| 그 외 | — | 거래세 0.20%(2026 인상), 배당 15.4%, 금융소득 2,000만원 경계 | 배당 15% 현지 원천징수 |

## 취득가액 엔진 (`policy/costBasis`)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | **이동평균법과 선입선출법 각각의 취득가액·차익을 병기**한다. SALT는 어느 쪽을 쓸지 **권고하지 않는다** | Must |
| FR-2 | lot 소진은 매도마다 순차 처리한다. FIFO는 `acquiredAt` 오름차순, 이동평균은 단일 가중평균 lot | Must |
| FR-3 | `remainingQuantity`가 음수가 되는 소진을 **예외로 막는다**(`LotOverConsumedError`) | Must |
| FR-4 | 외화 lot은 `unitCost`(체결통화)와 `unitCostKrw`(결제일 환율)를 둘 다 계산한다 | Must |
| FR-5 | **크립토 의제취득가액**: 2027-01-01 전 보유분은 `max(실제 취득가액, 2026-12-31 시가)`. 시가가 없으면 계산하지 않고 `degraded` | Must |
| FR-6 | 재계산은 **전량**이다. 증분하지 않는다 — 과거 거래가 늦게 들어오면 FIFO 순서가 바뀐다 | Must |

## 손실 수확 솔버 (`policy/harvest`) — 이 기능의 핵심

**문제:** 올해 실현차익 500만원 → 세금 55만원. 평가손실 300만원 종목을 **연내 결제까지** 실현하면 통산 후 200만원 → 공제 안 → **세금 0원.** 실현하지 않으면 그 손실은 올해 계산에 안 들어온다.

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-30 | 평가손실 보유 종목 집합에서 **과세표준을 목표값(기본 0)으로 만드는 매도 조합**을 계산한다 | Must |
| FR-31 | 후보 **3개**를 반환한다: ① `min_amount` 최소 매도금액 ② `min_symbols` 최소 종목 수 ③ `exact_deduction` 공제를 정확히 채우는 조합 | Must |
| FR-32 | **부분 매도 수량까지 산출**한다. 종목 단위 전량 매도만 제안하면 과세표준을 정확히 맞출 수 없다 | Must |
| FR-33 | 제약: 각 종목의 **매도 가능 수량 ≤ 보유 수량**, **결제 가능 마지막일**, **원화 손익 기준**(달러 손익 아님) | Must |
| FR-34 | `exact_deduction` 후보가 목표 과세표준을 **±1원**으로 맞춘다 | Must |
| FR-35 | 각 후보에 `mustSellBy`(권고 마감일)와 `caveats[]`를 붙인다 | Must |
| FR-36 | **재매수 안내는 사실로만** 한다: 국내 세법에 wash sale 규정이 없다는 점 + **재매수 시 취득가액이 낮아져 미래 과세가 늘어난다**는 점을 함께 표시. **재매수 권유 문구 금지** | Must |
| FR-37 | **매도를 유도하지 않는다.** 후보 3개는 대칭 렌더이고 추천 배지가 없다 | Must |
| FR-38 | 솔버는 **순수 함수**다. 입력을 한 번에 받고 계산 중 DB를 부르지 않는다 | Must |

## 환율 함정 탐지 (`policy/fxTrap`) — 다른 앱에 없는 것

**문제:** 원화 환산이 매수·매도 각 결제일 기준환율이므로 **달러로 손실인데 원화로 이익이 나서 세금이 나온다.** 매수 시 환율이 낮고 매도 시 높으면 발생한다. 사용자가 이걸 알 방법이 지금 없다.

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-40 | 종목별로 `sign(pnlUsd) != sign(pnlKrw)`인 경우를 탐지한다 | Must |
| FR-41 | **양방향 모두** 탐지한다: 달러손실/원화이익, 달러이익/원화손실 | Must |
| FR-42 | 매수 결제일 환율과 (가정된) 매도 결제일 환율을 함께 반환한다. **가정값임을 표시**한다 | Must |
| FR-43 | 미래 매도 시나리오의 환율 가정을 사용자가 바꿀 수 있게 파라미터로 노출한다 | Should |

## Acceptance Criteria

- [ ] 이동평균·FIFO 취득가액이 **둘 다** 계산되고 값이 다른 케이스가 테스트에 있다
- [ ] lot 초과 소진이 예외로 막힌다
- [ ] 크립토 의제취득가액이 `max(실제, 연말시가)`로 계산되고, 시가 없으면 `degraded`다
- [ ] **12/31 매도가 다음 과세연도로 집계된다**
- [ ] 마지막 매도일(12/30)과 권고일(12/29)이 둘 다 계산된다
- [ ] 캘린더 없는 날짜에서 영업일 가정이 0건이다
- [ ] 미국주식 실현손익이 결제일 기준환율로 원화 환산된다
- [ ] 환율 결측 종목이 분리되고 나머지가 계산된다
- [ ] **솔버가 후보 3개를 반환하고 `exact_deduction`이 목표 과세표준을 ±1원으로 맞춘다**
- [ ] 솔버 매도 수량이 보유 수량을 초과하지 않는다
- [ ] 솔버가 원화 손익 기준으로 계산한다
- [ ] 마감일이 지난 종목이 후보에서 제외된다
- [ ] 솔버 계산 중 DB 호출이 0건이다
- [ ] `caveats[]`에 "재매수 시 취득가액이 낮아져 미래 과세가 늘어난다"가 있고 **재매수 권유 문구가 0건**이다
- [ ] 후보에 추천 배지가 0건이다
- [ ] **달러 손실 / 원화 이익 케이스가 탐지된다** (합성 케이스)
- [ ] 반대 방향(달러이익/원화손실)도 탐지된다
- [ ] 크립토 3열이 계산되고 연내 매도 세금이 0이다
- [ ] **손익분기 연말시가 ±1원에서 유불리가 역전된다**
- [ ] 연말시가 < 취득가액에서 스텝업 절세액이 0원이다
- [ ] 3열에 추천 배지가 0건이다
- [ ] `kr_stock`에서 양도차익 계산이 0건이고 비과세 문구가 있다
- [ ] 대주주 기준 초과 시 경고가 나오고 판정 문구가 없다
- [ ] **크립토 시행일을 2029-01-01로 바꾸면 D-Day와 3열이 전부 재계산된다** (하드코딩 0건)
- [ ] `status` 4종 전환이 동작하고 `deferred`에서도 계산기가 돈다
- [ ] `lawConfigShown`이 응답에 있다
- [ ] 지시형·압박 문구가 서버 응답에 0건이다
- [ ] `unsupported[]`에 스테이킹·NFT·외국납부세액공제·파생상품이 노출된다

## Open Questions

- **결제일 기준환율 소스 확정** — F001 `SRV-REQ-014` Open Question과 동일. **이 기능의 정확도가 여기 달려 있다.**
- 세금 절사 규칙의 법령 근거. `roundingMode` 기본 `HALF_UP`.
- 솔버의 조합 탐색 방식. 종목 50개면 부분집합이 2^50이다 — **탐욕 + 부분 매도 조정**이 기본안이고 최적해를 보장하지 않는다는 점을 명시해야 한다.
- 원화마켓 "공시가 평균" 산정 방식(국세청 고시 확인).
- 해외주식 "전체 합산"의 범위. 미국 외 시장이 실제로 있는지.
