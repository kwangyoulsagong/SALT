## Summary

이 컨텍스트의 성능 목표는 처리량이 아니라 **정시성**이다. 지표 · 추천이 바뀐 사실(`signal_update` — 푸시 1종, D5 · 기본안 — 감사 문서 B21)이 **바뀐 그날 안에** 도달해야 한다. *(개정 2026-09-21 — "D-1 세금 알림 정시성"은 ADR-002로 소멸. 되돌릴 수 없는 마감이 없어졌으므로 SLO를 완화했다)*

### B. 버전 게이트 미들웨어

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | 게이트 판정에 **DB 조회가 없다.** 인메모리 캐시 + 5분 TTL | Must |
| FR-11 | 캐시 미스에서도 요청을 막지 않는다. **판정 불가 시 통과**시킨다(fail-open) | Must |
| FR-12 | semver 비교가 O(1)이고 정규식 컴파일이 요청마다 일어나지 않는다 | Must |
| FR-13 | 헤더가 없으면 **즉시 통과**한다. 파싱 비용 0 | Must |

**왜 fail-open인가**: 게이트는 보안 장치가 아니라 UX 장치다. 캐시 실패로 전원이 잠기는 것이 낡은 앱이 잠깐 도는 것보다 훨씬 나쁘다. (렌더 게이트와 반대 방향인 이유: 저쪽은 **잘못된 정보 노출**을 막고, 이쪽은 **호환성 안내**를 할 뿐이다.)

### C. 발송 처리량

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | provider 호출을 **배치 API**로 묶는다(Expo는 100건/요청) | Must |
| FR-21 | 전송은 **트랜잭션 밖**이고 동시성 상한을 둔다(기본 10) | Must |
| FR-22 | 전송 타임아웃 5s. 초과는 `FAILED` + 재시도 대상 | Must |
| FR-23 | provider rate limit 응답(429)에 **백오프**한다. 즉시 재시도가 0건이다 | Must |
| FR-24 | dispatch 워커는 **다중 인스턴스**로 수평 확장 가능하다(SKIP LOCKED) | Must |

### D. 발송 대상 산정 — 개정 2026-09-21

세금 D-Day 판정 워커(ADR-002로 삭제)를 **알림 생성 이벤트 → 발송 대상 산정**으로 바꿨다. 스파이크는 월요일 07:00 밴드 갱신이다(`DB-REQ-028` C절).

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-30 | 새 알림 × 활성 기기를 **쿼리 2회 이하**로 읽는다. N+1이 0건이다 | Must |
| FR-31 | INSERT를 **한 번의 `createMany`** 로 한다 | Must |
| FR-32 | 산정 전체가 **10초를 넘으면 알람**을 울린다 | Must |
| FR-33 | 산정이 다른 요청 경로의 커넥션을 고갈시키지 않게 **전용 풀 상한**을 둔다 | Should |

## 부하 시나리오

| 시나리오 | 조건 | 기대 |
|---|---|---|
| 월요일 밴드 갱신 동시 발송 (2026-09-21 개정) | 전 사용자 × 활성 기기 | 15분 이내 전건 `SENT` |
| provider 장애 | 전건 5s 타임아웃 | 재시도 3회 후 `FAILED`, 워커 생존 |

## Acceptance Criteria

- [ ] **`signal_update` 푸시가 알림 생성 + 15분 이내에 발송된다** (2026-09-21 개정)
- [ ] dispatch 워커가 1분 주기다
- [ ] **큐 적체 5분 알람이 있다**
- [ ] 발송 지연 분포가 메트릭으로 수집된다
- [ ] **게이트 판정에 DB 조회가 없고 오버헤드가 3ms 이하다**
- [ ] **게이트가 fail-open이다**
- [ ] 헤더 없는 요청이 즉시 통과한다
- [ ] provider 호출이 배치 API다
- [ ] 전송이 트랜잭션 밖이고 동시성 상한이 있다
- [ ] **429에 백오프하고 즉시 재시도가 0건이다**
- [ ] dispatch가 다중 인스턴스에서 중복 전송 0건이다
- [ ] **발송 대상 산정이 쿼리 2회 이하고 N+1이 0건이다**
- [ ] INSERT가 한 번의 `createMany`다
- [ ] 산정 10초 초과 알람이 있다
- [ ] 워커 커넥션 합이 풀의 30% 이하다
- [ ] KMS 복호화가 배치로 일어난다
- [ ] KMS 실패가 워커를 죽이지 않는다
- [ ] **알림 생성 후 15분 미발송 알람이 있다**
- [ ] 세금 D-Day 관련 예산 · 대시보드 · 알람이 0건이다 (ADR-002 · B21)
- [ ] 메트릭·로그에 토큰·금액이 0건이다
- [ ] 위 7개 부하 시나리오가 검증된다
